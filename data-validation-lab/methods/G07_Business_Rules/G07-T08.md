# G07-T08 — Business Rules | VAT / Tax Rate Validation

## ID
G07-T08

## Group
7 — Business Rules

## Type
VAT / Tax Rate Validation — Tax Rate Applied Is Not Valid for the Product or Jurisdiction

## Live Scenario
A multi-jurisdiction e-commerce platform sells products across the UK and EU. UK VAT rates are 20% (standard), 5% (reduced — children's car seats, home energy), and 0% (zero-rated — food, children's clothing). An EU VAT update in 2024 changes the rate for digital services from 20% to 17% in two member states. A developer updates the rate in the EU rate table but forgets to also update the rate lookup logic in the UK checkout. For three weeks, UK transactions on digital services are charged at 17% instead of 20%. The under-collected VAT must be retrospectively paid to HMRC, and customer invoices must be amended.

## The Question
> VAT and tax rates must match the valid rate for the product category and jurisdiction. An applied rate not in the valid set for that combination is a validation failure. SQL validates by joining to the rate reference table and flagging mismatches.
> **"Find all Products where VATRate is not in the valid UK VAT rate set (0, 5, 20), and find all Orders where the implied VAT amount doesn't reconcile with the product's VATRate."**

## Table Reference
**Products** — `schemas/03_Products.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Validate VAT rates against permitted values
DECLARE @ValidVATRates TABLE (Rate DECIMAL(5,2), Description VARCHAR(50));
INSERT INTO @ValidVATRates VALUES
    (0.00, 'Zero-rated (food, children''s clothing, books)'),
    (5.00, 'Reduced rate (home energy, children''s car seats)'),
    (20.00, 'Standard rate (most goods and services)');

SELECT
    p.ProductID,
    p.ProductName,
    p.ProductCode,
    p.VATRate,
    vr.Description AS ValidRateDescription,
    CASE
        WHEN p.VATRate IS NULL
             THEN 'MISSING: No VAT rate assigned'
        WHEN vr.Rate IS NULL
             THEN 'INVALID: ' + CAST(p.VATRate AS VARCHAR) + '% not a valid UK VAT rate'
        ELSE 'Valid: ' + vr.Description
    END AS VATValidation
FROM Products p
LEFT JOIN @ValidVATRates vr ON p.VATRate = vr.Rate
WHERE p.VATRate IS NULL
   OR vr.Rate IS NULL
ORDER BY p.VATRate;

-- Step 2: Implied VAT calculation vs expected
-- For each order, the expected VAT on TotalAmount depends on the product's VATRate
-- TotalAmount is assumed to be tax-inclusive; ex-VAT = TotalAmount / (1 + VATRate/100)
SELECT
    o.OrderID,
    o.TotalAmount AS GrossAmount,
    p.VATRate,
    ROUND(o.TotalAmount / (1 + p.VATRate / 100.0) * (p.VATRate / 100.0), 2) AS ImpliedVATAmount,
    ROUND(o.TotalAmount / (1 + p.VATRate / 100.0), 2) AS NetAmount,
    CASE
        WHEN p.VATRate = 20 THEN 'Standard rate order'
        WHEN p.VATRate = 5  THEN 'Reduced rate order'
        WHEN p.VATRate = 0  THEN 'Zero-rated order'
        ELSE 'Non-standard rate'
    END AS VATCategory
FROM Orders o
JOIN Products p ON o.ProductID = p.ProductID
WHERE p.VATRate IS NOT NULL
ORDER BY o.OrderID;

-- Step 3: VAT collected by rate — reconciliation summary
SELECT
    p.VATRate,
    COUNT(o.OrderID) AS OrderCount,
    SUM(o.TotalAmount) AS GrossRevenue,
    ROUND(SUM(o.TotalAmount / (1 + p.VATRate / 100.0)), 2) AS NetRevenue,
    ROUND(SUM(o.TotalAmount / (1 + p.VATRate / 100.0) * (p.VATRate / 100.0)), 2) AS VATCollected
FROM Orders o
JOIN Products p ON o.ProductID = p.ProductID
WHERE p.VATRate IS NOT NULL
GROUP BY p.VATRate
ORDER BY p.VATRate DESC;

-- Step 4: Products with VATRate outside 0–100 range (impossible)
SELECT
    ProductID,
    ProductName,
    VATRate,
    CASE
        WHEN VATRate < 0   THEN 'IMPOSSIBLE: Negative VAT rate'
        WHEN VATRate > 100 THEN 'IMPOSSIBLE: VAT rate > 100%'
        ELSE 'Range plausible'
    END AS RangeCheck
FROM Products
WHERE VATRate < 0 OR VATRate > 100;

-- Step 5: Change detection — products whose VAT rate changed recently
-- In a real system, use an audit table; here we compare VATRate across product categories
SELECT
    LEFT(ProductCode, 3) AS CategoryCode,
    COUNT(DISTINCT VATRate) AS DistinctRates,
    STRING_AGG(CAST(VATRate AS VARCHAR) + '% (P' + CAST(ProductID AS VARCHAR) + ')', ', ')
        WITHIN GROUP (ORDER BY VATRate) AS AllRates,
    CASE
        WHEN COUNT(DISTINCT VATRate) > 1
             THEN 'WARNING: Mixed VAT rates in same product category'
        ELSE 'Consistent'
    END AS CategoryConsistency
FROM Products
WHERE VATRate IS NOT NULL AND ProductCode IS NOT NULL
GROUP BY LEFT(ProductCode, 3)
HAVING COUNT(DISTINCT VATRate) > 1;
```

## Expected Output

**Step 1 — Invalid VAT rates:**
| ProductID | ProductName | VATRate | VATValidation |
|---|---|---|---|
| P008 | Digital Service A | 17.00 | INVALID: 17% not a valid UK VAT rate |
| P015 | Widget B | NULL | MISSING: No VAT rate assigned |

**Step 3 — VAT reconciliation:**
| VATRate | OrderCount | GrossRevenue | NetRevenue | VATCollected |
|---|---|---|---|---|
| 20.00 | 15 | 18000.00 | 15000.00 | 3000.00 |
| 5.00 | 3 | 3150.00 | 3000.00 | 150.00 |
| 0.00 | 2 | 500.00 | 500.00 | 0.00 |

## Explanation

**Valid rate set vs range check**
VAT rates are not continuous — they are discrete approved values (0, 5, 20 in the UK). A range check (`BETWEEN 0 AND 100`) is insufficient; a rate of 17% looks plausible but is invalid in the UK context. Membership validation against a reference table of valid rates is the correct approach.

**Tax-inclusive vs tax-exclusive amounts**
`TotalAmount / (1 + VATRate/100)` extracts the net (ex-VAT) amount from a tax-inclusive gross. `Net × VATRate/100` gives the VAT component. Getting the denominator wrong (dividing by `VATRate/100` instead of `1 + VATRate/100`) is a common calculation error that produces different amounts.

**Category-level consistency**
Step 5 checks whether all products in the same category have the same VAT rate. Different rates within a category (e.g., some digital services at 20%, others at 17%) indicate either a legitimate rate exception (requiring documentation) or a data entry error (one product updated, others not).

**Jurisdiction complexity**
This example uses UK-only rates. A multi-jurisdiction system needs a `(Country, Category) → VATRate` mapping table. Different countries have different rates for the same product category — e-books are VAT-exempt in some EU states but standard-rated in others.

## Severity
**High** — Incorrect VAT rates create tax liability exposure: under-collected VAT must be paid to HMRC from revenue rather than collected from customers. Over-collected VAT requires customer refunds and invoice amendments. Both require regulatory reporting. In severe cases, incorrect VAT treatment may constitute a criminal offence under the VAT Act 1994.
