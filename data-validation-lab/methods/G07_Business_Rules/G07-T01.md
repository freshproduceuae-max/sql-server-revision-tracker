# G07-T01 — Business Rules | Minimum Order Value

## ID
G07-T01

## Group
7 — Business Rules

## Type
Minimum Order Value — Order Amount Below Business-Defined Threshold

## Live Scenario
An e-commerce platform's terms and conditions state a minimum order value of £10.00 for standard checkout. A promotional campaign engineer tests a £0.01 coupon code that reduces any order to £0.01, but the validation logic that enforces the minimum order value runs before the coupon is applied. When the coupon is applied as a post-checkout adjustment, the final order total drops to £0.01 — below the minimum. The platform processes 1,200 sub-minimum orders during the 48-hour campaign window before the issue is noticed. Fulfilment costs (pick, pack, ship) average £4.50 per order, resulting in a loss on every sub-minimum transaction.

## The Question
> Business rules define constraints that go beyond data type validity. A minimum order value is a business rule: an order is structurally valid (a positive decimal) but violates business policy if it is below the threshold. SQL enforces these post-hoc.
> **"Find all Orders where TotalAmount is below £10.00, and classify them by severity: free (£0), token (< £1), and below-minimum (£1–£9.99)."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Orders below minimum order value
DECLARE @MinOrderValue DECIMAL(10,2) = 10.00;

SELECT
    o.OrderID,
    o.CustomerID,
    o.OrderDate,
    o.TotalAmount,
    o.Status,
    CASE
        WHEN o.TotalAmount = 0           THEN 'FREE: Zero-value order'
        WHEN o.TotalAmount < 0           THEN 'INVALID: Negative order amount'
        WHEN o.TotalAmount < 1.00        THEN 'TOKEN: Under £1.00'
        WHEN o.TotalAmount < @MinOrderValue THEN 'SUB-MINIMUM: Below £10 threshold'
        ELSE 'Within minimum order value'
    END AS MinOrderViolation
FROM Orders o
WHERE o.TotalAmount < @MinOrderValue
ORDER BY o.TotalAmount;

-- Step 2: Customer breakdown — repeat sub-minimum offenders
SELECT
    o.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    COUNT(*) AS SubMinOrderCount,
    SUM(o.TotalAmount) AS TotalSubMinSpend,
    AVG(o.TotalAmount) AS AvgSubMinOrder,
    MIN(o.TotalAmount) AS LowestOrder,
    MIN(o.OrderDate) AS FirstSubMinDate
FROM Orders o
JOIN Customers c ON o.CustomerID = c.CustomerID
WHERE o.TotalAmount < @MinOrderValue
  AND o.TotalAmount >= 0
GROUP BY o.CustomerID, c.FirstName, c.LastName
ORDER BY SubMinOrderCount DESC;

-- Step 3: Revenue impact — what valid orders would have generated
SELECT
    COUNT(*) AS SubMinOrderCount,
    SUM(TotalAmount) AS ActualRevenue,
    COUNT(*) * @MinOrderValue AS RevenueIfAtMinimum,
    COUNT(*) * @MinOrderValue - SUM(TotalAmount) AS RevenueLost
FROM Orders
WHERE TotalAmount < @MinOrderValue
  AND TotalAmount > 0;

-- Step 4: Sub-minimum orders by month (trend analysis)
SELECT
    YEAR(OrderDate) AS OrderYear,
    MONTH(OrderDate) AS OrderMonth,
    COUNT(*) AS SubMinCount,
    SUM(TotalAmount) AS TotalSubMinAmount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY YEAR(OrderDate)), 1) AS PctOfYearlySubMin
FROM Orders
WHERE TotalAmount < @MinOrderValue
  AND TotalAmount >= 0
GROUP BY YEAR(OrderDate), MONTH(OrderDate)
ORDER BY OrderYear, OrderMonth;

-- Step 5: Product-level check — are any products priced below the minimum order value?
SELECT
    ProductID,
    ProductName,
    Price,
    CASE
        WHEN Price < @MinOrderValue THEN 'ISSUE: Product price below minimum order value — cannot be ordered alone'
        ELSE 'Price above minimum order value'
    END AS PriceMinCheck
FROM Products
WHERE Price < @MinOrderValue AND Price > 0
ORDER BY Price;
```

## Explanation

**Business rules vs database constraints**
A CHECK constraint can enforce `TotalAmount >= 10.00` at write time. But business rules involving promotions, discounts, and compound calculations often cannot be enforced by a simple column-level constraint — they require application logic or validation queries to catch violations after all modifications are applied.

**Negative orders as a separate violation**
A negative TotalAmount is a different class of violation from a sub-minimum positive amount. Step 1 handles both: negative values indicate sign errors or unprocessed refunds; sub-minimum positive values indicate the minimum order rule was bypassed.

**`PARTITION BY YEAR` for within-group percentage**
`COUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY YEAR(OrderDate))` computes what percentage of each year's sub-minimum orders fell in each month. This helps identify whether the violation is seasonal (promotional periods) or systematic (a permanently broken validation rule).

**Product price vs order minimum**
Step 5 identifies products whose unit price is below the order minimum — meaning a single-item order of that product inherently violates the minimum. These products can only be bought in multi-item baskets, or the business rule needs an exception for them.

## Severity
**Medium** — Sub-minimum orders may be individually small losses, but at scale they erode margins. The severity depends on fulfilment cost relative to order value: if fulfilment costs £4.50 and the order is £0.50, the unit economics are severely negative. At high volume, this represents a material operating loss.
