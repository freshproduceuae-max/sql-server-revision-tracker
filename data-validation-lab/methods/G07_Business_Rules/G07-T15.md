# G07-T15 — Business Rules | Inactive Product or Customer Usage

## ID
G07-T15

## Group
7 — Business Rules

## Type
Inactive Product or Customer Usage — Activity on Deactivated or Discontinued Records

## Live Scenario
A retail chain discontinues a product line (`IsActive = 0`) after a product recall due to safety concerns. The product is delisted from the website and removed from the point-of-sale system. However, a third-party marketplace integration was not updated and continues to list the recalled product. Over 8 weeks, 234 orders are placed through the marketplace for the discontinued product. The orders are fulfilled from remaining warehouse stock (the warehouse system did not have the recall flag). Regulatory action by the Trading Standards Authority results in a £45,000 fine and a mandatory recall notice.

## The Question
> Transactions, orders, and other activities must only involve records that are currently active and permitted for use. An order for a discontinued product, a transaction linked to a closed account, or a target set for an inactive employee all represent business rule violations that SQL can detect.
> **"Find all Orders that reference a Product with IsActive = 0, all SalesTargets for Employees who are terminated, and all Customers with IsActive = 0 who still have open orders."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`
**Customers** — `schemas/01_Customers.csv`
**SalesTargets** — `schemas/06_SalesTargets.csv`
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Step 1: Orders for inactive products
SELECT
    o.OrderID,
    o.CustomerID,
    o.ProductID,
    o.OrderDate,
    o.Status,
    o.TotalAmount,
    p.ProductName,
    p.IsActive AS ProductIsActive,
    CASE
        WHEN p.ProductID IS NULL THEN 'ORPHAN: Product record not found'
        WHEN p.IsActive = 0      THEN 'VIOLATION: Order for discontinued product'
        ELSE 'Product active'
    END AS ProductActiveCheck
FROM Orders o
LEFT JOIN Products p ON o.ProductID = p.ProductID
WHERE p.ProductID IS NULL OR p.IsActive = 0
ORDER BY o.OrderDate DESC;

-- Step 2: Sales targets for terminated employees
SELECT
    st.TargetID,
    st.SalespersonID,
    st.Year,
    st.Quarter,
    st.TargetAmount,
    e.FullName,
    e.TerminationDate,
    DATEDIFF(DAY, e.TerminationDate, GETDATE()) AS DaysSinceTermination,
    CASE
        WHEN e.EmployeeID IS NULL           THEN 'ORPHAN: Employee not found'
        WHEN e.TerminationDate IS NOT NULL
             AND e.TerminationDate < GETDATE()
                                            THEN 'VIOLATION: Target for terminated employee'
        ELSE 'Employee active'
    END AS EmployeeActiveCheck
FROM SalesTargets st
LEFT JOIN Employees e ON st.SalespersonID = e.EmployeeID
WHERE e.EmployeeID IS NULL
   OR (e.TerminationDate IS NOT NULL AND e.TerminationDate < GETDATE())
ORDER BY e.TerminationDate;

-- Step 3: Inactive customers with open orders
SELECT
    c.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    c.IsActive AS CustomerIsActive,
    o.OrderID,
    o.Status,
    o.TotalAmount,
    o.OrderDate,
    'VIOLATION: Open order for inactive customer' AS Issue
FROM Customers c
JOIN Orders o ON c.CustomerID = o.CustomerID
WHERE c.IsActive = 0
  AND o.Status IN ('Pending', 'Processing', 'Shipped')
ORDER BY o.OrderDate DESC;

-- Step 4: Inactive products with recent activity summary
SELECT
    p.ProductID,
    p.ProductName,
    p.IsActive,
    COUNT(o.OrderID) AS OrdersSinceDeactivation,
    SUM(o.TotalAmount) AS RevenueFromInactiveProduct,
    MIN(o.OrderDate) AS EarliestOrderDate,
    MAX(o.OrderDate) AS MostRecentOrderDate
FROM Products p
JOIN Orders o ON p.ProductID = o.ProductID
WHERE p.IsActive = 0
GROUP BY p.ProductID, p.ProductName, p.IsActive
ORDER BY OrdersSinceDeactivation DESC;

-- Step 5: Summary of all inactive entity activity
SELECT 'Orders on inactive products' AS Violation, COUNT(*) AS Count
FROM Orders o JOIN Products p ON o.ProductID = p.ProductID WHERE p.IsActive = 0

UNION ALL

SELECT 'Targets for terminated employees', COUNT(*)
FROM SalesTargets st
JOIN Employees e ON st.SalespersonID = e.EmployeeID
WHERE e.TerminationDate IS NOT NULL AND e.TerminationDate < GETDATE()

UNION ALL

SELECT 'Open orders for inactive customers', COUNT(*)
FROM Orders o
JOIN Customers c ON o.CustomerID = c.CustomerID
WHERE c.IsActive = 0 AND o.Status IN ('Pending','Processing','Shipped')

ORDER BY Count DESC;
```

## Explanation

**IsActive as a soft-delete flag**
`IsActive = 0` is a soft-delete pattern: the record is retained for historical purposes but should no longer participate in new transactions. Validation checks that `IsActive = 0` records are not referenced by active records in other tables.

**Timing of deactivation**
Step 4 aggregates all orders on inactive products without filtering by date — some orders may predate the deactivation (legitimate historical orders). In production, add `WHERE o.OrderDate > p.DeactivatedDate` to focus on post-deactivation violations. This requires storing a `DeactivatedDate` on the Products table.

**Cascade deactivation responsibility**
When a product is deactivated, the business process should:
1. Remove it from all active listings (marketplace, POS, website)
2. Cancel or redirect pending orders
3. Update stock management to prevent further fulfilment
SQL validation catches failures in any of these steps.

**Employee termination cascade**
Sales targets for terminated employees should be either reassigned or closed. Leaving them open means commission reports include terminated employees, confusing comparison reports and potentially triggering commission payments to closed accounts.

## Severity
**High** — Orders for recalled or discontinued products may violate product safety regulations (Trading Standards, Consumer Protection Act). Orders for inactive customers create fulfilment, billing, and data protection issues (processing data for a GDPR-closed account). Both have direct regulatory and financial consequences.
