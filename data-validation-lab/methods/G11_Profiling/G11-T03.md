# G11-T03 — Profiling | Numeric Column Statistics

## ID
G11-T03

## Group
11 — Profiling

## Type
Numeric Column Statistics — Computing Descriptive Statistics to Understand Value Range and Distribution

## Live Scenario
A risk analyst receives a dataset of loan application amounts from a partner bank. Before using these amounts in a risk model, they profile the column. MIN is £500 (plausible), MAX is £9,999,999 (suspiciously high — the bank's product cap is £50,000). MEAN is £8,420, but MEDIAN is £4,200 — a large mean-median gap indicating right-skew from extreme values. Standard deviation is £47,000 — larger than the mean, indicating massive spread. The analyst runs a percentile analysis: P99 is £68,000 (above the £50,000 cap) and P99.9 is £9,999,999. The 0.1% of values above the product cap are almost certainly data entry errors (max integer value entered when the field is blank) — they would inflate the risk model's average loan size by 15%.

## The Question
> Numeric column statistics provide the descriptive summary of a column's distribution: minimum, maximum, mean, median, standard deviation, and percentiles. SQL computes these using aggregate functions and window functions, producing a full statistical profile in a single query.
> **"Produce complete descriptive statistics for TotalAmount in Orders and Amount in Transactions: min, max, mean, median, standard deviation, and key percentiles (P25, P75, P90, P95, P99)."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Transactions** — `schemas/05_Transactions.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Full descriptive statistics for Orders.TotalAmount
SELECT
    COUNT(*)                                              AS RowCount,
    COUNT(TotalAmount)                                    AS NonNullCount,
    COUNT(*) - COUNT(TotalAmount)                         AS NullCount,
    MIN(TotalAmount)                                      AS MinValue,
    MAX(TotalAmount)                                      AS MaxValue,
    MAX(TotalAmount) - MIN(TotalAmount)                   AS Range,
    ROUND(AVG(TotalAmount), 2)                            AS MeanValue,
    ROUND(STDEV(TotalAmount), 2)                          AS StdDev,
    ROUND(VAR(TotalAmount), 2)                            AS Variance,
    ROUND(STDEV(TotalAmount) / NULLIF(AVG(TotalAmount), 0) * 100, 1)
        AS CoefficientOfVariationPct,
    SUM(TotalAmount)                                      AS TotalSum,
    ROUND(PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY TotalAmount) OVER (), 2) AS P25,
    ROUND(PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY TotalAmount) OVER (), 2) AS MedianP50,
    ROUND(PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY TotalAmount) OVER (), 2) AS P75,
    ROUND(PERCENTILE_CONT(0.90) WITHIN GROUP (ORDER BY TotalAmount) OVER (), 2) AS P90,
    ROUND(PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY TotalAmount) OVER (), 2) AS P95,
    ROUND(PERCENTILE_CONT(0.99) WITHIN GROUP (ORDER BY TotalAmount) OVER (), 2) AS P99
FROM Orders
WHERE TotalAmount IS NOT NULL;

-- Step 2: Interquartile range and outlier detection
WITH Stats AS (
    SELECT
        PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Q1,
        PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Q3,
        AVG(TotalAmount) OVER () AS Mean,
        STDEV(TotalAmount) OVER () AS StdDev
    FROM Orders
    WHERE TotalAmount IS NOT NULL
),
StatSummary AS (
    SELECT DISTINCT Q1, Q3, Q3 - Q1 AS IQR, Mean, StdDev FROM Stats
)
SELECT
    o.OrderID,
    o.TotalAmount,
    ss.Q1,
    ss.Q3,
    ss.IQR,
    ss.Mean,
    ss.StdDev,
    ROUND((o.TotalAmount - ss.Mean) / NULLIF(ss.StdDev, 0), 2) AS ZScore,
    CASE
        WHEN o.TotalAmount < ss.Q1 - 1.5 * ss.IQR
             THEN 'LOW OUTLIER: Below Q1 - 1.5×IQR fence'
        WHEN o.TotalAmount > ss.Q3 + 1.5 * ss.IQR
             THEN 'HIGH OUTLIER: Above Q3 + 1.5×IQR fence'
        WHEN ABS((o.TotalAmount - ss.Mean) / NULLIF(ss.StdDev, 0)) > 3
             THEN 'Z-SCORE OUTLIER: More than 3 standard deviations from mean'
        ELSE 'Within normal range'
    END AS OutlierFlag
FROM Orders o
CROSS JOIN StatSummary ss
WHERE TotalAmount IS NOT NULL
ORDER BY o.TotalAmount DESC;

-- Step 3: Distribution shape indicators
WITH AmountStats AS (
    SELECT
        AVG(TotalAmount) AS Mean,
        PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Median,
        STDEV(TotalAmount) AS StdDev
    FROM Orders
    WHERE TotalAmount IS NOT NULL
)
SELECT DISTINCT
    ROUND(Mean, 2) AS Mean,
    ROUND(Median, 2) AS Median,
    ROUND(StdDev, 2) AS StdDev,
    ROUND(Mean - Median, 2) AS MeanMedianSkew,
    CASE
        WHEN ABS(Mean - Median) < StdDev * 0.1
             THEN 'Approximately symmetric'
        WHEN Mean > Median
             THEN 'RIGHT-SKEWED: Mean > Median — high-value outliers pulling mean up'
        ELSE 'LEFT-SKEWED: Mean < Median — low-value outliers pulling mean down'
    END AS SkewnessIndicator,
    CASE
        WHEN StdDev > Mean
             THEN 'HIGH VARIABILITY: StdDev > Mean — extreme spread relative to average'
        WHEN StdDev > Mean * 0.5
             THEN 'MODERATE VARIABILITY: CoV > 50%'
        ELSE 'LOW VARIABILITY: CoV < 50%'
    END AS SpreadIndicator
FROM AmountStats;

-- Step 4: Product Price statistics
SELECT
    MIN(Price)    AS MinPrice,
    MAX(Price)    AS MaxPrice,
    AVG(Price)    AS MeanPrice,
    STDEV(Price)  AS StdDevPrice,
    COUNT(*)      AS ProductCount,
    SUM(CASE WHEN Price = 0 THEN 1 ELSE 0 END) AS ZeroPriceCount,
    SUM(CASE WHEN Price < 0 THEN 1 ELSE 0 END) AS NegativePriceCount,
    PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY Price) OVER () AS MedianPrice
FROM Products
WHERE Price IS NOT NULL;
```

**Step 3 — Distribution shape:**

## Explanation

**PERCENTILE_CONT for exact percentiles**
`PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY col) OVER ()` computes the exact median using linear interpolation between adjacent values. The `OVER ()` clause (empty window) applies the percentile to all rows and returns the same value for each row — use `SELECT DISTINCT` or a CTE to collapse to a single summary row.

**IQR outlier fences**
The Tukey fences define outlier boundaries: Lower = Q1 − 1.5 × IQR, Upper = Q3 + 1.5 × IQR. Values outside these fences are "mild outliers." Beyond Q1 − 3 × IQR and Q3 + 3 × IQR are "extreme outliers." Unlike Z-score outlier detection, the IQR method works well for right-skewed distributions where Z-scores underperform.

**Mean-median gap as skewness indicator**
When `Mean > Median`, the distribution is right-skewed: a few very high values pull the mean above the median. For financial amounts, right skew is common and expected. A large mean-median gap (730.50 on a median of 650) means the average is not representative of the typical order.

**Coefficient of variation (CoV)**
`STDEV / MEAN × 100` expresses spread as a percentage of the mean, enabling comparisons across columns with different scales. A CoV > 100% (standard deviation exceeds mean) indicates extremely high relative variability — common in datasets with a mix of very small and very large values.

## Severity
**Medium** — Without numeric statistics, analysts cannot detect outliers, assess model input quality, or understand the data's scale. Undetected extreme values inflate means, distort regression models, and cause scaling errors in machine learning pipelines. Descriptive statistics are the first step in any quantitative data quality assessment.
