# G11-T05 — Profiling | Pattern Frequency Analysis

## ID
G11-T05

## Group
11 — Profiling

## Type
Pattern Frequency Analysis — Identifying the Most Common Structural Patterns in String Fields

## Live Scenario
A data migration project is moving 450,000 customer records from a legacy system. The source `Phone` column has been a free-text field for 15 years. Profiling reveals 47 distinct phone number formats: `07700 900847`, `+447700900847`, `07700900847`, `(0)7700 900847`, `07700-900847`, and 42 other variations. The ETL must normalise all formats to E.164 (`+447700900847`). Without pattern frequency analysis, the developer writes 5 normalisation rules covering 90% of records but misses 7 rare formats — 31,500 records receive malformed phone numbers that fail the downstream SMS gateway's format validation. The gateway silently rejects these, and those customers never receive order confirmations.

## The Question
> Pattern frequency analysis extracts the structural pattern of each value (replacing digits with 'N', letters with 'A', and keeping special characters) and counts how often each pattern appears. This reveals formatting inconsistencies, dominant patterns, and rare variants that need special handling.
> **"Analyse the structural patterns in the Phone and PostalCode columns of Customers, and in the ProductCode column of Products, showing the frequency of each pattern and flagging rare or non-conforming patterns."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Phone number pattern analysis
-- Replace digits with N, letters with A, keep spaces/hyphens/plus signs
WITH PhonePatterns AS (
    SELECT
        Phone,
        -- Build a structural pattern: N=digit, A=letter, keep separators
        -- SQL Server doesn't have a built-in regex replace, so we approximate
        -- by checking known pattern characteristics
        CASE
            WHEN Phone IS NULL OR LTRIM(RTRIM(Phone)) = ''
                 THEN 'NULL/EMPTY'
            WHEN Phone LIKE '+44[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]'
                 THEN '+44NNNNNNNNNN (E.164 international)'
            WHEN Phone LIKE '07[0-9][0-9][0-9] [0-9][0-9][0-9][0-9][0-9][0-9]'
                 THEN '0NNNN NNNNNN (UK local with space)'
            WHEN Phone LIKE '07[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]'
                 THEN '0NNNNNNNNNNN (UK local no separator)'
            WHEN Phone LIKE '07[0-9][0-9][0-9]-[0-9][0-9][0-9][0-9][0-9][0-9]'
                 THEN '0NNNN-NNNNNN (UK local with hyphen)'
            WHEN Phone LIKE '([0-9])[0-9][0-9][0-9][0-9] [0-9][0-9][0-9][0-9][0-9][0-9]'
                 THEN '(N)NNNN NNNNNN (bracketed prefix)'
            WHEN LEN(REPLACE(REPLACE(REPLACE(REPLACE(Phone,' ',''),'-',''),'(',''),')','')) = 11
             AND REPLACE(REPLACE(REPLACE(REPLACE(Phone,' ',''),'-',''),'(',''),')','')
                 LIKE '[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]'
                 THEN '11 digits (format varies)'
            ELSE 'OTHER: ' + LEFT(Phone, 5) + '...'
        END AS Pattern
    FROM Customers
)
SELECT
    Pattern,
    COUNT(*) AS Frequency,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct,
    STRING_AGG(Phone, ' | ') AS ExampleValues,
    CASE
        WHEN COUNT(*) = 1 THEN 'RARE PATTERN: Only 1 occurrence — review manually'
        WHEN Pattern = 'NULL/EMPTY' THEN 'MISSING: No phone stored'
        ELSE 'Present'
    END AS PatternFlag
FROM PhonePatterns
GROUP BY Pattern
ORDER BY Frequency DESC;

-- Step 2: PostalCode pattern analysis
WITH PostcodePatterns AS (
    SELECT
        PostalCode,
        CASE
            WHEN PostalCode IS NULL OR LTRIM(PostalCode) = '' THEN 'NULL/EMPTY'
            WHEN PostalCode LIKE '[A-Z][0-9] [0-9][A-Z][A-Z]'    THEN 'AN NAA (e.g. E1 1AA)'
            WHEN PostalCode LIKE '[A-Z][0-9][0-9] [0-9][A-Z][A-Z]'   THEN 'ANN NAA (e.g. W12 8QT)'
            WHEN PostalCode LIKE '[A-Z][A-Z][0-9] [0-9][A-Z][A-Z]'   THEN 'AAN NAA (e.g. SW1 8QT)'
            WHEN PostalCode LIKE '[A-Z][A-Z][0-9][0-9] [0-9][A-Z][A-Z]' THEN 'AANN NAA (e.g. SW1W 8QT)'
            WHEN PostalCode LIKE '[A-Z][0-9][A-Z] [0-9][A-Z][A-Z]'   THEN 'ANA NAA (e.g. W1A 1AA)'
            WHEN PostalCode LIKE '[A-Z][A-Z][0-9][A-Z] [0-9][A-Z][A-Z]' THEN 'AANA NAA (e.g. EC1A 1BB)'
            WHEN PostalCode NOT LIKE '% %'                             THEN 'NO SPACE: Missing separator'
            ELSE 'OTHER: ' + PostalCode
        END AS Pattern
    FROM Customers
)
SELECT
    Pattern,
    COUNT(*) AS Frequency,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct,
    STRING_AGG(PostalCode, ', ') AS Examples
FROM PostcodePatterns
WHERE PostalCode IS NOT NULL
GROUP BY Pattern
ORDER BY Frequency DESC;

-- Step 3: ProductCode pattern analysis
SELECT
    CASE
        WHEN ProductCode LIKE '[A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9]'
             THEN 'AAA-NNNN (standard format)'
        WHEN ProductCode LIKE '[A-Z][A-Z]-[0-9][0-9][0-9]'
             THEN 'AA-NNN (short format)'
        WHEN ProductCode LIKE '[0-9][0-9][0-9][0-9][0-9][0-9]'
             THEN 'NNNNNN (numeric only)'
        WHEN ProductCode IS NULL OR ProductCode = ''
             THEN 'NULL/EMPTY'
        ELSE 'NON-STANDARD: ' + ProductCode
    END AS CodePattern,
    COUNT(*) AS Frequency,
    STRING_AGG(ProductCode, ', ') AS Examples
FROM Products
GROUP BY
    CASE
        WHEN ProductCode LIKE '[A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9]' THEN 'AAA-NNNN (standard format)'
        WHEN ProductCode LIKE '[A-Z][A-Z]-[0-9][0-9][0-9]'           THEN 'AA-NNN (short format)'
        WHEN ProductCode LIKE '[0-9][0-9][0-9][0-9][0-9][0-9]'       THEN 'NNNNNN (numeric only)'
        WHEN ProductCode IS NULL OR ProductCode = ''                   THEN 'NULL/EMPTY'
        ELSE 'NON-STANDARD: ' + ProductCode
    END
ORDER BY Frequency DESC;

-- Step 4: Length distribution as a pattern proxy
SELECT
    LEN(Phone) AS PhoneLength,
    COUNT(*) AS Frequency,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct,
    STRING_AGG(Phone, ', ') AS Examples
FROM Customers
WHERE Phone IS NOT NULL
GROUP BY LEN(Phone)
ORDER BY Frequency DESC;
```

## Explanation

**Pattern extraction via CASE**
SQL Server lacks a built-in regex replacement function (unlike PostgreSQL's `regexp_replace`). Pattern extraction uses `LIKE` patterns with character classes (`[A-Z]`, `[0-9]`) to classify each value into a structural template. The patterns are tested from most-specific to least-specific (first matching CASE wins).

**Length as a proxy pattern**
Step 4 uses `LEN(Phone)` as a simpler pattern proxy. While it loses structural information (a 11-character value could be `07700900123` or `+44700900123`), it quickly reveals the spread of lengths. An email column with lengths ranging from 5 to 250 has a very different profile from one with all values between 15 and 30.

**STRING_AGG for example values**
`STRING_AGG(Phone, ' | ')` collects sample values for each pattern, making the output self-documenting — the analyst can see example values alongside the pattern without writing a second query. For large datasets, add `TOP 3` using a subquery to limit examples.

**Pattern frequency as an ETL specification input**
The frequency profile directly informs ETL normalisation logic: write handlers for patterns covering >1% of records first; individually review the rare patterns (<1%). The 47-format scenario in the live example shows how pattern analysis prevents "tail" formats from being missed.

## Severity
**Medium** — Pattern inconsistencies cause validation failures, ETL transformation errors, and downstream system rejections. A phone field with 12 structural formats cannot be validated with a single regex — each format requires its own normalisation rule. Pattern analysis is the prerequisite for designing robust format normalisation.
