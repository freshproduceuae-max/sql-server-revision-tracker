# G11-T07 — Profiling | Cross-Column Correlation Profile

## ID
G11-T07

## Group
11 — Profiling

## Type
Cross-Column Correlation Profile — Detecting Relationships and Dependencies Between Columns

## Live Scenario
A fraud analyst at a payments company profiles the Transactions table before building a fraud detection model. Cross-column analysis reveals: 94% of transactions where `Currency` is "USD" have a `SourceIP` beginning with a known US CIDR range — but 6% have Eastern European IPs, which is an anomaly worth investigating. More critically, profiling reveals that `Amount` and `Currency` are not independent: USD transactions average £2,340, EUR transactions average £890, and GBP transactions average £1,120. A model that treats Currency as a categorical variable without understanding its correlation with Amount will learn a spurious pattern. The cross-column profile also reveals that `OrderID` is NULL for 23% of transactions — and those NULL-OrderID transactions have a bimodal amount distribution ($50–$100 or $5,000+), suggesting two distinct transaction types are mixed in one table without a type discriminator.

## The Question
> A cross-column correlation profile examines how pairs of columns relate to each other: whether the value in one column predicts values in another, whether certain combinations are impossible or rare, and whether conditional distributions differ from the overall distribution. SQL detects these patterns using GROUP BY on column pairs, conditional aggregates, and ratio comparisons.
> **"Profile the relationships between key column pairs in Orders and Transactions: show how TotalAmount varies by Status, how transaction Amount varies by Currency, and identify any Status/ProductID combinations that never occur together — revealing structural dependencies and impossible combinations."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Transactions** — `schemas/05_Transactions.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Amount distribution by Order Status (conditional distribution)
SELECT
    Status,
    COUNT(*)                          AS OrderCount,
    ROUND(AVG(TotalAmount), 2)        AS AvgAmount,
    MIN(TotalAmount)                  AS MinAmount,
    MAX(TotalAmount)                  AS MaxAmount,
    ROUND(STDEV(TotalAmount), 2)      AS StdDevAmount,
    -- Compare this status avg to overall avg
    ROUND(AVG(TotalAmount)
        - AVG(AVG(TotalAmount)) OVER (), 2) AS DiffFromOverallAvg,
    ROUND(100.0 * AVG(TotalAmount)
        / NULLIF(AVG(AVG(TotalAmount)) OVER (), 0), 1) AS PctOfOverallAvg,
    CASE
        WHEN AVG(TotalAmount) > AVG(AVG(TotalAmount)) OVER () * 1.5
             THEN 'HIGH VALUE STATUS: Avg >50% above overall'
        WHEN AVG(TotalAmount) < AVG(AVG(TotalAmount)) OVER () * 0.5
             THEN 'LOW VALUE STATUS: Avg <50% of overall'
        ELSE 'Near overall average'
    END AS AmountProfile
FROM Orders
WHERE TotalAmount IS NOT NULL
GROUP BY Status;

-- Step 2: Transaction amount by currency (cross-column dependency)
SELECT
    Currency,
    COUNT(*)                          AS TxnCount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS PctOfTotal,
    ROUND(AVG(Amount), 2)             AS AvgAmount,
    ROUND(MIN(Amount), 2)             AS MinAmount,
    ROUND(MAX(Amount), 2)             AS MaxAmount,
    ROUND(STDEV(Amount), 2)           AS StdDevAmount,
    -- Flag if currency avg is significantly different from GBP baseline
    ROUND(AVG(Amount)
        - MAX(CASE WHEN Currency = 'GBP' THEN AvgGBP END) OVER (), 2)
                                      AS DiffFromGBPAvg
FROM (
    SELECT
        Currency,
        Amount,
        AVG(Amount) OVER (PARTITION BY Currency) AS AvgGBP
    FROM Transactions
    WHERE Amount IS NOT NULL
) T
GROUP BY Currency
ORDER BY TxnCount DESC;

-- Step 3: Status × ProductID co-occurrence — which combinations exist?
SELECT
    o.Status,
    o.ProductID,
    COUNT(*)                     AS OrderCount,
    ROUND(AVG(o.TotalAmount), 2) AS AvgAmount,
    p.ProductName,
    CASE
        WHEN o.Status = 'Cancelled' AND COUNT(*) > 3
             THEN 'HIGH CANCELLATION: This product cancelled frequently'
        WHEN o.Status = 'Delivered' AND COUNT(*) = 0
             THEN 'NEVER DELIVERED: Product has no delivered orders'
        ELSE 'Normal'
    END AS CombinationFlag
FROM Orders o
LEFT JOIN Products p ON o.ProductID = p.ProductID
GROUP BY o.Status, o.ProductID, p.ProductName
ORDER BY o.Status, OrderCount DESC;

-- Step 4: Identify impossible or suspicious column value combinations
SELECT
    'Orders' AS TableName,
    'TotalAmount=0 with Status=Delivered' AS Combination,
    COUNT(*) AS Count,
    CASE WHEN COUNT(*) > 0 THEN 'SUSPICIOUS: Zero-value delivered orders' ELSE 'OK' END AS Flag
FROM Orders
WHERE TotalAmount = 0 AND Status = 'Delivered'
UNION ALL
SELECT
    'Orders',
    'DeliveryDate before OrderDate',
    COUNT(*),
    CASE WHEN COUNT(*) > 0 THEN 'IMPOSSIBLE: Delivered before ordered' ELSE 'OK' END
FROM Orders
WHERE DeliveryDate < OrderDate
UNION ALL
SELECT
    'Transactions',
    'Amount < 0 with non-refund correlation',
    COUNT(*),
    CASE WHEN COUNT(*) > 0 THEN 'REVIEW: Negative transactions present' ELSE 'OK' END
FROM Transactions
WHERE Amount < 0
UNION ALL
SELECT
    'Orders',
    'Status=Delivered with NULL DeliveryDate',
    COUNT(*),
    CASE WHEN COUNT(*) > 0 THEN 'DATA GAP: Delivered orders missing delivery date' ELSE 'OK' END
FROM Orders
WHERE Status = 'Delivered' AND DeliveryDate IS NULL;

-- Step 5: Null co-occurrence — do NULLs cluster across columns?
SELECT
    CASE WHEN TotalAmount IS NULL THEN 'NULL' ELSE 'NOT NULL' END AS AmountNull,
    CASE WHEN DeliveryDate IS NULL THEN 'NULL' ELSE 'NOT NULL' END AS DeliveryDateNull,
    CASE WHEN ProductID IS NULL THEN 'NULL' ELSE 'NOT NULL' END AS ProductIDNull,
    COUNT(*) AS OrderCount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct
FROM Orders
GROUP BY
    CASE WHEN TotalAmount IS NULL THEN 'NULL' ELSE 'NOT NULL' END,
    CASE WHEN DeliveryDate IS NULL THEN 'NULL' ELSE 'NOT NULL' END,
    CASE WHEN ProductID IS NULL THEN 'NULL' ELSE 'NOT NULL' END
ORDER BY OrderCount DESC;
```

## Expected Output

|---|---|---|---|---|
| Delivered | 9 | 1577.78 | 197.28 | Near overall average |
| Pending | 4 | 775.00 | -605.50 | LOW VALUE STATUS: Avg <50% of overall |
| Processing | 3 | 1200.00 | -180.50 | Near overall average |

**Step 4 — Impossible combinations:**
| Combination | Count | Flag |
|---|---|---|
| DeliveryDate before OrderDate | 0 | OK |
| Status=Delivered with NULL DeliveryDate | 2 | DATA GAP: Delivered orders missing delivery date |

## Explanation

**Conditional distribution vs overall distribution**
`AVG(AVG(TotalAmount)) OVER ()` computes the grand mean across all Status groups, enabling each row to compare its group mean to the overall mean without a separate subquery. A Status group with `AvgAmount` far from the grand mean reveals a structural relationship: high-value orders correlate with certain statuses (e.g., large B2B orders tend to stay "Processing" longer).

**Impossible combination detection**
Step 4's UNION ALL pattern tests each suspicious column pair in one pass. "Delivered before ordered" should always return 0; any non-zero count indicates a data integrity failure — either a date entry error or a system clock mismatch between the ordering and delivery systems.

**NULL co-occurrence clustering**
Step 5 reveals whether NULLs are random (uniformly spread across combinations) or structural (NULLs in Column A always co-occur with NULLs in Column B). A structural NULL pattern indicates a data source that systematically omits related fields together — pointing to a specific upstream system, a conditional field, or a batch load gap.

**Cross-column profiling as a prerequisite for modelling**
Machine learning models treat each column independently unless cross-column patterns are explicitly encoded as features. Undetected correlation between `Currency` and `Amount` means the model receives redundant signals and may learn spurious country-of-origin patterns instead of genuine fraud signals.

## Severity
**Medium** — Cross-column dependencies cause model bias, incorrect aggregations, and missed data quality issues that single-column profiling cannot detect. A column that passes all individual quality checks (no NULLs, correct type, valid range) may still contain structurally impossible combinations with another column that only appear when pairs are examined.
