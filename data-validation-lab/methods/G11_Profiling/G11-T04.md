# G11-T04 — Profiling | Cardinality and Uniqueness Check

## ID
G11-T04

## Group
11 — Profiling

## Type
Cardinality and Uniqueness Check — Measuring How Many Distinct Values Each Column Contains

## Live Scenario
A data engineer is designing a database index strategy. Before adding indexes, they profile column cardinality to guide decisions: high-cardinality columns (near-unique values like CustomerID) benefit from B-tree indexes; low-cardinality columns (like a binary IsActive flag) are better served by filtered indexes or no index. The profiling also reveals a data quality issue: `PostalCode` has 400 distinct values across 2,000 customer records — a ratio suggesting it's being used as a free-text field (with entries like "unknown", "N/A", "NA", "see notes", and postcodes from three different countries in different formats). A column designed to hold only UK postcodes has 40 non-standard values that slip through because there is no CHECK constraint.

## The Question
> Cardinality measures the number of distinct values in a column. High cardinality indicates a column with many unique values (good for identifiers, bad for categories); low cardinality indicates a column with few distinct values (ideal for enumerations). SQL measures cardinality using COUNT(DISTINCT) and compares it to the total row count.
> **"Measure the cardinality (distinct value count and uniqueness ratio) of every column in the Customers and Orders tables, classify each by its cardinality profile, and identify any columns where cardinality is unexpectedly high or low."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Cardinality profile for Customers
WITH CustomerCardinality AS (
    SELECT 'CustomerID'  AS ColName, COUNT(*) AS TotalRows, COUNT(DISTINCT CustomerID)  AS DistinctValues FROM Customers UNION ALL
    SELECT 'FirstName',  COUNT(*), COUNT(DISTINCT FirstName)  FROM Customers UNION ALL
    SELECT 'LastName',   COUNT(*), COUNT(DISTINCT LastName)   FROM Customers UNION ALL
    SELECT 'Email',      COUNT(*), COUNT(DISTINCT Email)      FROM Customers UNION ALL
    SELECT 'Phone',      COUNT(*), COUNT(DISTINCT Phone)      FROM Customers UNION ALL
    SELECT 'PostalCode', COUNT(*), COUNT(DISTINCT PostalCode) FROM Customers UNION ALL
    SELECT 'Country',    COUNT(*), COUNT(DISTINCT Country)    FROM Customers UNION ALL
    SELECT 'IsActive',   COUNT(*), COUNT(DISTINCT IsActive)   FROM Customers
)
SELECT
    ColName,
    TotalRows,
    DistinctValues,
    ROUND(100.0 * DistinctValues / NULLIF(TotalRows, 0), 1) AS UniquenessRatioPct,
    CASE
        WHEN DistinctValues = TotalRows
             THEN 'UNIQUE KEY: All values distinct — suitable as primary key'
        WHEN DistinctValues = 1
             THEN 'CONSTANT: Only one distinct value — zero information'
        WHEN DistinctValues = 2
             THEN 'BINARY: Two values — flag/boolean column'
        WHEN DistinctValues <= 10
             THEN 'LOW CARDINALITY: ' + CAST(DistinctValues AS VARCHAR) + ' values — categorical'
        WHEN ROUND(100.0 * DistinctValues / NULLIF(TotalRows, 0), 1) >= 90
             THEN 'HIGH CARDINALITY: ' + CAST(DistinctValues AS VARCHAR) + ' of ' + CAST(TotalRows AS VARCHAR) + ' unique — quasi-identifier'
        ELSE 'MEDIUM CARDINALITY: ' + CAST(DistinctValues AS VARCHAR) + ' distinct values'
    END AS CardinalityProfile,
    CASE
        WHEN ColName IN ('CustomerID') AND DistinctValues < TotalRows
             THEN 'ALERT: ID column has duplicate values — not a valid primary key'
        WHEN ColName IN ('Email') AND DistinctValues < TotalRows
             THEN 'ALERT: Email column has duplicate values — uniqueness constraint missing?'
        WHEN ColName IN ('Country') AND DistinctValues > 50
             THEN 'REVIEW: Country column has >50 values — check for encoding variants'
        ELSE 'OK'
    END AS CardinalityAlert
FROM CustomerCardinality
ORDER BY DistinctValues DESC;

-- Step 2: Find columns where high cardinality is unexpected
WITH OrderCardinality AS (
    SELECT 'OrderID',     COUNT(*), COUNT(DISTINCT OrderID)     FROM Orders UNION ALL
    SELECT 'CustomerID',  COUNT(*), COUNT(DISTINCT CustomerID)  FROM Orders UNION ALL
    SELECT 'ProductID',   COUNT(*), COUNT(DISTINCT ProductID)   FROM Orders UNION ALL
    SELECT 'Status',      COUNT(*), COUNT(DISTINCT Status)      FROM Orders UNION ALL
    SELECT 'TotalAmount', COUNT(*), COUNT(DISTINCT TotalAmount) FROM Orders
)
SELECT
    ColName,
    TotalRows,
    DistinctValues,
    ROUND(100.0 * DistinctValues / NULLIF(TotalRows, 0), 1) AS UniquenessRatioPct
FROM OrderCardinality t(ColName, TotalRows, DistinctValues)
ORDER BY UniquenessRatioPct DESC;

-- Step 3: Duplicate-safe uniqueness test — which columns could be primary keys?
SELECT
    ColName,
    TotalRows,
    DistinctValues,
    TotalRows - DistinctValues AS DuplicateCount,
    CASE
        WHEN TotalRows = DistinctValues
             THEN 'CANDIDATE KEY: No duplicates'
        ELSE 'NOT UNIQUE: ' + CAST(TotalRows - DistinctValues AS VARCHAR)
             + ' duplicate values — cannot be primary key'
    END AS PKCandidate
FROM (
    SELECT 'Customers.CustomerID' AS ColName, COUNT(*) AS TotalRows, COUNT(DISTINCT CustomerID) AS DistinctValues FROM Customers UNION ALL
    SELECT 'Customers.Email',      COUNT(*), COUNT(DISTINCT Email)      FROM Customers UNION ALL
    SELECT 'Orders.OrderID',       COUNT(*), COUNT(DISTINCT OrderID)    FROM Orders UNION ALL
    SELECT 'Transactions.TransactionID', COUNT(*), COUNT(DISTINCT TransactionID) FROM Transactions
) PK_Check(ColName, TotalRows, DistinctValues)
ORDER BY TotalRows - DistinctValues;

-- Step 4: Value frequency of low-cardinality columns — show all distinct values
SELECT DISTINCT
    Country AS Value,
    COUNT(*) OVER (PARTITION BY Country) AS Frequency,
    ROUND(100.0 * COUNT(*) OVER (PARTITION BY Country) / COUNT(*) OVER (), 1) AS Pct,
    'Country' AS ColumnName
FROM Customers
WHERE Country IS NOT NULL
UNION ALL
SELECT DISTINCT
    CAST(IsActive AS VARCHAR),
    COUNT(*) OVER (PARTITION BY IsActive),
    ROUND(100.0 * COUNT(*) OVER (PARTITION BY IsActive) / COUNT(*) OVER (), 1),
    'IsActive'
FROM Customers
ORDER BY ColumnName, Frequency DESC;
```

## Explanation

**COUNT(DISTINCT col) for cardinality**
`COUNT(DISTINCT col)` counts unique non-NULL values. The uniqueness ratio `DistinctValues / TotalRows × 100` classifies columns:
- 100%: unique identifier
- 0.01–1%: low-cardinality categorical (e.g., status with 3 values in 300 rows)
- Between: varies by domain

**Binary column detection**
`DistinctValues = 2` identifies binary columns — those that function as flags or booleans. These should be stored as BIT (SQL Server) or BOOLEAN (other systems), not VARCHAR or INT.

**Candidate key validation**
`COUNT(*) = COUNT(DISTINCT col)` confirms a column could be a primary key — no duplicates exist. Step 3 tests the actual candidate keys (CustomerID, OrderID) and the business key (Email) in one query. If `Email` shows 11 of 12 distinct, there are two customers with the same email — a uniqueness constraint violation.

**Window COUNT for per-value frequency**
`COUNT(*) OVER (PARTITION BY Country)` computes the row count for each country without a separate GROUP BY. Combined with `DISTINCT`, this gives one row per value with its frequency — a compact single-query approach to value distribution for low-cardinality columns.

## Severity
**Medium** — Cardinality mismatches cause index design errors, incorrect JOIN assumptions, and modelling failures. A column assumed to be a unique identifier that has duplicates will cause incorrect JOIN results; a column assumed to be categorical that has high cardinality will consume excessive memory in BI tools and ML feature encoding.
