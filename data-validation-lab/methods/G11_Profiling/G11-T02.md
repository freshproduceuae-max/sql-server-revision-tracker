# G11-T02 — Profiling | Value Distribution Analysis

## ID
G11-T02

## Group
11 — Profiling

## Type
Value Distribution Analysis — Understanding the Frequency and Spread of Values in Each Column

## Live Scenario
A data analyst is preparing a dataset for a machine learning model that predicts customer churn. Before modelling, the analyst profiles the `Country` column and discovers: 78% of records are "UK", 15% are "US", 4% are "Germany", and 3% are spread across 47 other countries. A downstream one-hot encoding step creates 50 columns. However, the analyst also notices "UK", "United Kingdom", "GB", and "GBR" all appear — four representations of the same country, collectively 83% of records. The model's training set has "UK" as the dominant value; the scoring set uses "United Kingdom", causing the model to treat them as different categories and produce wrong predictions for 83% of scoring records.

## The Question
> Value distribution analysis shows the frequency of each distinct value in a column, reveals dominant values, identifies rare values (potential errors or outliers), and uncovers encoding inconsistencies where the same real-world value is stored in multiple forms.
> **"For each categorical column in Customers and Orders, show the top distinct values by frequency, their percentage of total rows, and identify any values that appear only once (singletons — potential data entry errors)."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Country distribution in Customers
SELECT
    Country,
    COUNT(*) AS Frequency,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct,
    REPLICATE('█', COUNT(*)) AS FrequencyBar,
    CASE
        WHEN COUNT(*) = 1
             THEN 'SINGLETON: Appears only once — check for entry error'
        WHEN ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) < 1.0
             THEN 'RARE (<1%): Low frequency — verify this is not a variant/typo'
        WHEN ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) > 80.0
             THEN 'DOMINANT (>80%): Highly concentrated distribution'
        ELSE 'Normal frequency'
    END AS FrequencyFlag
FROM Customers
WHERE Country IS NOT NULL
GROUP BY Country
ORDER BY Frequency DESC;

-- Step 2: Order Status distribution
SELECT
    Status,
    COUNT(*) AS OrderCount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct,
    SUM(TotalAmount) AS TotalValue,
    AVG(TotalAmount) AS AvgValue,
    MIN(TotalAmount) AS MinValue,
    MAX(TotalAmount) AS MaxValue
FROM Orders
GROUP BY Status
ORDER BY OrderCount DESC;

-- Step 3: Numeric distribution — TotalAmount value bands
SELECT
    CASE
        WHEN TotalAmount < 100     THEN 'Under £100'
        WHEN TotalAmount < 500     THEN '£100-£499'
        WHEN TotalAmount < 1000    THEN '£500-£999'
        WHEN TotalAmount < 5000    THEN '£1,000-£4,999'
        WHEN TotalAmount < 10000   THEN '£5,000-£9,999'
        ELSE '£10,000+'
    END AS ValueBand,
    COUNT(*) AS OrderCount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct,
    SUM(TotalAmount) AS BandTotal,
    AVG(TotalAmount) AS BandAvg
FROM Orders
GROUP BY
    CASE
        WHEN TotalAmount < 100     THEN 'Under £100'
        WHEN TotalAmount < 500     THEN '£100-£499'
        WHEN TotalAmount < 1000    THEN '£500-£999'
        WHEN TotalAmount < 5000    THEN '£1,000-£4,999'
        WHEN TotalAmount < 10000   THEN '£5,000-£9,999'
        ELSE '£10,000+'
    END
ORDER BY MIN(TotalAmount);

-- Step 4: Uniqueness analysis — how many distinct values vs total rows?
SELECT
    ColName,
    TotalRows,
    DistinctValues,
    ROUND(100.0 * DistinctValues / NULLIF(TotalRows, 0), 1) AS UniquenessRatio,
    CASE
        WHEN DistinctValues = TotalRows
             THEN 'All values unique — good for ID column, suspicious for description'
        WHEN DistinctValues = 1
             THEN 'SINGLE VALUE: Column is constant — low information value'
        WHEN DistinctValues <= 10
             THEN 'LOW CARDINALITY: ' + CAST(DistinctValues AS VARCHAR) + ' distinct values — good for categoricals'
        WHEN ROUND(100.0 * DistinctValues / NULLIF(TotalRows, 0), 1) > 90
             THEN 'HIGH CARDINALITY: ' + CAST(DistinctValues AS VARCHAR) + ' distinct values — near-unique'
        ELSE 'Moderate cardinality'
    END AS CardinalityProfile
FROM (
    SELECT 'CustomerID' AS ColName, COUNT(*) AS TotalRows, COUNT(DISTINCT CustomerID) AS DistinctValues FROM Customers UNION ALL
    SELECT 'Country',    COUNT(*), COUNT(DISTINCT Country) FROM Customers UNION ALL
    SELECT 'IsActive',   COUNT(*), COUNT(DISTINCT IsActive) FROM Customers UNION ALL
    SELECT 'Orders.Status', COUNT(*), COUNT(DISTINCT Status) FROM Orders UNION ALL
    SELECT 'Products.IsActive', COUNT(*), COUNT(DISTINCT IsActive) FROM Products
) Cardinality
ORDER BY DistinctValues;

-- Step 5: Singleton detection — values appearing exactly once (potential data entry errors)
SELECT
    'Country' AS ColName,
    Country AS Value,
    COUNT(*) AS Freq,
    'SINGLETON: Value appears once — verify spelling' AS SingCheck
FROM Customers
GROUP BY Country
HAVING COUNT(*) = 1
UNION ALL
SELECT 'Orders.Status', Status, COUNT(*), 'SINGLETON STATUS'
FROM Orders
GROUP BY Status
HAVING COUNT(*) = 1
ORDER BY ColName;
```

## Explanation

**SUM() OVER() for percentage computation**
`SUM(COUNT(*)) OVER ()` computes the total across all groups without a GROUP BY clause on the outer query. This is the window function pattern for percentage calculations: each row's `COUNT(*) / total_count × 100` gives its percentage. No subquery or CTE is needed.

**Cardinality as a column characteristic**
Cardinality (number of distinct values) is a key dimension of every column's profile: low cardinality (2–20 values) = categorical; high cardinality (~unique values) = identifier or free-text; intermediate = ordinal or quantitative. Step 4 classifies columns by cardinality to guide data type and modelling decisions.

**Singletons as data quality signals**
A singleton value (appears exactly once) in a categorical column is suspicious. "Germany" appearing once in a `Country` column where all other countries appear dozens of times could mean: a legitimate single German customer, "Germany" as a misspelling of another country, or a legacy country name from an imported dataset. Singletons warrant individual review.

**Frequency bar chart**
`REPLICATE('█', COUNT(*))` produces a simple text-based bar chart in the query output. This visualisation within SQL allows quick distribution scanning without needing a BI tool. For high-frequency columns, scale it: `REPLICATE('█', COUNT(*) / 5)` for every 5 records.

## Severity
**Medium** — Distribution anomalies indicate data quality issues (variant encodings, rare errors) and modelling risks (class imbalance, feature leakage). Without a distribution profile, downstream analytical models, aggregations, and reports may be distorted by unexpected frequency patterns — particularly singleton values that represent data entry errors masquerading as valid categories.
