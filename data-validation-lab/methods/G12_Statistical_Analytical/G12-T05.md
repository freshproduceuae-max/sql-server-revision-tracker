# G12-T05 — Statistical/Analytical | Benford's Law Analysis

## ID
G12-T05

## Group
12 — Statistical/Analytical

## Type
Benford's Law Analysis — Detecting Non-Natural Leading Digit Distributions as a Fraud Signal

## Live Scenario
A forensic accountant is auditing 18,000 expense reimbursement claims submitted by employees over two years. Benford's Law predicts that in naturally occurring financial data, about 30.1% of amounts should start with the digit 1, 17.6% with 2, and so on. Running Benford's analysis on the expense data reveals: the digit 5 appears as the leading digit in 24.8% of claims vs the expected 7.9% — a massive over-representation. Cross-referencing shows hundreds of claims for £500, £5,000, and £5,500 — amounts just below the £500 and £5,000 approval thresholds. The pattern is classic threshold manipulation: employees split or capped expenses at approval limits. Without Benford's analysis, the pattern would not emerge from individual claim review. The analysis flagged 340 claims for further investigation, resulting in £127,000 of fraudulent reimbursements being identified.

## The Question
> Benford's Law states that in many naturally occurring numerical datasets, the leading digit d appears with probability log₁₀(1 + 1/d). Significant deviations from this distribution in financial data are a signal of fabrication, rounding, or threshold manipulation. SQL computes the leading digit distribution and compares it to Benford's expected frequencies.
> **"Apply Benford's Law analysis to the TotalAmount column in Orders and the Amount column in Transactions: compute the leading digit distribution, compare it to Benford's expected frequencies, calculate the chi-square contribution of each digit, and flag digits that deviate significantly from expectation."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Extract leading digit and compute observed frequencies
WITH BenfordExpected AS (
    -- Benford's Law: P(d) = log10(1 + 1/d)
    SELECT 1 AS Digit, 30.1 AS ExpectedPct UNION ALL
    SELECT 2, 17.6 UNION ALL
    SELECT 3, 12.5 UNION ALL
    SELECT 4, 9.7 UNION ALL
    SELECT 5, 7.9 UNION ALL
    SELECT 6, 6.7 UNION ALL
    SELECT 7, 5.8 UNION ALL
    SELECT 8, 5.1 UNION ALL
    SELECT 9, 4.6
),
OrderLeadingDigit AS (
    SELECT
        -- Extract leading digit: convert to string, take first character, cast to int
        CAST(LEFT(CAST(ABS(TotalAmount) AS BIGINT), 1) AS INT) AS LeadingDigit
    FROM Orders
    WHERE TotalAmount > 0   -- Benford applies to positive non-zero values
      AND TotalAmount IS NOT NULL
),
ObservedFreq AS (
    SELECT
        LeadingDigit,
        COUNT(*) AS ObservedCount,
        ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS ObservedPct
    FROM OrderLeadingDigit
    GROUP BY LeadingDigit
)
SELECT
    b.Digit,
    ISNULL(o.ObservedCount, 0) AS ObservedCount,
    ISNULL(o.ObservedPct, 0) AS ObservedPct,
    b.ExpectedPct,
    ROUND(ISNULL(o.ObservedPct, 0) - b.ExpectedPct, 2) AS Deviation,
    -- Chi-square contribution: (Observed - Expected)^2 / Expected
    -- Using counts: Expected count = ExpectedPct/100 * TotalN
    ROUND(
        POWER(ISNULL(o.ObservedPct, 0) - b.ExpectedPct, 2) / NULLIF(b.ExpectedPct, 0)
    , 3) AS ChiSqContribution,
    CASE
        WHEN ABS(ISNULL(o.ObservedPct, 0) - b.ExpectedPct) > 10
             THEN 'CRITICAL DEVIATION: >10pp from Benford — high fraud signal'
        WHEN ABS(ISNULL(o.ObservedPct, 0) - b.ExpectedPct) > 5
             THEN 'SIGNIFICANT DEVIATION: >5pp from Benford — review required'
        WHEN ABS(ISNULL(o.ObservedPct, 0) - b.ExpectedPct) > 2
             THEN 'MODERATE DEVIATION: >2pp — monitor'
        WHEN ISNULL(o.ObservedCount, 0) = 0
             THEN 'ABSENT: No values start with this digit — extreme anomaly'
        ELSE 'Conforms to Benford'
    END AS BenfordFlag
FROM BenfordExpected b
LEFT JOIN ObservedFreq o ON b.Digit = o.LeadingDigit
ORDER BY b.Digit;

-- Step 2: Total chi-square statistic and conformance verdict
WITH BenfordExpected AS (
    SELECT 1 AS Digit, 30.1 AS ExpectedPct UNION ALL
    SELECT 2, 17.6 UNION ALL SELECT 3, 12.5 UNION ALL SELECT 4, 9.7 UNION ALL
    SELECT 5, 7.9 UNION ALL SELECT 6, 6.7 UNION ALL SELECT 7, 5.8 UNION ALL
    SELECT 8, 5.1 UNION ALL SELECT 9, 4.6
),
LeadingDigits AS (
    SELECT CAST(LEFT(CAST(ABS(TotalAmount) AS BIGINT), 1) AS INT) AS LeadingDigit
    FROM Orders
    WHERE TotalAmount > 0 AND TotalAmount IS NOT NULL
),
Observed AS (
    SELECT LeadingDigit, COUNT(*) AS N,
           ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS ObsPct
    FROM LeadingDigits GROUP BY LeadingDigit
)
SELECT
    SUM(POWER(ISNULL(o.ObsPct,0) - b.ExpectedPct, 2) / NULLIF(b.ExpectedPct,0))
        AS TotalChiSquare,
    -- Critical value at df=8, p=0.05 is 15.507
    CASE
        WHEN SUM(POWER(ISNULL(o.ObsPct,0) - b.ExpectedPct, 2) / NULLIF(b.ExpectedPct,0)) > 15.507
             THEN 'NON-CONFORMING: Chi-square exceeds critical value (df=8, p=0.05) — significant Benford deviation'
        ELSE 'CONFORMING: Distribution consistent with Benford Law at 95% confidence'
    END AS ConformanceVerdict,
    COUNT(DISTINCT CAST(LEFT(CAST(ABS(TotalAmount) AS BIGINT), 1) AS INT)) AS DigitsPresent,
    (SELECT COUNT(*) FROM Orders WHERE TotalAmount > 0) AS SampleSize
FROM BenfordExpected b
LEFT JOIN Observed o ON b.Digit = o.LeadingDigit;

-- Step 3: Second-digit analysis (more sensitive for threshold manipulation)
WITH LeadingTwo AS (
    SELECT
        CASE
            WHEN LEN(CAST(ABS(TotalAmount) AS BIGINT)) >= 2
                 THEN CAST(SUBSTRING(CAST(ABS(TotalAmount) AS VARCHAR), 2, 1) AS INT)
            ELSE NULL
        END AS SecondDigit
    FROM Orders
    WHERE TotalAmount > 0 AND TotalAmount IS NOT NULL
)
SELECT
    SecondDigit,
    COUNT(*) AS Count,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS ObsPct,
    -- Benford second-digit: all digits 0-9 converge toward ~10%
    10.0 AS ExpectedPct,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER () - 10.0, 1) AS Deviation
FROM LeadingTwo
WHERE SecondDigit IS NOT NULL
GROUP BY SecondDigit
ORDER BY SecondDigit;
```

## Explanation

**Benford's Law applicability**
Benford's Law applies to datasets where values span multiple orders of magnitude, arise from multiplicative processes, and are not artificially constrained. It works well for: sales amounts, invoice values, transaction amounts, and population figures. It does NOT apply to: uniform distributions (dice rolls), artificially bounded data (zip codes), or small datasets where random variation dominates.

**Leading digit extraction**
`CAST(LEFT(CAST(ABS(TotalAmount) AS BIGINT), 1) AS INT)` converts the amount to a positive integer (removing sign and decimal), converts to string, takes the first character, and casts back to INT. `ABS()` handles negative values (refunds, credits); `BIGINT` prevents overflow for large amounts; `LEFT(..., 1)` robustly extracts the first digit regardless of the number's magnitude.

**Chi-square test for conformance**
The chi-square statistic measures total deviation across all 9 digits. With 8 degrees of freedom (9 digits − 1), the critical value at the 95% confidence level is 15.507. A chi-square above 15.507 rejects the null hypothesis that the data conforms to Benford's Law. For small samples (N < 100), Benford's analysis is unreliable and the chi-square test should not be used.

**Second-digit analysis**
Step 3 analyses the second digit, which converges toward a uniform 10% distribution for each digit 0–9. Second-digit over-representation of 9 and 0 is a classic signal of "just below" threshold manipulation: amounts like £4,999, £9,999, and £49,900 all have second digit 9, while threshold-manipulation targets create clusters around these values.

## Severity
**Medium** — Benford's Law analysis is a probabilistic fraud indicator, not a definitive fraud detection tool. A non-conforming distribution warrants investigation but does not prove fraud: legitimate datasets from bounded price ranges, standardised fee schedules, or small sample sizes naturally deviate from Benford. Used as one component of a broader fraud detection framework, it has documented effectiveness in catching fictitious invoice schemes, expense manipulation, and data fabrication.
