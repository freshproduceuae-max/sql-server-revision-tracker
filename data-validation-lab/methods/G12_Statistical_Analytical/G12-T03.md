# G12-T03 — Statistical/Analytical | Sampling Bias Detection

## ID
G12-T03

## Group
12 — Statistical/Analytical

## Type
Sampling Bias Detection — Verifying That a Data Sample Represents the Full Population

## Live Scenario
A data science team is building a product recommendation model. They sample 20% of orders for the training set using a system-assigned row number modulo 5. After training, the model performs poorly for orders in the "Cancelled" and "Returned" categories. Investigation reveals the sampling logic inadvertently excluded most Cancelled orders — they were assigned sequential IDs in a batch at the end of each day and most fell into the same modulo bucket (row numbers 5, 10, 15, … all map to 0 mod 5). The training sample contains only 4% Cancelled orders vs 18% in the full dataset. The model never learned Cancelled order patterns and cannot correctly handle them at inference time. Sampling bias detection — comparing the sample's column distributions to the population's — would have caught this before model training.

## The Question
> Sampling bias occurs when a drawn sample does not represent the statistical properties of the full population. Bias detection compares distributions of key columns between the sample and the population, flags columns where the proportions deviate significantly, and tests whether the sample is representative by stratification group.
> **"Compare the distribution of Status, Country, and TotalAmount value bands between a 25% random sample of Orders and the full Orders population — flag any category where the sample proportion differs from the population proportion by more than 5 percentage points."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Draw a deterministic 25% sample using TABLESAMPLE or modulo
-- Using modulo on OrderID (deterministic, reproducible)
WITH FullPopulation AS (
    SELECT o.*, c.Country
    FROM Orders o
    LEFT JOIN Customers c ON o.CustomerID = c.CustomerID
),
Sample25Pct AS (
    SELECT o.*, c.Country
    FROM Orders o
    LEFT JOIN Customers c ON o.CustomerID = c.CustomerID
    -- Take every 4th row by OrderID hash for reproducibility
    WHERE ABS(CHECKSUM(o.OrderID)) % 4 = 0
),

-- Step 2: Compare Status distribution: population vs sample
PopStatus AS (
    SELECT
        Status,
        COUNT(*) AS PopCount,
        ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS PopPct
    FROM FullPopulation
    GROUP BY Status
),
SampleStatus AS (
    SELECT
        Status,
        COUNT(*) AS SampleCount,
        ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS SamplePct
    FROM Sample25Pct
    GROUP BY Status
)
SELECT
    COALESCE(p.Status, s.Status) AS Status,
    p.PopCount,
    p.PopPct,
    s.SampleCount,
    s.SamplePct,
    ROUND(ISNULL(s.SamplePct, 0) - ISNULL(p.PopPct, 0), 1) AS PctPointDiff,
    CASE
        WHEN s.Status IS NULL
             THEN 'MISSING IN SAMPLE: Category absent from sample entirely'
        WHEN ABS(ISNULL(s.SamplePct, 0) - ISNULL(p.PopPct, 0)) > 10
             THEN 'SEVERE BIAS: >10 percentage point difference'
        WHEN ABS(ISNULL(s.SamplePct, 0) - ISNULL(p.PopPct, 0)) > 5
             THEN 'MODERATE BIAS: >5 percentage point difference'
        ELSE 'Representative'
    END AS BiasFlag
FROM PopStatus p
FULL OUTER JOIN SampleStatus s ON p.Status = s.Status;

-- Step 3: Compare numeric distribution: TotalAmount
SELECT
    'Population' AS DataSet,
    COUNT(*) AS RowCount,
    ROUND(AVG(TotalAmount), 2) AS MeanAmount,
    ROUND(MIN(TotalAmount), 2) AS MinAmount,
    ROUND(MAX(TotalAmount), 2) AS MaxAmount,
    ROUND(STDEV(TotalAmount), 2) AS StdDev,
    ROUND(PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY TotalAmount) OVER (), 2) AS Median
FROM Orders
WHERE TotalAmount IS NOT NULL
UNION ALL
SELECT
    'Sample 25%',
    COUNT(*),
    ROUND(AVG(TotalAmount), 2),
    ROUND(MIN(TotalAmount), 2),
    ROUND(MAX(TotalAmount), 2),
    ROUND(STDEV(TotalAmount), 2),
    ROUND(PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY TotalAmount) OVER (), 2)
FROM Orders
WHERE TotalAmount IS NOT NULL
  AND ABS(CHECKSUM(OrderID)) % 4 = 0;

-- Step 4: Stratified sample size check — is each stratum adequately represented?
WITH StrataCounts AS (
    SELECT
        Status,
        COUNT(*) AS PopCount,
        SUM(CASE WHEN ABS(CHECKSUM(OrderID)) % 4 = 0 THEN 1 ELSE 0 END) AS SampleCount
    FROM Orders
    GROUP BY Status
)
SELECT
    Status,
    PopCount,
    SampleCount,
    ROUND(100.0 * SampleCount / NULLIF(PopCount, 0), 1) AS SampleRatePct,
    CASE
        WHEN SampleCount = 0
             THEN 'EXCLUDED: No records from this stratum in sample'
        WHEN SampleCount < 5
             THEN 'THIN: Fewer than 5 sample records — statistically unreliable'
        WHEN ABS(100.0 * SampleCount / NULLIF(PopCount, 0) - 25) > 10
             THEN 'UNEVEN RATE: Sample rate deviates >10pp from target 25%'
        ELSE 'Representative sample rate'
    END AS StratumFlag
FROM StrataCounts
ORDER BY PopCount DESC;
```

## Explanation

**CHECKSUM(OrderID) % N for reproducible sampling**
`ABS(CHECKSUM(OrderID)) % 4 = 0` selects approximately 25% of rows deterministically — running the query twice on the same data returns the same sample. Unlike `TABLESAMPLE`, which samples at page level and can produce uneven results for small tables, the CHECKSUM approach distributes evenly across the keyspace. The CHECKSUM is a hash of the key value, not a sequential number — so it avoids the modulo-on-sequential-ID bias that caused the live scenario's problem.

**FULL OUTER JOIN for missing category detection**
Using a FULL OUTER JOIN between population and sample status distributions catches categories present in one but absent from the other. A LEFT JOIN would miss categories that exist only in the sample (new values); a RIGHT JOIN would miss categories absent from the sample (the critical bias scenario).

**5-percentage-point threshold**
The 5pp threshold is a common starting point for bias detection. For model training datasets, even a 2pp bias in a rare positive class (e.g., fraud = 2% of population) may cause the model to systematically underfit that class. The appropriate threshold depends on: class frequency (rarer classes need tighter thresholds), model sensitivity (classification vs regression), and downstream use (fraud detection vs revenue forecasting).

**Stratified sample rate check (Step 4)**
Step 4 tests whether each stratum (Status group) achieves approximately the target sample rate (25%). A stratum where only 10% of records were sampled will be underrepresented in the training data relative to its population frequency. This test catches both modulo-bucket effects and accidental filtering.

## Severity
**High** — A biased training sample produces a biased model. Models trained on under-represented minority classes systematically misclassify those classes at inference time — precisely the cases where correct classification is often most valuable (fraud, churn, rare disease). Sampling bias detection is a prerequisite for any model training data preparation step.
