# G13-T03 — Hierarchical/Structural | Hierarchy Completeness and Depth Validation

## ID
G13-T03

## Group
13 — Hierarchical/Structural

## Type
Hierarchy Completeness and Depth Validation — Verifying All Levels Exist and Depth Is Within Expected Bounds

## Live Scenario
A retail company uses a four-level product category hierarchy: Department → Category → Sub-category → Product. A BI analyst building a category drill-down report notices some products appear at the top level — they are assigned directly to a Department without an intermediate Category or Sub-category. The drill-down breaks for these products because the BI tool expects exactly four levels. Investigation reveals the issue originated when 320 products were bulk-imported from a supplier catalogue that only had a two-level hierarchy. The products were assigned directly to the closest available parent, skipping the intermediate levels. The hierarchy validation query identifies all products that bypass expected levels, enabling a data steward to correctly assign the missing intermediate categories before the report goes live.

## The Question
> Hierarchy completeness validation checks that: every node has a parent (except roots), no level is skipped in a multi-level hierarchy, the hierarchy depth falls within expected bounds, and leaf nodes (nodes with no children) are at the expected level. SQL validates these properties using recursive CTEs to compute node depth and level counts.
> **"In the Employees table, validate the management hierarchy: verify all non-root employees have a valid manager, calculate the depth of each employee's position, identify any spans of control that are unusually wide (more than 10 direct reports) or the hierarchy is unusually deep (more than 6 levels), and flag leaf nodes not at the expected lowest level."**

## Table Reference
**Employees** — `schemas/04_Employees.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Compute hierarchy depth for each employee
WITH EmployeeHierarchy AS (
    -- Anchor: root employees (no manager)
    SELECT
        EmployeeID,
        FullName,
        ManagerID,
        Department,
        0 AS Depth
    FROM Employees
    WHERE ManagerID IS NULL

    UNION ALL

    SELECT
        e.EmployeeID,
        e.FullName,
        e.ManagerID,
        e.Department,
        h.Depth + 1
    FROM Employees e
    JOIN EmployeeHierarchy h ON h.EmployeeID = e.ManagerID
    WHERE e.ManagerID <> e.EmployeeID
)
SELECT
    eh.EmployeeID,
    eh.FullName,
    eh.ManagerID,
    eh.Department,
    eh.Depth,
    -- Direct report count (span of control)
    (SELECT COUNT(*) FROM Employees sub WHERE sub.ManagerID = eh.EmployeeID) AS DirectReports,
    -- Is this a leaf node (no direct reports)?
    CASE WHEN NOT EXISTS (SELECT 1 FROM Employees sub WHERE sub.ManagerID = eh.EmployeeID)
         THEN 1 ELSE 0 END AS IsLeaf,
    CASE
        WHEN eh.Depth = 0 THEN 'ROOT'
        WHEN NOT EXISTS (SELECT 1 FROM Employees sub WHERE sub.ManagerID = eh.EmployeeID)
             THEN 'LEAF'
        ELSE 'INTERNAL NODE'
    END AS NodeType,
    -- Span of control flags
    CASE
        WHEN (SELECT COUNT(*) FROM Employees sub WHERE sub.ManagerID = eh.EmployeeID) > 10
             THEN 'WIDE SPAN: >10 direct reports — management overload risk'
        WHEN (SELECT COUNT(*) FROM Employees sub WHERE sub.ManagerID = eh.EmployeeID) = 1
             AND eh.Depth > 0
             THEN 'SINGLE REPORT: Manager with exactly 1 direct report — potential hierarchy bloat'
        ELSE 'Normal span'
    END AS SpanFlag,
    CASE
        WHEN eh.Depth > 6
             THEN 'DEEP HIERARCHY: >6 levels — communication chain very long'
        ELSE 'Acceptable depth'
    END AS DepthFlag
FROM EmployeeHierarchy eh
ORDER BY eh.Depth, eh.FullName
OPTION (MAXRECURSION 50);

-- Step 2: Hierarchy summary statistics
WITH EmployeeHierarchy AS (
    SELECT EmployeeID, ManagerID, 0 AS Depth FROM Employees WHERE ManagerID IS NULL
    UNION ALL
    SELECT e.EmployeeID, e.ManagerID, h.Depth + 1
    FROM Employees e JOIN EmployeeHierarchy h ON h.EmployeeID = e.ManagerID
    WHERE e.ManagerID <> e.EmployeeID
)
SELECT
    COUNT(*) AS TotalEmployees,
    MAX(Depth) AS MaxDepth,
    MIN(Depth) AS MinDepth,
    ROUND(AVG(CAST(Depth AS FLOAT)), 1) AS AvgDepth,
    COUNT(CASE WHEN Depth = 0 THEN 1 END) AS RootCount,
    COUNT(CASE WHEN NOT EXISTS (SELECT 1 FROM Employees s WHERE s.ManagerID = eh.EmployeeID)
               THEN 1 END) AS LeafCount,
    CASE
        WHEN COUNT(CASE WHEN Depth = 0 THEN 1 END) > 1
             THEN 'MULTIPLE ROOTS: Hierarchy has ' + CAST(COUNT(CASE WHEN Depth=0 THEN 1 END) AS VARCHAR) + ' root nodes'
        WHEN COUNT(CASE WHEN Depth = 0 THEN 1 END) = 0
             THEN 'NO ROOT: All employees have a manager — possible cycle or missing root'
        ELSE 'Single root'
    END AS RootCheck
FROM EmployeeHierarchy eh
OPTION (MAXRECURSION 50);

-- Step 3: Employees not reachable from the root (disconnected components)
WITH ReachableFromRoot AS (
    SELECT EmployeeID FROM Employees WHERE ManagerID IS NULL
    UNION ALL
    SELECT e.EmployeeID
    FROM Employees e
    JOIN ReachableFromRoot r ON r.EmployeeID = e.ManagerID
    WHERE e.ManagerID <> e.EmployeeID
)
SELECT
    e.EmployeeID,
    e.FullName,
    e.ManagerID,
    e.Department,
    'DISCONNECTED: Not reachable from any root node' AS Issue
FROM Employees e
WHERE NOT EXISTS (SELECT 1 FROM ReachableFromRoot r WHERE r.EmployeeID = e.EmployeeID)
OPTION (MAXRECURSION 50);

-- Step 4: Span of control distribution
SELECT
    DirectReportCount,
    COUNT(*) AS ManagerCount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct,
    CASE
        WHEN DirectReportCount = 0 THEN 'Leaf node (no direct reports)'
        WHEN DirectReportCount BETWEEN 1 AND 3 THEN 'Small team'
        WHEN DirectReportCount BETWEEN 4 AND 7 THEN 'Standard team'
        WHEN DirectReportCount BETWEEN 8 AND 10 THEN 'Large team'
        ELSE 'OVERSIZED SPAN: >10 direct reports'
    END AS SpanCategory
FROM (
    SELECT
        e.EmployeeID,
        COUNT(sub.EmployeeID) AS DirectReportCount
    FROM Employees e
    LEFT JOIN Employees sub ON sub.ManagerID = e.EmployeeID
    GROUP BY e.EmployeeID
) SpanCounts
GROUP BY DirectReportCount
ORDER BY DirectReportCount;
```

## Explanation

**Recursive CTE for depth computation**
The anchor clause selects root nodes (`ManagerID IS NULL`). The recursive clause joins employees to their manager's row via `JOIN EmployeeHierarchy h ON h.EmployeeID = e.ManagerID` and increments the depth by 1. Each employee's depth equals the length of the chain from the root to that employee. This is the canonical approach for computing node level in an adjacency-list hierarchy.

**Multiple roots as a structural warning**
A management hierarchy should have exactly one root (the CEO or top-level entity). Multiple roots indicate: disconnected sub-trees (different business units loaded separately without a unifying parent), data quality errors (some employees' root manager was deleted), or an intentional flat structure (all senior leaders report to "no manager"). The query flags multiple roots because they prevent correct depth calculations and hierarchy reporting.

**Span of control as an organisational data quality signal**
A manager with 1 direct report may represent legitimate structure (a specialist with a unique role), or hierarchy bloat (an intermediate manager layer that adds no value). A manager with 15 direct reports may be overloaded. While organisational design is a business decision, extreme span values in a database context often indicate: bulk imports that assigned too many employees to a single manager, or records where the ManagerID field was defaulted to a single senior employee.

**Disconnected components (Step 3)**
Step 3 finds employees who cannot be reached by traversing the hierarchy from the root. These employees are in a separate "island" — possibly the result of their root manager being deleted without reassigning their team, or records imported with a ManagerID that was never created. Disconnected nodes are invisible to any top-down hierarchy report.

## Severity
**Medium** — Hierarchy depth and completeness violations directly impact drill-down reporting, org chart rendering, rollup aggregations, and recursive SQL queries. A broken management hierarchy produces wrong territory assignments, incorrect commission roll-ups, and org chart visualisations that are missing entire branches.
