# G06-T01 — Consistency | Cross-Column Logical Contradiction

## ID
G06-T01

## Group
6 — Consistency

## Type
Cross-Column Logical Contradiction — Two Columns in the Same Row Contradict Each Other

## Live Scenario
An HR system records each employee's employment status across two columns: `TerminationDate` (the date they left the company) and `IsActive` (a boolean flag indicating current employment). A batch update that marks employees as inactive sets `IsActive = 0` but fails to populate `TerminationDate` for 61 records, and a separate migration populates `TerminationDate` for 14 records without clearing `IsActive`. The result: 61 employees show as active with no termination date yet appear in "leavers" reports, and 14 employees show a termination date but are still marked active, allowing them to pass access-control checks that filter on `IsActive = 1`.

## The Question
> When two columns both encode the same underlying fact (employment status), they must agree. A terminated employee must have `IsActive = 0` AND a `TerminationDate`. An active employee must have `IsActive = 1` AND no `TerminationDate`. Any combination that violates this pairing is a logical contradiction.
> **"Find all Employees where IsActive and TerminationDate contradict each other — active employees with a termination date set, or inactive employees with no termination date."**

## Table Reference
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Step 1: Find logical contradictions between IsActive and TerminationDate
SELECT
    EmployeeID,
    FullName,
    HireDate,
    TerminationDate,
    -- IsActive assumed as: TerminationDate IS NULL = active
    CASE WHEN TerminationDate IS NULL THEN 1 ELSE 0 END AS DerivedIsActive,
    CASE
        WHEN TerminationDate IS NOT NULL AND DATEDIFF(DAY, TerminationDate, GETDATE()) < 0
             THEN 'Future termination date — currently still active'
        WHEN TerminationDate IS NOT NULL
             THEN 'Has TerminationDate — treated as inactive'
        ELSE 'No TerminationDate — treated as active'
    END AS EmploymentStatus,
    CASE
        -- Active employee with a past termination date: contradiction
        WHEN TerminationDate IS NOT NULL AND TerminationDate <= GETDATE()
             THEN 'CONTRADICTION: TerminationDate set but may still appear active'
        -- Hire date after termination date
        WHEN TerminationDate IS NOT NULL AND TerminationDate < HireDate
             THEN 'CONTRADICTION: Terminated before hired'
        ELSE 'Consistent'
    END AS ConsistencyFlag
FROM Employees
WHERE TerminationDate IS NOT NULL AND TerminationDate < HireDate
   OR (TerminationDate IS NOT NULL AND TerminationDate <= GETDATE()
       AND HireDate IS NOT NULL);

-- Step 2: Contradiction between derived status and HireDate logic
SELECT
    EmployeeID,
    FullName,
    HireDate,
    TerminationDate,
    CASE
        WHEN TerminationDate IS NULL THEN 'Active'
        ELSE 'Terminated'
    END AS DerivedStatus,
    -- Flag impossible combinations
    CASE
        WHEN TerminationDate IS NOT NULL AND TerminationDate < HireDate
             THEN 'CRITICAL: Terminated before hired'
        WHEN TerminationDate IS NOT NULL AND TerminationDate = HireDate
             THEN 'WARNING: Hired and terminated same day'
        WHEN HireDate > GETDATE()
             THEN 'WARNING: Future hire date — not yet employed'
        WHEN TerminationDate > GETDATE()
             THEN 'INFO: Future termination date scheduled'
        ELSE 'OK'
    END AS LogicCheck
FROM Employees
WHERE (TerminationDate IS NOT NULL AND TerminationDate <= HireDate)
   OR HireDate > GETDATE();

-- Step 3: Cross-column check on Orders — Status vs DeliveryDate
-- Rule: Delivered orders must have a DeliveryDate; Pending orders must not
SELECT
    OrderID,
    Status,
    DeliveryDate,
    CASE
        WHEN Status = 'Delivered' AND DeliveryDate IS NULL
             THEN 'CONTRADICTION: Status=Delivered but no DeliveryDate'
        WHEN Status IN ('Pending', 'Processing') AND DeliveryDate IS NOT NULL
             THEN 'CONTRADICTION: Has DeliveryDate but Status is still Pending/Processing'
        WHEN Status = 'Cancelled' AND DeliveryDate IS NOT NULL
             THEN 'WARNING: Cancelled order has a DeliveryDate set'
        ELSE 'Consistent'
    END AS StatusDateConsistency
FROM Orders
WHERE (Status = 'Delivered' AND DeliveryDate IS NULL)
   OR (Status IN ('Pending', 'Processing') AND DeliveryDate IS NOT NULL)
   OR (Status = 'Cancelled' AND DeliveryDate IS NOT NULL);

-- Step 4: Summary of all cross-column contradictions
SELECT 'Employees: Terminated before hired' AS Rule, COUNT(*) AS ViolationCount
FROM Employees WHERE TerminationDate IS NOT NULL AND TerminationDate < HireDate
UNION ALL
SELECT 'Orders: Delivered without DeliveryDate', COUNT(*)
FROM Orders WHERE Status = 'Delivered' AND DeliveryDate IS NULL
UNION ALL
SELECT 'Orders: Pending with DeliveryDate set', COUNT(*)
FROM Orders WHERE Status IN ('Pending','Processing') AND DeliveryDate IS NOT NULL
ORDER BY ViolationCount DESC;
```

## Explanation

**Derived vs stored redundancy**
When the same fact is stored in two columns (`IsActive` derived from `TerminationDate IS NULL`), both must be kept in sync. The problem with redundancy is that updates to one column don't automatically update the other. The architectural fix is to store the fact once and derive the other value: compute `IsActive` as `CASE WHEN TerminationDate IS NULL THEN 1 ELSE 0 END` rather than storing it separately.

**Business rules as cross-column constraints**
"A delivered order must have a delivery date" is a business rule that requires two columns to agree. These cannot be enforced by a single-column NOT NULL constraint — they need a CHECK constraint: `CHECK (NOT (Status = 'Delivered' AND DeliveryDate IS NULL))`.

**CASE expressions for multi-condition consistency**
A single CASE expression can evaluate multiple column combinations simultaneously, making contradictions readable as named conditions rather than raw boolean expressions. This is especially valuable in validation queries shared with business stakeholders.

**Contradiction vs incompleteness**
A delivered order with no delivery date is a contradiction (the status says it's done, the date says it hasn't happened). A pending order with no expected delivery date is incompleteness (a value is missing but no columns contradict each other). Both are data quality issues but require different remediation strategies.

## Severity
**High** — Cross-column contradictions corrupt business logic that depends on derived state. Access control checks filtering on `IsActive = 1` will include terminated employees if `IsActive` is not kept in sync with `TerminationDate`. In financial systems, contradictory status flags cause records to be included in or excluded from calculations where they do not belong.
