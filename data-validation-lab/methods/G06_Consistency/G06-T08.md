# G06-T08 — Consistency | Conditional Field Dependency

## ID
G06-T08

## Group
6 — Consistency

## Type
Conditional Field Dependency — A Field is Required or Forbidden Based on Another Field's Value

## Live Scenario
A financial onboarding system collects different information depending on customer type: business customers must have a `CompanyRegistrationNumber`, while individual customers must have a `DateOfBirth`. A migration from a legacy system incorrectly sets `CustomerType = 'Business'` for 234 records that are actually individual consumers — their `CompanyRegistrationNumber` is NULL (correct for individuals, but now they appear to be businesses with missing registration numbers). The KYC (Know Your Customer) team's automated check fails on these records, freezing £890,000 in transactions pending manual review.

## The Question
> Conditional field requirements are business rules where field A's value determines whether field B is mandatory, forbidden, or constrained. SQL enforces these rules by evaluating the condition (A = 'X') and then checking whether the dependent field (B) meets its requirement.
> **"Find all Customers where the combination of country and a required field violates conditional dependency rules — e.g., UK customers should have a postal code, and find all Orders where Cancelled status should have a NULL DeliveryDate."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Orders** — `schemas/02_Orders.csv`
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Step 1: Country-conditional field requirements
-- UK customers must have PostalCode; non-UK customers should have Country set
SELECT
    CustomerID,
    FirstName,
    LastName,
    Country,
    PostalCode,
    CASE
        WHEN Country = 'UK' AND (PostalCode IS NULL OR LTRIM(RTRIM(PostalCode)) = '')
             THEN 'REQUIRED: UK customer missing PostalCode'
        WHEN Country IS NULL AND PostalCode IS NOT NULL
             THEN 'WARNING: PostalCode set but no Country'
        WHEN Country NOT IN ('UK','US','CA','AU') AND Country IS NOT NULL AND PostalCode IS NULL
             THEN 'INFO: Non-standard country with no PostalCode'
        ELSE 'OK'
    END AS CountryPostalCodeRule
FROM Customers
WHERE (Country = 'UK' AND (PostalCode IS NULL OR LTRIM(RTRIM(PostalCode)) = ''))
   OR (Country IS NULL AND PostalCode IS NOT NULL);

-- Step 2: Order status conditional field rules
-- Delivered → DeliveryDate required
-- Cancelled → DeliveryDate must be NULL
-- Shipped → DeliveryDate should be NULL (not yet delivered)
SELECT
    OrderID,
    Status,
    DeliveryDate,
    CASE
        WHEN Status = 'Delivered' AND DeliveryDate IS NULL
             THEN 'VIOLATION: Delivered orders must have DeliveryDate'
        WHEN Status = 'Cancelled' AND DeliveryDate IS NOT NULL
             THEN 'VIOLATION: Cancelled orders must not have DeliveryDate'
        WHEN Status = 'Pending' AND DeliveryDate IS NOT NULL
             THEN 'VIOLATION: Pending orders must not have DeliveryDate'
        WHEN Status = 'Shipped' AND DeliveryDate IS NOT NULL
             AND DeliveryDate <= GETDATE()
             THEN 'WARNING: Shipped order has a past DeliveryDate — should be Delivered'
        ELSE 'OK'
    END AS ConditionalRule
FROM Orders
WHERE (Status = 'Delivered' AND DeliveryDate IS NULL)
   OR (Status = 'Cancelled' AND DeliveryDate IS NOT NULL)
   OR (Status = 'Pending'   AND DeliveryDate IS NOT NULL);

-- Step 3: Employee termination conditional rules
-- Terminated employees must have TerminationDate
-- Active employees must NOT have TerminationDate in the past
SELECT
    EmployeeID,
    FullName,
    EmploymentType,
    HireDate,
    TerminationDate,
    CASE
        WHEN EmploymentType = 'Contract' AND TerminationDate IS NULL
             THEN 'WARNING: Contract employee with no end date'
        WHEN EmploymentType = 'Full-Time' AND TerminationDate IS NOT NULL
             AND TerminationDate < GETDATE()
             THEN 'INFO: Full-time employee with past termination date — verify if still employed'
        WHEN TerminationDate IS NOT NULL AND HireDate IS NULL
             THEN 'VIOLATION: Termination date set with no hire date'
        ELSE 'OK'
    END AS EmploymentTypeRule
FROM Employees
WHERE (EmploymentType = 'Contract' AND TerminationDate IS NULL)
   OR (TerminationDate IS NOT NULL AND HireDate IS NULL);

-- Step 4: Summary of all conditional dependency violations
SELECT
    'Customers: UK without PostalCode' AS Rule,
    COUNT(*) AS ViolationCount
FROM Customers
WHERE Country = 'UK' AND (PostalCode IS NULL OR LTRIM(RTRIM(PostalCode)) = '')

UNION ALL

SELECT
    'Orders: Delivered without DeliveryDate',
    COUNT(*)
FROM Orders
WHERE Status = 'Delivered' AND DeliveryDate IS NULL

UNION ALL

SELECT
    'Orders: Cancelled with DeliveryDate',
    COUNT(*)
FROM Orders
WHERE Status = 'Cancelled' AND DeliveryDate IS NOT NULL

UNION ALL

SELECT
    'Employees: Contract without TerminationDate',
    COUNT(*)
FROM Employees
WHERE EmploymentType = 'Contract' AND TerminationDate IS NULL

ORDER BY ViolationCount DESC;
```

## Explanation

**Conditional NOT NULL vs unconditional NOT NULL**
A simple `NOT NULL` constraint makes a column mandatory for every row. A conditional dependency requires the column to be NOT NULL only when another column has a specific value. This cannot be expressed as a column-level NOT NULL constraint — it requires a table-level CHECK constraint: `CHECK (NOT (Status = 'Delivered' AND DeliveryDate IS NULL))`.

**Implication rules**
Conditional dependency rules are logical implications: "if A, then B must hold." In SQL CASE expressions, this translates to: `WHEN <condition_A> AND NOT <condition_B> THEN 'VIOLATION'`. Each implication is a separate WHEN clause.

**Multiple implications per field**
A single field may have multiple conditional requirements: `DeliveryDate` must be NOT NULL when `Status = 'Delivered'`, and must be NULL when `Status IN ('Cancelled', 'Pending')`. Each condition is a separate branch in the CASE expression.

**CHECK constraints for enforcement**
```sql
ALTER TABLE Orders ADD CONSTRAINT chk_DeliveryDateOnDelivered
CHECK (
    (Status = 'Delivered' AND DeliveryDate IS NOT NULL) OR
    (Status <> 'Delivered')
);
```
This enforces the rule at write time. The SQL validation query detects existing violations in data loaded before the constraint was added.

## Severity
**High** — Conditional field violations indicate that business-critical attributes are present when they shouldn't be or absent when they must exist. In KYC/AML compliance, a missing required field can freeze accounts and trigger regulatory notifications. In fulfilment systems, a delivered order without a delivery date corrupts SLA calculations and customer communications.
