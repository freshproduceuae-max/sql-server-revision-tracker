# G06-T14 — Consistency | Cardinality Constraint Violation

## ID
G06-T14

## Group
6 — Consistency

## Type
Cardinality Constraint Violation — Relationship Has Wrong Number of Associated Records

## Live Scenario
An e-commerce platform has a business rule: every order must have at least one transaction (a payment event), and at most three transactions (initial payment, one partial refund, one full refund). A refund processing bug creates four transaction records for Order 1089 — an initial payment plus three partial refunds — when only two refunds should have been possible. The order's net balance is calculated by summing all transactions, but the extra transaction doubles the refund amount, producing a negative net balance of -£220 for an order that should be £0 settled. A nightly settlement job attempts to pay the customer an extra £220.

## The Question
> Cardinality rules ("one-to-one," "one-to-many with a maximum," "exactly N") constrain how many child records a parent may have. Violations occur when a parent has too few or too many children. SQL detects these using GROUP BY + HAVING.
> **"Find all Orders that have zero transactions (minimum cardinality violated) or more than 3 transactions (maximum cardinality violated), and find all Employees who manage more than 10 direct reports (a business-defined maximum)."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Transactions** — `schemas/05_Transactions.csv`
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Step 1: Orders with no transactions (minimum = 1 violated)
SELECT
    o.OrderID,
    o.CustomerID,
    o.OrderDate,
    o.Status,
    o.TotalAmount,
    0 AS TransactionCount,
    'VIOLATION: Order has no transactions (min cardinality = 1)' AS Issue
FROM Orders o
WHERE o.Status IN ('Delivered', 'Processing', 'Shipped')
  AND NOT EXISTS (
    SELECT 1 FROM Transactions t WHERE t.OrderID = o.OrderID
  );

-- Step 2: Orders with too many transactions (maximum = 3 violated)
SELECT
    t.OrderID,
    COUNT(*) AS TransactionCount,
    SUM(t.Amount) AS TotalTransactionAmount,
    o.TotalAmount AS OrderAmount,
    'VIOLATION: Order has more than 3 transactions (max cardinality = 3)' AS Issue
FROM Transactions t
JOIN Orders o ON t.OrderID = o.OrderID
GROUP BY t.OrderID, o.TotalAmount
HAVING COUNT(*) > 3
ORDER BY TransactionCount DESC;

-- Step 3: Combined cardinality report — all orders with their transaction count
WITH OrderTransactionCounts AS (
    SELECT
        o.OrderID,
        o.CustomerID,
        o.Status,
        o.TotalAmount,
        COUNT(t.TransactionID) AS TxCount
    FROM Orders o
    LEFT JOIN Transactions t ON o.OrderID = t.OrderID
    GROUP BY o.OrderID, o.CustomerID, o.Status, o.TotalAmount
)
SELECT
    OrderID,
    CustomerID,
    Status,
    TotalAmount,
    TxCount,
    CASE
        WHEN TxCount = 0 AND Status IN ('Delivered','Processing','Shipped')
             THEN 'VIOLATION: No transactions for active/closed order'
        WHEN TxCount > 3
             THEN 'VIOLATION: Exceeds max transaction limit (3)'
        WHEN TxCount = 0 AND Status = 'Pending'
             THEN 'OK: Pending order awaiting first transaction'
        ELSE 'OK: Within cardinality bounds (1–3)'
    END AS CardinalityStatus
FROM OrderTransactionCounts
ORDER BY TxCount DESC;

-- Step 4: Employees managing too many direct reports
SELECT
    ManagerID,
    m.FullName AS ManagerName,
    COUNT(*) AS DirectReportCount,
    STRING_AGG(e.EmployeeID, ', ') AS DirectReportIDs,
    CASE
        WHEN COUNT(*) > 10 THEN 'VIOLATION: >10 direct reports (max span of control)'
        WHEN COUNT(*) > 7  THEN 'WARNING: 8–10 direct reports — approaching limit'
        ELSE 'Within span-of-control limit'
    END AS SpanOfControlFlag
FROM Employees e
JOIN Employees m ON e.ManagerID = m.EmployeeID
GROUP BY e.ManagerID, m.FullName
HAVING COUNT(*) > 7
ORDER BY DirectReportCount DESC;

-- Step 5: Product-order cardinality — how many distinct products per order
SELECT
    OrderID,
    COUNT(DISTINCT ProductID) AS DistinctProducts,
    COUNT(*) AS TotalOrderLines,
    CASE
        WHEN COUNT(DISTINCT ProductID) = 0 THEN 'VIOLATION: Order has no products'
        WHEN COUNT(*) > COUNT(DISTINCT ProductID)
             THEN 'WARNING: Duplicate product in order lines'
        ELSE 'OK'
    END AS OrderLineConsistency
FROM Orders
GROUP BY OrderID
HAVING COUNT(*) > COUNT(DISTINCT ProductID)
    OR COUNT(*) = 0;
```

## Explanation

**Minimum cardinality: NOT EXISTS**
An order with zero transactions violates a minimum-1 cardinality rule. `NOT EXISTS (SELECT 1 FROM Transactions WHERE OrderID = o.OrderID)` efficiently checks for the absence of child records without counting all of them — it stops as soon as one row is found (or confirms none exists).

**Maximum cardinality: GROUP BY + HAVING COUNT > N**
`HAVING COUNT(*) > 3` identifies parent records with more children than the permitted maximum. `GROUP BY OrderID` brings all child records for each parent together into one aggregated row for the comparison.

**Cardinality vs uniqueness**
Maximum cardinality of 1 is equivalent to a unique constraint (one child per parent). Maximum cardinality of N > 1 cannot be enforced by a UNIQUE constraint — it requires a trigger or application-layer enforcement. SQL validation queries detect violations after the fact.

**Span of control**
Step 4 applies cardinality to the management hierarchy: a manager with more than 10 direct reports may indicate a hierarchy data error (multiple employees assigned to the wrong manager) or a genuine span-of-control policy violation. Both are worth investigating.

## Severity
**High** — Maximum cardinality violations can cause financial over-processing (extra refunds, duplicate payments) when business logic assumes a bounded number of child records. Minimum cardinality violations cause NULL results in required calculations (order net balance with no transactions).
