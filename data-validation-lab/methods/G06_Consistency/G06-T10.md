# G06-T10 — Consistency | Lookup Code Mismatch

## ID
G06-T10

## Group
6 — Consistency

## Type
Lookup Code Mismatch — Stored Code Does Not Match the Referenced Lookup Table

## Live Scenario
A logistics platform stores ISO 4217 currency codes in a `Transactions.Currency` column and country codes in `Customers.Country` using ISO 3166-1 alpha-2 codes. A partner integration sends currency code `'GBP'` correctly, but country as `'UK'` (commonly used but non-standard) while the system's reference table expects `'GB'` (ISO 3166-1 standard). The `Customers` table accumulates 1,847 rows with `Country = 'UK'` that fail all WHERE clauses filtering on `Country = 'GB'` — they are invisible to UK-specific reports. A quarterly UK market analysis understates UK customers by 42%.

## The Question
> Code columns that reference a controlled vocabulary (ISO codes, internal reference codes, classification codes) must contain only values present in the reference table. A value not in the lookup table is either invalid or a variant encoding of a valid code. SQL detects mismatches via anti-join patterns.
> **"Find all Transactions where Currency is not a recognised ISO 4217 code, and find all Customers where Country code is not in the expected set — demonstrating lookup code validation."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Transactions** — `schemas/05_Transactions.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Currency code validation against ISO 4217 subset
-- In practice, replace this table variable with your actual CurrencyCodes reference table
DECLARE @ValidCurrencies TABLE (CurrencyCode CHAR(3));
INSERT INTO @ValidCurrencies VALUES
    ('GBP'), ('EUR'), ('USD'), ('JPY'), ('AUD'), ('CAD'),
    ('CHF'), ('CNY'), ('HKD'), ('NOK'), ('SEK'), ('DKK'),
    ('NZD'), ('SGD'), ('ZAR'), ('MXN'), ('BRL'), ('INR');

SELECT
    TransactionID,
    Currency,
    Amount,
    'Currency code not in ISO 4217 reference set' AS Issue
FROM Transactions
WHERE Currency NOT IN (SELECT CurrencyCode FROM @ValidCurrencies)
   OR Currency IS NULL
ORDER BY Currency;

-- Step 2: Country code validation (ISO 3166-1 alpha-2 subset)
DECLARE @ValidCountries TABLE (CountryCode CHAR(2), CountryName VARCHAR(60));
INSERT INTO @ValidCountries VALUES
    ('GB', 'United Kingdom'), ('US', 'United States'), ('DE', 'Germany'),
    ('FR', 'France'), ('AU', 'Australia'), ('CA', 'Canada'),
    ('JP', 'Japan'), ('IN', 'India'), ('CN', 'China'), ('BR', 'Brazil');

SELECT
    c.CustomerID,
    c.FirstName,
    c.LastName,
    c.Country AS StoredCountry,
    vc.CountryName AS LookupName,
    CASE
        WHEN c.Country IS NULL           THEN 'Missing country code'
        WHEN vc.CountryCode IS NULL      THEN 'Code not in reference table'
        ELSE 'Valid code'
    END AS LookupStatus
FROM Customers c
LEFT JOIN @ValidCountries vc ON c.Country = vc.CountryCode
WHERE vc.CountryCode IS NULL
   OR c.Country IS NULL;

-- Step 3: Variant encoding detection (GB vs UK, USA vs US)
SELECT
    CustomerID,
    Country AS StoredCode,
    CASE Country
        WHEN 'UK'  THEN 'GB'   -- common alias for ISO GB
        WHEN 'USA' THEN 'US'   -- 3-letter used instead of 2-letter
        WHEN 'ENG' THEN 'GB'   -- England instead of United Kingdom
        WHEN 'SCO' THEN 'GB'   -- Scotland instead of United Kingdom
        ELSE NULL
    END AS SuggestedISOCode,
    CASE Country
        WHEN 'UK'  THEN 'Non-standard: UK should be GB (ISO 3166-1)'
        WHEN 'USA' THEN 'Non-standard: USA should be US (ISO 3166-1 alpha-2)'
        ELSE 'Unknown code variant'
    END AS DiagnosticNote
FROM Customers
WHERE Country IN ('UK', 'USA', 'ENG', 'SCO', 'GBR')
   OR (Country NOT IN (SELECT CountryCode FROM @ValidCountries) AND Country IS NOT NULL);

-- Step 4: Missing lookup reference impact — how many records are excluded from UK queries
SELECT
    Country,
    COUNT(*) AS CustomerCount,
    CASE
        WHEN Country IN ('GB','UK','GBR','ENG','SCO','WAL')
             THEN 'United Kingdom (all variants)'
        ELSE Country
    END AS CountryGroup
FROM Customers
WHERE Country IN ('GB','UK','GBR','ENG','SCO','WAL')
GROUP BY Country;

-- Step 5: Summary of lookup code violations
SELECT 'Transactions: Invalid Currency' AS Check, COUNT(*) AS ViolationCount
FROM Transactions
WHERE Currency NOT IN ('GBP','EUR','USD','JPY','AUD','CAD','CHF')
   OR Currency IS NULL

UNION ALL

SELECT 'Customers: Invalid Country', COUNT(*)
FROM Customers
WHERE Country NOT IN ('GB','US','DE','FR','AU','CA','JP','IN','CN','BR')
   OR Country IS NULL

ORDER BY ViolationCount DESC;
```

## Explanation

**Anti-join for lookup validation**
`LEFT JOIN @ValidCodes ON stored.Code = ref.Code WHERE ref.Code IS NULL` is the anti-join pattern: any stored code with no matching reference record is invalid. This is more flexible than `NOT IN (...)` for large reference sets and handles NULLs correctly.

**Variant encoding vs invalid codes**
Step 3 distinguishes between truly invalid codes (no mapping exists) and variant encodings (a non-standard alias for a valid code). Variants can be corrected with a mapping table; truly invalid codes require investigation to determine the intended value.

**Reference table vs hardcoded list**
For small stable code sets (2–3 values), a hardcoded `IN (...)` list is acceptable. For larger or changing sets (ISO currencies: 180+ codes), a dedicated reference table (`CurrencyCodes`) is essential. The reference table can be updated without changing query logic when new codes are added.

**Invisible records**
The most dangerous effect of lookup code mismatches is that affected records are not returned by standard filters. A customer with `Country = 'UK'` is invisible to `WHERE Country = 'GB'` queries — they exist in the table but are systematically excluded from all UK-specific reports.

## Severity
**High** — Lookup code mismatches cause systematic exclusion of valid records from filtered queries. The excluded records are not missing from the database — they are present but invisible to any query that filters on the correct code value. UK customer counts, EUR transaction totals, and any geo-specific KPI is understated by the volume of non-conforming records.
