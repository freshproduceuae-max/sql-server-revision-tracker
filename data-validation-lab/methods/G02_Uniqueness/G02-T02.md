# G02-T02 — Uniqueness | Duplicate Primary Key

## ID
G02-T02

## Group
2 — Uniqueness / Duplicates

## Type
Duplicate Primary Key

## Live Scenario
A legacy migration script loads 10,000 product records from a flat file. The source file uses a composite ProductCode as the primary key. The target table has no PK constraint (the DBA disabled constraints for the bulk load and forgot to re-enable them). ProductCode 'P0042' appears 7 times — each with a different price. Every JOIN on ProductCode now returns 7 rows instead of 1, inflating every report that touches that product by 7×.

## The Question
> Primary keys must be unique by definition — but constraints can be disabled, bypassed, or simply not exist.
> **"Find every value that appears more than once in the primary key column of the Products table. Return the duplicate keys, how many times each appears, and the full row detail for each offending record."**

## Table Reference
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Which PK values are duplicated?
SELECT
    ProductID,
    COUNT(*) AS Occurrences
FROM Products
GROUP BY ProductID
HAVING COUNT(*) > 1
ORDER BY Occurrences DESC;

-- Step 2: Full row detail for every duplicate PK value
SELECT p.*
FROM Products p
WHERE p.ProductID IN (
    SELECT ProductID
    FROM Products
    GROUP BY ProductID
    HAVING COUNT(*) > 1
)
ORDER BY p.ProductID;

-- Step 3: Rank within each duplicate PK group
WITH DupRanked AS (
    SELECT *,
        ROW_NUMBER() OVER (
            PARTITION BY ProductID
            ORDER BY (SELECT NULL)   -- no natural ordering on which to keep
        ) AS RowNum
    FROM Products
    WHERE ProductID IN (
        SELECT ProductID FROM Products GROUP BY ProductID HAVING COUNT(*) > 1
    )
)
SELECT
    ProductID,
    ProductName,
    SellingPrice,
    RowNum,
    CASE WHEN RowNum = 1 THEN 'First occurrence' ELSE 'DUPLICATE — investigate' END AS Status
FROM DupRanked
ORDER BY ProductID, RowNum;

-- Step 4: Quick PK health summary for any table
SELECT
    'Products' AS TableName,
    COUNT(*)                                          AS TotalRows,
    COUNT(DISTINCT ProductID)                         AS UniqueKeys,
    COUNT(*) - COUNT(DISTINCT ProductID)              AS DuplicateRowsAboveFirst,
    CASE WHEN COUNT(*) = COUNT(DISTINCT ProductID)
         THEN 'PK is unique — OK'
         ELSE 'PK VIOLATION — ' + CAST(COUNT(*) - COUNT(DISTINCT ProductID) AS VARCHAR) + ' duplicate rows'
    END AS PKStatus
FROM Products;
```

## Expected Output

**Step 1:**
| ProductID | Occurrences |
|---|---|
| P042 | 7 |
| P019 | 2 |

**Step 4 (health summary):**
| TableName | TotalRows | UniqueKeys | DuplicateRowsAboveFirst | PKStatus |
|---|---|---|---|---|
| Products | 22 | 20 | 2 | PK VIOLATION — 2 duplicate rows |

## Explanation

**COUNT(*) vs COUNT(DISTINCT col)**
`COUNT(*)` counts every row. `COUNT(DISTINCT ProductID)` counts each unique value once. The difference tells you exactly how many extra (duplicate) rows exist: `COUNT(*) - COUNT(DISTINCT ProductID)`. If the result is 0, the column is effectively a primary key regardless of whether a constraint exists.

**When ORDER BY (SELECT NULL) is correct**
In the ranked query, `ORDER BY (SELECT NULL)` means "no meaningful order within the duplicate group." This is intentional when the rows are identical or when there is no reliable basis for choosing which duplicate to keep. It signals to the reader that row selection within the group requires a business decision, not just a sort.

**Disabling constraints is dangerous**
SQL Server allows `ALTER TABLE Products NOCHECK CONSTRAINT ALL` before a bulk load. If the constraints are not re-enabled afterward, duplicates silently enter the table. Always re-enable and validate constraints after bulk operations:
```sql
ALTER TABLE Products CHECK CONSTRAINT ALL;
DBCC CHECKCONSTRAINTS('Products');
```

## Severity
**Critical** — A duplicate primary key corrupts every query that joins to this table. JOINs fan out silently, multiplying rows in the result set. Aggregations double-count. The error is invisible unless you know to look for it.
