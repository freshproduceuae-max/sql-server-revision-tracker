# G02-T01 — Uniqueness | Exact Duplicate Row

## ID
G02-T01

## Group
2 — Uniqueness / Duplicates

## Type
Exact Duplicate Row — Every Column Matches

## Live Scenario
A marketing agency merges two customer databases after an acquisition. Both systems exported their records to CSV. When the files were concatenated and loaded, 412 customers appeared twice — every column identical, including the customer ID. The campaign tool sent every communication twice to those customers, generating a wave of unsubscribes and complaints.

## The Question
> After a data merge, you suspect some records were loaded twice — the same row appearing more than once in the table.
> **"Find all exact duplicate rows in the Customers table — where every column is identical. Return the duplicates grouped so you can see which rows to remove, and how many exact copies exist."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Find groups where every business column is identical
SELECT
    FirstName,
    LastName,
    Email,
    Phone,
    DOB,
    Country,
    COUNT(*) AS DuplicateCount,
    MIN(CustomerID) AS KeepThisID,
    MAX(CustomerID) AS DeleteThisID
FROM Customers
GROUP BY
    FirstName, LastName, Email, Phone, DOB, Country
HAVING COUNT(*) > 1
ORDER BY DuplicateCount DESC;

-- Step 2: Show the full duplicate rows with a row number to identify which to keep
WITH RankedDuplicates AS (
    SELECT *,
        ROW_NUMBER() OVER (
            PARTITION BY FirstName, LastName, Email, Phone, DOB, Country
            ORDER BY CustomerID ASC
        ) AS RowRank
    FROM Customers
)
SELECT
    CustomerID,
    FirstName,
    LastName,
    Email,
    Phone,
    Country,
    RowRank,
    CASE WHEN RowRank = 1 THEN 'KEEP' ELSE 'DELETE' END AS Action
FROM RankedDuplicates
WHERE Email IN (
    SELECT Email FROM Customers
    GROUP BY FirstName, LastName, Email, Phone, DOB, Country
    HAVING COUNT(*) > 1
)
ORDER BY Email, RowRank;

-- Step 3: Preview the DELETE before running it
SELECT CustomerID
FROM (
    SELECT CustomerID,
        ROW_NUMBER() OVER (
            PARTITION BY FirstName, LastName, Email, Phone, DOB, Country
            ORDER BY CustomerID ASC
        ) AS RowRank
    FROM Customers
) ranked
WHERE RowRank > 1;   -- These are the IDs that would be deleted
```

## Expected Output

**Step 1:**
| FirstName | LastName | Email | DuplicateCount | KeepThisID | DeleteThisID |
|---|---|---|---|---|---|
| James | Carter | james.carter@email.com | 2 | 1 | 11 |

**Step 2:**
| CustomerID | Email | RowRank | Action |
|---|---|---|---|
| 1 | james.carter@email.com | 1 | KEEP |
| 11 | james.carter@email.com | 2 | DELETE |

## Explanation

**GROUP BY all business columns with HAVING COUNT(*) > 1**
This is the canonical pattern for finding exact duplicates. Grouping on every meaningful column collapses identical rows together; HAVING COUNT(*) > 1 filters to only the groups with more than one member. The surrogate key (CustomerID) is intentionally excluded from the GROUP BY — you are looking for content duplicates, not key duplicates.

**ROW_NUMBER() for ranking within each duplicate group**
`ROW_NUMBER() OVER (PARTITION BY ... ORDER BY CustomerID ASC)` assigns rank 1 to the row with the lowest CustomerID in each duplicate group — treating the earliest record as the master. Every other row in that group (RowRank > 1) is a candidate for deletion.

**Always SELECT before DELETE**
The Step 3 query previews which CustomerIDs would be deleted. Run this first, verify the count and IDs look correct, then convert the SELECT to a DELETE:
```sql
DELETE FROM Customers
WHERE CustomerID IN (
    SELECT CustomerID FROM (
        SELECT CustomerID, ROW_NUMBER() OVER (
            PARTITION BY FirstName, LastName, Email, Phone, DOB, Country
            ORDER BY CustomerID ASC
        ) AS RowRank FROM Customers
    ) r WHERE RowRank > 1
);
```

## Severity
**Critical** — Exact row duplicates cause double-counting in every aggregation, double-sending in every communication, and double-billing in every financial process.
