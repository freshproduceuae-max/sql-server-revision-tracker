# G02-T05 — Uniqueness | Phonetic Duplicate (SOUNDEX Match)

## ID
G02-T05

## Group
2 — Uniqueness / Duplicates

## Type
Phonetic Duplicate — SOUNDEX Match

## Live Scenario
A government agency registers businesses by company name. "Acme Technologies Ltd" and "Akme Technologies Limited" are the same company entered by two different clerks. The agency's duplicate check compares exact strings — it misses them. The company now has two registrations, two tax IDs, and two sets of correspondence. A phonetic-first deduplication pass is needed to surface these before the annual regulatory audit.

## The Question
> Two records represent the same real-world entity but the name is spelled or abbreviated differently.
> **"Use SOUNDEX to find all pairs of customers whose last names sound the same. Then narrow the candidates by also requiring they share the same first-name initial, to reduce false positives. Return the SOUNDEX code so readers can verify the match."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Pure SOUNDEX match on last name
SELECT
    A.CustomerID                            AS ID_A,
    A.FirstName + ' ' + A.LastName          AS FullName_A,
    B.CustomerID                            AS ID_B,
    B.FirstName + ' ' + B.LastName          AS FullName_B,
    SOUNDEX(A.LastName)                     AS LastNameSoundex,
    A.Country,
    A.DOB
FROM Customers A
JOIN Customers B
    ON  SOUNDEX(A.LastName) = SOUNDEX(B.LastName)
    AND A.CustomerID       <> B.CustomerID
    AND A.CustomerID        < B.CustomerID
ORDER BY LastNameSoundex;

-- Narrowed: same SOUNDEX last name + same first initial + same country
SELECT
    A.CustomerID                            AS ID_A,
    A.FirstName + ' ' + A.LastName          AS FullName_A,
    B.CustomerID                            AS ID_B,
    B.FirstName + ' ' + B.LastName          AS FullName_B,
    SOUNDEX(A.LastName)                     AS LastNameSoundex,
    LEFT(A.FirstName, 1)                    AS FirstInitial,
    A.Country,
    DIFFERENCE(A.LastName, B.LastName)      AS SimilarityScore,
    DIFFERENCE(A.FirstName, B.FirstName)    AS FirstNameScore
FROM Customers A
JOIN Customers B
    ON  SOUNDEX(A.LastName)  = SOUNDEX(B.LastName)
    AND LEFT(A.FirstName, 1) = LEFT(B.FirstName, 1)   -- same first initial
    AND A.Country            = B.Country               -- same country
    AND A.CustomerID        <> B.CustomerID
    AND A.CustomerID         < B.CustomerID
ORDER BY SOUNDEX(A.LastName), ID_A;

-- SOUNDEX code reference for all customers (useful for bulk review)
SELECT
    CustomerID,
    FirstName,
    LastName,
    SOUNDEX(FirstName)  AS FirstNameCode,
    SOUNDEX(LastName)   AS LastNameCode,
    SOUNDEX(FirstName + LastName) AS FullNameCode
FROM Customers
ORDER BY LastNameCode, FirstNameCode;
```

## Expected Output

| ID_A | FullName_A | ID_B | FullName_B | LastNameSoundex | FirstInitial | SimilarityScore |
|---|---|---|---|---|---|---|
| 1 | James Carter | 8 | James Karter | C636 | J | 4 |

## Explanation

**How SOUNDEX works character by character**
SOUNDEX keeps the first letter, then encodes each subsequent consonant as a digit (B/F/P/V=1, C/G/J/K/Q/S/X/Z=2, D/T=3, L=4, M/N=5, R=6). Vowels and H/W are ignored. Codes are padded to exactly 4 characters. "Carter" → C636; "Karter" → K636. Note the first letter differs — which is why `SOUNDEX('Carter') <> SOUNDEX('Karter')`. For cross-initial matching, use `SOUNDEX(SUBSTRING(Name,2,100))` to compare without the first letter.

**DIFFERENCE() adds a confidence score**
SOUNDEX is binary — codes either match or don't. DIFFERENCE() adds nuance: 4 means near-identical phonetics, 3 means strongly similar, 2 is possible. Use DIFFERENCE >= 3 as a threshold for strong candidates.

**Reducing false positives with a second attribute**
SOUNDEX alone produces many false positives (all "Smith" variants match all other "Smith" variants regardless of first name or country). Requiring `LEFT(FirstName, 1) = LEFT(B.FirstName, 1)` AND same Country cuts the candidate list dramatically while still catching the target cases.

**SOUNDEX is English-centric**
SOUNDEX was designed for English names. It performs poorly on Arabic, Chinese, Hindi, or other non-English names. For multilingual datasets, consider METAPHONE (available via CLR) or Python's `jellyfish` library for Levenshtein distance-based fuzzy matching.

## Severity
**High** — Phonetic duplicates are invisible to exact-match deduplication. In any system where name is the primary search field, they cause identity confusion, duplicate records, and missed conflict checks.
