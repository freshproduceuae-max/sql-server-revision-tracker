# G02-T10 — Uniqueness | Soft-Delete Duplicate

## ID
G02-T10

## Group
2 — Uniqueness / Duplicates

## Type
Soft-Delete Duplicate — Active + Deleted Version of Same Record

## Live Scenario
A SaaS platform uses soft deletes: instead of removing rows, it sets `IsDeleted = 1` and `DeletedAt = GETDATE()`. A customer cancels, gets marked deleted, then re-subscribes — a new row is created with `IsDeleted = 0`. So far correct. But a bug in the re-subscription flow fails to mark the old row as deleted first. Now the customer has two rows with `IsDeleted = 0` — both active. Every query that filters `WHERE IsDeleted = 0` returns two rows for this customer.

## The Question
> Your table uses soft deletes (an IsDeleted or IsActive flag) rather than physical row removal. The uniqueness rule applies only to active records.
> **"Find all customers who have more than one row where IsDeleted = 0 (i.e., more than one active record). Also find cases where a customer has both an active and a soft-deleted record, which may indicate the re-subscription flow worked — or failed."**

## Table Reference
**Customers** — `schemas/01_Customers.csv` (using IsActive as the equivalent flag)

## Solution Query

```sql
-- Step 1: Multiple ACTIVE records for the same natural key (the real problem)
SELECT
    Email,
    COUNT(*) AS ActiveRecordCount,
    STRING_AGG(CAST(CustomerID AS VARCHAR), ', ') AS ActiveCustomerIDs
FROM Customers
WHERE IsActive = 1            -- or: WHERE IsDeleted = 0
  AND Email IS NOT NULL
GROUP BY Email
HAVING COUNT(*) > 1
ORDER BY ActiveRecordCount DESC;

-- Step 2: Full detail — which pairs have duplicate active records?
WITH ActiveRanked AS (
    SELECT *,
        ROW_NUMBER() OVER (
            PARTITION BY Email
            ORDER BY CustomerID ASC
        ) AS ActiveRank,
        COUNT(*) OVER (PARTITION BY Email) AS ActiveCount
    FROM Customers
    WHERE IsActive = 1
      AND Email IS NOT NULL
)
SELECT
    CustomerID,
    FirstName + ' ' + LastName  AS CustomerName,
    Email,
    ActiveRank,
    ActiveCount,
    CASE
        WHEN ActiveRank = 1 THEN 'First active record'
        ELSE 'DUPLICATE ACTIVE — should be soft-deleted'
    END AS ActiveStatus
FROM ActiveRanked
WHERE ActiveCount > 1
ORDER BY Email, ActiveRank;

-- Step 3: Customers with BOTH an active AND a soft-deleted record
-- (This is the expected state after a re-subscription — verify it's intentional)
SELECT
    a.CustomerID    AS ActiveID,
    a.Email,
    a.FirstName + ' ' + a.LastName AS Name,
    d.CustomerID    AS DeletedID,
    'Has both active and deleted record' AS Status
FROM Customers a
JOIN Customers d
    ON  a.Email         = d.Email
    AND a.IsActive      = 1
    AND d.IsActive      = 0
    AND a.CustomerID   <> d.CustomerID
WHERE a.Email IS NOT NULL
ORDER BY a.Email;

-- Step 4: Full soft-delete status per email
SELECT
    Email,
    SUM(CASE WHEN IsActive = 1 THEN 1 ELSE 0 END) AS ActiveCount,
    SUM(CASE WHEN IsActive = 0 THEN 1 ELSE 0 END) AS DeletedCount,
    COUNT(*) AS TotalRows,
    CASE
        WHEN SUM(CASE WHEN IsActive = 1 THEN 1 ELSE 0 END) > 1
            THEN 'PROBLEM: Multiple active records'
        WHEN SUM(CASE WHEN IsActive = 1 THEN 1 ELSE 0 END) = 1
         AND SUM(CASE WHEN IsActive = 0 THEN 1 ELSE 0 END) > 0
            THEN 'Expected: Active + history'
        WHEN SUM(CASE WHEN IsActive = 0 THEN 1 ELSE 0 END) > 0
         AND SUM(CASE WHEN IsActive = 1 THEN 1 ELSE 0 END) = 0
            THEN 'Fully deleted — no active record'
        ELSE 'Normal: one active record'
    END AS SoftDeleteStatus
FROM Customers
WHERE Email IS NOT NULL
GROUP BY Email
ORDER BY SoftDeleteStatus, Email;
```

## Expected Output

**Step 4:**
| Email | ActiveCount | DeletedCount | TotalRows | SoftDeleteStatus |
|---|---|---|---|---|
| james.carter@email.com | 2 | 0 | 2 | PROBLEM: Multiple active records |
| sara.jones@email.com | 1 | 1 | 2 | Expected: Active + history |
| tom.brooks@email.com | 0 | 1 | 1 | Fully deleted — no active record |

## Explanation

**Soft-delete pattern — the intended design**
A soft-delete table stores all history. Queries add `WHERE IsDeleted = 0` (or `WHERE IsActive = 1`) to see only current records. The uniqueness rule applies only to active records: at most one active row per natural key. Historical (deleted) rows can repeat the same natural key as many times as the entity has been created and deleted over its lifetime.

**Why this requires a conditional unique index, not a standard one**
A standard UNIQUE constraint on Email would prevent a re-subscribed customer from being re-inserted (their old deleted row still holds the email). The correct database-level guard is a filtered unique index:
```sql
CREATE UNIQUE INDEX UIX_Customers_ActiveEmail
ON Customers (Email)
WHERE IsActive = 1;
```
This enforces uniqueness only among active rows. The validation query is the equivalent manual check.

**Step 4's CASE statement classifies every email's state**
By summarising active vs deleted counts per email, Step 4 produces a full soft-delete health report. It distinguishes between the error state (multiple active records), the expected state (one active + deleted history), the fully deleted state, and the normal single-active state — in one query.

## Severity
**Critical** — Multiple active records in a soft-delete system are invisible to application queries that filter `WHERE IsActive = 1`. They cause every operation on that entity to execute twice: two emails sent, two payments taken, two role assignments granted.
