# G10-T03 — Data Type/Storage | String Truncation Risk

## ID
G10-T03

## Group
10 — Data Type/Storage

## Type
String Truncation Risk — Values Near or Exceeding the Column's Maximum Length

## Live Scenario
A customer-facing web form accepts addresses up to 500 characters. The underlying database column `DeliveryAddress` is `VARCHAR(200)`. When a customer enters a long address with apartment details ("Apartment 4B, Building 12, The Moorings Business Park, Westfield Road, Manchester"), the INSERT statement silently truncates the address at 200 characters. The delivery fails — the truncated address omits the postcode. A package is returned as undeliverable. The customer service cost to handle the return and reship is £34. Across 120 similar truncations per month, the annual cost is £48,960. SQL Server in `SET ANSI_WARNINGS ON` mode (the default) raises an error on truncation; in applications that suppress errors, the truncation is silent.

## The Question
> String truncation occurs when a value is longer than the column's maximum length, causing data loss at the point of storage. SQL detects truncation risk by comparing the actual length of values to the column's defined maximum and flagging values that are near or at the limit.
> **"Identify columns in the Orders and Customers tables where values are approaching the maximum length, flag any values at exactly the maximum length (which may indicate truncation), and identify fields with unexpected length variation."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Length analysis for text fields — detect values near column maximum
SELECT
    'Customers.Email' AS ColumnRef,
    MAX(LEN(Email))   AS MaxLength,
    AVG(LEN(Email))   AS AvgLength,
    MIN(LEN(Email))   AS MinLength,
    COUNT(CASE WHEN LEN(Email) > 50  THEN 1 END) AS Over50Chars,
    COUNT(CASE WHEN LEN(Email) = MAX(LEN(Email)) OVER () THEN 1 END) AS AtMaxLength,
    'Review: standard email max is 254 chars (RFC 5321)' AS ColumnNote
FROM Customers
UNION ALL
SELECT
    'Customers.PostalCode',
    MAX(LEN(PostalCode)),
    AVG(LEN(PostalCode)),
    MIN(LEN(PostalCode)),
    COUNT(CASE WHEN LEN(PostalCode) > 8 THEN 1 END),
    COUNT(CASE WHEN LEN(PostalCode) = MAX(LEN(PostalCode)) OVER () THEN 1 END),
    'UK postcode max 8 chars including space'
FROM Customers
UNION ALL
SELECT
    'Orders.Notes',
    MAX(LEN(Notes)),
    AVG(LEN(Notes)),
    MIN(LEN(Notes)),
    COUNT(CASE WHEN LEN(Notes) > 200 THEN 1 END),
    COUNT(CASE WHEN LEN(Notes) = MAX(LEN(Notes)) OVER () THEN 1 END),
    'Free-text field — check for truncation at defined column max'
FROM Orders
WHERE Notes IS NOT NULL;

-- Step 2: Values at or very near the maximum length — possible truncation indicator
DECLARE @TruncationWarningThreshold INT = 95;  -- Flag if >95% of max length

SELECT
    CustomerID,
    Email,
    LEN(Email) AS EmailLength,
    CASE
        WHEN LEN(Email) = 100
             THEN 'AT MAX: Exactly 100 chars — may be truncated from longer value'
        WHEN LEN(Email) > 90
             THEN 'NEAR MAX: ' + CAST(LEN(Email) AS VARCHAR) + ' chars — approaching limit'
        ELSE 'Normal length'
    END AS TruncationRisk
FROM Customers
WHERE LEN(Email) >= 90;

-- Step 3: Detect end-of-string truncation patterns (text cut mid-word)
SELECT
    o.OrderID,
    o.Notes,
    LEN(o.Notes) AS NoteLength,
    RIGHT(o.Notes, 1) AS LastChar,
    CASE
        WHEN RIGHT(LTRIM(RTRIM(o.Notes)), 1) NOT IN ('.', '!', '?', ')', '"')
         AND LEN(o.Notes) > 50
             THEN 'POSSIBLE TRUNCATION: Text does not end with punctuation — may be cut off'
        ELSE 'Appears complete'
    END AS TruncationSignal
FROM Orders o
WHERE o.Notes IS NOT NULL
  AND LEN(o.Notes) > 50
ORDER BY NoteLength DESC;

-- Step 4: Field length statistics across all key string columns
SELECT
    ColName,
    RowCount,
    MinLen,
    MaxLen,
    AvgLen,
    CASE
        WHEN MaxLen > AvgLen * 5 THEN 'HIGH VARIANCE: Max length is >5× average — check for outliers'
        WHEN MaxLen > 200        THEN 'LONG FIELD: Values exceed 200 chars — verify column definition'
        ELSE 'Normal length distribution'
    END AS LengthProfile
FROM (
    SELECT 'Email'      AS ColName, COUNT(*) AS RowCount,
           MIN(LEN(Email)) AS MinLen, MAX(LEN(Email)) AS MaxLen, AVG(LEN(Email)) AS AvgLen
    FROM Customers WHERE Email IS NOT NULL
    UNION ALL
    SELECT 'Phone', COUNT(*),
           MIN(LEN(Phone)), MAX(LEN(Phone)), AVG(LEN(Phone))
    FROM Customers WHERE Phone IS NOT NULL
    UNION ALL
    SELECT 'Country', COUNT(*),
           MIN(LEN(Country)), MAX(LEN(Country)), AVG(LEN(Country))
    FROM Customers WHERE Country IS NOT NULL
    UNION ALL
    SELECT 'ProductName', COUNT(*),
           MIN(LEN(ProductName)), MAX(LEN(ProductName)), AVG(LEN(ProductName))
    FROM Products WHERE ProductName IS NOT NULL
) LengthStats
ORDER BY MaxLen DESC;
```

## Explanation

**LEN() vs DATALENGTH()**
`LEN(string)` returns the number of characters, excluding trailing spaces. `DATALENGTH(string)` returns the byte count, which differs for Unicode (`NVARCHAR`) columns where each character uses 2 bytes. For truncation detection, `LEN()` is the right choice; for storage capacity planning, `DATALENGTH()` is needed.

**Values at exactly the maximum: the truncation signature**
If a column's maximum value length equals the declared column width (e.g., `MAX(LEN(Notes)) = 200` for a `VARCHAR(200)` column), this is strong evidence that values have been truncated — natural text distributions rarely produce values that end precisely at the column boundary. Multiple values at the exact maximum strengthens this conclusion.

**End-of-string pattern detection**
Step 3 uses `RIGHT(LTRIM(RTRIM(Notes)), 1)` to examine the last non-space character. Legitimate notes end with punctuation (full stop, question mark) or a closing quote. A note ending in a mid-word letter (e.g., "The delivery address was confir") suggests truncation. This is a heuristic, not definitive proof.

**High variance as a red flag**
Step 4's `MaxLen > AvgLen * 5` flags columns where the maximum is disproportionately large relative to the average. This suggests either a few anomalous long values (potential truncation victims in narrow columns) or a column that needs reclassification from `VARCHAR(50)` to `VARCHAR(MAX)`.

## Severity
**Medium** — String truncation causes silent data loss at the point of storage. Unlike a type conversion error (which raises an exception), truncation in warning-suppressed environments simply cuts the value and continues. The lost data (end of an address, last name characters, a critical note) may be unrecoverable. In customer-facing systems, truncation causes delivery failures and support costs.
