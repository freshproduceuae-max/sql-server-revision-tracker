# G10-T08 — Data Type/Storage | File Path and Attachment Validity

## ID
G10-T08

## Group
10 — Data Type/Storage

## Type
File Path and Attachment Validity — Stored File References That Do Not Conform to Valid Path Patterns

## Live Scenario
An insurance claims system stores document paths in a `VARCHAR(500)` column: `\\fileserver\claims\2024\CLM-00847.pdf`. After a server migration, the fileserver hostname changes from `\\fileserver\` to `\\fs01.internal\`. 14,847 existing claim records still reference the old path. The application tries to open attachments, gets "path not found," and displays a generic error. Claims adjusters cannot access the supporting documents for 14,847 claims and must request documents to be re-uploaded — a 3-week backlog. A second issue: the DBA running a cleanup script accidentally stores a path containing double backslashes (`\\\\server\\share\\file.pdf`) by escaping incorrectly. These paths open a network share but from the wrong root.

## The Question
> File path and URL fields contain references to external resources. Validity checks verify that the path matches expected patterns (correct prefix, valid characters, no double slashes, correct extension). SQL uses PATINDEX, LIKE, and CHARINDEX to perform these structural checks.
> **"Validate the AttachmentPath column in Orders: check that paths match expected patterns (UNC paths or relative paths), detect null or empty paths for records that should have attachments, and flag paths with common structural errors."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Classify all attachment paths
SELECT
    OrderID,
    AttachmentPath,
    LEN(AttachmentPath) AS PathLength,
    CASE
        WHEN AttachmentPath IS NULL
             THEN 'NULL: No attachment stored'
        WHEN LTRIM(RTRIM(AttachmentPath)) = ''
             THEN 'EMPTY: Blank path stored'
        WHEN LEFT(AttachmentPath, 2) = '\\'
             THEN 'UNC PATH: \\server\share format'
        WHEN AttachmentPath LIKE '[A-Z]:\%'
             THEN 'LOCAL PATH: Drive letter path — not suitable for network access'
        WHEN AttachmentPath LIKE 'http%'
             THEN 'HTTP URL: Web resource reference'
        WHEN AttachmentPath LIKE '/%'
             THEN 'UNIX PATH: Forward-slash absolute path'
        WHEN AttachmentPath LIKE './%' OR AttachmentPath LIKE '../%'
             THEN 'RELATIVE PATH: Relative reference — depends on current directory'
        ELSE 'UNRECOGNISED FORMAT: Does not match expected path pattern'
    END AS PathType
FROM Orders
WHERE AttachmentPath IS NOT NULL;

-- Step 2: Structural validation — detect common path errors
SELECT
    OrderID,
    AttachmentPath,
    CASE
        -- Double backslash in the middle (not at the start of UNC)
        WHEN CHARINDEX('\\\\', STUFF(AttachmentPath, 1, 2, '')) > 0
             THEN 'DOUBLE BACKSLASH: Escaped path contains \\\\ mid-path'
        -- Path too short to be meaningful
        WHEN LEN(AttachmentPath) < 5
             THEN 'TOO SHORT: Path is implausibly short'
        -- No file extension
        WHEN CHARINDEX('.', REVERSE(AttachmentPath)) = 0
          OR CHARINDEX('\', REVERSE(AttachmentPath)) < CHARINDEX('.', REVERSE(AttachmentPath))
             THEN 'NO EXTENSION: Path has no file extension — may be a directory'
        -- Extension check — expected document types
        WHEN RIGHT(LOWER(AttachmentPath),
                   CHARINDEX('.', REVERSE(LOWER(AttachmentPath))) - 1)
             NOT IN ('pdf', 'doc', 'docx', 'xlsx', 'jpg', 'png', 'tiff', 'csv')
             THEN 'UNEXPECTED EXTENSION: '
                  + RIGHT(LOWER(AttachmentPath),
                          CHARINDEX('.', REVERSE(LOWER(AttachmentPath))) - 1)
                  + ' — verify file type is permitted'
        ELSE 'Path structure OK'
    END AS StructuralCheck
FROM Orders
WHERE AttachmentPath IS NOT NULL
  AND LTRIM(RTRIM(AttachmentPath)) <> '';

-- Step 3: Orders that should have attachments but don't
SELECT
    o.OrderID,
    o.Status,
    o.TotalAmount,
    o.OrderDate,
    'MISSING ATTACHMENT: ' + o.Status + ' orders above £500 should have a document' AS MissingFlag
FROM Orders o
WHERE o.AttachmentPath IS NULL
  AND o.Status = 'Delivered'
  AND o.TotalAmount > 500
ORDER BY o.TotalAmount DESC;

-- Step 4: Duplicate attachment paths — same file referenced by multiple orders
SELECT
    AttachmentPath,
    COUNT(*) AS OrderCount,
    STRING_AGG(CAST(OrderID AS VARCHAR), ', ') AS OrderIDs,
    'SHARED ATTACHMENT: Same path on ' + CAST(COUNT(*) AS VARCHAR)
        + ' orders — may indicate copy-paste error or shared document' AS DuplicateFlag
FROM Orders
WHERE AttachmentPath IS NOT NULL
  AND LTRIM(RTRIM(AttachmentPath)) <> ''
GROUP BY AttachmentPath
HAVING COUNT(*) > 1
ORDER BY OrderCount DESC;

-- Step 5: File extension summary — what types of documents are stored?
SELECT
    LOWER(RIGHT(AttachmentPath,
               CHARINDEX('.', REVERSE(AttachmentPath)) - 1)) AS FileExtension,
    COUNT(*) AS Count,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS Pct
FROM Orders
WHERE AttachmentPath IS NOT NULL
  AND CHARINDEX('.', AttachmentPath) > 0
GROUP BY LOWER(RIGHT(AttachmentPath,
               CHARINDEX('.', REVERSE(AttachmentPath)) - 1))
ORDER BY Count DESC;
```

## Explanation

**CHARINDEX for path structure analysis**
`CHARINDEX('\\\\', STUFF(AttachmentPath, 1, 2, ''))` removes the first two characters (the legitimate `\\` at the start of a UNC path) then searches for `\\\\` (four backslashes, representing two literal backslashes) in the remainder. This distinguishes the valid UNC prefix from double-backslash errors in the middle of a path.

**REVERSE + CHARINDEX for extension extraction**
`CHARINDEX('.', REVERSE(AttachmentPath))` finds the position of the last dot (the file extension separator) by reversing the string and finding the first dot. `RIGHT(AttachmentPath, position - 1)` extracts the characters after the last dot. This handles paths like `\\server\folder.name\file.pdf` correctly — only the extension after the last dot is relevant.

**LEFT() for path type classification**
`LEFT(AttachmentPath, 2) = '\\'` identifies UNC paths. `AttachmentPath LIKE '[A-Z]:\%'` identifies local paths with a drive letter. The LIKE pattern `[A-Z]:\%` uses a character class to match any letter A–Z followed by a colon and backslash. These classifications sort paths by architectural type before structural checking.

**Shared attachments as a data quality indicator**
Step 4 identifies multiple orders referencing the same file path. In some systems this is valid (a blanket purchase order covering multiple transactions). In others, it indicates a copy-paste error where the same attachment path was applied to the wrong order. The flag prompts review without assuming error.

## Severity
**Medium** — Invalid file paths cause application errors when users attempt to access attachments. For claims, compliance documents, or audit evidence, inaccessible attachments represent a business process failure. Storage paths also represent a security concern: `..` path traversal sequences or absolute paths on the application server may expose unintended directories.
