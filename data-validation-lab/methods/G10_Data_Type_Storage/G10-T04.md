# G10-T04 — Data Type/Storage | JSON/XML Field Validity

## ID
G10-T04

## Group
10 — Data Type/Storage

## Type
JSON/XML Field Validity — Semi-Structured Data Stored in Text Fields Contains Invalid or Malformed Content

## Live Scenario
A mobile app stores user preferences as JSON in a `Metadata` VARCHAR column. An API version change alters the JSON schema: the key `"user_prefs"` is renamed to `"preferences"`. The mobile app is updated but 23% of the user base has not updated. The preference-reading function uses `JSON_VALUE(Metadata, '$.user_prefs')` and returns NULL for all updated-app users (whose JSON uses `$.preferences`) — their preferences are silently ignored and the app falls back to defaults. Simultaneously, a data migration script produces malformed JSON for 847 records by concatenating strings without proper escaping: `{"name": "O'Brien"}` becomes `{"name": "O'Brien"}` which is valid JSON, but `{"city": "San Jose, CA"}` concatenated incorrectly becomes `{"city": "San Jose, CA"}` — still valid — while `{"note": "Quote: "important""}` becomes invalid JSON. NULL is returned for all these records' JSON_VALUE calls without any error.

## The Question
> JSON and XML fields contain semi-structured data. Validity checks verify (1) the document is syntactically well-formed, (2) expected keys/paths exist, and (3) values at specific paths have the expected types. SQL Server provides ISJSON(), JSON_VALUE(), XML parsing, and TRY_CAST to perform these checks.
> **"Validate that the Metadata and XMLData columns in Orders contain well-formed JSON/XML, verify that expected JSON keys are present, and flag any records where the semi-structured content is malformed or missing required fields."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: JSON validity check using ISJSON()
SELECT
    OrderID,
    Metadata,
    LEN(Metadata) AS MetadataLength,
    ISJSON(Metadata) AS IsValidJSON,
    CASE
        WHEN Metadata IS NULL
             THEN 'NULL: No metadata stored'
        WHEN LTRIM(RTRIM(Metadata)) = ''
             THEN 'EMPTY: Metadata field is blank'
        WHEN ISJSON(Metadata) = 0
             THEN 'INVALID JSON: Syntax error in metadata — cannot parse'
        WHEN ISJSON(Metadata) = 1
             THEN 'Valid JSON'
        ELSE 'UNKNOWN: ISJSON returned unexpected result'
    END AS JSONStatus
FROM Orders
WHERE Metadata IS NOT NULL
ORDER BY ISJSON(Metadata), OrderID;

-- Step 2: Check for expected JSON keys in valid documents
SELECT
    OrderID,
    Metadata,
    JSON_VALUE(Metadata, '$.status')   AS JSONStatus,
    JSON_VALUE(Metadata, '$.priority') AS JSONPriority,
    JSON_VALUE(Metadata, '$.source')   AS JSONSource,
    CASE
        WHEN ISJSON(Metadata) = 0
             THEN 'SKIP: Invalid JSON — cannot extract keys'
        WHEN JSON_VALUE(Metadata, '$.status') IS NULL
             THEN 'MISSING KEY: $.status not present in JSON'
        ELSE 'Required key present'
    END AS KeyPresenceCheck
FROM Orders
WHERE Metadata IS NOT NULL
  AND ISJSON(Metadata) = 1;

-- Step 3: XML validity check using TRY_CAST to XML type
SELECT
    OrderID,
    XMLData,
    LEN(XMLData) AS XMLLength,
    CASE
        WHEN XMLData IS NULL
             THEN 'NULL: No XML data'
        WHEN LTRIM(RTRIM(XMLData)) = ''
             THEN 'EMPTY: XML field is blank'
        WHEN TRY_CAST(XMLData AS XML) IS NULL
             THEN 'INVALID XML: Malformed document — cannot parse'
        ELSE 'Valid XML'
    END AS XMLStatus,
    TRY_CAST(XMLData AS XML) AS ParsedXML  -- NULL if invalid
FROM Orders
WHERE XMLData IS NOT NULL;

-- Step 4: Extract values from valid XML using XQuery
SELECT
    o.OrderID,
    o.XMLData,
    TRY_CAST(o.XMLData AS XML).value('(/order/customer)[1]', 'VARCHAR(100)')
        AS XMLCustomer,
    TRY_CAST(o.XMLData AS XML).value('(/order/amount)[1]', 'DECIMAL(18,2)')
        AS XMLAmount,
    TRY_CAST(o.XMLData AS XML).value('(/order/status)[1]', 'VARCHAR(50)')
        AS XMLOrderStatus,
    CASE
        WHEN TRY_CAST(o.XMLData AS XML).value('(/order/amount)[1]', 'DECIMAL(18,2)')
             IS NULL
             THEN 'MISSING XML ELEMENT: /order/amount not found'
        WHEN ABS(TRY_CAST(o.XMLData AS XML).value('(/order/amount)[1]', 'DECIMAL(18,2)')
             - o.TotalAmount) > 0.01
             THEN 'XML-DB MISMATCH: XML amount differs from TotalAmount column'
        ELSE 'XML content consistent with row data'
    END AS XMLConsistency
FROM Orders o
WHERE o.XMLData IS NOT NULL
  AND TRY_CAST(o.XMLData AS XML) IS NOT NULL;

-- Step 5: Summary — field population and validity rates
SELECT
    'Metadata' AS FieldName,
    COUNT(*) AS TotalRows,
    SUM(CASE WHEN Metadata IS NULL THEN 1 ELSE 0 END) AS NullCount,
    SUM(CASE WHEN Metadata IS NOT NULL AND ISJSON(Metadata) = 1 THEN 1 ELSE 0 END) AS ValidCount,
    SUM(CASE WHEN Metadata IS NOT NULL AND ISJSON(Metadata) = 0 THEN 1 ELSE 0 END) AS InvalidCount
FROM Orders
UNION ALL
SELECT
    'XMLData',
    COUNT(*),
    SUM(CASE WHEN XMLData IS NULL THEN 1 ELSE 0 END),
    SUM(CASE WHEN XMLData IS NOT NULL AND TRY_CAST(XMLData AS XML) IS NOT NULL THEN 1 ELSE 0 END),
    SUM(CASE WHEN XMLData IS NOT NULL AND TRY_CAST(XMLData AS XML) IS NULL THEN 1 ELSE 0 END)
FROM Orders;
```

## Explanation

**ISJSON() for JSON validation**
`ISJSON(string)` returns 1 (valid JSON), 0 (invalid JSON), or NULL (NULL input). This is the first-pass check before any JSON_VALUE extraction — calling `JSON_VALUE` on invalid JSON returns NULL without error, silently hiding the malformation. Always validate before extracting.

**TRY_CAST to XML type**
SQL Server's XML data type enforces well-formedness. `TRY_CAST(XMLData AS XML)` attempts to parse the string as XML: if it succeeds, the result is a typed XML value; if it fails, TRY_CAST returns NULL. This is more reliable than pattern-matching for XML tags because CAST validates the full document structure.

**JSON_VALUE for path extraction**
`JSON_VALUE(json, '$.key')` extracts a scalar value from a JSON document using a path expression. It returns NULL if the path doesn't exist (missing key) or if the document is invalid. Use `JSON_QUERY(json, '$.array')` for extracting objects or arrays (non-scalar values).

**XQuery for XML content extraction**
`.value('(/order/amount)[1]', 'DECIMAL(18,2)')` uses XQuery to navigate the XML tree. The `[1]` index selects the first matching node. Cross-validating the extracted XML amount against the `TotalAmount` column (Step 4) confirms that the semi-structured data agrees with the structured column — a consistency check between two representations of the same fact.

## Severity
**Medium** — Invalid JSON/XML fields cause silent failures when application code attempts to parse them: the function returns NULL, the application falls back to defaults, and no error is raised. For configuration data or audit trails stored in semi-structured columns, silent parse failures mean settings are ignored and events go unrecorded.
