# G10-T09 — Data Type/Storage | Null vs Empty String Confusion

## ID
G10-T09

## Group
10 — Data Type/Storage

## Type
Null vs Empty String Confusion — Business Logic Treats NULL and Empty String as Equivalent When They Are Not

## Live Scenario
A contact form allows users to optionally provide a phone number. Some users leave the field blank; the web application sends an empty string `""` to the API; the API inserts `""` into the Phone column. Other users don't see the field on mobile (it's hidden for mobile layout) — the API sends no phone field; the database inserts `NULL`. The customer service system treats `NULL` as "unknown" and empty string as "provided but blank" differently: NULL records trigger an outbound call to request the number; empty string records are treated as "opted out of providing phone." This causes 2,400 customers who simply left the field blank to be reclassified as "opted out" — they receive no call and are never asked for their phone number. The CRM now shows 2,400 false opt-outs.

## The Question
> NULL means "unknown" or "not applicable"; empty string means "known to be empty." Mixing them causes business logic errors because `WHERE Phone IS NULL` misses empty strings and `WHERE Phone = ''` misses NULLs. SQL detects this by separating and counting both categories.
> **"For each text column in Customers and Orders, count the NULL values, empty string values, whitespace-only values, and populated values separately, and flag any column where NULL and empty string are intermixed."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: NULL vs empty string audit for Customers text columns
SELECT
    ColName,
    TotalRows,
    NullCount,
    EmptyCount,
    WhitespaceCount,
    PopulatedCount,
    CASE
        WHEN NullCount > 0 AND EmptyCount > 0
             THEN 'MIXED: Both NULL (' + CAST(NullCount AS VARCHAR)
                  + ') and empty string (' + CAST(EmptyCount AS VARCHAR)
                  + ') present — standardise to one form'
        WHEN NullCount > 0 AND WhitespaceCount > 0
             THEN 'MIXED: Both NULL and whitespace-only values present'
        WHEN EmptyCount > 0
             THEN 'EMPTY STRINGS: ' + CAST(EmptyCount AS VARCHAR)
                  + ' blank values — consider converting to NULL'
        WHEN WhitespaceCount > 0
             THEN 'WHITESPACE: ' + CAST(WhitespaceCount AS VARCHAR)
                  + ' space-only values — treat as empty'
        WHEN NullCount = TotalRows
             THEN 'ALL NULL: Column is entirely unpopulated'
        ELSE 'Consistent: only NULLs or only populated values'
    END AS ConsistencyStatus
FROM (
    SELECT 'Email' AS ColName,
           COUNT(*) AS TotalRows,
           SUM(CASE WHEN Email IS NULL THEN 1 ELSE 0 END) AS NullCount,
           SUM(CASE WHEN Email = '' THEN 1 ELSE 0 END) AS EmptyCount,
           SUM(CASE WHEN Email IS NOT NULL AND LTRIM(RTRIM(Email)) = '' AND Email <> '' THEN 1 ELSE 0 END) AS WhitespaceCount,
           SUM(CASE WHEN LTRIM(RTRIM(ISNULL(Email,''))) <> '' THEN 1 ELSE 0 END) AS PopulatedCount
    FROM Customers
    UNION ALL
    SELECT 'Phone',
           COUNT(*),
           SUM(CASE WHEN Phone IS NULL THEN 1 ELSE 0 END),
           SUM(CASE WHEN Phone = '' THEN 1 ELSE 0 END),
           SUM(CASE WHEN Phone IS NOT NULL AND LTRIM(RTRIM(Phone)) = '' AND Phone <> '' THEN 1 ELSE 0 END),
           SUM(CASE WHEN LTRIM(RTRIM(ISNULL(Phone,''))) <> '' THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'PostalCode',
           COUNT(*),
           SUM(CASE WHEN PostalCode IS NULL THEN 1 ELSE 0 END),
           SUM(CASE WHEN PostalCode = '' THEN 1 ELSE 0 END),
           SUM(CASE WHEN PostalCode IS NOT NULL AND LTRIM(RTRIM(PostalCode)) = '' AND PostalCode <> '' THEN 1 ELSE 0 END),
           SUM(CASE WHEN LTRIM(RTRIM(ISNULL(PostalCode,''))) <> '' THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'Orders.Notes',
           COUNT(*),
           SUM(CASE WHEN Notes IS NULL THEN 1 ELSE 0 END),
           SUM(CASE WHEN Notes = '' THEN 1 ELSE 0 END),
           SUM(CASE WHEN Notes IS NOT NULL AND LTRIM(RTRIM(Notes)) = '' AND Notes <> '' THEN 1 ELSE 0 END),
           SUM(CASE WHEN LTRIM(RTRIM(ISNULL(Notes,''))) <> '' THEN 1 ELSE 0 END)
    FROM Orders
) NullAudit;

-- Step 2: Customers where NULL and empty string appear for the same field
SELECT
    CustomerID,
    FirstName,
    Phone,
    CASE
        WHEN Phone IS NULL              THEN 'NULL'
        WHEN LTRIM(RTRIM(Phone)) = ''   THEN 'EMPTY STRING'
        ELSE 'POPULATED: ' + Phone
    END AS PhoneCategory,
    Email,
    CASE
        WHEN Email IS NULL             THEN 'NULL'
        WHEN LTRIM(RTRIM(Email)) = ''  THEN 'EMPTY STRING'
        ELSE 'POPULATED'
    END AS EmailCategory
FROM Customers
WHERE Phone IS NULL OR LTRIM(RTRIM(ISNULL(Phone,''))) = ''
ORDER BY CustomerID;

-- Step 3: Show how NULL vs empty string affects COUNT and WHERE
SELECT
    -- COUNT(*) counts all rows including NULLs
    COUNT(*) AS TotalRows,
    -- COUNT(col) excludes NULLs
    COUNT(Phone) AS NonNullPhones,
    -- WHERE IS NULL vs WHERE = '' behave differently
    SUM(CASE WHEN Phone IS NULL THEN 1 ELSE 0 END) AS NullPhones,
    SUM(CASE WHEN Phone = '' THEN 1 ELSE 0 END) AS EmptyPhones,
    SUM(CASE WHEN Phone IS NULL OR LTRIM(RTRIM(ISNULL(Phone,''))) = '' THEN 1 ELSE 0 END) AS NullOrEmptyPhones,
    -- A WHERE clause that misses one form
    SUM(CASE WHEN Phone IS NULL THEN 1 ELSE 0 END) AS FindsOnlyNulls,  -- misses empty strings
    SUM(CASE WHEN Phone = '' THEN 1 ELSE 0 END) AS FindsOnlyEmpty,     -- misses NULLs
    -- The correct combined check
    SUM(CASE WHEN NULLIF(LTRIM(RTRIM(Phone)), '') IS NULL THEN 1 ELSE 0 END) AS CorrectMissingCount
FROM Customers;

-- Step 4: Standardise — convert empty strings to NULL (query shows what would change)
SELECT
    CustomerID,
    Phone AS CurrentValue,
    NULLIF(LTRIM(RTRIM(Phone)), '') AS StandardisedValue,
    CASE
        WHEN NULLIF(LTRIM(RTRIM(Phone)), '') IS NULL AND Phone IS NOT NULL
             THEN 'WOULD CHANGE: Empty/whitespace → NULL'
        ELSE 'No change needed'
    END AS StandardisationAction
FROM Customers
WHERE Phone IS NOT NULL AND LTRIM(RTRIM(Phone)) = '';
```

## Explanation

**NULL vs empty string semantics**
`NULL` = unknown or not applicable. `''` = known to be empty. SQL treats them differently: `Phone IS NULL` is TRUE only for NULL; `Phone = ''` is TRUE only for empty string; `Phone = ''` when Phone is NULL evaluates to UNKNOWN (not TRUE), so the row is excluded. A WHERE clause targeting only one form silently misses the other.

**NULLIF for standardisation**
`NULLIF(LTRIM(RTRIM(Phone)), '')` is the canonical one-liner to convert empty/whitespace strings to NULL: `LTRIM(RTRIM(Phone))` strips leading/trailing spaces; `NULLIF(..., '')` converts the empty result to NULL. This is the standard approach for normalising the two forms to a single representation.

**COUNT(*) vs COUNT(col)**
`COUNT(*)` counts all rows; `COUNT(Phone)` counts rows where Phone IS NOT NULL. The difference (`COUNT(*) - COUNT(Phone)`) is the NULL count. This is why `COUNT(Phone) = 9` while `COUNT(*) = 12` — 3 NULLs are excluded. But the 1 empty string is still counted by `COUNT(Phone)`, showing it behaves differently from NULL in aggregation.

**The correct missing-value check**
`NULLIF(LTRIM(RTRIM(col)), '') IS NULL` is the safe combined check: it catches NULL, empty string, and whitespace-only values. This is more readable than `col IS NULL OR LTRIM(RTRIM(col)) = ''` and avoids the risk of forgetting one branch.

## Severity
**Medium** — NULL/empty string confusion causes wrong counts, incorrect WHERE clause filtering, and business logic errors (opt-out vs unknown). In systems that use IS NULL to trigger follow-up actions, empty strings silently bypass those actions. Standardising to NULL (using `UPDATE ... SET col = NULLIF(LTRIM(RTRIM(col)), '')`) is the recommended fix.
