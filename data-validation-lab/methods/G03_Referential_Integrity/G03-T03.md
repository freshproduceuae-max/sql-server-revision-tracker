# G03-T03 — Referential Integrity | Self-Referencing FK Violation

## ID
G03-T03

## Group
3 — Referential Integrity

## Type
Self-Referencing FK Violation — ManagerID = Own EmployeeID

## Live Scenario
During a bulk import of an org chart from HR software, a transformation bug sets some employees' ManagerID to their own EmployeeID. An employee cannot manage themselves. The org chart visualisation breaks for those employees, the recursive CTE that walks the hierarchy loops forever until SQL Server hits the recursion limit, and the payroll approval chain is broken.

## The Question
> A table references itself via a FK — common in org charts, category trees, and geographic hierarchies. Self-reference (a row pointing to itself) is almost always an error.
> **"In the Employees table, find any employee whose ManagerID equals their own EmployeeID (reports to themselves), any ManagerID that doesn't exist in the Employees table, and any circular two-way loops."**

## Table Reference
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Check 1: Employee reporting to themselves (self-loop)
SELECT
    EmployeeID,
    FullName,
    ManagerID,
    Department,
    'Self-referencing: ManagerID = own EmployeeID' AS Issue
FROM Employees
WHERE ManagerID = EmployeeID;

-- Check 2: ManagerID references a non-existent EmployeeID (orphan in self-ref table)
SELECT
    e.EmployeeID,
    e.FullName,
    e.ManagerID,
    'ManagerID does not exist in Employees table' AS Issue
FROM Employees e
WHERE e.ManagerID IS NOT NULL
  AND NOT EXISTS (
      SELECT 1 FROM Employees m WHERE m.EmployeeID = e.ManagerID
  );

-- Check 3: Two-way circular loop — A is manager of B and B is manager of A
SELECT
    A.EmployeeID   AS EmpA_ID,
    A.FullName     AS EmpA_Name,
    B.EmployeeID   AS EmpB_ID,
    B.FullName     AS EmpB_Name,
    'Circular loop: A manages B AND B manages A' AS Issue
FROM Employees A
JOIN Employees B
    ON  A.ManagerID = B.EmployeeID
    AND B.ManagerID = A.EmployeeID
    AND A.EmployeeID < B.EmployeeID;   -- prevent duplicate pairs

-- Check 4: Walk the full hierarchy with a Recursive CTE (only after checks 1–3 pass)
WITH OrgHierarchy AS (
    -- Anchor: top-level managers (no manager)
    SELECT
        EmployeeID,
        FullName,
        ManagerID,
        0 AS HierarchyLevel,
        CAST(EmployeeID AS VARCHAR(500)) AS ReportingPath
    FROM Employees
    WHERE ManagerID IS NULL

    UNION ALL

    -- Recursive: each employee below
    SELECT
        e.EmployeeID,
        e.FullName,
        e.ManagerID,
        oh.HierarchyLevel + 1,
        CAST(oh.ReportingPath + ' > ' + e.EmployeeID AS VARCHAR(500))
    FROM Employees e
    JOIN OrgHierarchy oh ON e.ManagerID = oh.EmployeeID
)
SELECT
    EmployeeID,
    FullName,
    ManagerID,
    HierarchyLevel,
    ReportingPath
FROM OrgHierarchy
ORDER BY ReportingPath
OPTION (MAXRECURSION 100);
```

## Expected Output

**Check 1 (self-loop):**
| EmployeeID | FullName | ManagerID | Issue |
|---|---|---|---|
| E007 | David Park | E007 | Self-referencing: ManagerID = own EmployeeID |

**Check 2 (non-existent manager):**
| EmployeeID | FullName | ManagerID | Issue |
|---|---|---|---|
| E017 | John Smith | E099 | ManagerID does not exist in Employees table |

**Check 4 (hierarchy):**
| EmployeeID | FullName | HierarchyLevel | ReportingPath |
|---|---|---|---|
| E010 | Robert Blake | 0 | E010 |
| E001 | Sarah Thompson | 1 | E010 > E001 |

## Explanation

**Always validate before recursing**
A recursive CTE that encounters a circular reference (A → B → A) will loop indefinitely until SQL Server throws a MAXRECURSION error. Always run Check 1 (self-loops) and Check 3 (two-way circles) and fix them before using the recursive CTE. The OPTION (MAXRECURSION 100) cap is a safety net, not a solution.

**Self-JOIN for circular loop detection**
Check 3 joins the table to itself on reversed ManagerID/EmployeeID relationships. If A.ManagerID = B.EmployeeID AND B.ManagerID = A.EmployeeID, then A and B report to each other — a two-way circular loop. The `AND A.EmployeeID < B.EmployeeID` prevents showing the same pair twice.

**Alias clarity in self-referencing queries**
When joining a table to itself, always use clear aliases (`e` for the employee being checked, `m` for the manager being looked up). This is the standard convention for self-referencing FK validation — it makes the query readable without needing comments.

**ReportingPath as a validation tool**
The Recursive CTE builds a path string like `E010 > E001 > E003`. If an employee appears twice in their own path, there is a circular reference. Paths that are unreasonably long (say, more than 10 levels for a typical company) may indicate data entry errors in the hierarchy.

## Severity
**High** — Self-referencing violations break org chart visualisations, hierarchy-based access control, recursive aggregations (roll-up reporting), and any tool that walks the tree. Circular references cause infinite loops in code that traverses the hierarchy.
