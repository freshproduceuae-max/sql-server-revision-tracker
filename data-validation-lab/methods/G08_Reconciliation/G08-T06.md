# G08-T06 — Reconciliation | Sub-Ledger to General Ledger Drift

## ID
G08-T06

## Group
8 — Reconciliation

## Type
Sub-Ledger to General Ledger Drift — Detail Records No Longer Sum to the Control Account Balance

## Live Scenario
An accounts receivable (AR) sub-ledger tracks individual customer invoices and payments. The AR control account in the general ledger holds the aggregate balance. A posting error during a system upgrade causes 14 manual journal entries to credit the GL control account without a corresponding posting in the AR sub-ledger. Three months later, the AR aging report (from the sub-ledger) shows £312,000 outstanding, but the GL control account shows £289,000 — a £23,000 difference. Collections staff are chasing customers for invoices the GL says are already paid. The discrepancy grows each month because no reconciliation was scheduled after the upgrade.

## The Question
> Sub-ledger to GL reconciliation confirms that the sum of individual transactions in the detail system equals the balance in the control account. Drift occurs when postings reach one system but not the other. SQL detects it by summing the sub-ledger and comparing to the expected GL balance.
> **"For each month, compare the sum of Transactions.Amount (the sub-ledger) to the sum of Orders.TotalAmount (the control total), and identify both the monthly variance and the cumulative drift over time."**

## Table Reference
**Transactions** — `schemas/05_Transactions.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Monthly sub-ledger vs control total with cumulative drift
WITH MonthlyControl AS (
    SELECT
        YEAR(OrderDate)  AS Yr,
        MONTH(OrderDate) AS Mo,
        SUM(TotalAmount) AS ControlTotal,
        COUNT(*)         AS ControlCount
    FROM Orders
    WHERE Status NOT IN ('Cancelled')
    GROUP BY YEAR(OrderDate), MONTH(OrderDate)
),
MonthlySubLedger AS (
    SELECT
        YEAR(TransactionDate)  AS Yr,
        MONTH(TransactionDate) AS Mo,
        SUM(Amount)  AS SubLedgerTotal,
        COUNT(*)     AS SubLedgerCount
    FROM Transactions
    GROUP BY YEAR(TransactionDate), MONTH(TransactionDate)
),
MonthlyCombined AS (
    SELECT
        COALESCE(mc.Yr, ms.Yr) AS Yr,
        COALESCE(mc.Mo, ms.Mo) AS Mo,
        ISNULL(mc.ControlTotal,    0) AS ControlTotal,
        ISNULL(ms.SubLedgerTotal,  0) AS SubLedgerTotal,
        ISNULL(mc.ControlCount,    0) AS ControlCount,
        ISNULL(ms.SubLedgerCount,  0) AS SubLedgerCount
    FROM MonthlyControl mc
    FULL OUTER JOIN MonthlySubLedger ms
        ON mc.Yr = ms.Yr AND mc.Mo = ms.Mo
)
SELECT
    Yr AS Year,
    Mo AS Month,
    ControlTotal,
    SubLedgerTotal,
    ROUND(ControlTotal - SubLedgerTotal, 2) AS MonthlyVariance,
    ROUND(SUM(ControlTotal - SubLedgerTotal)
          OVER (ORDER BY Yr, Mo ROWS UNBOUNDED PRECEDING), 2) AS CumulativeDrift,
    ControlCount,
    SubLedgerCount,
    ControlCount - SubLedgerCount AS CountDifference,
    CASE
        WHEN ABS(ControlTotal - SubLedgerTotal) < 0.01 THEN 'Reconciled'
        WHEN ControlTotal > SubLedgerTotal
             THEN 'SUB-LEDGER SHORT: GL control exceeds sub-ledger by '
                  + CAST(ROUND(ControlTotal - SubLedgerTotal, 2) AS VARCHAR)
        ELSE 'CONTROL SHORT: Sub-ledger exceeds GL control by '
             + CAST(ROUND(SubLedgerTotal - ControlTotal, 2) AS VARCHAR)
    END AS ReconciliationStatus
FROM MonthlyCombined
ORDER BY Yr, Mo;

-- Step 2: Running drift — cumulative unreconciled balance over time
WITH AllPostings AS (
    SELECT
        CAST(OrderDate AS DATE)  AS PostDate,
        TotalAmount              AS Amount,
        'Control'                AS Ledger,
        OrderID                  AS RefID
    FROM Orders
    WHERE Status NOT IN ('Cancelled')

    UNION ALL

    SELECT
        CAST(TransactionDate AS DATE),
        Amount,
        'SubLedger',
        CAST(TransactionID AS INT)
    FROM Transactions
),
DailyTotals AS (
    SELECT
        PostDate,
        SUM(CASE WHEN Ledger = 'Control'    THEN Amount ELSE 0 END) AS ControlDay,
        SUM(CASE WHEN Ledger = 'SubLedger'  THEN Amount ELSE 0 END) AS SubLedgerDay
    FROM AllPostings
    GROUP BY PostDate
)
SELECT
    PostDate,
    ControlDay,
    SubLedgerDay,
    ControlDay - SubLedgerDay AS DailyVariance,
    SUM(ControlDay - SubLedgerDay) OVER (ORDER BY PostDate ROWS UNBOUNDED PRECEDING) AS RunningDrift
FROM DailyTotals
ORDER BY PostDate;

-- Step 3: Identify specific orders that exist in control but have no sub-ledger entry
SELECT
    o.OrderID,
    o.CustomerID,
    o.OrderDate,
    o.TotalAmount AS UnpostedAmount,
    o.Status,
    'POSTED TO CONTROL ONLY: No sub-ledger transaction exists' AS DriftCause
FROM Orders o
WHERE NOT EXISTS (
    SELECT 1 FROM Transactions t WHERE t.OrderID = o.OrderID
)
AND o.Status NOT IN ('Cancelled', 'Pending')
ORDER BY o.TotalAmount DESC;
```

## Explanation

**Cumulative drift with window SUM**
`SUM(variance) OVER (ORDER BY Yr, Mo ROWS UNBOUNDED PRECEDING)` accumulates the monthly variance into a running total. This shows whether the gap is growing (new mispostings each month) or stable (a historical error not repeated). A growing cumulative drift indicates an ongoing systematic issue; a stable one indicates a one-time event.

**Two-directional variance**
The variance can be positive (control > sub-ledger: GL was posted but sub-ledger wasn't) or negative (sub-ledger > control: sub-ledger was posted but GL wasn't). Both directions are materially different: the first understates the sub-ledger balance; the second means the GL is understated. The CASE statement distinguishes both.

**Line-level drill-down**
Step 3 moves from period-level to order-level, identifying the specific records causing the drift. `NOT EXISTS` finds orders in the control system with no matching sub-ledger transaction — the direct evidence of a missed posting.

## Severity
**High** — Sub-ledger to GL drift causes trial balance failures and is a key audit finding. Collections, payments, and balance sheet reporting all become unreliable. The longer drift is undetected, the more manual journal entries are required for correction — each carrying its own audit trail and approval requirement.
