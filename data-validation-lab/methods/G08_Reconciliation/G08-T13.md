# G08-T13 — Reconciliation | Tax Liability Reconciliation

## ID
G08-T13

## Group
8 — Reconciliation

## Type
Tax Liability Reconciliation — VAT Output Tax Does Not Match Sum of VAT on Invoices

## Live Scenario
A UK retailer files quarterly VAT returns. The VAT control account in the nominal ledger should equal the sum of VAT charged on all sales invoices for the quarter. An import routine for a new product category incorrectly assigns a 20% VAT rate to items that should be zero-rated (children's clothing). Over a quarter, 847 invoices totalling £312,000 are charged VAT of £52,000 that should be £0. The VAT return overstates output tax by £52,000. The retailer pays the inflated figure to HMRC and must then claim a refund — a process requiring amended returns, supporting evidence, and a 6–8 week wait for the refund. A supplier also notices they've been charged VAT on zero-rated items and raises a credit note request.

## The Question
> Tax reconciliation validates that the VAT (or other tax) computed from transaction details matches the tax declared in the control account or tax return. SQL identifies incorrectly rated transactions and computes the exposure.
> **"Using the VATRate from the Products table and the TotalAmount from Orders, calculate the VAT due on each order, compare it to what was actually collected in Transactions, and identify any orders where the effective VAT rate is incorrect."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Expected VAT per order using product VAT rate
WITH OrderVAT AS (
    SELECT
        o.OrderID,
        o.CustomerID,
        o.OrderDate,
        o.TotalAmount,
        o.Status,
        p.ProductID,
        p.ProductName,
        p.VATRate,
        -- Net amount (ex-VAT) from a VAT-inclusive total
        ROUND(o.TotalAmount / (1 + p.VATRate / 100.0), 2) AS NetAmount,
        -- VAT due on this order
        ROUND(o.TotalAmount - (o.TotalAmount / (1 + p.VATRate / 100.0)), 2) AS VATDue
    FROM Orders o
    JOIN Products p ON o.ProductID = p.ProductID
    WHERE o.Status NOT IN ('Cancelled')
)
SELECT
    ov.OrderID,
    ov.ProductName,
    ov.TotalAmount AS GrossAmount,
    ov.VATRate,
    ov.NetAmount,
    ov.VATDue AS ExpectedVAT,
    ISNULL(SUM(t.Amount), 0) AS ActualReceived,
    ROUND(ISNULL(SUM(t.Amount), 0) - ov.TotalAmount, 2) AS PaymentVariance,
    CASE
        WHEN ov.VATRate = 0   THEN 'Zero-rated — no VAT applicable'
        WHEN ov.VATRate = 5   THEN 'Reduced rate (5%)'
        WHEN ov.VATRate = 20  THEN 'Standard rate (20%)'
        ELSE 'NON-STANDARD RATE: ' + CAST(ov.VATRate AS VARCHAR) + '% — verify classification'
    END AS VATClassification
FROM OrderVAT ov
LEFT JOIN Transactions t ON ov.OrderID = t.OrderID
GROUP BY ov.OrderID, ov.ProductName, ov.TotalAmount, ov.VATRate, ov.NetAmount, ov.VATDue
ORDER BY ov.VATDue DESC;

-- Step 2: Quarterly VAT summary — total output tax by rate band
SELECT
    YEAR(o.OrderDate)   AS TaxYear,
    DATEPART(QUARTER, o.OrderDate) AS TaxQuarter,
    p.VATRate,
    COUNT(o.OrderID)    AS OrderCount,
    SUM(o.TotalAmount)  AS GrossRevenue,
    ROUND(SUM(o.TotalAmount / (1 + p.VATRate / 100.0)), 2) AS NetRevenue,
    ROUND(SUM(o.TotalAmount - o.TotalAmount / (1 + p.VATRate / 100.0)), 2) AS VATCollected,
    CASE p.VATRate
        WHEN 0  THEN 'Zero-rated supplies'
        WHEN 5  THEN 'Reduced rate supplies'
        WHEN 20 THEN 'Standard rate supplies'
        ELSE 'Other/Exempt'
    END AS VATCategory
FROM Orders o
JOIN Products p ON o.ProductID = p.ProductID
WHERE o.Status NOT IN ('Cancelled')
GROUP BY YEAR(o.OrderDate), DATEPART(QUARTER, o.OrderDate), p.VATRate
ORDER BY TaxYear, TaxQuarter, p.VATRate;

-- Step 3: Products with potentially incorrect VAT rates
SELECT
    p.ProductID,
    p.ProductName,
    p.VATRate AS CurrentRate,
    COUNT(o.OrderID) AS OrdersAffected,
    SUM(o.TotalAmount) AS TotalGross,
    ROUND(SUM(o.TotalAmount - o.TotalAmount / (1 + p.VATRate / 100.0)), 2) AS VATCharged,
    CASE
        WHEN p.VATRate NOT IN (0, 5, 20)
             THEN 'INVALID RATE: Not a valid UK VAT rate (0%, 5%, 20%)'
        WHEN p.VATRate = 20 AND p.Price < 5.00
             THEN 'REVIEW: Low-value item at standard rate — may be reduced/zero rated'
        ELSE 'Rate appears valid'
    END AS RateFlag
FROM Products p
LEFT JOIN Orders o ON p.ProductID = o.ProductID AND o.Status NOT IN ('Cancelled')
WHERE p.VATRate NOT IN (0, 5, 20)
   OR (p.VATRate = 20 AND p.Price < 5.00)
GROUP BY p.ProductID, p.ProductName, p.VATRate, p.Price
ORDER BY VATCharged DESC;

-- Step 4: VAT reconciliation — control account vs invoice sum
SELECT
    'VAT per invoice calculation'  AS Source,
    ROUND(SUM(o.TotalAmount - o.TotalAmount / (1 + p.VATRate / 100.0)), 2) AS VATAmount
FROM Orders o
JOIN Products p ON o.ProductID = p.ProductID
WHERE o.Status NOT IN ('Cancelled')

UNION ALL

SELECT
    'Total transactions received',
    ROUND(SUM(Amount), 2)
FROM Transactions
WHERE Amount > 0;
```

## Explanation

**VAT-inclusive reverse calculation**
UK VAT is typically quoted as a VAT-inclusive price. To extract the VAT component: `VAT = GrossAmount × (Rate / (100 + Rate))`. Equivalently: `Net = Gross / (1 + Rate/100)`, then `VAT = Gross - Net`. This is Step 1's formula. Applying the wrong rate to a VAT-inclusive amount produces both a wrong net and a wrong VAT figure.

**Valid UK VAT rate set**
UK VAT has three rates: 0% (zero-rated: food, children's clothing, books), 5% (reduced: domestic fuel, children's car seats), and 20% (standard: everything else). `VATRate NOT IN (0, 5, 20)` catches rates that are neither of these — a common data entry error (e.g., 19%, 21%, or 2.0 entered as a decimal fraction of 0.20).

**Quarterly grouping for VAT returns**
`DATEPART(QUARTER, OrderDate)` groups by Q1–Q4. UK VAT returns are filed quarterly with specific quarter-end dates (31 March, 30 June, 30 September, 31 December for calendar-year VAT periods). The Step 2 summary maps directly to the VAT return boxes: Box 1 (output tax), Box 6 (net value of sales).

**Control account reconciliation**
Step 4 compares VAT computed from invoices against total transactions — the same reconciliation the finance team performs each quarter before filing. A variance indicates either un-posted transactions, incorrect rates, or transactions settled at a different amount than invoiced.

## Severity
**High** — VAT errors have direct cash consequences: overpaid VAT must be claimed back from HMRC (delayed cash), underpaid VAT incurs penalties and interest. In the UK, VAT penalties of up to 100% of the underpaid VAT apply for deliberate errors. Errors affecting multiple periods require amended returns and may trigger VAT inspections.
