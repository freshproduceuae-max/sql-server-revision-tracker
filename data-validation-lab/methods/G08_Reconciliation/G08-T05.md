# G08-T05 — Reconciliation | Intercompany Elimination Failure

## ID
G08-T05

## Group
8 — Reconciliation

## Type
Intercompany Elimination Failure — Intra-Group Transactions Not Eliminated in Consolidated Accounts

## Live Scenario
A holding company owns three subsidiaries. During monthly consolidation, the finance team must eliminate intercompany transactions — sales from Subsidiary A to Subsidiary B are revenue for A but a cost for B, and must cancel out in the group accounts. A consolidation spreadsheet fails to pick up a £180,000 intercompany loan repayment because the loan was recorded in different currencies (GBP at A, USD at B with a stale exchange rate). The consolidated balance sheet overstates both assets (loan receivable not eliminated) and liabilities (loan payable not eliminated), inflating the group balance sheet by £180,000 on each side. The external auditor flags it during the year-end audit.

## The Question
> Intercompany reconciliation requires matching transactions recorded by one entity against the mirror entry recorded by the counterparty. SQL identifies unmatched intercompany items by joining on shared reference keys and flagging mismatches in amount, currency, or timing.
> **"Identify Orders where the CustomerID belongs to an internal entity (Customer country flagged as 'Internal'), compare the TotalAmount to its corresponding Transaction amount, and flag any intercompany pairs where the values do not agree within tolerance."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Customers** — `schemas/01_Customers.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Identify intercompany orders (internal customers) and match to transactions
WITH InternalCustomers AS (
    SELECT CustomerID, FirstName + ' ' + LastName AS EntityName, Country
    FROM Customers
    WHERE Country = 'Internal'  -- Flag used to mark intra-group entities
),
IntercompanyOrders AS (
    SELECT
        o.OrderID,
        o.CustomerID,
        ic.EntityName,
        o.OrderDate,
        o.TotalAmount AS OrderValue,
        o.Status
    FROM Orders o
    JOIN InternalCustomers ic ON o.CustomerID = ic.CustomerID
    WHERE o.Status NOT IN ('Cancelled')
),
OrderTransactions AS (
    SELECT
        t.OrderID,
        SUM(t.Amount) AS TxTotal,
        COUNT(t.TransactionID) AS TxCount,
        STRING_AGG(t.Currency, ', ') AS Currencies
    FROM Transactions t
    GROUP BY t.OrderID
)
SELECT
    io.OrderID,
    io.EntityName,
    io.OrderDate,
    io.OrderValue,
    ISNULL(ot.TxTotal, 0) AS TransactionTotal,
    ot.TxCount,
    ot.Currencies,
    ROUND(io.OrderValue - ISNULL(ot.TxTotal, 0), 2) AS ICVariance,
    CASE
        WHEN ot.OrderID IS NULL
             THEN 'UNMATCHED: Intercompany order has no transaction record'
        WHEN ABS(io.OrderValue - ot.TxTotal) < 0.01
             THEN 'ELIMINATED: Intercompany pair agrees'
        WHEN ot.Currencies LIKE '%,%'
             THEN 'CURRENCY MISMATCH: Multiple currencies — exchange rate risk'
        ELSE 'IC VARIANCE: Investigate — ' + CAST(ROUND(ABS(io.OrderValue - ot.TxTotal),2) AS VARCHAR)
    END AS EliminationStatus
FROM IntercompanyOrders io
LEFT JOIN OrderTransactions ot ON io.OrderID = ot.OrderID
ORDER BY ABS(io.OrderValue - ISNULL(ot.TxTotal, 0)) DESC;

-- Step 2: Aggregate intercompany exposure by entity
WITH InternalCustomers AS (
    SELECT CustomerID, FirstName + ' ' + LastName AS EntityName
    FROM Customers
    WHERE Country = 'Internal'
)
SELECT
    ic.EntityName,
    COUNT(DISTINCT o.OrderID)        AS ICOrderCount,
    SUM(o.TotalAmount)               AS TotalICValue,
    SUM(ISNULL(t.Amount, 0))         AS TotalSettled,
    SUM(o.TotalAmount) - SUM(ISNULL(t.Amount, 0)) AS TotalUneliminated,
    ROUND(100.0 * (SUM(o.TotalAmount) - SUM(ISNULL(t.Amount, 0)))
          / NULLIF(SUM(o.TotalAmount), 0), 1) AS UneliminatedPct
FROM Orders o
JOIN InternalCustomers ic ON o.CustomerID = ic.CustomerID
LEFT JOIN Transactions t  ON o.OrderID = t.OrderID
WHERE o.Status NOT IN ('Cancelled')
GROUP BY ic.EntityName
ORDER BY TotalUneliminated DESC;

-- Step 3: Period summary — intercompany eliminations required this month
SELECT
    YEAR(o.OrderDate)  AS Yr,
    MONTH(o.OrderDate) AS Mo,
    COUNT(DISTINCT o.OrderID) AS ICOrders,
    SUM(o.TotalAmount)        AS GrossICValue,
    SUM(ISNULL(t.Amount, 0))  AS SettledICValue,
    SUM(o.TotalAmount) - SUM(ISNULL(t.Amount, 0)) AS EliminationGap,
    CASE
        WHEN ABS(SUM(o.TotalAmount) - SUM(ISNULL(t.Amount, 0))) < 1.00
             THEN 'Period fully eliminated'
        ELSE 'PERIOD GAP: ' + CAST(ROUND(SUM(o.TotalAmount) - SUM(ISNULL(t.Amount,0)),2) AS VARCHAR)
    END AS PeriodStatus
FROM Orders o
JOIN Customers c  ON o.CustomerID = c.CustomerID AND c.Country = 'Internal'
LEFT JOIN Transactions t ON o.OrderID = t.OrderID
WHERE o.Status NOT IN ('Cancelled')
GROUP BY YEAR(o.OrderDate), MONTH(o.OrderDate)
ORDER BY Yr, Mo;
```

## Explanation

**Intercompany elimination logic**
In consolidated group accounts, a sale from entity A to entity B is simultaneously revenue (A's books) and a cost/asset (B's books). Consolidation requires these to cancel. SQL models this by identifying all orders where the customer is an internal entity, then verifying that a matching transaction exists with an agreeing amount.

**Currency mismatch risk**
The most common failure mode is currency divergence: entity A records £180,000 and entity B records $180,000 using yesterday's rate. `STRING_AGG(Currency, ', ')` detects orders settled in multiple currencies, flagging them for exchange rate review. A correct elimination requires converting both sides to a common reporting currency at the same rate.

**Aggregate vs line-level elimination**
Step 2 rolls up by entity to show total intercompany exposure — useful for treasury and consolidation teams who need to know the total uneliminated balance per subsidiary, not just individual orders. Step 3 shows period-level exposure for the month-end close timetable.

## Severity
**High** — Intercompany elimination failures overstate both group revenue and group costs simultaneously (or inflate assets and liabilities), distorting every reported metric. In public company reporting (IFRS 10, US GAAP ASC 810), failure to eliminate intercompany transactions is a material misstatement requiring restatement.
