# G08-T01 — Reconciliation | Header vs Detail Sum Mismatch

## ID
G08-T01

## Group
8 — Reconciliation

## Type
Header vs Detail Sum Mismatch — Aggregate Header Total Does Not Match Sum of Detail Lines

## Live Scenario
A purchase order system stores order headers in `Orders` (with a pre-computed `TotalAmount`) and individual line items in a `Transactions` table. A batch data migration from a legacy system imports headers and lines separately, and a rounding error in the migration script applies different rounding rules to header totals (round to 2 decimal places using banker's rounding) versus line items (round to 2 decimal places using standard rounding). For orders with many small line items, the rounding differences accumulate: an order with 50 × £0.033 items has a header total of £1.65 but a line sum of £1.50 (50 × £0.03). The monthly financial close cannot balance because the general ledger's order total differs from the payments reconciliation by £142.

## The Question
> Header records often store a pre-computed total for performance. If the header total is not recomputed when detail records change, or if rounding is applied differently, the header-detail reconciliation fails. SQL detects this by recomputing the sum from detail records and comparing to the header.
> **"Find all Orders where TotalAmount in the header does not match the sum of Amount from the related Transactions, and calculate the discrepancy for each."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Header vs detail reconciliation
WITH DetailTotals AS (
    SELECT
        OrderID,
        SUM(Amount) AS DetailSum,
        COUNT(*) AS LineCount,
        MIN(Amount) AS MinLine,
        MAX(Amount) AS MaxLine
    FROM Transactions
    GROUP BY OrderID
)
SELECT
    o.OrderID,
    o.CustomerID,
    o.Status,
    o.TotalAmount AS HeaderTotal,
    dt.DetailSum AS DetailTotal,
    dt.LineCount,
    ROUND(o.TotalAmount - ISNULL(dt.DetailSum, 0), 2) AS Discrepancy,
    ABS(ROUND(o.TotalAmount - ISNULL(dt.DetailSum, 0), 2)) AS AbsDiscrepancy,
    CASE
        WHEN dt.OrderID IS NULL
             THEN 'NO DETAIL: No transactions found — header only'
        WHEN ABS(o.TotalAmount - dt.DetailSum) < 0.01
             THEN 'RECONCILED (within £0.01 rounding tolerance)'
        WHEN ABS(o.TotalAmount - dt.DetailSum) < 1.00
             THEN 'MINOR DISCREPANCY: Under £1 — likely rounding'
        WHEN ABS(o.TotalAmount - dt.DetailSum) < 10.00
             THEN 'MODERATE DISCREPANCY: £1–£10 — investigate'
        ELSE 'SIGNIFICANT DISCREPANCY: £10+ — urgent review'
    END AS ReconciliationStatus
FROM Orders o
LEFT JOIN DetailTotals dt ON o.OrderID = dt.OrderID
WHERE ABS(o.TotalAmount - ISNULL(dt.DetailSum, 0)) > 0.01
   OR dt.OrderID IS NULL
ORDER BY AbsDiscrepancy DESC;

-- Step 2: Period-level reconciliation — monthly header vs detail totals
SELECT
    YEAR(o.OrderDate)  AS OrderYear,
    MONTH(o.OrderDate) AS OrderMonth,
    SUM(o.TotalAmount) AS MonthlyHeaderTotal,
    SUM(t.Amount)      AS MonthlyDetailTotal,
    ROUND(SUM(o.TotalAmount) - SUM(t.Amount), 2) AS MonthlyDiscrepancy,
    COUNT(DISTINCT o.OrderID) AS OrderCount,
    COUNT(t.TransactionID)    AS TransactionCount,
    CASE
        WHEN ABS(SUM(o.TotalAmount) - SUM(t.Amount)) < 0.01 THEN 'Reconciled'
        ELSE 'DISCREPANCY — investigate'
    END AS MonthlyStatus
FROM Orders o
LEFT JOIN Transactions t ON o.OrderID = t.OrderID
GROUP BY YEAR(o.OrderDate), MONTH(o.OrderDate)
ORDER BY OrderYear, OrderMonth;

-- Step 3: Largest discrepancies first — prioritised remediation list
SELECT TOP 10
    o.OrderID,
    o.TotalAmount AS HeaderTotal,
    SUM(t.Amount) AS DetailTotal,
    ABS(o.TotalAmount - SUM(t.Amount)) AS Discrepancy,
    COUNT(t.TransactionID) AS TxCount,
    'Priority reconciliation item' AS Action
FROM Orders o
LEFT JOIN Transactions t ON o.OrderID = t.OrderID
GROUP BY o.OrderID, o.TotalAmount
HAVING ABS(o.TotalAmount - ISNULL(SUM(t.Amount), 0)) > 0.01
ORDER BY Discrepancy DESC;

-- Step 4: Check if discrepancy correlates with line count
-- More lines → more rounding → larger discrepancy?
WITH LineCountAnalysis AS (
    SELECT
        o.OrderID,
        ABS(o.TotalAmount - SUM(t.Amount)) AS Discrepancy,
        COUNT(t.TransactionID) AS LineCount
    FROM Orders o
    JOIN Transactions t ON o.OrderID = t.OrderID
    GROUP BY o.OrderID, o.TotalAmount
    HAVING ABS(o.TotalAmount - SUM(t.Amount)) > 0.00
)
SELECT
    CASE
        WHEN LineCount = 1 THEN '1 line'
        WHEN LineCount <= 5 THEN '2–5 lines'
        WHEN LineCount <= 10 THEN '6–10 lines'
        ELSE '11+ lines'
    END AS LineCountBand,
    COUNT(*) AS OrderCount,
    AVG(Discrepancy) AS AvgDiscrepancy,
    MAX(Discrepancy) AS MaxDiscrepancy
FROM LineCountAnalysis
GROUP BY
    CASE
        WHEN LineCount = 1 THEN '1 line'
        WHEN LineCount <= 5 THEN '2–5 lines'
        WHEN LineCount <= 10 THEN '6–10 lines'
        ELSE '11+ lines'
    END
ORDER BY AvgDiscrepancy DESC;
```

## Explanation

**The reconciliation pattern**
`SUM(detail) = header_total` is the fundamental accounting identity. SQL reconciliation: (1) aggregate details with GROUP BY on the linking key; (2) join to the header; (3) compute the difference; (4) filter on non-zero differences. A zero difference confirms the identity holds.

**Tolerance for rounding**
`ABS(header - detail) < 0.01` allows a 1-penny tolerance. This accounts for legitimate floating-point rounding differences when detail amounts are computed as `unit_price × quantity` with different rounding applications. Without tolerance, valid records generate false positives.

**Two granularities: row-level and period-level**
Step 1 checks each individual order (row-level). Step 2 checks the monthly aggregate — a higher-level reconciliation that may balance even when individual orders don't (some orders over by £X, others under by £X, netting to zero). Both checks are needed: row-level catches individual errors; period-level catches the net financial impact.

**Discrepancy and line count**
Step 4 tests whether larger discrepancies correlate with more line items — evidence of cumulative rounding. If average discrepancy increases monotonically with line count, rounding is the root cause. If there's no correlation, the discrepancy has a different source (missing lines, incorrect amounts).

## Severity
**High** — Header-detail mismatches cause financial close failures and general ledger imbalances. In regulated financial reporting, the trial balance must reconcile to the penny. Unexplained discrepancies require journal adjustments and audit explanations — costly and time-consuming.
