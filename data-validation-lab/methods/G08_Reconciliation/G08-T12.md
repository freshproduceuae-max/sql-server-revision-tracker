# G08-T12 — Reconciliation | Inventory Count vs System Balance

## ID
G08-T12

## Group
8 — Reconciliation

## Type
Inventory Count vs System Balance — Physical Stock Count Does Not Match System Record

## Live Scenario
A warehouse conducts a quarterly physical stock count. The count team records 1,847 units of SKU-4421 on the shelves. The warehouse management system (WMS) shows 1,903 units — a 56-unit discrepancy worth £2,240 at cost. Investigation reveals: 12 units were received from a supplier but the goods receipt note was never posted to the WMS (the delivery driver left without waiting for signature); 31 units were scrapped following a quality inspection but the write-off transaction was never entered; and 13 units were counted twice because they were stored in two locations that were both included in the count sheet. The shrinkage rate (unresolved variance / opening stock) is 0.7%, above the 0.5% policy threshold.

## The Question
> Inventory reconciliation compares the book balance (computed from opening stock + receipts − sales − adjustments) to the physical count. SQL validates the book balance by recomputing it from all movement records and comparing to the stated closing balance.
> **"For each product, compute the net movement from Transactions (as a proxy for inventory movements), identify any products where the net movement is inconsistent, and flag products where the order count suggests potential stock discrepancy."**

## Table Reference
**Transactions** — `schemas/05_Transactions.csv`
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Product-level movement summary and implied stock position
WITH ProductMovements AS (
    SELECT
        o.ProductID,
        COUNT(DISTINCT o.OrderID)     AS OrderCount,
        SUM(o.TotalAmount)            AS TotalOrderValue,
        SUM(t.Amount)                 AS TotalTransactionValue,
        COUNT(t.TransactionID)        AS TransactionCount,
        MIN(o.OrderDate)              AS FirstOrder,
        MAX(o.OrderDate)              AS LastOrder
    FROM Orders o
    LEFT JOIN Transactions t ON o.OrderID = t.OrderID
    WHERE o.Status NOT IN ('Cancelled')
    GROUP BY o.ProductID
)
SELECT
    p.ProductID,
    p.ProductName,
    p.StockQuantity AS SystemBalance,
    pm.OrderCount,
    pm.TotalOrderValue,
    pm.TotalTransactionValue,
    pm.TransactionCount,
    ROUND(pm.TotalOrderValue - ISNULL(pm.TotalTransactionValue, 0), 2) AS UnpaidValue,
    CASE
        WHEN pm.OrderCount > p.StockQuantity * 2
             THEN 'HIGH TURNOVER: Order count significantly exceeds stock — verify replenishment'
        WHEN pm.OrderCount = 0
             THEN 'NO ORDERS: Product has system stock but no order activity'
        WHEN p.StockQuantity <= 0
             THEN 'ZERO/NEGATIVE STOCK: Count-system discrepancy possible'
        ELSE 'Normal activity pattern'
    END AS StockConsistencyFlag
FROM Products p
LEFT JOIN ProductMovements pm ON p.ProductID = pm.ProductID
ORDER BY p.StockQuantity DESC;

-- Step 2: Detect products that appear in orders but are marked inactive (stock management issue)
SELECT
    p.ProductID,
    p.ProductName,
    p.IsActive,
    p.StockQuantity,
    COUNT(o.OrderID) AS RecentOrders,
    SUM(o.TotalAmount) AS RecentOrderValue,
    CASE
        WHEN p.IsActive = 0 AND COUNT(o.OrderID) > 0
             THEN 'INACTIVE PRODUCT WITH ORDERS: Stock records may be stale'
        WHEN p.StockQuantity = 0 AND COUNT(o.OrderID) > 0
             THEN 'ZERO STOCK WITH ORDERS: Possible oversell or count error'
        ELSE 'Consistent'
    END AS InventoryFlag
FROM Products p
LEFT JOIN Orders o
    ON  p.ProductID = o.ProductID
    AND o.Status NOT IN ('Cancelled')
GROUP BY p.ProductID, p.ProductName, p.IsActive, p.StockQuantity
HAVING p.IsActive = 0 AND COUNT(o.OrderID) > 0
    OR p.StockQuantity = 0 AND COUNT(o.OrderID) > 0
ORDER BY RecentOrders DESC;

-- Step 3: Transaction value vs order value by product — detect settlement gaps
WITH ProductReconciliation AS (
    SELECT
        o.ProductID,
        SUM(o.TotalAmount)              AS TotalOrderValue,
        SUM(ISNULL(t.Amount, 0))        AS TotalSettled,
        COUNT(DISTINCT o.OrderID)       AS TotalOrders,
        SUM(CASE WHEN t.TransactionID IS NULL THEN 1 ELSE 0 END) AS UnsettledOrders
    FROM Orders o
    LEFT JOIN Transactions t ON o.OrderID = t.OrderID
    WHERE o.Status NOT IN ('Cancelled')
    GROUP BY o.ProductID
)
SELECT
    p.ProductID,
    p.ProductName,
    p.Price AS UnitPrice,
    pr.TotalOrders,
    pr.UnsettledOrders,
    pr.TotalOrderValue,
    pr.TotalSettled,
    ROUND(pr.TotalOrderValue - pr.TotalSettled, 2) AS OutstandingBalance,
    ROUND(100.0 * pr.UnsettledOrders / NULLIF(pr.TotalOrders, 0), 1) AS UnsettledPct
FROM ProductReconciliation pr
JOIN Products p ON pr.ProductID = p.ProductID
WHERE pr.UnsettledOrders > 0
ORDER BY OutstandingBalance DESC;

-- Step 4: Identify negative stock implied by returns/adjustments
SELECT
    o.ProductID,
    p.ProductName,
    p.StockQuantity AS CurrentSystemStock,
    COUNT(t.TransactionID) AS RefundTransactions,
    SUM(ABS(t.Amount))     AS TotalRefundValue,
    'REFUND ACTIVITY: Verify physical count against system after adjustments' AS Flag
FROM Transactions t
JOIN Orders o ON t.OrderID = o.OrderID
JOIN Products p ON o.ProductID = p.ProductID
WHERE t.Amount < 0  -- Negative amounts = refunds/credits
GROUP BY o.ProductID, p.ProductName, p.StockQuantity
ORDER BY TotalRefundValue DESC;
```

## Explanation

**Book balance identity**
The inventory book balance follows: `Closing = Opening + Receipts − Issues − Adjustments`. SQL validates this by summing all movement records (receipts as positive, issues/sales as negative). If the computed closing balance differs from the system's stated `StockQuantity`, either a movement was not posted or the opening balance was incorrect.

**Proxy movements from Orders**
Where a dedicated inventory movement table doesn't exist, the Orders table provides a proxy: each order represents an outbound movement. Count of orders is a lower-bound estimate of units sold; it's not equivalent to unit quantity but flags products with unusually high turnover relative to their stated stock.

**Zero-stock oversell detection**
`StockQuantity = 0 AND ORDER COUNT > 0` catches the common case of stock being sold after the system balance reaches zero — either because physical stock was miscounted, because the system allowed negative stock, or because a receipt was not posted. All three scenarios require investigation.

**Refund reconciliation**
Step 4 identifies products with return/credit transactions. Returns should increase stock; if the system balance doesn't reflect posted returns, the book balance is understated. Returns without a corresponding stock receipt posting create a permanent book-to-physical discrepancy.

## Severity
**Medium** — Inventory discrepancies cause procurement errors (ordering too much or too little), financial reporting errors (inventory is a balance sheet asset), and operational failures (committing to orders that cannot be fulfilled). Above a materiality threshold, inventory write-downs require disclosure in statutory accounts.
