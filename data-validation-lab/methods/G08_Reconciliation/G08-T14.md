# G08-T14 — Reconciliation | Aged Debtor Discrepancy

## ID
G08-T14

## Group
8 — Reconciliation

## Type
Aged Debtor Discrepancy — Outstanding Balances in Aged Debtor Report Do Not Match Ledger

## Live Scenario
A credit controller runs the monthly aged debtor report. It shows £412,000 outstanding across 87 customers. The AR control account in the nominal ledger shows £389,000 — a £23,000 shortfall. The discrepancy has three sources: (1) six invoices totalling £8,400 were manually written off in the ledger as bad debts but not removed from the aged debtor report; (2) £11,200 of credit notes were issued and posted to the ledger but not applied to specific invoices in the AR system; (3) £3,400 of payments were received and posted to the bank but awaiting allocation in AR. The aged debtor report overstates outstanding debt, causing wasted effort chasing settled balances.

## The Question
> Aged debtor (accounts receivable aging) analysis classifies outstanding orders by how long they have been unpaid. SQL computes the aged balance directly from Orders and Transactions, compares it to expected totals, and flags debts by age band.
> **"Produce an aged debtor analysis for all customers with unpaid orders — classifying outstanding balances into age bands (current, 30, 60, 90, 90+ days overdue) — and identify any customers where the total outstanding differs from their order history."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Customers** — `schemas/01_Customers.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Aged debtor analysis by customer and age band
WITH OrderBalances AS (
    SELECT
        o.OrderID,
        o.CustomerID,
        o.OrderDate,
        o.TotalAmount AS InvoiceAmount,
        ISNULL(SUM(t.Amount), 0) AS AmountReceived,
        o.TotalAmount - ISNULL(SUM(t.Amount), 0) AS OutstandingBalance,
        DATEDIFF(DAY, o.OrderDate, GETDATE()) AS AgeDays,
        o.Status
    FROM Orders o
    LEFT JOIN Transactions t ON o.OrderID = t.OrderID
    WHERE o.Status NOT IN ('Cancelled')
    GROUP BY o.OrderID, o.CustomerID, o.OrderDate, o.TotalAmount, o.Status
    HAVING o.TotalAmount - ISNULL(SUM(t.Amount), 0) > 0.01
)
SELECT
    ob.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    COUNT(ob.OrderID) AS OutstandingInvoices,
    SUM(ob.OutstandingBalance) AS TotalOutstanding,
    -- Age band breakdown
    SUM(CASE WHEN ob.AgeDays <= 30  THEN ob.OutstandingBalance ELSE 0 END) AS Current_0_30,
    SUM(CASE WHEN ob.AgeDays BETWEEN 31 AND 60  THEN ob.OutstandingBalance ELSE 0 END) AS Days31_60,
    SUM(CASE WHEN ob.AgeDays BETWEEN 61 AND 90  THEN ob.OutstandingBalance ELSE 0 END) AS Days61_90,
    SUM(CASE WHEN ob.AgeDays > 90 THEN ob.OutstandingBalance ELSE 0 END) AS Over90Days,
    MAX(ob.AgeDays) AS OldestDebtAge,
    CASE
        WHEN MAX(ob.AgeDays) > 90
             THEN 'CRITICAL: Debt over 90 days — escalate to collections'
        WHEN MAX(ob.AgeDays) > 60
             THEN 'OVERDUE: Debt 60-90 days — issue final reminder'
        WHEN MAX(ob.AgeDays) > 30
             THEN 'CHASING: Debt 30-60 days — send reminder'
        ELSE 'Current — within terms'
    END AS CollectionsAction
FROM OrderBalances ob
JOIN Customers c ON ob.CustomerID = c.CustomerID
GROUP BY ob.CustomerID, c.FirstName, c.LastName
ORDER BY TotalOutstanding DESC;

-- Step 2: Portfolio-level aged debtor summary
WITH OrderBalances AS (
    SELECT
        o.OrderID,
        o.TotalAmount - ISNULL(SUM(t.Amount), 0) AS OutstandingBalance,
        DATEDIFF(DAY, o.OrderDate, GETDATE()) AS AgeDays
    FROM Orders o
    LEFT JOIN Transactions t ON o.OrderID = t.OrderID
    WHERE o.Status NOT IN ('Cancelled')
    GROUP BY o.OrderID, o.OrderDate, o.TotalAmount
    HAVING o.TotalAmount - ISNULL(SUM(t.Amount), 0) > 0.01
)
SELECT
    'Current (0-30 days)'    AS AgeBand, COUNT(*) AS Invoices, SUM(OutstandingBalance) AS Balance
FROM OrderBalances WHERE AgeDays <= 30
UNION ALL
SELECT '31-60 days',   COUNT(*), SUM(OutstandingBalance) FROM OrderBalances WHERE AgeDays BETWEEN 31 AND 60
UNION ALL
SELECT '61-90 days',   COUNT(*), SUM(OutstandingBalance) FROM OrderBalances WHERE AgeDays BETWEEN 61 AND 90
UNION ALL
SELECT '90+ days',     COUNT(*), SUM(OutstandingBalance) FROM OrderBalances WHERE AgeDays > 90
UNION ALL
SELECT 'TOTAL',        COUNT(*), SUM(OutstandingBalance) FROM OrderBalances;

-- Step 3: Customers where total outstanding does not match what's expected from order history
WITH CustomerExpected AS (
    SELECT
        CustomerID,
        SUM(TotalAmount) AS TotalOrdered,
        SUM(CASE WHEN Status = 'Cancelled' THEN TotalAmount ELSE 0 END) AS Cancelled
    FROM Orders
    GROUP BY CustomerID
),
CustomerReceived AS (
    SELECT
        o.CustomerID,
        SUM(t.Amount) AS TotalReceived
    FROM Transactions t
    JOIN Orders o ON t.OrderID = o.OrderID
    GROUP BY o.CustomerID
)
SELECT
    ce.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    ce.TotalOrdered,
    ce.Cancelled AS CancelledOrders,
    ce.TotalOrdered - ce.Cancelled AS NetOrderValue,
    ISNULL(cr.TotalReceived, 0) AS TotalReceived,
    (ce.TotalOrdered - ce.Cancelled) - ISNULL(cr.TotalReceived, 0) AS ImpliedOutstanding,
    CASE
        WHEN (ce.TotalOrdered - ce.Cancelled) - ISNULL(cr.TotalReceived, 0) < 0
             THEN 'OVERPAID: Received more than invoiced — potential duplicate payment'
        WHEN (ce.TotalOrdered - ce.Cancelled) - ISNULL(cr.TotalReceived, 0) > 0
             THEN 'OUTSTANDING: ' + CAST(ROUND((ce.TotalOrdered - ce.Cancelled) - ISNULL(cr.TotalReceived,0),2) AS VARCHAR)
        ELSE 'Fully settled'
    END AS DebtorStatus
FROM CustomerExpected ce
JOIN Customers c ON ce.CustomerID = c.CustomerID
LEFT JOIN CustomerReceived cr ON ce.CustomerID = cr.CustomerID
ORDER BY ImpliedOutstanding DESC;
```

## Explanation

**Aged debtor calculation**
Outstanding balance per invoice = `TotalAmount − SUM(transactions)`. `DATEDIFF(DAY, OrderDate, GETDATE())` gives the age in days from invoice date to today. The four standard age bands (current, 30, 60, 90+ days) match the standard AR aging report format used in accounting software.

**HAVING clause on aggregates**
The `HAVING o.TotalAmount - ISNULL(SUM(t.Amount), 0) > 0.01` filter in the CTE eliminates fully settled orders from the aged analysis. This is more efficient than computing outstanding for every order and then filtering — the HAVING clause works at aggregate level.

**Conditional SUM for age band columns**
`SUM(CASE WHEN AgeDays BETWEEN 31 AND 60 THEN Balance ELSE 0 END)` is the standard pivot pattern for producing age band columns in a single row per customer. Each CASE expression contributes the balance only when it falls in the relevant band, producing a columnar aging breakdown.

**Overpaid detection**
Step 3 catches a related problem: customers where total received exceeds total invoiced. This indicates either duplicate payments (money owed back to customer) or transactions allocated to the wrong customer. Negative outstanding balances are a liability, not an asset, and must not appear in the aged debtor report.

## Severity
**Medium** — Inaccurate aged debtor reports misdirect collections effort, overstate receivables on the balance sheet, and may cause unnecessary credit actions against customers who have already paid. At year-end, the AR balance must agree to the control account; unexplained differences require provisions and audit explanations.
