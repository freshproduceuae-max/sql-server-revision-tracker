# G08-T03 — Reconciliation | Bank Statement vs Ledger Mismatch

## ID
G08-T03

## Group
8 — Reconciliation

## Type
Bank Statement vs Ledger Mismatch — Payments in Bank Do Not Reconcile to Accounting Records

## Live Scenario
A company's treasury team reconciles the bank statement against the accounts payable ledger monthly. In March, the bank statement shows a payment of £15,400 to a supplier, but the ledger shows an invoice of £15,040 — a £360 transposition error (4 and 0 transposed in the bank sort code entry). The payment was processed at the wrong amount. The supplier received £360 more than invoiced and did not flag the overpayment. A second discrepancy: a £2,800 direct debit appears on the bank statement but has no matching ledger entry — it was processed by the bank but the accounting system was offline when the file was transmitted, so the entry was never posted.

## The Question
> Bank reconciliation compares two independently maintained records of the same cash flows: the bank's record (bank statement) and the company's record (accounts payable/receivable ledger). Any discrepancy requires investigation and journal adjustment.
> **"Reconcile the sum of Transactions against the sum of Orders.TotalAmount for each month, identify unmatched items in each set, and produce a formal reconciliation statement showing opening balance, movements, and closing balance."**

## Table Reference
**Transactions** — `schemas/05_Transactions.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Monthly reconciliation — compare order values to transaction amounts
WITH MonthlyOrders AS (
    SELECT
        YEAR(OrderDate)  AS Yr,
        MONTH(OrderDate) AS Mo,
        SUM(TotalAmount) AS OrderTotal,
        COUNT(*) AS OrderCount
    FROM Orders
    WHERE Status NOT IN ('Cancelled')
    GROUP BY YEAR(OrderDate), MONTH(OrderDate)
),
MonthlyTransactions AS (
    SELECT
        YEAR(TransactionDate)  AS Yr,
        MONTH(TransactionDate) AS Mo,
        SUM(Amount) AS TxTotal,
        COUNT(*) AS TxCount
    FROM Transactions
    GROUP BY YEAR(TransactionDate), MONTH(TransactionDate)
)
SELECT
    COALESCE(mo.Yr, mt.Yr) AS Year,
    COALESCE(mo.Mo, mt.Mo) AS Month,
    ISNULL(mo.OrderTotal, 0) AS OrderTotal,
    ISNULL(mo.OrderCount, 0) AS OrderCount,
    ISNULL(mt.TxTotal, 0)   AS TransactionTotal,
    ISNULL(mt.TxCount, 0)   AS TransactionCount,
    ROUND(ISNULL(mo.OrderTotal, 0) - ISNULL(mt.TxTotal, 0), 2) AS Variance,
    CASE
        WHEN ABS(ISNULL(mo.OrderTotal, 0) - ISNULL(mt.TxTotal, 0)) < 0.01
             THEN 'RECONCILED'
        WHEN mo.Yr IS NULL THEN 'TRANSACTIONS WITH NO ORDERS IN PERIOD'
        WHEN mt.Yr IS NULL THEN 'ORDERS WITH NO TRANSACTIONS IN PERIOD'
        ELSE 'VARIANCE: Investigate'
    END AS ReconciliationResult
FROM MonthlyOrders mo
FULL OUTER JOIN MonthlyTransactions mt
    ON mo.Yr = mt.Yr AND mo.Mo = mt.Mo
ORDER BY Year, Month;

-- Step 2: Formal reconciliation statement (rolling balance)
WITH RunningTotals AS (
    SELECT
        OrderID,
        OrderDate,
        TotalAmount AS Value,
        'Order' AS RecordType,
        Status
    FROM Orders
    WHERE Status NOT IN ('Cancelled')

    UNION ALL

    SELECT
        CAST(TransactionID AS INT),
        TransactionDate,
        Amount,
        'Transaction',
        Currency
    FROM Transactions
    WHERE Amount > 0
)
SELECT
    YEAR(OrderDate) AS Yr,
    MONTH(OrderDate) AS Mo,
    SUM(CASE WHEN RecordType = 'Order' THEN Value ELSE 0 END) AS OrderInflows,
    SUM(CASE WHEN RecordType = 'Transaction' THEN Value ELSE 0 END) AS TxInflows,
    SUM(CASE WHEN RecordType = 'Order' THEN Value ELSE 0 END)
    - SUM(CASE WHEN RecordType = 'Transaction' THEN Value ELSE 0 END) AS MonthlyVariance
FROM RunningTotals
GROUP BY YEAR(OrderDate), MONTH(OrderDate)
ORDER BY Yr, Mo;

-- Step 3: Identify orders with no matching transaction (unreconciled ledger items)
SELECT
    o.OrderID,
    o.CustomerID,
    o.OrderDate,
    o.TotalAmount,
    o.Status,
    'UNMATCHED LEDGER ITEM: Order has no transaction record' AS ReconciliationNote
FROM Orders o
WHERE NOT EXISTS (
    SELECT 1 FROM Transactions t WHERE t.OrderID = o.OrderID
)
AND o.Status NOT IN ('Pending', 'Cancelled')  -- Pending orders are expected to lack transactions
ORDER BY o.TotalAmount DESC;

-- Step 4: Amount matching — find transactions whose amount matches an order (fuzzy match)
-- Useful for identifying near-matches where a transposition error occurred
SELECT
    o.OrderID,
    o.TotalAmount AS OrderAmount,
    t.TransactionID,
    t.Amount AS TxAmount,
    ABS(o.TotalAmount - t.Amount) AS AmountDifference,
    CASE
        WHEN o.TotalAmount = t.Amount THEN 'EXACT MATCH'
        WHEN ABS(o.TotalAmount - t.Amount) < 1.00 THEN 'NEAR MATCH: Within £1'
        WHEN ABS(o.TotalAmount - t.Amount) < o.TotalAmount * 0.01 THEN 'NEAR MATCH: Within 1%'
        ELSE 'MISMATCH'
    END AS MatchStatus
FROM Orders o
JOIN Transactions t ON o.OrderID = t.OrderID
WHERE ABS(o.TotalAmount - t.Amount) > 0.01
ORDER BY AmountDifference DESC;

-- Step 5: Outstanding (unreconciled) balance
SELECT
    SUM(o.TotalAmount) AS TotalOrderValue,
    SUM(CASE WHEN t.TransactionID IS NOT NULL THEN t.Amount ELSE 0 END) AS TotalSettled,
    SUM(o.TotalAmount) - SUM(CASE WHEN t.TransactionID IS NOT NULL THEN t.Amount ELSE 0 END)
        AS OutstandingBalance,
    COUNT(DISTINCT o.OrderID) AS TotalOrders,
    COUNT(DISTINCT t.TransactionID) AS TotalSettledTx
FROM Orders o
LEFT JOIN Transactions t ON o.OrderID = t.OrderID
WHERE o.Status NOT IN ('Cancelled');
```

## Explanation

**FULL OUTER JOIN for two-sided reconciliation**
A standard JOIN would miss items present in only one side. `FULL OUTER JOIN` returns rows from both sides — items in orders with no matching transaction AND transactions with no matching order both appear. `COALESCE(mo.Yr, mt.Yr)` handles the case where only one side has data for a period.

**The formal reconciliation structure**
A bank reconciliation follows a standard format:
- Opening balance (known)
- + Credits (inflows in the period)
- – Debits (outflows in the period)
- = Closing balance (computed)
Both sides (bank and ledger) must produce the same closing balance, with differences explained by timing items (payments in transit, deposits in transit).

**Transposition errors**
Step 4 flags amount near-mismatches between orders and transactions. A £15,400 transaction matching a £15,040 order has a £360 difference — consistent with a transposition error. Sorting by `AmountDifference` surfaces the largest discrepancies for priority investigation.

**Outstanding balance as the reconciliation output**
Step 5 produces the key output of a reconciliation: total value of orders, total settled via transactions, and the outstanding (unreconciled) balance. This balance should equal the sum of all outstanding invoices in the accounts payable ledger.

## Severity
**High** — Bank reconciliation failures prevent financial close, indicate either payment errors or posting failures, and create audit qualifications if unresolved. Overpayments to suppliers create recoverable debts that are often difficult to recover. Missing ledger entries cause understated liabilities and inaccurate cash flow reporting.
