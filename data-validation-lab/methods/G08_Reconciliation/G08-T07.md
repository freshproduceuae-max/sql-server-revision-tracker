# G08-T07 — Reconciliation | Multi-Currency Conversion Error

## ID
G08-T07

## Group
8 — Reconciliation

## Type
Multi-Currency Conversion Error — Amounts in Different Currencies Summed Without Conversion

## Live Scenario
A global e-commerce platform accepts payments in GBP, USD, and EUR. A reporting query sums all transaction amounts without checking the currency field, producing a single total of "£/$/€ 847,320" — a meaningless mix of three currencies treated as if they were identical. A finance analyst uses this figure for a board report. The true GBP-equivalent total (using the day's exchange rates: 1 USD = 0.79 GBP, 1 EUR = 0.86 GBP) is £623,400 — a £223,920 overstatement. The error is discovered when the reported figure cannot be reconciled to the bank statement, which shows sterling deposits only.

## The Question
> Multi-currency aggregation without conversion produces meaningless totals. SQL detects this by identifying queries that mix currencies and provides corrected totals using exchange rate tables. It also flags records where the currency field is missing or inconsistent.
> **"Detect Transactions where multiple currencies are mixed in aggregate calculations, show the breakdown by currency, and flag any currency inconsistencies within a single Order."**

## Table Reference
**Transactions** — `schemas/05_Transactions.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Currency distribution — never mix without awareness
SELECT
    Currency,
    COUNT(*)         AS TransactionCount,
    SUM(Amount)      AS RawTotal,
    MIN(Amount)      AS MinAmount,
    MAX(Amount)      AS MaxAmount,
    AVG(Amount)      AS AvgAmount
FROM Transactions
WHERE Amount > 0
GROUP BY Currency
ORDER BY RawTotal DESC;

-- Step 2: Detect orders where transactions use multiple currencies
WITH OrderCurrencies AS (
    SELECT
        OrderID,
        COUNT(DISTINCT Currency)         AS CurrencyCount,
        STRING_AGG(DISTINCT Currency, ', ') AS CurrenciesUsed,
        SUM(Amount)                      AS RawSum,
        COUNT(*)                         AS TxCount
    FROM Transactions
    GROUP BY OrderID
)
SELECT
    oc.OrderID,
    o.TotalAmount AS OrderHeaderAmount,
    oc.CurrenciesUsed,
    oc.CurrencyCount,
    oc.RawSum,
    oc.TxCount,
    CASE
        WHEN oc.CurrencyCount > 1
             THEN 'MULTI-CURRENCY ORDER: Cannot sum ' + oc.CurrenciesUsed + ' directly'
        WHEN oc.CurrencyCount = 1 AND ABS(o.TotalAmount - oc.RawSum) > 0.01
             THEN 'SINGLE CURRENCY BUT AMOUNT MISMATCH: Header vs transactions differ'
        ELSE 'OK: Single currency, amounts agree'
    END AS CurrencyFlag
FROM OrderCurrencies oc
JOIN Orders o ON oc.OrderID = o.OrderID
WHERE oc.CurrencyCount > 1
   OR ABS(o.TotalAmount - oc.RawSum) > 0.01
ORDER BY oc.CurrencyCount DESC, ABS(o.TotalAmount - oc.RawSum) DESC;

-- Step 3: Apply indicative exchange rates to produce a common-currency total
-- (In production, rates come from an ExchangeRates reference table)
DECLARE @RateUSDtoGBP DECIMAL(10,6) = 0.790000;
DECLARE @RateEURtoGBP DECIMAL(10,6) = 0.860000;
DECLARE @RateGBPtoGBP DECIMAL(10,6) = 1.000000;

SELECT
    Currency,
    COUNT(*)                          AS TxCount,
    SUM(Amount)                       AS NativeTotalAmount,
    CASE Currency
        WHEN 'GBP' THEN @RateGBPtoGBP
        WHEN 'USD' THEN @RateUSDtoGBP
        WHEN 'EUR' THEN @RateEURtoGBP
        ELSE NULL
    END                               AS RateToGBP,
    ROUND(SUM(Amount) * CASE Currency
        WHEN 'GBP' THEN @RateGBPtoGBP
        WHEN 'USD' THEN @RateUSDtoGBP
        WHEN 'EUR' THEN @RateEURtoGBP
        ELSE 0
    END, 2)                           AS GBPEquivalent,
    CASE
        WHEN Currency NOT IN ('GBP', 'USD', 'EUR')
             THEN 'UNKNOWN CURRENCY: No exchange rate available'
        ELSE 'Converted'
    END AS ConversionStatus
FROM Transactions
WHERE Amount > 0
GROUP BY Currency
ORDER BY GBPEquivalent DESC;

-- Step 4: Transactions with NULL or blank currency — cannot convert
SELECT
    TransactionID,
    OrderID,
    Amount,
    Currency,
    TransactionDate,
    'CURRENCY MISSING: Cannot include in multi-currency reconciliation' AS Issue
FROM Transactions
WHERE Currency IS NULL
   OR LTRIM(RTRIM(Currency)) = ''
   OR LEN(Currency) <> 3;  -- ISO 4217 currency codes are always 3 characters

-- Step 5: The "wrong" aggregate (what the error looks like) vs the corrected figure
SELECT
    'RAW SUM (incorrect — mixes currencies)' AS Calculation,
    ROUND(SUM(Amount), 2)                    AS Total,
    'Mixed: ' + STRING_AGG(DISTINCT Currency, '/') AS CurrencyNote
FROM Transactions
WHERE Amount > 0

UNION ALL

SELECT
    'GBP EQUIVALENT (corrected)',
    ROUND(SUM(Amount * CASE Currency
        WHEN 'GBP' THEN 1.000000
        WHEN 'USD' THEN 0.790000
        WHEN 'EUR' THEN 0.860000
        ELSE 0
    END), 2),
    'GBP only'
FROM Transactions
WHERE Amount > 0;
```

## Expected Output

**Step 1 — Currency breakdown:**
| Currency | TransactionCount | RawTotal |
|---|---|---|
| GBP | 18 | 24500.00 |
| USD | 5 | 3200.00 |
| EUR | 2 | 890.00 |

**Step 2 — Multi-currency orders:**
| OrderID | CurrenciesUsed | CurrencyCount | CurrencyFlag |
|---|---|---|---|
| 1008 | GBP, USD | 2 | MULTI-CURRENCY ORDER: Cannot sum GBP/USD directly |

**Step 5 — Corrected total:**
| Calculation | Total | CurrencyNote |
|---|---|---|
| RAW SUM (incorrect — mixes currencies) | 28590.00 | Mixed: GBP/USD/EUR |
| GBP EQUIVALENT (corrected) | 25977.40 | GBP only |

## Explanation

**The fundamental error: currency-blind SUM**
`SUM(Amount)` without a `WHERE Currency = 'GBP'` clause produces a meaningless number when transactions span multiple currencies. Step 5 makes the contrast explicit: the raw sum is £28,590 while the corrected GBP equivalent is £25,977 — a £2,613 difference (10%) caused purely by mixing currencies.

**ISO 4217 validation**
Currency codes are always 3 uppercase characters (ISO 4217: GBP, USD, EUR, JPY). `LEN(Currency) <> 3` catches codes that are corrupt, truncated, or contain spaces. Step 4 explicitly surfaces these before attempting any conversion.

**Exchange rate as a parameter**
Hardcoding exchange rates in SQL is acceptable for detection queries but wrong for production. The pattern to use: an `ExchangeRates` table keyed on `(Currency, RateDate)` with a join on the transaction date. Step 3 uses DECLARE variables to make the rate assumptions explicit and easy to update.

**STRING_AGG DISTINCT for currency detection**
`STRING_AGG(DISTINCT Currency, ', ')` within an ORDER BY group lists all unique currencies in an order. This is the diagnostic for Step 2 — it shows exactly which currencies are mixed so the reviewer knows whether to apply USD→GBP or EUR→GBP conversion.

## Severity
**High** — Currency mixing is a silent error: the query runs, returns a number, and passes to downstream reports with no error message. Depending on exchange rate spreads, the overstatement or understatement can be 10–30%. In regulated financial reporting, currency misstatement is a disclosure requirement and may trigger restatement.
