# G05-T08 — Range/Boundary | Statistical Outlier Detection

## ID
G05-T08

## Group
5 — Range/Boundary

## Type
Statistical Outlier Detection — Value More Than N Standard Deviations from Mean

## Live Scenario
A retail analytics platform monitors daily sales totals by store. On a typical day, a store generates between £8,000 and £25,000. One day, store 42 records a total of £1,247,000. Investigation reveals a data entry operator accidentally typed an extra zero when manually entering the day's takings. The automated report that week shows store 42 as the top performer by a factor of 50× — the operations team makes staffing decisions based on this data before the error is identified.

## The Question
> Statistical outlier detection uses the mean and standard deviation of the distribution to flag values that are implausibly far from the centre. The standard approach is: flag values more than 3 standard deviations from the mean (the "3-sigma rule"). In skewed distributions, IQR-based outlier detection is more appropriate.
> **"Find all Transactions where Amount is more than 3 standard deviations above the mean transaction amount for its currency. Also identify the 99th percentile threshold and flag anything above it."**

## Table Reference
**Transactions** — `schemas/05_Transactions.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Calculate mean and standard deviation, then flag 3-sigma outliers
WITH Stats AS (
    SELECT
        Currency,
        AVG(Amount)                          AS MeanAmount,
        STDEV(Amount)                        AS StdDevAmount,
        AVG(Amount) + 3 * STDEV(Amount)     AS Upper3Sigma,
        AVG(Amount) - 3 * STDEV(Amount)     AS Lower3Sigma
    FROM Transactions
    WHERE Amount IS NOT NULL
    GROUP BY Currency
)
SELECT
    t.TransactionID,
    t.Amount,
    t.Currency,
    s.MeanAmount,
    s.StdDevAmount,
    ROUND((t.Amount - s.MeanAmount) / NULLIF(s.StdDevAmount, 0), 2) AS ZScore,
    s.Upper3Sigma,
    CASE
        WHEN ABS((t.Amount - s.MeanAmount) / NULLIF(s.StdDevAmount, 0)) > 3
             THEN 'OUTLIER: |Z| > 3 (more than 3σ from mean)'
        WHEN ABS((t.Amount - s.MeanAmount) / NULLIF(s.StdDevAmount, 0)) > 2
             THEN 'WARNING: |Z| > 2 (more than 2σ from mean)'
        ELSE 'Within normal range'
    END AS OutlierStatus
FROM Transactions t
JOIN Stats s ON t.Currency = s.Currency
WHERE t.Amount IS NOT NULL
  AND ABS((t.Amount - s.MeanAmount) / NULLIF(s.StdDevAmount, 0)) > 2
ORDER BY ABS((t.Amount - s.MeanAmount) / NULLIF(s.StdDevAmount, 0)) DESC;

-- Step 2: IQR-based outlier detection (better for skewed distributions)
WITH Percentiles AS (
    SELECT
        Currency,
        PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY Amount) OVER (PARTITION BY Currency) AS Q1,
        PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY Amount) OVER (PARTITION BY Currency) AS Q3
    FROM Transactions
    WHERE Amount IS NOT NULL
),
IQRStats AS (
    SELECT DISTINCT
        Currency,
        Q1,
        Q3,
        Q3 - Q1 AS IQR,
        Q1 - 1.5 * (Q3 - Q1) AS LowerFence,
        Q3 + 1.5 * (Q3 - Q1) AS UpperFence
    FROM Percentiles
)
SELECT
    t.TransactionID,
    t.Amount,
    t.Currency,
    i.Q1,
    i.Q3,
    i.IQR,
    i.UpperFence,
    CASE
        WHEN t.Amount > i.Q3 + 3 * i.IQR THEN 'Extreme outlier (> Q3 + 3×IQR)'
        WHEN t.Amount > i.UpperFence       THEN 'Mild outlier (> Q3 + 1.5×IQR)'
        WHEN t.Amount < i.LowerFence       THEN 'Low outlier (< Q1 - 1.5×IQR)'
        ELSE 'Within IQR fence'
    END AS IQROutlierStatus
FROM Transactions t
JOIN IQRStats i ON t.Currency = i.Currency
WHERE t.Amount > i.UpperFence OR t.Amount < i.LowerFence;

-- Step 3: 99th percentile threshold
SELECT
    Currency,
    PERCENTILE_CONT(0.99) WITHIN GROUP (ORDER BY Amount) OVER (PARTITION BY Currency) AS P99,
    COUNT(*) OVER (PARTITION BY Currency) AS CurrencyTxCount
FROM Transactions
WHERE Amount IS NOT NULL
GROUP BY Currency, Amount;  -- window function requires this pattern

-- Simpler P99 approach
SELECT
    Currency,
    MAX(Amount) AS MaxAmount,
    AVG(Amount) AS MeanAmount,
    STDEV(Amount) AS StdDev,
    COUNT(*) AS TxCount
FROM Transactions
WHERE Amount IS NOT NULL
GROUP BY Currency;

-- Step 4: Flag today's outliers compared to recent history (rolling context)
WITH RecentStats AS (
    SELECT
        AVG(Amount) AS RecentMean,
        STDEV(Amount) AS RecentStdDev
    FROM Transactions
    WHERE TransactionDate >= DATEADD(DAY, -30, GETDATE())
)
SELECT
    t.TransactionID,
    t.Amount,
    t.TransactionDate,
    r.RecentMean,
    ROUND((t.Amount - r.RecentMean) / NULLIF(r.RecentStdDev, 0), 2) AS ZScoreVsRecent30Days
FROM Transactions t
CROSS JOIN RecentStats r
WHERE t.TransactionDate >= DATEADD(DAY, -7, GETDATE())
  AND ABS((t.Amount - r.RecentMean) / NULLIF(r.RecentStdDev, 0)) > 3
ORDER BY ZScoreVsRecent30Days DESC;
```

## Explanation

**Z-score (standard score)**
`Z = (value - mean) / standard deviation`. A Z-score of 0 = at the mean. Z > 2 = more than 2 standard deviations above average (unusual). Z > 3 = more than 3 standard deviations (very unusual, < 0.3% of normal distribution). `NULLIF(StdDev, 0)` prevents division-by-zero when all values in a group are identical.

**Why 3 sigma is not always the right threshold**
In a normal distribution, ~0.3% of values fall beyond ±3σ. A dataset with 10,000 transactions would have ~30 "outliers" by pure chance. Adjust the threshold based on how many false positives are acceptable. For financial fraud detection, 2σ may be appropriate. For error detection, 4σ may reduce noise.

**IQR vs standard deviation for skewed distributions**
Transaction amounts are typically right-skewed (many small, few large). The mean and standard deviation are pulled up by the large values, making them poor measures of "typical." IQR (Q3 − Q1) is resistant to outliers and provides a more robust outlier fence. Use IQR for skewed financial data, Z-score for approximately normal distributions.

**Rolling comparison (Step 4)**
Comparing today's values to a rolling 30-day baseline detects anomalies in context. A value that would be a Z = 1.5 for all-time data might be Z = 5 for the last 30 days if the business has been operating at lower volumes recently. Context-sensitive outlier detection is more operationally useful.

## Severity
**High** — Statistical outliers in financial data indicate data entry errors, system glitches, or potential fraud. In business reporting, a single outlier can dominate averages and mislead decision-making. The sooner outliers are flagged and investigated, the less damage they cause downstream.
