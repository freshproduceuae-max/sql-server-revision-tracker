# G05-T12 — Range/Boundary | Gap in Date Sequence

## ID
G05-T12

## Group
5 — Range/Boundary

## Type
Gap in Date Sequence — Missing Expected Dates in a Continuous Series

## Live Scenario
A financial platform generates daily closing price records for each security. A nightly batch job failed silently on three non-consecutive nights due to a disk space issue. There are no records for those dates. A volatility calculation that requires 30 consecutive trading days now errors with a "divide by zero" when it hits the missing dates. A risk dashboard that queries the most recent 30 days shows gaps, which an analyst interprets as "the security was not traded" rather than "data is missing" — causing incorrect risk classifications.

## The Question
> When a series of records should be continuous (daily, weekly, monthly), a gap in the sequence means expected records are missing. The gap must be detected by comparing the actual dates present to a generated calendar of expected dates.
> **"Find all dates between the first and last TransactionDate in the Transactions table that have no transaction records — identify gaps in the daily transaction record."**

## Table Reference
**Transactions** — `schemas/05_Transactions.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Generate a calendar of expected dates and LEFT JOIN to find missing ones
WITH DateRange AS (
    -- Generate every date from the first to the last transaction date
    SELECT MIN(TransactionDate) AS StartDate, MAX(TransactionDate) AS EndDate
    FROM Transactions
    WHERE TransactionDate IS NOT NULL
),
Calendar AS (
    -- Recursive CTE generates each date in the range
    SELECT StartDate AS CalDate FROM DateRange
    UNION ALL
    SELECT DATEADD(DAY, 1, CalDate)
    FROM Calendar
    WHERE CalDate < (SELECT EndDate FROM DateRange)
)
SELECT
    c.CalDate AS MissingDate,
    DATENAME(WEEKDAY, c.CalDate) AS DayOfWeek
FROM Calendar c
LEFT JOIN Transactions t ON t.TransactionDate = c.CalDate
WHERE t.TransactionDate IS NULL
ORDER BY c.CalDate
OPTION (MAXRECURSION 1000);

-- Step 2: Find gaps in order sequence by CustomerID (each customer should have no date gaps > 90 days)
WITH OrderedByCustomer AS (
    SELECT
        CustomerID,
        OrderDate,
        LEAD(OrderDate) OVER (PARTITION BY CustomerID ORDER BY OrderDate) AS NextOrderDate
    FROM Orders
)
SELECT
    CustomerID,
    OrderDate AS LastOrderBefore,
    NextOrderDate AS FirstOrderAfter,
    DATEDIFF(DAY, OrderDate, NextOrderDate) AS GapDays
FROM OrderedByCustomer
WHERE DATEDIFF(DAY, OrderDate, NextOrderDate) > 90
ORDER BY GapDays DESC;

-- Step 3: Weekly transaction gap check (each week should have activity)
WITH WeeklyActivity AS (
    SELECT
        DATEPART(YEAR, TransactionDate) AS TxYear,
        DATEPART(WEEK, TransactionDate) AS TxWeek,
        COUNT(*) AS TxCount
    FROM Transactions
    GROUP BY DATEPART(YEAR, TransactionDate), DATEPART(WEEK, TransactionDate)
),
AllWeeks AS (
    -- Generate all weeks between first and last date
    SELECT
        DATEPART(YEAR, MIN(TransactionDate)) AS MinYear,
        DATEPART(WEEK, MIN(TransactionDate)) AS MinWeek,
        DATEPART(YEAR, MAX(TransactionDate)) AS MaxYear,
        DATEPART(WEEK, MAX(TransactionDate)) AS MaxWeek
    FROM Transactions
)
-- The simplest approach: check consecutive weeks
SELECT
    a.TxYear,
    a.TxWeek,
    a.TxCount,
    LEAD(a.TxYear * 100 + a.TxWeek) OVER (ORDER BY a.TxYear, a.TxWeek)
        - (a.TxYear * 100 + a.TxWeek) AS WeekGap
FROM WeeklyActivity a
ORDER BY a.TxYear, a.TxWeek;

-- Step 4: Month-level gap check for sales
SELECT
    YEAR(OrderDate) AS OrderYear,
    MONTH(OrderDate) AS OrderMonth,
    COUNT(*) AS OrderCount,
    SUM(TotalAmount) AS MonthlyRevenue,
    LAG(COUNT(*)) OVER (ORDER BY YEAR(OrderDate), MONTH(OrderDate)) AS PrevMonthCount,
    CASE
        WHEN LAG(COUNT(*)) OVER (ORDER BY YEAR(OrderDate), MONTH(OrderDate)) IS NULL THEN 'First month'
        ELSE 'Month has data'
    END AS MonthStatus
FROM Orders
GROUP BY YEAR(OrderDate), MONTH(OrderDate)
ORDER BY OrderYear, OrderMonth;
```

## Explanation

**Recursive CTE calendar generation**
A recursive CTE starting from `MIN(date)` and adding 1 day per iteration generates every date in the range. The `OPTION (MAXRECURSION n)` parameter must be set high enough for the date range — 365 for one year, 1000 for ~3 years. The LEFT JOIN between the calendar and the data table exposes missing dates as NULLs in the data column.

**Business calendar gaps vs calendar gaps**
Missing a Tuesday is different from missing a weekend (if the business doesn't operate weekends). Step 1's output includes `DATENAME(WEEKDAY, CalDate)` so the analyst can filter out expected non-trading days (weekends, public holidays). A more complete solution joins to a BusinessCalendar table that marks trading days.

**LEAD for consecutive-record gap detection**
`LEAD(date)` within a partition returns the next date for the same entity (customer, product). `DATEDIFF(DAY, current, LEAD(date))` gives the gap in days between consecutive records. A gap > threshold indicates a missing period. This is efficient because it uses a window function rather than a self-join.

**The difference between expected and actual sequences**
Not all series must be daily. Weekly sales reports expect weekly gaps; annual contracts have yearly gaps. The threshold in Step 2 (90 days for customer order gap) is business-defined. Replace with the appropriate interval for the specific series being validated.

## Severity
**High** — Gaps in date sequences corrupt time-series analysis, break continuous calculations (moving averages, streak counters), and mislead analysts into assuming "no data = no activity." In financial data, missing trading days corrupt return calculations and risk models.
