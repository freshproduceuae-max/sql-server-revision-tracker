# G05-T17 — Range/Boundary | SLA Breach Threshold

## ID
G05-T17

## Group
5 — Range/Boundary

## Type
SLA Breach — Response or Fulfilment Time Exceeds Contracted Threshold

## Live Scenario
An e-commerce company promises "standard delivery within 5 working days" and "express delivery within 2 working days." A logistics partner integration creates orders with OrderDate set to the date records are received in the system — which is sometimes the day after the customer placed the order due to a batch process. Orders that take 4 days to ship appear to be on time (4 < 5), but were actually 5 days from the customer's perspective (customer order + 1 day batch lag + 4 days shipping). A customer service audit finds that 12% of "on time" deliveries were actually late from the customer's viewpoint, resulting in a breach of the Trading Standards SLA guarantee.

## The Question
> SLA compliance requires measuring elapsed time against a threshold and flagging any case where the actual time exceeds the contracted limit. The threshold may be calendar days, business days, or hours. SQL can detect breaches in existing data and classify them by severity.
> **"Find all Orders where the gap between OrderDate and DeliveryDate exceeds the SLA threshold (5 days for standard, 2 days for express), and calculate how many days over the SLA each breach is."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: SLA threshold lookup and breach detection
DECLARE @StandardSLADays INT = 5;
DECLARE @ExpressSLADays  INT = 2;

SELECT
    OrderID,
    CustomerID,
    OrderDate,
    DeliveryDate,
    Status,
    DATEDIFF(DAY, OrderDate, DeliveryDate) AS ActualDays,
    CASE
        WHEN Status = 'Express' THEN @ExpressSLADays
        ELSE @StandardSLADays
    END AS SLAThreshold,
    DATEDIFF(DAY, OrderDate, DeliveryDate) -
        CASE WHEN Status = 'Express' THEN @ExpressSLADays ELSE @StandardSLADays END
        AS DaysOverSLA,
    CASE
        WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) >
             CASE WHEN Status = 'Express' THEN @ExpressSLADays ELSE @StandardSLADays END
             THEN 'SLA BREACH'
        ELSE 'Within SLA'
    END AS SLAStatus
FROM Orders
WHERE DeliveryDate IS NOT NULL
  AND Status IN ('Delivered', 'Shipped')
ORDER BY DaysOverSLA DESC;

-- Step 2: Classify breach severity
SELECT
    OrderID,
    CustomerID,
    DATEDIFF(DAY, OrderDate, DeliveryDate) AS ActualDays,
    CASE
        WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) > @StandardSLADays + 5 THEN 'CRITICAL: >10 days'
        WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) > @StandardSLADays + 2 THEN 'HIGH: 8–10 days'
        WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) > @StandardSLADays     THEN 'WARNING: 6–7 days'
        ELSE 'Within SLA'
    END AS BreachSeverity
FROM Orders
WHERE DeliveryDate IS NOT NULL
  AND DATEDIFF(DAY, OrderDate, DeliveryDate) > @StandardSLADays
ORDER BY ActualDays DESC;

-- Step 3: SLA compliance summary by month
SELECT
    YEAR(OrderDate)  AS OrderYear,
    MONTH(OrderDate) AS OrderMonth,
    COUNT(*) AS TotalDelivered,
    SUM(CASE WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) <= @StandardSLADays THEN 1 ELSE 0 END) AS WithinSLA,
    SUM(CASE WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) >  @StandardSLADays THEN 1 ELSE 0 END) AS BreachedSLA,
    ROUND(
        100.0 * SUM(CASE WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) <= @StandardSLADays THEN 1 ELSE 0 END)
        / NULLIF(COUNT(*), 0), 1
    ) AS CompliancePct
FROM Orders
WHERE DeliveryDate IS NOT NULL
  AND Status IN ('Delivered', 'Shipped')
GROUP BY YEAR(OrderDate), MONTH(OrderDate)
ORDER BY OrderYear, OrderMonth;

-- Step 4: Orders still undelivered past SLA (open breaches)
SELECT
    OrderID,
    CustomerID,
    OrderDate,
    DATEDIFF(DAY, OrderDate, GETDATE()) AS DaysSinceOrder,
    DATEDIFF(DAY, OrderDate, GETDATE()) - @StandardSLADays AS DaysOverdue,
    'Open SLA breach — not yet delivered' AS Issue
FROM Orders
WHERE Status IN ('Pending', 'Processing', 'Shipped')
  AND DeliveryDate IS NULL
  AND DATEDIFF(DAY, OrderDate, GETDATE()) > @StandardSLADays
ORDER BY DaysOverdue DESC;

-- Step 5: Expected delivery date calculation and breach forecast
SELECT
    OrderID,
    OrderDate,
    DATEADD(DAY, @StandardSLADays, OrderDate) AS ExpectedDeliveryDate,
    DeliveryDate AS ActualDeliveryDate,
    DATEDIFF(DAY, DATEADD(DAY, @StandardSLADays, OrderDate), DeliveryDate) AS DaysLate
FROM Orders
WHERE DeliveryDate IS NOT NULL
  AND DATEDIFF(DAY, DATEADD(DAY, @StandardSLADays, OrderDate), DeliveryDate) > 0
ORDER BY DaysLate DESC;
```

| 1008 | 2024-02-20 | 2024-02-28 | 8 | 5 | 3 | SLA BREACH |

| 2024 | 2 | 7 | 6 | 1 | 85.7 |

## Explanation

**DATEDIFF for elapsed time**
`DATEDIFF(DAY, OrderDate, DeliveryDate)` returns the number of calendar days between the two dates. For SLAs measured in hours, use `DATEDIFF(HOUR, ...)`. For business days, a calendar table or scalar function is needed — DATEDIFF counts all 7 days of the week.

**Open vs closed breaches**
Step 4 detects orders that are already in breach and still open (no DeliveryDate set). These are real-time operational alerts; the historical closed breaches in Steps 1–3 are for post-hoc compliance reporting. Both types are needed for full SLA management.

**Breach classification by severity**
Not all breaches are equal. A 1-day breach may be tolerable; a 14-day breach is a formal SLA failure with contractual consequences. Classifying breaches by severity (Days Over SLA) lets operations teams prioritise escalations.

**`DATEADD` for expected date**
`DATEADD(DAY, @StandardSLADays, OrderDate)` computes the deadline date. Comparing this to `DeliveryDate` gives a clean positive (late) or negative (early) difference, making Step 5's `DaysLate` column intuitive.

## Severity
**High** — SLA breaches have direct contractual, financial, and reputational consequences. In B2B supply chain contracts, SLA breaches trigger penalty payments. In consumer-facing operations, repeated breaches damage NPS scores and trigger regulatory scrutiny under consumer protection legislation.
