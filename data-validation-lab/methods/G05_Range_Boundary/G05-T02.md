# G05-T02 — Range/Boundary | Value Above Maximum

## ID
G05-T02

## Group
5 — Range/Boundary

## Type
Value Above Maximum — Numeric Value Exceeds Permitted Upper Bound

## Live Scenario
A medical device platform records patient blood oxygen saturation (SpO2) readings from pulse oximeters. SpO2 is a percentage: valid values are 70–100% for meaningful clinical readings (below 70% the sensor loses accuracy; above 100% is physically impossible). A firmware bug in a batch of devices sends `999` as a sentinel value for "sensor not connected." This overflows the plausibility range. A clinical dashboard shows several patients with SpO2 = 999%, triggering false-positive alerts and nursing staff spending 45 minutes chasing phantom critical values before the root cause is found.

## The Question
> Values above a defined maximum are as problematic as values below a minimum. The maximum may be a physical limit (100% for a percentage), a business rule limit (maximum order quantity), or a system constraint.
> **"Find all Orders where TotalAmount exceeds £50,000 (the maximum single-order limit for this business), and all Products where StockQuantity exceeds 10,000 (suspicious overstock that may indicate a data entry error)."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`
**SalesTargets** — `schemas/06_SalesTargets.csv`

## Solution Query

```sql
-- Step 1: Find orders above the maximum single-order value
DECLARE @MaxOrderValue DECIMAL(18,2) = 50000.00;

SELECT
    OrderID,
    CustomerID,
    OrderDate,
    TotalAmount,
    TotalAmount - @MaxOrderValue AS Overage,
    ROUND((TotalAmount - @MaxOrderValue) / @MaxOrderValue * 100, 1) AS OveragePct,
    'TotalAmount exceeds £50,000 limit' AS Issue
FROM Orders
WHERE TotalAmount > @MaxOrderValue
ORDER BY TotalAmount DESC;

-- Step 2: Products with suspiciously high stock levels
SELECT
    ProductID,
    ProductName,
    StockQuantity,
    CASE
        WHEN StockQuantity > 10000  THEN 'Above 10,000 — possible data entry error (extra zero?)'
        WHEN StockQuantity > 5000   THEN 'Above 5,000 — flag for stock review'
        ELSE 'Within normal range'
    END AS StockCheck
FROM Products
WHERE StockQuantity > 5000
ORDER BY StockQuantity DESC;

-- Step 3: SalesTargets above absolute maximum (sanity check)
SELECT
    TargetID,
    SalespersonID,
    Year,
    Quarter,
    TargetAmount,
    'TargetAmount exceeds annual revenue — implausible' AS Issue
FROM SalesTargets
WHERE TargetAmount > 10000000  -- £10M per quarter is implausible for this business
ORDER BY TargetAmount DESC;

-- Step 4: Multi-column above-maximum health check
SELECT 'Orders > £50k'           AS Check, COUNT(*) AS ViolationCount, MAX(TotalAmount) AS MaxObserved
FROM Orders WHERE TotalAmount > 50000
UNION ALL
SELECT 'Products stock > 10,000', COUNT(*), MAX(StockQuantity)
FROM Products WHERE StockQuantity > 10000
UNION ALL
SELECT 'SalesTargets > £10M',     COUNT(*), MAX(TargetAmount)
FROM SalesTargets WHERE TargetAmount > 10000000;

-- Step 5: Distribution above vs at maximum vs below for Orders
SELECT
    CASE
        WHEN TotalAmount > 50000    THEN 'Above maximum (> £50k)'
        WHEN TotalAmount = 50000    THEN 'At maximum (= £50k)'
        WHEN TotalAmount > 10000    THEN 'High (£10k–£50k)'
        WHEN TotalAmount > 1000     THEN 'Medium (£1k–£10k)'
        ELSE 'Normal (≤ £1k)'
    END AS AmountBand,
    COUNT(*) AS OrderCount,
    SUM(TotalAmount) AS TotalValue
FROM Orders
WHERE TotalAmount IS NOT NULL
GROUP BY
    CASE
        WHEN TotalAmount > 50000    THEN 'Above maximum (> £50k)'
        WHEN TotalAmount = 50000    THEN 'At maximum (= £50k)'
        WHEN TotalAmount > 10000    THEN 'High (£10k–£50k)'
        WHEN TotalAmount > 1000     THEN 'Medium (£1k–£10k)'
        ELSE 'Normal (≤ £1k)'
    END
ORDER BY MIN(TotalAmount) DESC;
```

## Explanation

**`> maximum` as the exact boundary condition**
Above-maximum uses strict greater-than (`>`). A value exactly equal to the maximum is compliant. This matches business rule language like "the maximum order value is £50,000" — meaning £50,000 is permitted, £50,001 is not.

**Overage calculation for severity triage**
`TotalAmount - @MaxOrderValue` shows by how much each violating record exceeds the limit. A small overage (£0.01 above limit) may be a rounding issue; a large overage (£25,000 above limit) is a substantive data quality or fraud risk. Sort by overage to prioritise remediation.

**Implausibility vs business rule violation**
Some maximum thresholds are physical/logical limits (SpO2 > 100% is impossible). Others are business rules (order > £50k is flagged for manual approval). The distinction matters for remediation: physically impossible values should be nulled or rejected; business rule violations may require manual approval workflow.

**Distribution banding (Step 5)**
Rather than just listing violations, banding the full distribution shows the shape of the data. If 80% of orders are in the "Normal" band with one outlier in "Above maximum," it's likely a data entry error. If 20% are in "Above maximum," the limit may need to be reviewed.

## Severity
**High** — Values above maximum indicate data entry errors (extra zero), system malfunctions (sentinel values), or unauthorised activity (orders above approval threshold processed without sign-off). In clinical systems, physically impossible values (SpO2 > 100%) are Critical — they corrupt clinical decision support.
