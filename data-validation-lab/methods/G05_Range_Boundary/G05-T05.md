# G05-T05 — Range/Boundary | Age / Derived Value Out of Range

## ID
G05-T05

## Group
5 — Range/Boundary

## Type
Age / Derived Value Out of Range — Calculated Result Exceeds Plausible Bounds

## Live Scenario
A credit scoring system calculates customer age from `DateOfBirth` to determine credit product eligibility. The minimum age for a credit card is 18; the system should not have approved anyone below 18. A review finds 11 customers with calculated ages between 14 and 17 who were approved — their DOBs were entered in DD/MM format swapped (a 16-year-old born 15/03 had 03/15 entered, which the US-format system interpreted as 15th March, making them appear 18). The approvals went through because the age check ran on the stored (incorrect) DOB.

## The Question
> Derived values — values calculated from stored data — can fall outside valid ranges even when the underlying fields pass their own validation. Age calculated from DateOfBirth, duration calculated from start/end dates, and totals calculated from line items all require their own range checks.
> **"Calculate customer age from DateOfBirth and find all Customers who are under 18 (ineligible for credit products), over 120 (implausible, likely a bad date), or where age cannot be calculated (NULL DateOfBirth)."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Age calculation and range check
SELECT
    CustomerID,
    FirstName,
    LastName,
    DateOfBirth,
    -- Accurate age calculation (adjusts for whether birthday has passed this year)
    DATEDIFF(YEAR, DateOfBirth, GETDATE())
    - CASE WHEN DATEADD(YEAR, DATEDIFF(YEAR, DateOfBirth, GETDATE()), DateOfBirth) > GETDATE()
           THEN 1 ELSE 0 END                    AS CalculatedAge,
    CASE
        WHEN DateOfBirth IS NULL                THEN 'NULL DOB — cannot calculate age'
        WHEN DateOfBirth > CAST(GETDATE() AS DATE) THEN 'Future DOB — impossible'
        WHEN DATEDIFF(YEAR, DateOfBirth, GETDATE()) > 120
             THEN 'Age > 120 — implausible (DOB error)'
        WHEN DATEDIFF(YEAR, DateOfBirth, GETDATE())
             - CASE WHEN DATEADD(YEAR, DATEDIFF(YEAR, DateOfBirth, GETDATE()), DateOfBirth) > GETDATE()
                    THEN 1 ELSE 0 END < 18
             THEN 'Age < 18 — ineligible for credit products'
        ELSE 'Age within valid range (18-120)'
    END AS AgeCheck
FROM Customers
WHERE DateOfBirth IS NULL
   OR DateOfBirth > CAST(GETDATE() AS DATE)
   OR DATEDIFF(YEAR, DateOfBirth, GETDATE()) > 120
   OR (DATEDIFF(YEAR, DateOfBirth, GETDATE())
       - CASE WHEN DATEADD(YEAR, DATEDIFF(YEAR, DateOfBirth, GETDATE()), DateOfBirth) > GETDATE()
              THEN 1 ELSE 0 END) < 18;

-- Step 2: Order duration check (days between OrderDate and DeliveryDate)
SELECT
    OrderID,
    OrderDate,
    DeliveryDate,
    DATEDIFF(DAY, OrderDate, DeliveryDate) AS DeliveryDays,
    CASE
        WHEN DeliveryDate IS NULL               THEN 'DeliveryDate NULL'
        WHEN DeliveryDate < OrderDate           THEN 'Delivery before order — impossible'
        WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) > 365 THEN 'Delivery > 1 year — implausible'
        WHEN DATEDIFF(DAY, OrderDate, DeliveryDate) = 0   THEN 'Same-day delivery'
        ELSE 'Delivery duration within range'
    END AS DurationCheck
FROM Orders
WHERE DeliveryDate IS NOT NULL;

-- Step 3: Tenure calculation for employees
SELECT
    EmployeeID,
    FullName,
    HireDate,
    DATEDIFF(YEAR, HireDate, GETDATE()) AS TenureYears,
    CASE
        WHEN HireDate IS NULL                             THEN 'HireDate NULL'
        WHEN HireDate > CAST(GETDATE() AS DATE)           THEN 'Future hire date'
        WHEN DATEDIFF(YEAR, HireDate, GETDATE()) > 50    THEN 'Tenure > 50 years — verify DOH'
        WHEN HireDate < '1990-01-01'                     THEN 'Hired before 1990 — pre-dates company?'
        ELSE 'Tenure within range'
    END AS TenureCheck
FROM Employees
WHERE HireDate IS NULL
   OR HireDate > CAST(GETDATE() AS DATE)
   OR DATEDIFF(YEAR, HireDate, GETDATE()) > 50;

-- Step 4: Order item total vs header total derived check
-- (OrderTotal should equal sum of line items)
SELECT
    o.OrderID,
    o.TotalAmount AS HeaderTotal,
    SUM(oi.UnitPrice * oi.Quantity) AS CalculatedTotal,
    ABS(o.TotalAmount - SUM(oi.UnitPrice * oi.Quantity)) AS Discrepancy
FROM Orders o
JOIN OrderItems oi ON o.OrderID = oi.OrderID
GROUP BY o.OrderID, o.TotalAmount
HAVING ABS(o.TotalAmount - SUM(oi.UnitPrice * oi.Quantity)) > 0.01;
```

## Expected Output

|---|---|---|---|---|
| 5 | Jamie | 2010-03-15 | 16 | Age < 18 — ineligible for credit products |
| 9 | Robert | 1899-06-20 | 127 | Age > 120 — implausible (DOB error) |

**Step 2 — Order duration:**
| OrderID | OrderDate | DeliveryDate | DeliveryDays | DurationCheck |
|---|---|---|---|---|
| 1004 | 2024-02-01 | 2024-01-28 | -4 | Delivery before order — impossible |

## Explanation

**Accurate age calculation in SQL**
`DATEDIFF(YEAR, dob, GETDATE())` gives years but does not account for whether the birthday has passed this year. The adjustment `- CASE WHEN DATEADD(YEAR, years, dob) > GETDATE() THEN 1 ELSE 0 END` subtracts 1 year if the birthday hasn't happened yet. This gives the correct integer age in all cases.

**Derived values require their own validation**
Each component field may be valid individually — a DateOfBirth of `2010-03-15` is a real date in a valid range — but the derived value (age = 16) violates the business rule (must be ≥ 18). Field-level validation alone is insufficient; derived constraints must be checked explicitly.

**Negative duration as an impossible value**
`DATEDIFF(DAY, OrderDate, DeliveryDate) < 0` means delivery before the order was placed — a physical impossibility. This indicates either OrderDate or DeliveryDate was entered incorrectly, or the two values belong to different orders.

**Step 4: header vs line-item total**
A totals mismatch between the order header and the sum of line items is a derived value discrepancy. The header TotalAmount was calculated at a point in time; the line items may have been edited since. This is both a range check (the derived total should be ≥ 0 and match) and a consistency check.

## Severity
**High** — Age miscalculations lead to regulatory violations (under-18 credit approvals, age-restricted sales). Duration miscalculations break SLA reporting. A negative delivery duration indicates a data integrity error that corrupts all time-based analytics for the affected orders.
