# G05-T06 — Range/Boundary | Percentage / Rate Out of Range

## ID
G05-T06

## Group
5 — Range/Boundary

## Type
Percentage / Rate Out of Range — Value Outside 0–100 (or Domain-Specific Range)

## Live Scenario
A tax management system stores VAT rates in a `VATRate` column. Standard UK VAT is 20%, reduced rate is 5%, and zero-rated is 0%. A data entry error stores `200` (instead of `20`) for one product category. A different integration stores rates as decimals (`0.20`) while the column expects whole numbers (`20`). A third source stores negative rates for VAT reclaim entries (`-20`). The billing engine multiplies order totals by `VATRate / 100` — a rate of 200 produces invoices at triple the intended amount. Six invoices go out before the error is caught.

## The Question
> Percentages must fall within 0–100 (or occasionally beyond, for things like interest rates that can exceed 100%). Rates stored in different conventions (0.20 vs 20 for 20%) must be detected. Negative rates require explicit business justification.
> **"Find all SalesTargets where CommissionRate is outside the permitted range (0%–30%), and all Products where DiscountPercent is negative, zero when it should be positive, or greater than 100%."**

## Table Reference
**SalesTargets** — `schemas/06_SalesTargets.csv`
**Products** — `schemas/03_Products.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Commission rate range check (must be between 0% and 30%)
SELECT
    TargetID,
    SalespersonID,
    CommissionRate,
    CASE
        WHEN CommissionRate IS NULL             THEN 'NULL'
        WHEN CommissionRate < 0                 THEN 'Negative — not permitted'
        WHEN CommissionRate > 30                THEN 'Above 30% maximum'
        WHEN CommissionRate > 1 AND CommissionRate <= 30
                                                THEN 'Whole number percent — valid'
        WHEN CommissionRate > 0 AND CommissionRate <= 1
                                                THEN 'Decimal fraction — may be 0.25 instead of 25%?'
        WHEN CommissionRate = 0                 THEN 'Zero rate — intentional?'
        ELSE 'Valid'
    END AS RateCheck
FROM SalesTargets
WHERE CommissionRate IS NULL
   OR CommissionRate < 0
   OR CommissionRate > 30
   OR (CommissionRate > 0 AND CommissionRate < 1);

-- Step 2: Discount percent range check
SELECT
    ProductID,
    ProductName,
    DiscountPercent,
    CASE
        WHEN DiscountPercent IS NULL            THEN 'NULL — no discount'
        WHEN DiscountPercent < 0               THEN 'Negative discount — invalid'
        WHEN DiscountPercent > 100             THEN 'Discount > 100% — invalid (would pay customer)'
        WHEN DiscountPercent > 50              THEN 'Discount > 50% — flag for approval'
        WHEN DiscountPercent > 0 AND DiscountPercent < 1
                                                THEN 'Decimal fraction — is this 0.5% or 0.5 (50%)?'
        ELSE 'Valid discount range'
    END AS DiscountCheck
FROM Products
WHERE DiscountPercent IS NOT NULL
  AND (DiscountPercent < 0 OR DiscountPercent > 100
    OR (DiscountPercent > 0 AND DiscountPercent < 1));

-- Step 3: Detect decimal-vs-whole-number convention mismatch
-- If most values are between 1-30 but some are between 0-1, the latter are likely decimals
SELECT
    'CommissionRate' AS ColumnName,
    SUM(CASE WHEN CommissionRate BETWEEN 0 AND 1 THEN 1 ELSE 0 END) AS PossibleDecimalFormat,
    SUM(CASE WHEN CommissionRate BETWEEN 1 AND 100 THEN 1 ELSE 0 END) AS WholeNumberFormat,
    AVG(CommissionRate) AS AverageRate,
    MIN(CommissionRate) AS MinRate,
    MAX(CommissionRate) AS MaxRate
FROM SalesTargets
WHERE CommissionRate IS NOT NULL;

-- Step 4: VAT/tax rate plausibility check
-- UK VAT rates: 0, 5, 20
SELECT
    ProductID,
    ProductName,
    VATRate,
    CASE
        WHEN VATRate IS NULL                    THEN 'NULL — default rate applies?'
        WHEN VATRate NOT IN (0, 5, 20)         THEN 'Non-standard UK VAT rate: ' + CAST(VATRate AS VARCHAR)
        WHEN VATRate > 100                      THEN 'Rate > 100% — data entry error (200 instead of 20?)'
        WHEN VATRate BETWEEN 0 AND 1            THEN 'Decimal fraction — may be 0.20 instead of 20%'
        ELSE 'Valid UK VAT rate'
    END AS VATCheck
FROM Products
WHERE VATRate IS NOT NULL;

-- Step 5: Cross-column rate consistency (commission × target should be plausible)
SELECT
    st.TargetID,
    st.SalespersonID,
    st.TargetAmount,
    st.CommissionRate,
    st.TargetAmount * st.CommissionRate / 100 AS MaxCommissionEarnable,
    CASE
        WHEN st.TargetAmount * st.CommissionRate / 100 > 200000
             THEN 'Commission potential > £200k — verify rates'
        ELSE 'Commission potential plausible'
    END AS CommissionPlausibility
FROM SalesTargets st
WHERE CommissionRate > 0 AND TargetAmount > 0;
```

## Explanation

**Percentage vs decimal fraction**
A 20% commission can be stored as `20` (whole number percent) or `0.20` (decimal fraction). Most financial systems use whole number percents in storage. A value of `0.25` in a column where others range from `10` to `25` is likely `0.25%` (a decimal) rather than `25%`. Step 3 profiles the distribution to detect this convention mismatch.

**`NOT IN (0, 5, 20)` for UK VAT rates**
UK VAT has exactly three valid rates: 0% (zero-rated), 5% (reduced), 20% (standard). Any other value is wrong. This type of enumerated-values range check is more precise than a `BETWEEN` and catches non-zero non-standard rates like 7.5 or 15.

**The `> 100` case**
A discount or tax rate above 100% cannot exist in reality. This pattern typically indicates a data entry error where a percentage was entered as a basis points value (200 instead of 20) or as a permille value (200‰ instead of 20%).

**Derived plausibility check (Step 5)**
A commission rate of 30% on a target of £800,000 gives a maximum commission of £240,000 — which may or may not be plausible. Combining rate and target into a derived commission calculation surfaces implausible combinations even when each value individually is within its valid range.

## Severity
**High** — Invalid percentage rates cause incorrect financial calculations. A wrong VAT rate affects invoice totals, tax filings, and accounts payable. An incorrect commission rate overpays or underpays salespeople. Rates stored as decimal fractions when whole numbers are expected produce calculations that are 100× too small.
