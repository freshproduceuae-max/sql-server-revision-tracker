# G05-T13 — Range/Boundary | Threshold Breach (Business KPI)

## ID
G05-T13

## Group
5 — Range/Boundary

## Type
Threshold Breach — KPI or Business Metric Outside Acceptable Band

## Live Scenario
A retail chain monitors store performance KPIs. The contract with each store manager sets expected performance bands: conversion rate 2–8%, average basket size £15–£80, customer satisfaction score 3.5–5.0 (out of 5). A dashboard shows three stores below the minimum conversion rate and one store with a basket size of £142 — which turns out to be a single high-value corporate purchase that inflated the average. Data quality issues (duplicated transactions, incorrect discounts) are making some KPIs look artificially better or worse than reality.

## The Question
> Business KPIs have acceptable performance bands. Values outside the band may be data quality issues (inflated by duplicates, deflated by missing records) or genuine performance problems. SQL can flag KPI breaches and classify them by severity relative to the threshold.
> **"Find all Salesperson/Quarter combinations in SalesTargets where actual performance (TargetAmount) is more than 20% below the average for that quarter, and flag those more than 50% below as critical."**

## Table Reference
**SalesTargets** — `schemas/06_SalesTargets.csv`
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Step 1: Individual target vs quarterly average
WITH QuarterlyAverages AS (
    SELECT
        Year,
        Quarter,
        AVG(TargetAmount) AS AvgTarget,
        MIN(TargetAmount) AS MinTarget,
        MAX(TargetAmount) AS MaxTarget,
        STDEV(TargetAmount) AS StdDevTarget
    FROM SalesTargets
    GROUP BY Year, Quarter
)
SELECT
    st.TargetID,
    st.SalespersonID,
    st.Year,
    st.Quarter,
    st.TargetAmount,
    qa.AvgTarget,
    ROUND((st.TargetAmount - qa.AvgTarget) / NULLIF(qa.AvgTarget, 0) * 100, 1) AS PctVsAverage,
    CASE
        WHEN st.TargetAmount < qa.AvgTarget * 0.50  THEN 'CRITICAL: > 50% below quarterly average'
        WHEN st.TargetAmount < qa.AvgTarget * 0.80  THEN 'WARNING: > 20% below quarterly average'
        WHEN st.TargetAmount > qa.AvgTarget * 1.50  THEN 'HIGH: > 50% above quarterly average'
        ELSE 'Within acceptable band (±20% of average)'
    END AS KPIStatus
FROM SalesTargets st
JOIN QuarterlyAverages qa ON st.Year = qa.Year AND st.Quarter = qa.Quarter
WHERE st.TargetAmount < qa.AvgTarget * 0.80
   OR st.TargetAmount > qa.AvgTarget * 1.50
ORDER BY PctVsAverage;

-- Step 2: Store-level KPI band check (using Orders as proxy for store performance)
WITH StoreSummary AS (
    SELECT
        CustomerID AS StoreID,
        AVG(TotalAmount) AS AvgOrderValue,
        COUNT(*) AS OrderCount
    FROM Orders
    GROUP BY CustomerID
)
SELECT
    StoreID,
    AvgOrderValue,
    OrderCount,
    CASE
        WHEN AvgOrderValue < 15      THEN 'Basket size below minimum (£15) — data quality check needed'
        WHEN AvgOrderValue > 80      THEN 'Basket size above maximum (£80) — outliers pulling up average?'
        WHEN OrderCount < 3          THEN 'Low order count — not enough data for reliable KPI'
        ELSE 'KPI within band'
    END AS BasketKPI
FROM StoreSummary
WHERE AvgOrderValue < 15 OR AvgOrderValue > 80 OR OrderCount < 3;

-- Step 3: Trend-based threshold (current period vs previous period threshold)
WITH PeriodComparison AS (
    SELECT
        SalespersonID,
        Year,
        Quarter,
        TargetAmount,
        LAG(TargetAmount) OVER (PARTITION BY SalespersonID ORDER BY Year, Quarter) AS PrevQuarterTarget
    FROM SalesTargets
)
SELECT
    SalespersonID,
    Year,
    Quarter,
    TargetAmount AS CurrentTarget,
    PrevQuarterTarget,
    ROUND((TargetAmount - PrevQuarterTarget) / NULLIF(PrevQuarterTarget, 0) * 100, 1) AS QoQChange,
    CASE
        WHEN PrevQuarterTarget IS NULL                 THEN 'First period — no comparison'
        WHEN TargetAmount < PrevQuarterTarget * 0.70   THEN 'ALERT: >30% drop vs previous quarter'
        WHEN TargetAmount > PrevQuarterTarget * 1.50   THEN 'FLAG: >50% jump vs previous quarter — verify data'
        ELSE 'QoQ change within normal range'
    END AS QoQStatus
FROM PeriodComparison
WHERE PrevQuarterTarget IS NOT NULL
  AND (TargetAmount < PrevQuarterTarget * 0.70 OR TargetAmount > PrevQuarterTarget * 1.50)
ORDER BY ABS(TargetAmount - PrevQuarterTarget) DESC;

-- Step 4: Dashboard summary of KPI breaches
SELECT
    Year,
    Quarter,
    COUNT(*) AS TotalSalespeople,
    SUM(CASE WHEN TargetAmount < AVG(TargetAmount) OVER (PARTITION BY Year, Quarter) * 0.50
             THEN 1 ELSE 0 END) AS CriticalBelowAvg,
    SUM(CASE WHEN TargetAmount < AVG(TargetAmount) OVER (PARTITION BY Year, Quarter) * 0.80
             THEN 1 ELSE 0 END) AS BelowAvgThreshold,
    MIN(TargetAmount) AS MinTarget,
    MAX(TargetAmount) AS MaxTarget,
    AVG(TargetAmount) AS AvgTarget
FROM SalesTargets
GROUP BY Year, Quarter
ORDER BY Year, Quarter;
```

## Explanation

**Relative thresholds vs absolute thresholds**
Step 1 uses a relative threshold (% of quarterly average) because the absolute target value varies by quarter and salesperson. An absolute threshold (e.g., "flag if target < £50,000") would be incorrect for quarters where average targets are £200,000. Relative thresholds are more appropriate for cross-entity comparisons.

**Window function `AVG() OVER (PARTITION BY)`**
Computing the group average inline as a window function avoids a separate CTE for simple cases. `AVG(TargetAmount) OVER (PARTITION BY Year, Quarter)` calculates the quarterly average for each row without collapsing the rowset, enabling direct comparison in the same SELECT.

**QoQ (quarter-over-quarter) change as a trend breach**
Step 3 compares each period to the previous period using LAG. A >30% drop in a salesperson's target between quarters is either a business change (territory restructure) or a data error (target not set, wrong amount). This type of trend-based threshold catches issues that absolute or average-based thresholds miss.

**Data quality as the root cause of KPI breaches**
KPI breaches have two causes: genuine performance issues and data quality issues. A store showing 150% of average basket size may have duplicate transaction records inflating the average. Data quality validation should always run before KPI reporting to ensure the KPI reflects reality.

## Severity
**Medium** — KPI threshold breaches may indicate data quality issues or genuine performance problems. The severity depends on how the KPI is used: a data quality issue in a dashboard metric is Medium; the same issue in a regulatory capital ratio calculation is Critical.
