# G05-T21 — Range/Boundary | Population Distribution Threshold

## ID
G05-T21

## Group
5 — Range/Boundary

## Type
Population Distribution Threshold — Aggregate Metric Outside Expected Band

## Live Scenario
A bank monitors its loan portfolio monthly. Historical data shows the average loan default rate across all branches is 2.1% with a standard deviation of 0.4%. A new regional manager's branch shows a default rate of 6.8% for three consecutive months — more than eleven standard deviations above the mean. The anomaly is not flagged by existing reporting because the threshold is hardcoded as "> 5%" in an Excel dashboard that no one has updated in four years. The branch is eventually flagged by an external regulator. Internal review shows the correct threshold (mean + 3σ) would have triggered an alert three months earlier, preventing £1.4M in additional losses.

## The Question
> Population-level metrics — averages, rates, percentages — can be monitored against a dynamic threshold derived from the distribution itself (mean ± N standard deviations). This catches anomalies that hardcoded thresholds miss as the population evolves over time.
> **"For each salesperson's TargetAmount, flag those whose target is more than 2 standard deviations from the group mean, and show the z-score for each target to identify outliers in the target-setting process."**

## Table Reference
**SalesTargets** — `schemas/06_SalesTargets.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Z-score for each SalesTarget within its Year-Quarter group
WITH GroupStats AS (
    SELECT
        Year,
        Quarter,
        AVG(TargetAmount)  AS MeanTarget,
        STDEV(TargetAmount) AS StdDevTarget,
        COUNT(*) AS N
    FROM SalesTargets
    WHERE TargetAmount IS NOT NULL
    GROUP BY Year, Quarter
)
SELECT
    st.TargetID,
    st.SalespersonID,
    st.Year,
    st.Quarter,
    st.TargetAmount,
    gs.MeanTarget,
    gs.StdDevTarget,
    ROUND(
        (st.TargetAmount - gs.MeanTarget) / NULLIF(gs.StdDevTarget, 0),
        2
    ) AS ZScore,
    CASE
        WHEN ABS((st.TargetAmount - gs.MeanTarget) / NULLIF(gs.StdDevTarget, 0)) > 3
             THEN 'EXTREME OUTLIER (|Z| > 3)'
        WHEN ABS((st.TargetAmount - gs.MeanTarget) / NULLIF(gs.StdDevTarget, 0)) > 2
             THEN 'OUTLIER (|Z| > 2)'
        WHEN ABS((st.TargetAmount - gs.MeanTarget) / NULLIF(gs.StdDevTarget, 0)) > 1
             THEN 'Mild deviation (|Z| > 1)'
        ELSE 'Within 1σ of mean'
    END AS OutlierFlag
FROM SalesTargets st
JOIN GroupStats gs ON st.Year = gs.Year AND st.Quarter = gs.Quarter
ORDER BY ABS((st.TargetAmount - gs.MeanTarget) / NULLIF(gs.StdDevTarget, 0)) DESC;

-- Step 2: Transaction amount distribution check
WITH TxStats AS (
    SELECT
        Currency,
        AVG(Amount)  AS MeanAmount,
        STDEV(Amount) AS StdDevAmount,
        COUNT(*) AS N
    FROM Transactions
    WHERE Amount IS NOT NULL
    GROUP BY Currency
)
SELECT
    t.TransactionID,
    t.Amount,
    t.Currency,
    ts.MeanAmount,
    ts.StdDevAmount,
    ROUND((t.Amount - ts.MeanAmount) / NULLIF(ts.StdDevAmount, 0), 2) AS ZScore,
    CASE
        WHEN (t.Amount - ts.MeanAmount) / NULLIF(ts.StdDevAmount, 0) > 3
             THEN 'HIGH OUTLIER'
        WHEN (t.Amount - ts.MeanAmount) / NULLIF(ts.StdDevAmount, 0) < -3
             THEN 'LOW OUTLIER'
        ELSE 'Normal'
    END AS DistributionFlag
FROM Transactions t
JOIN TxStats ts ON t.Currency = ts.Currency
WHERE ABS((t.Amount - ts.MeanAmount) / NULLIF(ts.StdDevAmount, 0)) > 2
ORDER BY ABS((t.Amount - ts.MeanAmount) / NULLIF(ts.StdDevAmount, 0)) DESC;

-- Step 3: Rolling mean and control limits (UCL/LCL — Statistical Process Control)
-- Upper Control Limit = Mean + 3σ, Lower Control Limit = Mean - 3σ
WITH MonthlyStats AS (
    SELECT
        YEAR(TransactionDate) AS TxYear,
        MONTH(TransactionDate) AS TxMonth,
        AVG(Amount) AS MonthlyAvg,
        COUNT(*) AS TxCount
    FROM Transactions
    WHERE TransactionDate IS NOT NULL AND Amount IS NOT NULL
    GROUP BY YEAR(TransactionDate), MONTH(TransactionDate)
),
OverallStats AS (
    SELECT
        AVG(MonthlyAvg) AS GrandMean,
        STDEV(MonthlyAvg) AS StdDevOfMonthlyAvg
    FROM MonthlyStats
)
SELECT
    ms.TxYear,
    ms.TxMonth,
    ms.MonthlyAvg,
    ms.TxCount,
    os.GrandMean,
    os.GrandMean + 3 * os.StdDevOfMonthlyAvg AS UCL,
    os.GrandMean - 3 * os.StdDevOfMonthlyAvg AS LCL,
    CASE
        WHEN ms.MonthlyAvg > os.GrandMean + 3 * os.StdDevOfMonthlyAvg THEN 'Above UCL — investigate'
        WHEN ms.MonthlyAvg < os.GrandMean - 3 * os.StdDevOfMonthlyAvg THEN 'Below LCL — investigate'
        ELSE 'In control'
    END AS SPCStatus
FROM MonthlyStats ms
CROSS JOIN OverallStats os
ORDER BY ms.TxYear, ms.TxMonth;

-- Step 4: Percentile-based distribution boundaries (non-parametric)
SELECT
    SalespersonID,
    TargetAmount,
    PERCENTILE_CONT(0.10) WITHIN GROUP (ORDER BY TargetAmount) OVER () AS P10,
    PERCENTILE_CONT(0.90) WITHIN GROUP (ORDER BY TargetAmount) OVER () AS P90,
    CASE
        WHEN TargetAmount < PERCENTILE_CONT(0.10) WITHIN GROUP (ORDER BY TargetAmount) OVER ()
             THEN 'Below P10 — unexpectedly low target'
        WHEN TargetAmount > PERCENTILE_CONT(0.90) WITHIN GROUP (ORDER BY TargetAmount) OVER ()
             THEN 'Above P90 — unexpectedly high target'
        ELSE 'Within P10–P90 band'
    END AS PercentileBand
FROM SalesTargets
WHERE TargetAmount IS NOT NULL
ORDER BY TargetAmount;
```

## Explanation

**Z-score for population outlier detection**
`Z = (value - mean) / stddev` measures how many standard deviations a value is from the group mean. In a normal distribution, |Z| > 2 captures the outer 4.6% of values; |Z| > 3 captures the outer 0.3%. These thresholds are appropriate for initial outlier flagging — extreme values are unlikely to be legitimate.

**NULLIF(StdDevAmount, 0) prevents division by zero**
When a group has only one record, `STDEV()` returns NULL (not 0) in SQL Server. When all records have identical values, STDEV returns 0. `NULLIF(..., 0)` converts 0 to NULL so the division returns NULL instead of a division-by-zero error.

**Statistical Process Control (SPC)**
The UCL/LCL pattern in Step 3 applies SPC to detect when a process metric has moved out of its historical normal range. A point above the UCL (mean + 3σ) signals that something has changed — either a genuine process shift or a data quality problem. SPC is standard in manufacturing quality control and financial risk monitoring.

**Parametric (Z-score) vs non-parametric (percentile)**
Z-score assumes approximately normal distribution. For heavily skewed data (e.g., transaction amounts with large outliers), the mean and standard deviation are themselves distorted by the outliers. Percentile bands (P10–P90 in Step 4) are distribution-agnostic and more robust. Use both: Z-score for normally distributed metrics, percentile for skewed financial data.

## Severity
**Medium** — Distribution threshold breaches may indicate genuine anomalies (fraud, process failure, data entry errors) or legitimate outliers (large one-off transactions, exceptional performers). Automated flagging enables faster investigation; without dynamic thresholds, anomalies that evolve gradually escape detection as the population shifts.
