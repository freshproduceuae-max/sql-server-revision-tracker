# G05-T10 — Range/Boundary | Start Date After End Date

## ID
G05-T10

## Group
5 — Range/Boundary

## Type
Start Date After End Date — Inverted Date Range

## Live Scenario
A contract management system stores contract validity as `StartDate` and `EndDate`. A data migration reverses the column order in a CSV import — the system maps EndDate to StartDate and StartDate to EndDate for 89 contracts. The system's "active contract" query uses `WHERE StartDate <= GETDATE() AND EndDate >= GETDATE()`, which now excludes all 89 contracts (StartDate is in the future, EndDate is in the past). Revenue forecasting reports a gap of £3.2M in contracted revenue for the quarter — actually present but invisible due to the inverted dates.

## The Question
> Date pairs representing a range (start/end, from/to, effective/expiry) must always have start ≤ end. Start after end is a physical impossibility for a time interval and indicates a data entry error or import mapping error.
> **"Find all Orders where DeliveryDate is before OrderDate, all Employees where TerminationDate is before HireDate, and all SalesTargets where a quarterly period end is before its start."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Employees** — `schemas/04_Employees.csv`
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Orders where delivery is before order date
SELECT
    OrderID,
    CustomerID,
    OrderDate,
    DeliveryDate,
    DATEDIFF(DAY, DeliveryDate, OrderDate) AS DaysInverted,
    'DeliveryDate is before OrderDate — impossible' AS Issue
FROM Orders
WHERE DeliveryDate IS NOT NULL
  AND DeliveryDate < OrderDate
ORDER BY DaysInverted DESC;

-- Step 2: Employees where termination is before hire date
SELECT
    EmployeeID,
    FullName,
    HireDate,
    TerminationDate,
    DATEDIFF(DAY, TerminationDate, HireDate) AS DaysInverted,
    CASE
        WHEN TerminationDate < HireDate     THEN 'TerminationDate before HireDate — impossible'
        WHEN TerminationDate = HireDate     THEN 'Terminated same day as hired — verify'
        ELSE 'Date range valid'
    END AS DateRangeCheck
FROM Employees
WHERE TerminationDate IS NOT NULL
  AND TerminationDate <= HireDate;

-- Step 3: Generic date range validation function via CASE
SELECT
    'Orders.DeliveryDate >= OrderDate' AS RuleName,
    COUNT(*) AS ViolationCount
FROM Orders WHERE DeliveryDate < OrderDate
UNION ALL
SELECT 'Employees.TerminationDate >= HireDate', COUNT(*)
FROM Employees WHERE TerminationDate < HireDate
UNION ALL
SELECT 'Customers.ContractEnd >= ContractStart', COUNT(*)
FROM Customers WHERE ContractEnd < ContractStart;

-- Step 4: Zero-length ranges (start = end) — flag for review
SELECT
    OrderID,
    OrderDate,
    DeliveryDate,
    'Order and delivery on same date — same-day delivery, verify intentional' AS Note
FROM Orders
WHERE DeliveryDate IS NOT NULL
  AND DeliveryDate = OrderDate;

-- Step 5: Likely column swap detection
-- If many rows have the reversal, it may be a systematic mapping error
SELECT
    CASE
        WHEN DeliveryDate < OrderDate THEN 'Inverted (delivery before order)'
        WHEN DeliveryDate = OrderDate THEN 'Same day'
        WHEN DeliveryDate > OrderDate AND DATEDIFF(DAY, OrderDate, DeliveryDate) > 365
             THEN 'More than 1 year after order'
        ELSE 'Normal range'
    END AS DateRelationship,
    COUNT(*) AS OrderCount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS PctOfOrders
FROM Orders
WHERE DeliveryDate IS NOT NULL
GROUP BY
    CASE
        WHEN DeliveryDate < OrderDate THEN 'Inverted (delivery before order)'
        WHEN DeliveryDate = OrderDate THEN 'Same day'
        WHEN DeliveryDate > OrderDate AND DATEDIFF(DAY, OrderDate, DeliveryDate) > 365
             THEN 'More than 1 year after order'
        ELSE 'Normal range'
    END
ORDER BY OrderCount DESC;
```

## Explanation

**The fundamental constraint: start ≤ end**
Any pair of dates representing an interval must satisfy `StartDate <= EndDate`. `DATEDIFF(DAY, EndDate, StartDate) > 0` gives a positive number of days inverted — useful for sorting by severity (a 1-day inversion may be a timezone issue; a 365-day inversion is almost certainly a column swap).

**Systematic vs isolated inversions**
Step 5 shows what percentage of records are inverted. If 5% are inverted, it's likely isolated data entry errors. If 50% are inverted, it's almost certainly a systematic column mapping error in an import or migration. Percentage context is critical for determining the root cause.

**Same-day ranges (start = end)**
A contract starting and ending on the same day is usually valid (single-day contracts exist). In context: an order placed and delivered on the same day (same-day delivery) is plausible. An employee hired and terminated on the same day is unusual and warrants review. The business meaning determines whether equality is valid.

**CHECK constraint for prevention**
`ALTER TABLE Orders ADD CONSTRAINT chk_DateOrder CHECK (DeliveryDate >= OrderDate)` prevents future inversions at the database level. This is the definitive fix — SQL validation queries catch existing violations; constraints prevent new ones.

## Severity
**High** — Inverted date ranges make records invisible to range queries (`BETWEEN`, `WHERE start <= date <= end`). Affected records appear as gaps in revenue forecasts, contract registers, and active employee counts. In HR, an employee with inverted employment dates may not receive payroll correctly.
