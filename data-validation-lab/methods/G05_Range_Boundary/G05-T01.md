# G05-T01 — Range/Boundary | Value Below Minimum

## ID
G05-T01

## Group
5 — Range/Boundary

## Type
Value Below Minimum — Numeric Value Less Than Permitted Lower Bound

## Live Scenario
A payroll system applies a minimum wage rule: no employee's hourly rate should fall below £10.42 (UK National Minimum Wage for adults, 2023–24). After a bulk salary adjustment script runs, 12 employees have hourly rates of £9.50 or less — the script multiplied rates by 0.9 instead of 1.09 for a subset of records. The error is not discovered until the next pay cycle. The company owes back pay and faces a minimum wage compliance investigation.

## The Question
> Numeric values must satisfy a minimum threshold defined by business rules, legal requirements, or domain logic. Values below the minimum are definitively wrong and require immediate remediation.
> **"Find all Employees where the HourlyRate is below the minimum wage threshold of £10.42, and identify Transactions where Amount is negative (a transaction amount cannot be negative in this system)."**

## Table Reference
**Employees** — `schemas/04_Employees.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Find employees below minimum wage
DECLARE @MinWage DECIMAL(8,2) = 10.42;  -- UK NMW 2023-24 adult rate

SELECT
    EmployeeID,
    FullName,
    HourlyRate,
    @MinWage AS MinimumWage,
    @MinWage - HourlyRate AS Shortfall,
    ROUND((@MinWage - HourlyRate) / @MinWage * 100, 2) AS ShortfallPct
FROM Employees
WHERE HourlyRate < @MinWage
ORDER BY Shortfall DESC;

-- Step 2: Find transactions with negative amounts
SELECT
    TransactionID,
    OrderID,
    Amount,
    TransactionDate,
    'Negative transaction amount' AS Issue
FROM Transactions
WHERE Amount < 0
ORDER BY Amount;

-- Step 3: Combined below-minimum check across multiple columns and tables
SELECT 'Employees below NMW'      AS Check, COUNT(*) AS ViolationCount
FROM Employees WHERE HourlyRate < @MinWage
UNION ALL
SELECT 'Transactions with negative amount', COUNT(*)
FROM Transactions WHERE Amount < 0
UNION ALL
SELECT 'Products with zero or negative price', COUNT(*)
FROM Products WHERE Price <= 0
UNION ALL
SELECT 'Orders with zero or negative total', COUNT(*)
FROM Orders WHERE TotalAmount <= 0;

-- Step 4: Boundary test — include the threshold itself
-- "below minimum" = strictly less than (not less than or equal)
SELECT
    EmployeeID,
    HourlyRate,
    CASE
        WHEN HourlyRate < @MinWage  THEN 'BELOW minimum — violation'
        WHEN HourlyRate = @MinWage  THEN 'AT minimum — compliant but marginal'
        WHEN HourlyRate < @MinWage + 1.00 THEN 'Just above minimum — flag for review'
        ELSE 'Above minimum'
    END AS WageStatus
FROM Employees
WHERE HourlyRate <= @MinWage + 1.00
ORDER BY HourlyRate;
```

**Step 1 — Below minimum wage:**
| EmployeeID | FullName | HourlyRate | MinimumWage | Shortfall | ShortfallPct |
|---|---|---|---|---|---|
| E007 | Tom Baker | 9.50 | 10.42 | 0.92 | 8.83 |
| E012 | Jane Doe | 9.80 | 10.42 | 0.62 | 5.95 |

**Step 3 — Multi-table summary:**
| Check | ViolationCount |
|---|---|
| Employees below NMW | 2 |
| Transactions with negative amount | 0 |
| Products with zero or negative price | 1 |
| Orders with zero or negative total | 0 |

## Explanation

**`< minimum` vs `<= minimum`**
Below-minimum checks use strict less-than (`<`). An employee AT the minimum wage exactly (`= @MinWage`) is compliant. An employee below it (`< @MinWage`) is in violation. Step 4 shows the marginal zone around the threshold — employees just above minimum may need review in a different business context (e.g., upcoming wage increase).

**Parameterise the threshold, don't hard-code it**
Using `DECLARE @MinWage = 10.42` instead of embedding `10.42` in every condition makes the query maintainable. When minimum wage changes, update one line. This also makes the threshold visible and documentable.

**Shortfall calculation for remediation**
`@MinWage - HourlyRate` shows how much each employee is underpaid per hour. Multiplied by hours worked gives the back-pay liability. This calculation in Step 1 is directly useful for payroll remediation.

**Negative amounts as a separate case**
Negative transaction amounts are below the domain minimum of 0. They may represent refunds (which should be a separate transaction type) or data entry errors. The business meaning of a negative value in a given column must be established before deciding whether it is a violation.

## Severity
**Critical** — Below-minimum wage violations are a legal compliance failure with direct financial penalties, mandatory back pay, and potential public naming by HMRC. Negative amounts in financial columns indicate either incorrect data entry or an improper use of the field that breaks accounting reconciliation.
