# G05-T07 — Range/Boundary | Quantity / Count Below Zero

## ID
G05-T07

## Group
5 — Range/Boundary

## Type
Quantity / Count Below Zero — Negative Value in a Non-Negative Field

## Live Scenario
An inventory management system tracks `StockQuantity` for each product. Stock adjustments are entered manually. A warehouse operator enters `-50` for a stocktake adjustment where they intended `+50`. The product now shows -50 units in stock. The ordering system, which triggers auto-reorder when stock < minimum threshold (10), fires a reorder for -50 units. The supplier receives a purchase order for -50 units and doesn't know how to process it. Meanwhile, the product cannot be sold because the system rejects orders when stock < 0.

## The Question
> Quantity and count fields representing physical quantities (stock levels, item counts, quantities ordered) must be non-negative. A negative count does not represent a real-world state for these domain values.
> **"Find all Products where StockQuantity is negative, all OrderItems where Quantity is zero or negative, and all SalesTargets where TargetAmount is zero or negative."**

## Table Reference
**Products** — `schemas/03_Products.csv`
**Orders** — `schemas/02_Orders.csv`
**SalesTargets** — `schemas/06_SalesTargets.csv`

## Solution Query

```sql
-- Step 1: Negative stock quantities
SELECT
    ProductID,
    ProductName,
    StockQuantity,
    ABS(StockQuantity) AS MagnitudeOfError,
    CASE
        WHEN StockQuantity < -100   THEN 'Large negative — likely manual entry error'
        WHEN StockQuantity < 0      THEN 'Negative stock — adjustment error'
        WHEN StockQuantity = 0      THEN 'Zero stock — out of stock'
        ELSE 'Positive stock'
    END AS StockStatus
FROM Products
WHERE StockQuantity < 0
ORDER BY StockQuantity;

-- Step 2: Zero or negative order quantities
SELECT
    o.OrderID,
    o.CustomerID,
    o.TotalAmount,
    COUNT(oi.ItemID) AS LineItemCount,
    SUM(oi.Quantity) AS TotalItemsOrdered,
    MIN(oi.Quantity) AS MinLineQuantity
FROM Orders o
JOIN OrderItems oi ON o.OrderID = oi.OrderID
WHERE oi.Quantity <= 0
GROUP BY o.OrderID, o.CustomerID, o.TotalAmount
HAVING MIN(oi.Quantity) <= 0;

-- Direct OrderItems check
SELECT
    oi.ItemID,
    oi.OrderID,
    oi.ProductID,
    oi.Quantity,
    CASE
        WHEN oi.Quantity < 0    THEN 'Negative quantity — invalid'
        WHEN oi.Quantity = 0    THEN 'Zero quantity — should this line be deleted?'
        ELSE 'Valid quantity'
    END AS QuantityCheck
FROM OrderItems oi
WHERE oi.Quantity <= 0;

-- Step 3: Sales targets with non-positive amounts
SELECT
    TargetID,
    SalespersonID,
    Year,
    Quarter,
    TargetAmount,
    CASE
        WHEN TargetAmount < 0   THEN 'Negative target — impossible'
        WHEN TargetAmount = 0   THEN 'Zero target — unset or exempt'
        ELSE 'Valid target'
    END AS TargetCheck
FROM SalesTargets
WHERE TargetAmount <= 0;

-- Step 4: Multi-table summary of non-positive quantity/count violations
SELECT 'Products with negative stock'       AS Check, COUNT(*) AS Count, MIN(StockQuantity) AS MinValue
FROM Products WHERE StockQuantity < 0
UNION ALL
SELECT 'OrderItems with zero quantity',      COUNT(*), MIN(Quantity)
FROM OrderItems WHERE Quantity = 0
UNION ALL
SELECT 'OrderItems with negative quantity',  COUNT(*), MIN(Quantity)
FROM OrderItems WHERE Quantity < 0
UNION ALL
SELECT 'SalesTargets with zero/neg target',  COUNT(*), MIN(TargetAmount)
FROM SalesTargets WHERE TargetAmount <= 0;

-- Step 5: Cumulative stock impact of negative adjustments
SELECT
    p.ProductID,
    p.ProductName,
    p.StockQuantity,
    -- Estimate "correct" stock if adjustment sign was flipped
    p.StockQuantity + 2 * ABS(p.StockQuantity) AS IfAdjustmentReversed,
    'Probable corrected stock (if sign error)' AS Note
FROM Products p
WHERE p.StockQuantity < 0;
```

## Expected Output

**Step 1 — Negative stock:**
| ProductID | ProductName | StockQuantity | StockStatus |
|---|---|---|---|
| P007 | Widget B | -50 | Large negative — likely manual entry error |
| P013 | Gadget X | -3 | Negative stock — adjustment error |

**Step 4 — Summary:**
| Check | Count | MinValue |
|---|---|---|
| Products with negative stock | 2 | -50 |
| OrderItems with zero quantity | 0 | NULL |
| OrderItems with negative quantity | 0 | NULL |
| SalesTargets with zero/neg target | 1 | 0 |

## Explanation

**Non-negative vs positive: different business meanings**
`StockQuantity >= 0` is the correct constraint for most inventory fields — zero stock is valid (out of stock). `Quantity > 0` (strictly positive) is correct for order line items — an order line with quantity 0 should not exist.

**`ABS(StockQuantity)` for estimating the correction**
When a negative value is caused by a sign flip (operator entered `-50` instead of `+50`), the corrected value is `current + 2 * ABS(current)`. Step 5 provides this estimate. The DBA must verify this is the actual error before applying any correction.

**Zero quantities in order lines**
A zero-quantity order line is a schema anomaly — it should be deleted, not stored. It may cause issues in unit-price × quantity calculations (zero-value line) and can confuse order fulfilment systems that count line items.

**Physical vs ledger quantities**
Some inventory models allow "theoretical negative stock" in double-entry ledger systems (where a negative represents a commitment that hasn't been received yet). This is a deliberate design choice. Before flagging all negatives, confirm whether negative stock is used as a business concept in the system being validated.

## Severity
**High** — Negative stock quantities break ordering systems, trigger incorrect auto-reorders, and prevent sales of in-stock items. In physical inventory contexts, negative quantities represent an impossible state that indicates a data integrity failure.
