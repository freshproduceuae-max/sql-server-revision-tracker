# G04-T18 — Format/Pattern | Colour Code Format

## ID
G04-T18

## Group
4 — Format/Pattern

## Type
Colour Code Format — Invalid Hex Colour or RGB Value

## Live Scenario
A fashion e-commerce platform stores product colour codes for CSS rendering. The `ColourHex` column should contain 6-digit hex colour codes prefixed with `#` (e.g., `#FF5733`). Data entry staff and API integrations have introduced: `"FF5733"` (missing `#`), `"#FF573"` (only 5 digits), `"#GG5733"` (invalid hex digit `G`), `"red"` (CSS colour name instead of hex), `"rgb(255,87,51)"` (RGB function format), `"#FF5733CC"` (8-digit with alpha channel), and `"N/A"`. The CSS renderer only supports 6-digit hex; other formats are rendered as default black, making the product images look wrong.

## The Question
> Hex colour codes must follow the exact pattern `#` followed by exactly 6 characters from `[0-9A-Fa-f]`. Any deviation — wrong prefix, wrong length, invalid characters — produces an invalid colour.
> **"Find all Products where ColourHex does not match the valid 6-digit hex colour format (#RRGGBB)."**

## Table Reference
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Validate hex colour format #RRGGBB
SELECT
    ProductID,
    ProductName,
    ColourHex,
    CASE
        WHEN ColourHex IS NULL                                          THEN 'NULL'
        WHEN LEN(ColourHex) = 0                                        THEN 'Empty string'
        WHEN LEFT(ColourHex, 1) <> '#'                                 THEN 'Missing # prefix'
        WHEN LEN(ColourHex) <> 7                                       THEN 'Wrong length (must be 7: #RRGGBB)'
        WHEN ColourHex LIKE '#[^0-9A-Fa-f]%'
          OR ColourHex LIKE '#_[^0-9A-Fa-f]%'
          OR ColourHex LIKE '#__[^0-9A-Fa-f]%'
          OR ColourHex LIKE '#___[^0-9A-Fa-f]%'
          OR ColourHex LIKE '#____[^0-9A-Fa-f]%'
          OR ColourHex LIKE '#_____[^0-9A-Fa-f]%'                     THEN 'Invalid hex character'
        ELSE 'Valid #RRGGBB'
    END AS ColourHexValidation
FROM Products
WHERE ColourHex IS NULL
   OR LEN(ColourHex) <> 7
   OR LEFT(ColourHex,1) <> '#'
   OR ColourHex NOT LIKE '#[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]';

-- Step 2: Compact single-condition check
SELECT
    ProductID,
    ColourHex,
    'Invalid hex colour' AS Issue
FROM Products
WHERE ColourHex IS NOT NULL
  AND ColourHex NOT LIKE '#[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]';

-- Step 3: Detect specific format variants (for cleansing routing)
SELECT
    ProductID,
    ColourHex,
    CASE
        WHEN ColourHex LIKE '[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]'
             THEN 'Missing # — can fix by prepending #'
        WHEN ColourHex LIKE '#[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]' AND LEN(ColourHex) = 4
             THEN '3-digit shorthand (#RGB) — can expand to 6 digits'
        WHEN ColourHex LIKE 'rgb(%'
             THEN 'RGB function format — needs conversion'
        WHEN ColourHex LIKE '#[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]'
             THEN '8-digit with alpha (#RRGGBBAA) — strip alpha to fix'
        WHEN ColourHex LIKE '%[^0-9A-Fa-f# ]%'
             THEN 'Non-hex characters — likely CSS name or text'
        ELSE 'Other invalid format'
    END AS VariantType,
    CASE
        WHEN ColourHex LIKE '[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]'
             THEN '#' + ColourHex
        WHEN LEN(ColourHex) = 4 AND ColourHex LIKE '#[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]'
             THEN '#' + REPLICATE(SUBSTRING(ColourHex,2,1),2) + REPLICATE(SUBSTRING(ColourHex,3,1),2) + REPLICATE(SUBSTRING(ColourHex,4,1),2)
        WHEN LEN(ColourHex) = 9 AND ColourHex LIKE '#[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]%'
             THEN LEFT(ColourHex, 7)
        ELSE NULL
    END AS SuggestedFix
FROM Products
WHERE ColourHex IS NOT NULL
  AND ColourHex NOT LIKE '#[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]';
```

## Explanation

**Why 6 individual `[0-9A-Fa-f]` positions instead of `%`**
`LIKE '#[0-9A-Fa-f]%'` only validates the first character after `#`. The full pattern `#[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]` validates every position. Combined with `LEN = 7`, this gives exact 6-digit hex validation.

**3-digit CSS shorthand expansion**
`#F57` is a valid CSS shorthand for `#FF5577` (each digit doubled). SQL can expand this: `REPLICATE(SUBSTRING(code, 2, 1), 2)` for each digit. But confirm the system accepts expanded codes before auto-correcting.

**8-digit RGBA**
`#FF5733CC` includes an alpha (opacity) channel. If the system doesn't support alpha, strip the last 2 characters: `LEFT(ColourHex, 7)`.

**CSS colour names are not valid hex**
`'red'`, `'blue'`, `'transparent'` are valid CSS colour values but are not hex codes. If the target system only accepts hex, these must be converted to their hex equivalents through a lookup table.

## Severity
**Low** — Invalid colour codes cause visual rendering errors (wrong colours or default black) in web and mobile UIs. The business impact is cosmetic but can affect brand consistency and conversion rates on product pages.
