# G04-T22 — Format/Pattern | Sort Code / Routing Number Format

## ID
G04-T22

## Group
4 — Format/Pattern

## Type
Sort Code / Routing Number Format Validation

## Live Scenario
A payroll system processes salary payments via BACS (UK) and ACH (US). UK sort codes should be in the format `NN-NN-NN` (6 digits with 2 hyphens). US ABA routing numbers should be 9 digits with a valid check digit. The SortCode column contains: correct format (`20-32-45`), missing hyphens (`203245`), wrong hyphen positions (`2-03245`), spaces instead of hyphens (`20 32 45`), non-numeric digits (`20-3X-45`), and short values (`20-32`). BACS rejects 6% of payments, triggering manual processing at £15 per item.

## The Question
> Bank sort codes (UK) follow the exact format `NN-NN-NN` — 6 digits in three pairs separated by hyphens. US routing numbers are exactly 9 digits with a check digit algorithm. SQL LIKE validates the structural pattern.
> **"Find all Employees where SortCode does not match the UK BACS format (NN-NN-NN) — 2 digits, hyphen, 2 digits, hyphen, 2 digits — and where the digits-only value is not exactly 6 digits."**

## Table Reference
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Step 1: Validate UK sort code format NN-NN-NN
SELECT
    EmployeeID,
    FullName,
    SortCode,
    CASE
        WHEN SortCode IS NULL                                           THEN 'NULL'
        WHEN SortCode NOT LIKE '[0-9][0-9]-[0-9][0-9]-[0-9][0-9]'    THEN 'Does not match NN-NN-NN pattern'
        ELSE 'Valid UK sort code format'
    END AS SortCodeValidation
FROM Employees
WHERE SortCode IS NULL
   OR SortCode NOT LIKE '[0-9][0-9]-[0-9][0-9]-[0-9][0-9]';

-- Step 2: Detect what's wrong with each invalid sort code
SELECT
    EmployeeID,
    SortCode,
    REPLACE(REPLACE(SortCode, '-', ''), ' ', '') AS DigitsOnly,
    CASE
        WHEN SortCode IS NULL                                           THEN 'NULL'
        WHEN LEN(SortCode) <> 8                                        THEN 'Wrong total length (must be 8 with hyphens)'
        WHEN SortCode LIKE '%[^0-9-]%'                                 THEN 'Contains non-numeric/non-hyphen characters'
        WHEN LEN(REPLACE(REPLACE(SortCode, '-', ''), ' ', '')) <> 6   THEN 'Wrong number of digits (must be 6)'
        WHEN SortCode LIKE '[0-9][0-9]-[0-9][0-9]-[0-9][0-9]'        THEN 'Valid — no issue'
        ELSE 'Pattern mismatch'
    END AS IssueDetail
FROM Employees
WHERE SortCode IS NOT NULL
  AND SortCode NOT LIKE '[0-9][0-9]-[0-9][0-9]-[0-9][0-9]';

-- Step 3: Normalise sort codes entered without hyphens (203245 → 20-32-45)
SELECT
    EmployeeID,
    SortCode AS OriginalSortCode,
    CASE
        WHEN LEN(REPLACE(SortCode, '-', '')) = 6
             AND REPLACE(SortCode, '-', '') NOT LIKE '%[^0-9]%'
             THEN LEFT(REPLACE(SortCode,'-',''),2) + '-' +
                  SUBSTRING(REPLACE(SortCode,'-',''),3,2) + '-' +
                  RIGHT(REPLACE(SortCode,'-',''),2)
        ELSE 'Cannot normalise'
    END AS NormalisedSortCode
FROM Employees
WHERE SortCode IS NOT NULL
  AND SortCode NOT LIKE '[0-9][0-9]-[0-9][0-9]-[0-9][0-9]';

-- Step 4: US ABA routing number — 9 digits, check digit algorithm
-- Check digit: sum of (3×d1 + 7×d2 + 1×d3 + 3×d4 + 7×d5 + 1×d6 + 3×d7 + 7×d8 + 1×d9) mod 10 = 0
SELECT
    EmployeeID,
    RoutingNumber,
    CASE
        WHEN RoutingNumber NOT LIKE '[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]'
             THEN 'Not 9 digits'
        WHEN (
            3 * CAST(SUBSTRING(RoutingNumber,1,1) AS INT) +
            7 * CAST(SUBSTRING(RoutingNumber,2,1) AS INT) +
            1 * CAST(SUBSTRING(RoutingNumber,3,1) AS INT) +
            3 * CAST(SUBSTRING(RoutingNumber,4,1) AS INT) +
            7 * CAST(SUBSTRING(RoutingNumber,5,1) AS INT) +
            1 * CAST(SUBSTRING(RoutingNumber,6,1) AS INT) +
            3 * CAST(SUBSTRING(RoutingNumber,7,1) AS INT) +
            7 * CAST(SUBSTRING(RoutingNumber,8,1) AS INT) +
            1 * CAST(SUBSTRING(RoutingNumber,9,1) AS INT)
        ) % 10 <> 0
             THEN 'ABA check digit failed'
        ELSE 'Valid ABA routing number'
    END AS RoutingNumberCheck
FROM Employees
WHERE Country = 'US'
  AND RoutingNumber IS NOT NULL;

-- Step 5: Summary
SELECT
    CASE
        WHEN SortCode IS NULL                                        THEN 'NULL'
        WHEN SortCode LIKE '[0-9][0-9]-[0-9][0-9]-[0-9][0-9]'     THEN 'Valid'
        ELSE 'Invalid'
    END AS SortCodeStatus,
    COUNT(*) AS EmployeeCount
FROM Employees
GROUP BY
    CASE
        WHEN SortCode IS NULL                                        THEN 'NULL'
        WHEN SortCode LIKE '[0-9][0-9]-[0-9][0-9]-[0-9][0-9]'     THEN 'Valid'
        ELSE 'Invalid'
    END;
```

## Explanation

**UK sort code structure**
A UK sort code is exactly 6 digits identifying the bank and branch, conventionally written as three 2-digit pairs separated by hyphens: `NN-NN-NN`. The LIKE pattern `'[0-9][0-9]-[0-9][0-9]-[0-9][0-9]'` has exactly 8 characters — 6 digits and 2 hyphens — which can be combined with `LEN(SortCode) = 8` for belt-and-braces validation.

**ABA check digit algorithm**
The 9-digit ABA routing number uses a weighted sum: multiply each digit by a weight pattern `3, 7, 1` repeating, sum the results, and verify the total is divisible by 10 (mod 10 = 0). Step 4 implements this directly in SQL using SUBSTRING and CAST. Invalid routing numbers will fail this check even if they pass the 9-digit structural check.

**Normalising without hyphens**
Sort codes are often stored without hyphens in legacy systems. Step 3 uses LEFT/SUBSTRING/RIGHT to reformat `203245` to `20-32-45`. This normalisation can be used in a cleansing UPDATE.

**Why structural validation alone is not enough for financial routing codes**
A sort code like `00-00-00` passes the structural check but is not a real sort code. Check digit validation (Step 4 for ABA) or a lookup against the official sort code directory (SortCodes.co.uk for UK, Federal Reserve for US) is needed for definitive validation.

## Severity
**High** — Invalid sort codes or routing numbers cause payment failures, returned transactions, and financial penalties. In payroll, a single failed salary payment generates significant remediation work and employee relations risk.
