# G04-T23 — Format/Pattern | UUID / GUID Format

## ID
G04-T23

## Group
4 — Format/Pattern

## Type
UUID / GUID Format Validation

## Live Scenario
A microservices platform uses UUIDs as correlation IDs for distributed request tracing. The `CorrelationID` column in the audit log table is VARCHAR(50). Services generate UUIDs using different libraries: Python's `uuid` module (`"3f6c4b2e-1a2b-4c3d-8e9f-123456789abc"`), Java's `UUID.randomUUID()` (same format), but a legacy Perl script generates compact UUIDs without hyphens (`"3f6c4b2e1a2b4c3d8e9f123456789abc"`), and some systems prefix with `"id-"` (`"id-3f6c4b2e-1a2b-4c3d-8e9f-123456789abc"`). The log aggregation query does a string join on CorrelationID and misses 30% of matching events.

## The Question
> A UUID/GUID is a 128-bit identifier conventionally written as 32 hex digits in the format `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` (8-4-4-4-12). Any deviation from this format prevents reliable joining.
> **"Find all log records where the CorrelationID does not match the standard UUID format (8-4-4-4-12 hex groups separated by hyphens)."**

## Table Reference
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Validate UUID/GUID format using LIKE and TRY_CAST
SELECT
    TransactionID,
    CorrelationID,
    CASE
        WHEN CorrelationID IS NULL                                      THEN 'NULL'
        WHEN TRY_CAST(CorrelationID AS UNIQUEIDENTIFIER) IS NOT NULL   THEN 'Valid UUID'
        WHEN LEN(CorrelationID) = 32
             AND CorrelationID NOT LIKE '%[^0-9A-Fa-f]%'              THEN 'Compact UUID (no hyphens)'
        WHEN CorrelationID LIKE '[{]%[}]'                              THEN 'UUID with braces'
        ELSE 'Invalid UUID format'
    END AS UUIDValidation
FROM Transactions
WHERE CorrelationID IS NOT NULL;

-- Step 2: Strict LIKE pattern for the standard hyphenated UUID
SELECT
    TransactionID,
    CorrelationID,
    'Does not match standard UUID format' AS Issue
FROM Transactions
WHERE CorrelationID IS NOT NULL
  AND CorrelationID NOT LIKE
      '[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]-' +
      '[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]-' +
      '[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]-' +
      '[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]-' +
      '[0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f][0-9A-Fa-f]';

-- Step 3: Detect specific UUID format variants
SELECT
    TransactionID,
    CorrelationID,
    LEN(CorrelationID) AS Length,
    CASE
        WHEN LEN(CorrelationID) = 36 AND TRY_CAST(CorrelationID AS UNIQUEIDENTIFIER) IS NOT NULL
                                                    THEN 'Standard hyphenated UUID'
        WHEN LEN(CorrelationID) = 32
             AND CorrelationID NOT LIKE '%[^0-9A-Fa-f]%' THEN 'Compact (no hyphens) — can add hyphens'
        WHEN LEN(CorrelationID) = 38
             AND LEFT(CorrelationID,1) = '{'
             AND RIGHT(CorrelationID,1) = '}'       THEN 'Braced UUID {xxxxxxxx-...}'
        WHEN CorrelationID LIKE 'id-%'              THEN 'Prefixed with id-'
        WHEN CorrelationID LIKE '{%'
             AND CorrelationID NOT LIKE '%}'        THEN 'Unclosed brace'
        ELSE 'Other format'
    END AS UUIDVariant,
    -- Attempt to normalise to standard format
    CASE
        WHEN TRY_CAST(CorrelationID AS UNIQUEIDENTIFIER) IS NOT NULL
             THEN CAST(TRY_CAST(CorrelationID AS UNIQUEIDENTIFIER) AS VARCHAR(36))
        WHEN LEN(CorrelationID) = 32 AND CorrelationID NOT LIKE '%[^0-9A-Fa-f]%'
             THEN LEFT(CorrelationID,8) + '-' + SUBSTRING(CorrelationID,9,4) + '-' +
                  SUBSTRING(CorrelationID,13,4) + '-' + SUBSTRING(CorrelationID,17,4) + '-' +
                  RIGHT(CorrelationID,12)
        ELSE NULL
    END AS NormalisedUUID
FROM Transactions
WHERE CorrelationID IS NOT NULL;

-- Step 4: Check for duplicate correlation IDs (each should be unique)
SELECT
    CorrelationID,
    COUNT(*) AS Occurrences,
    STRING_AGG(CAST(TransactionID AS VARCHAR), ', ') AS TransactionIDs
FROM Transactions
WHERE CorrelationID IS NOT NULL
GROUP BY CorrelationID
HAVING COUNT(*) > 1
ORDER BY Occurrences DESC;
```

## Explanation

**`TRY_CAST(value AS UNIQUEIDENTIFIER)` — the best UUID validator in SQL Server**
SQL Server's UNIQUEIDENTIFIER type accepts the standard hyphenated form and the braced form `{...}`. `TRY_CAST` returns NULL for compact (no-hyphen) forms, prefixed forms, and any format that doesn't match. For standard-form UUIDs, this is simpler and more reliable than a 36-character LIKE pattern.

**Compact UUID normalisation**
A 32-character hex string without hyphens is a valid UUID value but in non-standard format. It can be converted to standard form by inserting hyphens at positions 8, 12, 16, and 20: `LEFT(8) + '-' + SUBSTRING(9,4) + '-' + ...`. After normalisation, `TRY_CAST` will accept it.

**UUID version and variant bits**
UUID v4 (random) has the 13th character (version) = `4` and the 17th character (variant) ∈ `{8,9,a,b}`. SQL can validate these positions: `SUBSTRING(id,15,1) = '4'` for v4. This is rarely needed in practice but is useful when debugging UUID generation library issues.

**Duplicate UUIDs are a separate concern**
Step 4 checks for duplicate correlation IDs. UUIDs are supposed to be globally unique. Duplicates indicate: re-use of the same UUID, a UUID generation bug, or a data import that duplicated rows. Duplicates break correlation ID-based tracing entirely.

## Severity
**Medium** — Invalid or inconsistent UUID formats break distributed system correlation (request tracing, event correlation, saga pattern orchestration). Records that can't be joined by correlation ID are invisible in cross-service analysis. Impact rises to High in audit and compliance contexts where every request must be traceable.
