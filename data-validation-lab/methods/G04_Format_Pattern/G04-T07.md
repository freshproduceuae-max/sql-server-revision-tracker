# G04-T07 — Format/Pattern | National ID / Tax Reference Format

## ID
G04-T07

## Group
4 — Format/Pattern

## Type
National ID / Tax Reference Format Validation

## Live Scenario
A payroll system stores UK National Insurance Numbers (NINOs) for employees. The format should be `AA 99 99 99 A` (two letters, six digits in three pairs, one letter). Data entry over five years has produced: `"AB123456C"` (correct, no spaces), `"AB 12 34 56 C"` (correct with spaces), `"AB1234C"` (too short), `"AB 12 34 56 CD"` (too many chars), `"QQ123456A"` (invalid prefix — Q and some other letters are not permitted as NINO prefixes), and `"123456789"` (no letters at all). HMRC submissions reject any record with a malformed NINO.

## The Question
> National ID formats are country-specific and often have additional rules beyond basic pattern matching (forbidden prefixes, forbidden suffixes, check digit rules). A LIKE pattern can catch structural violations; additional conditions are needed for business rules like forbidden characters.
> **"Find all Employees whose NationalID does not match the UK NINO pattern (2 letters + 6 digits + 1 letter), and additionally flag any that use a forbidden prefix (D, F, I, Q, U, V as first letter, or D, F, I, O, Q, U, V as second letter) per HMRC rules."**

## Table Reference
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Step 1: Normalise (remove spaces) and validate UK NINO format
SELECT
    EmployeeID,
    FullName,
    NationalID,
    REPLACE(NationalID, ' ', '') AS NormalisedNINO,
    CASE
        WHEN NationalID IS NULL                                          THEN 'NULL'
        WHEN LEN(REPLACE(NationalID, ' ', '')) <> 9                    THEN 'Wrong length (must be 9 chars without spaces)'
        WHEN REPLACE(NationalID, ' ', '') NOT LIKE
             '[A-Z][A-Z][0-9][0-9][0-9][0-9][0-9][0-9][A-D]'         THEN 'Pattern mismatch (AA999999A format required)'
        -- Forbidden first letters: D, F, I, Q, U, V
        WHEN LEFT(REPLACE(NationalID, ' ', ''), 1) IN ('D','F','I','Q','U','V')
                                                                        THEN 'Forbidden first letter per HMRC'
        -- Forbidden second letters: D, F, I, O, Q, U, V
        WHEN SUBSTRING(REPLACE(NationalID, ' ', ''), 2, 1) IN ('D','F','I','O','Q','U','V')
                                                                        THEN 'Forbidden second letter per HMRC'
        -- BG, GB, NK, KN, NT, TN, ZZ are forbidden prefixes
        WHEN LEFT(REPLACE(NationalID, ' ', ''), 2) IN ('BG','GB','NK','KN','NT','TN','ZZ')
                                                                        THEN 'Forbidden prefix combination per HMRC'
        -- Suffix must be A, B, C, or D only
        WHEN RIGHT(REPLACE(NationalID, ' ', ''), 1) NOT IN ('A','B','C','D')
                                                                        THEN 'Invalid suffix (must be A, B, C, or D)'
        ELSE 'Valid NINO format'
    END AS NINOValidation
FROM Employees;

-- Step 2: US SSN format validation (999-99-9999)
-- Included as an alternative pattern for comparison
SELECT
    EmployeeID,
    NationalID,
    CASE
        WHEN NationalID NOT LIKE '[0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9][0-9][0-9]'
             THEN 'Invalid SSN format (must be NNN-NN-NNNN)'
        -- SSNs cannot start with 000, 666, or 9xx
        WHEN LEFT(NationalID, 3) IN ('000', '666')
             OR LEFT(NationalID, 1) = '9'                               THEN 'Invalid SSN area number'
        -- Middle group cannot be 00
        WHEN SUBSTRING(NationalID, 5, 2) = '00'                        THEN 'Invalid SSN group number'
        -- Serial cannot be 0000
        WHEN RIGHT(NationalID, 4) = '0000'                             THEN 'Invalid SSN serial number'
        ELSE 'Valid SSN format'
    END AS SSNValidation
FROM Employees
WHERE Country = 'US';

-- Step 3: Summary of NINO violations by type
SELECT
    CASE
        WHEN NationalID IS NULL                                         THEN 'NULL'
        WHEN LEN(REPLACE(NationalID,' ','')) <> 9                      THEN 'Wrong length'
        WHEN REPLACE(NationalID,' ','') NOT LIKE '[A-Z][A-Z][0-9][0-9][0-9][0-9][0-9][0-9][A-D]'
                                                                        THEN 'Pattern mismatch'
        WHEN LEFT(REPLACE(NationalID,' ',''),1) IN ('D','F','I','Q','U','V')
                                                                        THEN 'Forbidden first letter'
        ELSE 'Valid'
    END AS ViolationType,
    COUNT(*) AS EmployeeCount
FROM Employees
GROUP BY
    CASE
        WHEN NationalID IS NULL                                         THEN 'NULL'
        WHEN LEN(REPLACE(NationalID,' ','')) <> 9                      THEN 'Wrong length'
        WHEN REPLACE(NationalID,' ','') NOT LIKE '[A-Z][A-Z][0-9][0-9][0-9][0-9][0-9][0-9][A-D]'
                                                                        THEN 'Pattern mismatch'
        WHEN LEFT(REPLACE(NationalID,' ',''),1) IN ('D','F','I','Q','U','V')
                                                                        THEN 'Forbidden first letter'
        ELSE 'Valid'
    END
ORDER BY EmployeeCount DESC;
```

## Explanation

**Pattern matching is necessary but not sufficient for NINOs**
The LIKE pattern `[A-Z][A-Z][0-9][0-9][0-9][0-9][0-9][0-9][A-D]` validates structure but not business rules. HMRC specifies additional constraints: forbidden first letters, forbidden second letters, forbidden two-letter prefixes, and a suffix restricted to A-D only. These require separate WHERE or CASE conditions after the structural check passes.

**Normalise before validating — but record both forms**
The normalised form (no spaces) is used for validation and storage; the original form may be needed for display or audit. Select both and validate on the normalised form.

**NINO as a unique identifier**
If NINOs are used as a unique employee identifier, also run a uniqueness check (see G02 Uniqueness) in addition to format validation. A valid format but duplicated NINO is a different class of error.

**Country-specific rules belong in reference data**
Forbidden prefix rules, check digit algorithms, and length constraints vary by country and change over time (HMRC has revised NINO rules several times). For maintainability, store these rules in a reference table rather than hard-coding them in SQL.

## Severity
**High** — Invalid national IDs cause HMRC submission failures, payroll processing errors, and regulatory penalties. They also create identity resolution problems when the same person appears with different (malformed) ID formats across systems.
