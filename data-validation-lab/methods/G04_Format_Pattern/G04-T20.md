# G04-T20 — Format/Pattern | XML Field Format

## ID
G04-T20

## Group
4 — Format/Pattern

## Type
XML Field Format — Malformed XML in a VARCHAR or XML Column

## Live Scenario
An insurance platform receives policy documents as XML from partner systems via a B2B API. Documents are stored in a VARCHAR(MAX) column because the partner systems sometimes send invalid XML that would be rejected by the XML column type. Over six months, 340 of 12,000 documents have accumulated with malformed XML: unclosed tags, invalid attribute quoting, missing XML declarations, and namespace conflicts. The claim processing pipeline uses `.value()` XQuery to extract policy numbers and returns NULL for all 340 malformed records. These claims remain unprocessed and are flagged as open in the SLA dashboard.

## The Question
> XML stored as VARCHAR must be well-formed before it can be queried with XQuery methods. SQL Server provides `TRY_CAST(value AS XML)` to test parseability. Malformed XML causes `.value()` and `.query()` methods to fail or return NULL.
> **"Find all Orders where the XMLData column (stored as VARCHAR) is not well-formed XML — either it cannot be parsed as XML at all, or it is missing the root element."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Validate XML parseability using TRY_CAST
SELECT
    OrderID,
    XMLData,
    CASE
        WHEN XMLData IS NULL                                        THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(XMLData))) = 0                        THEN 'Empty string'
        WHEN TRY_CAST(XMLData AS XML) IS NULL                      THEN 'Cannot parse as XML'
        ELSE 'Valid XML'
    END AS XMLValidation
FROM Orders
WHERE XMLData IS NULL
   OR TRY_CAST(XMLData AS XML) IS NULL;

-- Step 2: Check that valid XML has expected root element
SELECT
    OrderID,
    XMLData,
    TRY_CAST(XMLData AS XML).value('local-name((/*)[1])', 'VARCHAR(100)') AS RootElementName,
    CASE
        WHEN TRY_CAST(XMLData AS XML).value('local-name((/*)[1])', 'VARCHAR(100)') = 'Order'
             THEN 'Root element is Order — correct'
        WHEN TRY_CAST(XMLData AS XML).value('local-name((/*)[1])', 'VARCHAR(100)') IS NULL
             THEN 'No root element found'
        ELSE 'Unexpected root element: ' +
             TRY_CAST(XMLData AS XML).value('local-name((/*)[1])', 'VARCHAR(100)')
    END AS RootElementCheck
FROM Orders
WHERE XMLData IS NOT NULL
  AND TRY_CAST(XMLData AS XML) IS NOT NULL;

-- Step 3: Validate required XML child elements exist
SELECT
    OrderID,
    TRY_CAST(XMLData AS XML).value('(Order/CustomerID)[1]', 'VARCHAR(50)')  AS CustomerIDNode,
    TRY_CAST(XMLData AS XML).value('(Order/OrderDate)[1]', 'VARCHAR(50)')   AS OrderDateNode,
    TRY_CAST(XMLData AS XML).value('(Order/TotalAmount)[1]', 'VARCHAR(50)') AS TotalAmountNode,
    CASE
        WHEN TRY_CAST(XMLData AS XML).value('(Order/CustomerID)[1]', 'VARCHAR(50)') IS NULL
             THEN 'Missing CustomerID element'
        WHEN TRY_CAST(XMLData AS XML).value('(Order/OrderDate)[1]', 'VARCHAR(50)') IS NULL
             THEN 'Missing OrderDate element'
        WHEN TRY_CAST(XMLData AS XML).value('(Order/TotalAmount)[1]', 'VARCHAR(50)') IS NULL
             THEN 'Missing TotalAmount element'
        ELSE 'Required elements present'
    END AS RequiredElementCheck
FROM Orders
WHERE XMLData IS NOT NULL
  AND TRY_CAST(XMLData AS XML) IS NOT NULL;

-- Step 4: Detect common XML errors before CAST
SELECT
    OrderID,
    XMLData,
    CASE
        WHEN XMLData LIKE '%<%' AND XMLData NOT LIKE '%>%'  THEN 'Unclosed tag (< without >)'
        WHEN XMLData NOT LIKE '<%'                          THEN 'Does not start with XML element'
        WHEN XMLData LIKE '%&%' AND XMLData NOT LIKE '%&amp;%'
             AND XMLData NOT LIKE '%&lt;%'
             AND XMLData NOT LIKE '%&gt;%'
             AND XMLData NOT LIKE '%&quot;%'
             AND XMLData NOT LIKE '%&apos;%'
             AND XMLData NOT LIKE '%&#%'                    THEN 'Unescaped & character'
        ELSE 'Pre-check passed'
    END AS PreCastCheck
FROM Orders
WHERE XMLData IS NOT NULL
  AND TRY_CAST(XMLData AS XML) IS NULL;

-- Step 5: Summary of XML validation status
SELECT
    CASE
        WHEN XMLData IS NULL                        THEN 'NULL'
        WHEN TRY_CAST(XMLData AS XML) IS NULL       THEN 'Invalid XML'
        ELSE 'Valid XML'
    END AS XMLStatus,
    COUNT(*) AS OrderCount
FROM Orders
GROUP BY
    CASE
        WHEN XMLData IS NULL                        THEN 'NULL'
        WHEN TRY_CAST(XMLData AS XML) IS NULL       THEN 'Invalid XML'
        ELSE 'Valid XML'
    END;
```

## Explanation

**`TRY_CAST(value AS XML)` vs `CAST`**
`CAST(value AS XML)` raises an error and aborts the query if the string is not well-formed XML. `TRY_CAST(value AS XML)` returns NULL instead. Always use TRY_CAST when validating XML strings. Note: even TRY_CAST may fail (not return NULL) for some severely malformed inputs in older SQL Server versions — a pre-check (Step 4) reduces this risk.

**XQuery `.value()` method**
Once a string is confirmed as valid XML (TRY_CAST returns non-NULL), XQuery extracts values: `CAST(col AS XML).value('(xpath)[1]', 'datatype')`. The `[1]` subscript is required to select the first matching node. Without it, SQL Server raises an error if multiple nodes match.

**VARCHAR(MAX) vs XML column type for storing XML**
The native XML column type (`DECLARE @x XML; SET @x = value`) rejects malformed XML at insert time. Storing XML in VARCHAR bypasses this validation and is only appropriate for non-XML data that looks like XML or for audit/diagnostic columns. For real XML workloads, use the XML column type with schema validation.

**Unescaped `&` is the most common XML syntax error**
SQL parsers require `&` to be written as `&amp;` in XML content. A company name like `"Smith & Jones"` stored directly in an XML element breaks the parser. Pre-check Step 4 detects this common case.

## Severity
**High** — Invalid XML causes complete extraction failure. All `JSON_VALUE` / XQuery extractions from the malformed row return NULL, meaning every downstream field derived from that XML is blank. In document-centric systems (insurance, legal, healthcare), this means the record cannot be processed at all.
