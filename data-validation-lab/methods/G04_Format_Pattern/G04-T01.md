# G04-T01 — Format/Pattern | Email Address Format

## ID
G04-T01

## Group
4 — Format/Pattern

## Type
Email Address Format Validation

## Live Scenario
A marketing platform imports 50,000 customer email addresses from a third-party CRM. The import succeeds with no errors. The first campaign blast is sent — 8,300 emails bounce immediately. Investigation reveals the import included values like `"john.doe"`, `"@domain.com"`, `"user@"`, `"user@@domain.com"`, and free-text notes like `"no email provided"`. The CRM stored all of these in the same VARCHAR column with no validation.

## The Question
> Email addresses must follow the basic pattern `local-part@domain.extension`. SQL Server has no built-in email validator, so pattern matching with LIKE or CHARINDEX is used to catch the most common structural violations.
> **"Find all customers whose Email column does not match a basic valid email pattern — must contain exactly one @, must have characters before the @, must have a dot after the @, and must not have spaces."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Basic email format validation using LIKE
SELECT
    CustomerID,
    FirstName,
    LastName,
    Email,
    CASE
        WHEN Email IS NULL                                      THEN 'NULL — no email'
        WHEN LEN(LTRIM(RTRIM(Email))) = 0                      THEN 'Empty string'
        WHEN Email NOT LIKE '%@%'                              THEN 'Missing @ symbol'
        WHEN Email NOT LIKE '%@%.%'                            THEN 'Missing dot after @'
        WHEN Email LIKE '%@%@%'                                THEN 'Multiple @ symbols'
        WHEN Email LIKE '% %'                                  THEN 'Contains spaces'
        WHEN Email LIKE '@%'                                   THEN 'Nothing before @'
        WHEN Email LIKE '%@'                                   THEN 'Nothing after @'
        WHEN Email LIKE '%@.'                                  THEN 'Dot immediately after @'
        WHEN LEN(Email) - LEN(REPLACE(Email, '@', '')) > 1    THEN 'Multiple @ symbols'
        ELSE 'Format OK'
    END AS ValidationResult
FROM Customers
WHERE Email IS NULL
   OR LEN(LTRIM(RTRIM(Email))) = 0
   OR Email NOT LIKE '%_@_%.__%'     -- minimum: char, @, char, dot, 2+ chars
   OR Email LIKE '%@%@%'
   OR Email LIKE '% %';

-- Strict single-expression check: the one LIKE pattern that catches most violations
SELECT
    CustomerID,
    Email,
    'Invalid email format' AS Issue
FROM Customers
WHERE Email IS NOT NULL
  AND Email NOT LIKE '%_@__%.__%';   -- local-part + @ + 2+ chars + dot + 2+ chars

-- Summary by failure mode
SELECT
    CASE
        WHEN Email IS NULL                          THEN 'NULL'
        WHEN Email NOT LIKE '%@%'                  THEN 'No @ symbol'
        WHEN Email LIKE '%@%@%'                    THEN 'Multiple @'
        WHEN Email LIKE '% %'                      THEN 'Has spaces'
        WHEN Email LIKE '@%'                       THEN 'Starts with @'
        WHEN Email NOT LIKE '%@_%._%'              THEN 'Invalid domain format'
        ELSE 'Valid'
    END AS FailureMode,
    COUNT(*) AS CustomerCount
FROM Customers
GROUP BY
    CASE
        WHEN Email IS NULL                          THEN 'NULL'
        WHEN Email NOT LIKE '%@%'                  THEN 'No @ symbol'
        WHEN Email LIKE '%@%@%'                    THEN 'Multiple @'
        WHEN Email LIKE '% %'                      THEN 'Has spaces'
        WHEN Email LIKE '@%'                       THEN 'Starts with @'
        WHEN Email NOT LIKE '%@_%._%'              THEN 'Invalid domain format'
        ELSE 'Valid'
    END
ORDER BY CustomerCount DESC;
```

## Explanation

**LIKE pattern `'%_@__%.__%'` explained**
- `%_` — one or more characters before the @
- `@` — the @ symbol
- `__%` — at least two characters after the @ (domain name)
- `.` — a literal dot
- `__%` — at least two characters after the dot (TLD)

This catches the most common structural failures. It does not validate that the domain actually exists or that the TLD is real — that requires DNS lookup, not SQL.

**Why CHARINDEX is sometimes better than LIKE for @ count**
`LEN(Email) - LEN(REPLACE(Email, '@', ''))` counts the number of @ symbols without a subquery. It's more readable than `Email NOT LIKE '%@%@%'` for the multiple-@ check and handles edge cases like three or more @s.

**What this check does NOT catch**
SQL LIKE validation is structural only. It will not catch: valid-looking addresses at non-existent domains, disposable email addresses (e.g., `user@mailinator.com`), addresses with unicode characters, or addresses that violate RFC 5321 length limits (64 chars local-part, 255 chars total). For those, validation must happen at the application layer or via an external email verification API.

## Severity
**High** — Invalid email addresses cause immediate delivery failures and can trigger spam-filter penalties against the sending domain. In marketing platforms, bounce rates above 2% can result in the sending domain being blacklisted.
