# G04-T19 — Format/Pattern | JSON Field Format

## ID
G04-T19

## Group
4 — Format/Pattern

## Type
JSON Field Format — Malformed JSON in a VARCHAR/NVARCHAR Column

## Live Scenario
A SaaS analytics platform stores user preferences and event metadata as JSON in NVARCHAR columns. The `EventMetadata` column receives data from four different SDKs. SDK v1 sends valid JSON. SDK v2 occasionally sends single-quoted JSON (`{'key': 'value'}`) which is not valid JSON (requires double quotes). SDK v3 sometimes sends a raw string instead of a JSON object. SDK v4 truncates large payloads mid-object, leaving unclosed braces. The analytics pipeline uses `JSON_VALUE(EventMetadata, '$.userId')` and returns NULL for all four invalid formats — silently losing 18% of user ID data.

## The Question
> JSON stored in a VARCHAR/NVARCHAR column must be valid JSON. SQL Server provides `ISJSON()` to validate this. Malformed JSON causes `JSON_VALUE`, `JSON_QUERY`, and `OPENJSON` to return NULL or raise errors.
> **"Find all Orders where the Metadata column does not contain valid JSON, and classify each violation as: invalid format, empty, or missing required JSON keys."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Use ISJSON() to find malformed JSON
SELECT
    OrderID,
    Metadata,
    ISJSON(Metadata) AS IsValidJSON,
    CASE
        WHEN Metadata IS NULL           THEN 'NULL — no metadata'
        WHEN LEN(LTRIM(RTRIM(Metadata))) = 0  THEN 'Empty string'
        WHEN ISJSON(Metadata) = 0       THEN 'Invalid JSON format'
        WHEN ISJSON(Metadata) = 1       THEN 'Valid JSON'
        ELSE 'ISJSON returned unexpected value'
    END AS JSONValidation
FROM Orders
WHERE Metadata IS NULL
   OR ISJSON(Metadata) = 0;

-- Step 2: Attempt to extract a key and flag NULL results
-- Valid JSON that's missing a required key returns NULL from JSON_VALUE
SELECT
    OrderID,
    Metadata,
    JSON_VALUE(Metadata, '$.source')        AS SourceKey,
    JSON_VALUE(Metadata, '$.version')       AS VersionKey,
    JSON_VALUE(Metadata, '$.timestamp')     AS TimestampKey,
    CASE
        WHEN ISJSON(Metadata) = 0           THEN 'Invalid JSON'
        WHEN JSON_VALUE(Metadata, '$.source') IS NULL       THEN 'Missing required key: source'
        WHEN JSON_VALUE(Metadata, '$.version') IS NULL      THEN 'Missing required key: version'
        ELSE 'All required keys present'
    END AS RequiredKeyCheck
FROM Orders
WHERE Metadata IS NOT NULL
  AND ISJSON(Metadata) = 1;

-- Step 3: Validate JSON object vs JSON array (type check)
SELECT
    OrderID,
    Metadata,
    CASE
        WHEN ISJSON(Metadata) = 0               THEN 'Invalid JSON'
        WHEN LEFT(LTRIM(Metadata), 1) = '{'     THEN 'JSON Object'
        WHEN LEFT(LTRIM(Metadata), 1) = '['     THEN 'JSON Array'
        ELSE 'JSON scalar (not object or array)'
    END AS JSONType
FROM Orders
WHERE Metadata IS NOT NULL AND ISJSON(Metadata) = 1;

-- Step 4: Detect common single-quote JSON errors (not parseable by ISJSON)
SELECT
    OrderID,
    Metadata,
    'Single-quoted JSON — replace with double quotes' AS Issue
FROM Orders
WHERE Metadata IS NOT NULL
  AND ISJSON(Metadata) = 0
  AND Metadata LIKE '{''%'   -- starts with single quote after brace
  OR (ISJSON(Metadata) = 0 AND Metadata LIKE '%'':%'); -- single-quote key-value pattern

-- Step 5: Summary
SELECT
    CASE
        WHEN Metadata IS NULL               THEN 'NULL'
        WHEN ISJSON(Metadata) = 0           THEN 'Invalid JSON'
        WHEN ISJSON(Metadata) = 1           THEN 'Valid JSON'
        ELSE 'Other'
    END AS JSONStatus,
    COUNT(*) AS OrderCount
FROM Orders
GROUP BY
    CASE
        WHEN Metadata IS NULL               THEN 'NULL'
        WHEN ISJSON(Metadata) = 0           THEN 'Invalid JSON'
        WHEN ISJSON(Metadata) = 1           THEN 'Valid JSON'
        ELSE 'Other'
    END;
```

## Explanation

**`ISJSON()` — SQL Server's built-in JSON validator**
`ISJSON(expression)` returns 1 if the string is valid JSON, 0 if it is not, and NULL if the input is NULL. It was introduced in SQL Server 2016. It validates the full JSON structure (balanced braces/brackets, correct quoting, valid syntax) — not just the first character.

**`JSON_VALUE` returning NULL for missing keys vs invalid JSON**
`JSON_VALUE` returns NULL for two different reasons: the JSON is valid but the key doesn't exist, or the JSON is invalid. Always check `ISJSON() = 1` before interpreting a NULL `JSON_VALUE` result as "key not found."

**ISJSON validates syntax, not schema**
`ISJSON()` confirms the string is syntactically valid JSON. It does not validate that required keys are present, that values have the right types, or that arrays have the expected length. Schema validation requires `JSON_VALUE` extractions with additional checks (Step 2).

**Single-quoted JSON is the most common formatting error**
Python dictionaries use single quotes. When Python developers serialize data without using `json.dumps()`, the result is single-quoted. SQL Server's ISJSON rejects single-quoted JSON. The fix is a `REPLACE(Metadata, '''', '"')` but must be applied carefully — values containing apostrophes will break.

## Severity
**High** — Invalid JSON causes `JSON_VALUE` and `JSON_QUERY` to silently return NULL, dropping data from any query that extracts JSON fields. In event tracking, this means user behaviour data is lost with no error raised.
