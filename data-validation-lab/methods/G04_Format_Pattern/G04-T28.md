# G04-T28 — Format/Pattern | String Length Violation

## ID
G04-T28

## Group
4 — Format/Pattern

## Type
String Length Violation — Too Short, Too Long, or Truncated

## Live Scenario
A customer feedback platform migrates from a system with a 255-character description limit to one with a 500-character limit. In reverse, a downstream reporting tool exports data to a legacy system that only accepts 100-character product names. During the export, SQL Server silently truncates values longer than 100 characters — `"Premium Ergonomic Adjustable Standing Desk with Memory Settings"` becomes `"Premium Ergonomic Adjustable Standing Desk with Memory Set"`. The truncation introduces 340 corrupted product names in the legacy system, and the export produces no error message.

## The Question
> String length violations occur in two directions: values too long for the target column or system (truncation risk) and values too short to be meaningful (possibly incomplete data). SQL LEN() validates both.
> **"Find all Products where ProductName is empty or fewer than 3 characters (suspiciously short), or longer than 100 characters (at risk of truncation in downstream systems). Also find Customers where Description exceeds 500 characters."**

## Table Reference
**Products** — `schemas/03_Products.csv`
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Products with name length violations
SELECT
    ProductID,
    ProductName,
    LEN(ProductName) AS NameLength,
    CASE
        WHEN ProductName IS NULL                THEN 'NULL'
        WHEN LEN(ProductName) = 0              THEN 'Empty string'
        WHEN LEN(ProductName) < 3              THEN 'Too short (< 3 chars) — likely incomplete'
        WHEN LEN(ProductName) > 100            THEN 'Too long (> 100 chars) — truncation risk in legacy export'
        WHEN LEN(ProductName) BETWEEN 3 AND 10 THEN 'Short but plausible'
        ELSE 'Length OK'
    END AS LengthCheck
FROM Products
WHERE ProductName IS NULL
   OR LEN(ProductName) = 0
   OR LEN(ProductName) < 3
   OR LEN(ProductName) > 100;

-- Step 2: Customer notes/description length check
SELECT
    CustomerID,
    LEN(Notes) AS NotesLength,
    CASE
        WHEN Notes IS NULL                  THEN 'NULL'
        WHEN LEN(Notes) > 500              THEN 'Exceeds 500 char limit'
        WHEN LEN(Notes) = LEN(RTRIM(Notes))
             AND LEN(Notes) > 490          THEN 'Near limit (> 490) — check for truncation'
        ELSE 'OK'
    END AS NotesLengthCheck
FROM Customers
WHERE Notes IS NOT NULL
  AND LEN(Notes) > 490;

-- Step 3: Detect potential truncation — value ends mid-word (no space or punctuation near end)
SELECT
    ProductID,
    ProductName,
    LEN(ProductName) AS Length,
    RIGHT(ProductName, 1) AS LastChar,
    CASE
        WHEN LEN(ProductName) = 100
             AND RIGHT(ProductName, 1) NOT IN ('.', '!', '?', ')', '"', '''')
             AND RIGHT(ProductName, 1) <> ' '
             THEN 'Exactly 100 chars ending mid-word — likely truncated'
        WHEN LEN(ProductName) = 255
             THEN 'Exactly 255 chars — possible column width truncation'
        WHEN LEN(ProductName) = 50
             THEN 'Exactly 50 chars — possible column width truncation'
        ELSE 'No truncation signal'
    END AS TruncationSignal
FROM Products
WHERE LEN(ProductName) IN (50, 100, 255);

-- Step 4: Length distribution — understand the spread
SELECT
    CASE
        WHEN LEN(ProductName) IS NULL       THEN 'NULL'
        WHEN LEN(ProductName) = 0           THEN '0 (empty)'
        WHEN LEN(ProductName) BETWEEN 1 AND 10  THEN '1-10 chars'
        WHEN LEN(ProductName) BETWEEN 11 AND 50 THEN '11-50 chars'
        WHEN LEN(ProductName) BETWEEN 51 AND 100 THEN '51-100 chars'
        WHEN LEN(ProductName) BETWEEN 101 AND 255 THEN '101-255 chars'
        ELSE '255+ chars'
    END AS LengthBucket,
    COUNT(*) AS ProductCount,
    MIN(LEN(ProductName)) AS MinLength,
    MAX(LEN(ProductName)) AS MaxLength,
    AVG(LEN(ProductName)) AS AvgLength
FROM Products
GROUP BY
    CASE
        WHEN LEN(ProductName) IS NULL       THEN 'NULL'
        WHEN LEN(ProductName) = 0           THEN '0 (empty)'
        WHEN LEN(ProductName) BETWEEN 1 AND 10  THEN '1-10 chars'
        WHEN LEN(ProductName) BETWEEN 11 AND 50 THEN '11-50 chars'
        WHEN LEN(ProductName) BETWEEN 51 AND 100 THEN '51-100 chars'
        WHEN LEN(ProductName) BETWEEN 101 AND 255 THEN '101-255 chars'
        ELSE '255+ chars'
    END
ORDER BY MinLength;

-- Step 5: DATALENGTH vs LEN — detect trailing space padding
-- LEN ignores trailing spaces; DATALENGTH counts every byte
SELECT
    ProductID,
    ProductName,
    LEN(ProductName) AS LENResult,
    DATALENGTH(ProductName) AS DATALENGTHResult,
    DATALENGTH(ProductName) - LEN(ProductName) AS TrailingSpaceCount
FROM Products
WHERE DATALENGTH(ProductName) > LEN(ProductName)
  AND ProductName IS NOT NULL;
```

## Explanation

**LEN vs DATALENGTH**
`LEN(str)` returns the number of characters, excluding trailing spaces. `DATALENGTH(str)` returns the number of bytes — for VARCHAR, this equals the character count including trailing spaces; for NVARCHAR, it's double the character count. Use `DATALENGTH - LEN` to detect trailing space padding (Step 5).

**The "exactly N characters" truncation signal**
When a large number of rows have exactly the same maximum length (e.g., exactly 255 characters), and the column was previously `VARCHAR(255)`, it's a strong signal that values were truncated at the old column limit. Step 3 flags values at common column width limits (50, 100, 255) that end mid-word.

**Too-short strings as a completeness concern**
A product name of 1-2 characters is rarely intentional. Unlike NULL (clearly missing), a 2-character name passes a NOT NULL check but is almost certainly incomplete data. Length-too-short checks bridge format validation and completeness validation.

**Length distribution as a profiling tool**
Step 4 shows the distribution of string lengths. A bimodal distribution (many very short + many very long with nothing in between) suggests two different data sources with different naming conventions. An unexpected cluster at exactly 255 suggests truncation. Understanding the distribution guides the choice of minimum/maximum thresholds.

## Severity
**Medium** — String length violations cause truncation (data loss), import failures when the target column is smaller than the source, and display issues (names cut off in UI). Truncation is particularly dangerous because it often occurs silently without error messages.
