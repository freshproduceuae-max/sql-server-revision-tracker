# G04-T03 — Format/Pattern | Postcode / ZIP Code Format

## ID
G04-T03

## Group
4 — Format/Pattern

## Type
Postcode / ZIP Code Format Validation

## Live Scenario
A UK retail company runs a geo-targeted promotions campaign. The CRM has 120,000 customer addresses. The postcode field contains: valid UK postcodes (`SW1A 1AA`), valid-but-unspaced (`SW1A1AA`), US ZIP codes entered by mistake (`90210`), numeric-only values (`12345`), placeholder text (`"UNKNOWN"`), and partial postcodes (`"SW1"`). The postcode-to-region lookup table fails to match 35% of records, skewing the regional sales report.

## The Question
> Postcode formats are country-specific and must match a defined pattern. UK postcodes follow the pattern `AN NAA`, `ANN NAA`, `AAN NAA`, or `AANN NAA` (A = letter, N = digit). A single LIKE pattern can validate all four UK outward code shapes.
> **"Find all customer records where the PostalCode does not match either the standard UK postcode format (with or without the middle space) or a valid US ZIP code format (5-digit or ZIP+4)."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- UK postcode validation (all 4 outward code formats + inward code AA NAA)
SELECT
    CustomerID,
    PostalCode,
    Country,
    'Invalid UK postcode format' AS Issue
FROM Customers
WHERE Country = 'UK'
  AND PostalCode IS NOT NULL
  AND PostalCode NOT LIKE '[A-Z][0-9] [0-9][A-Z][A-Z]'          -- AN NAA  (e.g. W1 1AA)
  AND PostalCode NOT LIKE '[A-Z][0-9][0-9] [0-9][A-Z][A-Z]'     -- ANN NAA (e.g. W1A 1AA → actually AAN)
  AND PostalCode NOT LIKE '[A-Z][A-Z][0-9] [0-9][A-Z][A-Z]'     -- AAN NAA (e.g. SW1 1AA)
  AND PostalCode NOT LIKE '[A-Z][A-Z][0-9][0-9] [0-9][A-Z][A-Z]'-- AANN NAA(e.g. SW1A 1AA)
  AND PostalCode NOT LIKE '[A-Z][0-9][A-Z] [0-9][A-Z][A-Z]'     -- ANA NAA (e.g. W1A 1AA)
  AND PostalCode NOT LIKE '[A-Z][A-Z][0-9][A-Z] [0-9][A-Z][A-Z]';-- AANA NAA(e.g. EC1A 1BB)

-- US ZIP code validation (5-digit or ZIP+4)
SELECT
    CustomerID,
    PostalCode,
    Country,
    'Invalid US ZIP code format' AS Issue
FROM Customers
WHERE Country = 'US'
  AND PostalCode IS NOT NULL
  AND PostalCode NOT LIKE '[0-9][0-9][0-9][0-9][0-9]'            -- 5-digit ZIP
  AND PostalCode NOT LIKE '[0-9][0-9][0-9][0-9][0-9]-[0-9][0-9][0-9][0-9]'; -- ZIP+4

-- Universal postcode check: flag anything that looks structurally wrong regardless of country
SELECT
    CustomerID,
    PostalCode,
    Country,
    CASE
        WHEN PostalCode IS NULL                             THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(PostalCode))) = 0             THEN 'Empty'
        WHEN PostalCode LIKE '%[^A-Z0-9 -]%'              THEN 'Invalid characters'
        WHEN LEN(LTRIM(RTRIM(PostalCode))) < 3             THEN 'Too short'
        WHEN LEN(LTRIM(RTRIM(PostalCode))) > 10            THEN 'Too long'
        WHEN PostalCode NOT LIKE '%[0-9]%'                 THEN 'No digits — likely placeholder'
        ELSE 'Plausible'
    END AS FormatCheck
FROM Customers
WHERE PostalCode IS NULL
   OR LEN(LTRIM(RTRIM(PostalCode))) < 3
   OR PostalCode LIKE '%[^A-Z0-9 -]%'
   OR PostalCode NOT LIKE '%[0-9]%';

-- Summary by postcode format category
SELECT
    Country,
    CASE
        WHEN PostalCode IS NULL                 THEN 'NULL'
        WHEN PostalCode NOT LIKE '%[0-9]%'      THEN 'No digits'
        WHEN LEN(REPLACE(PostalCode,' ','')) < 5 THEN 'Too short'
        ELSE 'Plausible'
    END AS FormatCategory,
    COUNT(*) AS CustomerCount
FROM Customers
GROUP BY Country,
    CASE
        WHEN PostalCode IS NULL                  THEN 'NULL'
        WHEN PostalCode NOT LIKE '%[0-9]%'       THEN 'No digits'
        WHEN LEN(REPLACE(PostalCode,' ','')) < 5  THEN 'Too short'
        ELSE 'Plausible'
    END
ORDER BY Country, CustomerCount DESC;
```

## Explanation

**UK postcode structure**
A UK postcode has two parts: outward code (2–4 characters) and inward code (always `NAA` — digit + 2 letters). The six valid outward code formats are: `AN`, `ANN`, `AAN`, `AANN`, `ANA`, `AANA`. The LIKE pattern must cover all six. Using `COLLATE Latin1_General_CS_AS` enforces case sensitivity if the column stores mixed-case values.

**LIKE bracket expressions `[A-Z]` and `[0-9]`**
SQL Server LIKE supports character class ranges inside `[` `]`. `[A-Z]` matches any single uppercase letter; `[0-9]` matches any single digit. These are not full regular expressions — there is no `+` (one or more) quantifier in LIKE. Each position must have its own bracketed expression, making postcode LIKE patterns verbose but explicit.

**When to use PATINDEX instead of LIKE**
`PATINDEX('%[^A-Z0-9 -]%', PostalCode)` returns the position of the first invalid character. This is more useful when you want to show WHERE in the string the violation occurs, not just that one exists. LIKE returns boolean; PATINDEX returns position.

**Country-specific patterns should be separated**
Mixing UK and US postcodes in one LIKE pattern produces false positives. Always filter by Country (or a region flag) before applying country-specific format rules.

## Severity
**Medium** — Invalid postcodes break geo-targeting, delivery routing, tax jurisdiction assignment, and regional reporting. In logistics, a bad postcode on a delivery order causes a failed delivery attempt with direct cost impact.
