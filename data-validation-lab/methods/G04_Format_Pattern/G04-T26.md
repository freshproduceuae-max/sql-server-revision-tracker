# G04-T26 — Format/Pattern | Credit Card Number Format

## ID
G04-T26

## Group
4 — Format/Pattern

## Type
Credit Card Number Format — Structure and Luhn Check Digit

## Live Scenario
A PCI-DSS compliant payment platform stores masked card numbers (`************1234`) for display and the last 4 digits separately. During a data migration from a legacy system, a developer discovers that the legacy system stored partial card numbers in multiple formats: `"4111111111111111"` (16 digits, valid Visa), `"4111-1111-1111-1111"` (with hyphens), `"4111 1111 1111 1111"` (with spaces), `"41111111111111"` (14 digits, invalid), and some fields still contain full unmasked card numbers (PCI violation). The migration must identify format inconsistencies and flag any unmasked numbers before transfer.

## The Question
> Credit card numbers have an Issuer Identification Number (IIN) prefix that identifies the card scheme, a variable length (typically 13–19 digits), and a Luhn check digit. SQL can validate length, prefix, and check digit.
> **"Find all Orders where the CardNumber field does not match a valid credit card length, has the wrong format (should be digits only after removing spaces/hyphens), or fails the Luhn check digit algorithm."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Normalise (remove spaces/hyphens) and validate length/prefix
SELECT
    OrderID,
    CardNumber,
    REPLACE(REPLACE(CardNumber, ' ', ''), '-', '') AS NormalisedCard,
    LEN(REPLACE(REPLACE(CardNumber, ' ', ''), '-', '')) AS DigitCount,
    CASE
        WHEN CardNumber IS NULL                                         THEN 'NULL'
        WHEN REPLACE(REPLACE(CardNumber,' ',''),'-','') LIKE '%[^0-9*]%'
             THEN 'Contains non-numeric characters (other than spaces, hyphens, or mask *)'
        WHEN LEN(REPLACE(REPLACE(CardNumber,' ',''),'-','')) NOT BETWEEN 13 AND 19
             THEN 'Invalid length: ' + CAST(LEN(REPLACE(REPLACE(CardNumber,' ',''),'-','')) AS VARCHAR) + ' digits'
        -- Visa: starts with 4, 13 or 16 digits
        WHEN LEFT(REPLACE(REPLACE(CardNumber,' ',''),'-',''),1) = '4'
             AND LEN(REPLACE(REPLACE(CardNumber,' ',''),'-','')) IN (13,16) THEN 'Visa format'
        -- Mastercard: starts with 51-55, 16 digits
        WHEN LEFT(REPLACE(REPLACE(CardNumber,' ',''),'-',''),2) BETWEEN '51' AND '55'
             AND LEN(REPLACE(REPLACE(CardNumber,' ',''),'-','')) = 16 THEN 'Mastercard format'
        -- Amex: starts with 34 or 37, 15 digits
        WHEN LEFT(REPLACE(REPLACE(CardNumber,' ',''),'-',''),2) IN ('34','37')
             AND LEN(REPLACE(REPLACE(CardNumber,' ',''),'-','')) = 15 THEN 'Amex format'
        ELSE 'Unknown card scheme or invalid prefix/length combination'
    END AS CardFormatCheck
FROM Orders
WHERE CardNumber IS NOT NULL;

-- Step 2: Luhn algorithm implementation
-- Double every second digit from right, subtract 9 if > 9, sum all, total mod 10 = 0
WITH CardDigits AS (
    SELECT
        OrderID,
        REPLACE(REPLACE(CardNumber,' ',''),'-','') AS Card
    FROM Orders
    WHERE CardNumber IS NOT NULL
      AND REPLACE(REPLACE(CardNumber,' ',''),'-','') NOT LIKE '%[^0-9]%'
      AND LEN(REPLACE(REPLACE(CardNumber,' ',''),'-','')) BETWEEN 13 AND 19
),
LuhnCalc AS (
    SELECT
        OrderID,
        Card,
        LEN(Card) AS CardLen,
        -- Sum of digits at odd positions from right (1st, 3rd, 5th... from right = even positions from left for 16-digit)
        -- This is a simplified approach for 16-digit Visa cards
        (
            CAST(SUBSTRING(Card,16,1) AS INT) +
            CAST(SUBSTRING(Card,14,1) AS INT) +
            CAST(SUBSTRING(Card,12,1) AS INT) +
            CAST(SUBSTRING(Card,10,1) AS INT) +
            CAST(SUBSTRING(Card, 8,1) AS INT) +
            CAST(SUBSTRING(Card, 6,1) AS INT) +
            CAST(SUBSTRING(Card, 4,1) AS INT) +
            CAST(SUBSTRING(Card, 2,1) AS INT) +
            -- Doubled digits (even positions from right), subtract 9 if > 9
            CASE WHEN CAST(SUBSTRING(Card,15,1) AS INT)*2 > 9 THEN CAST(SUBSTRING(Card,15,1) AS INT)*2-9 ELSE CAST(SUBSTRING(Card,15,1) AS INT)*2 END +
            CASE WHEN CAST(SUBSTRING(Card,13,1) AS INT)*2 > 9 THEN CAST(SUBSTRING(Card,13,1) AS INT)*2-9 ELSE CAST(SUBSTRING(Card,13,1) AS INT)*2 END +
            CASE WHEN CAST(SUBSTRING(Card,11,1) AS INT)*2 > 9 THEN CAST(SUBSTRING(Card,11,1) AS INT)*2-9 ELSE CAST(SUBSTRING(Card,11,1) AS INT)*2 END +
            CASE WHEN CAST(SUBSTRING(Card, 9,1) AS INT)*2 > 9 THEN CAST(SUBSTRING(Card, 9,1) AS INT)*2-9 ELSE CAST(SUBSTRING(Card, 9,1) AS INT)*2 END +
            CASE WHEN CAST(SUBSTRING(Card, 7,1) AS INT)*2 > 9 THEN CAST(SUBSTRING(Card, 7,1) AS INT)*2-9 ELSE CAST(SUBSTRING(Card, 7,1) AS INT)*2 END +
            CASE WHEN CAST(SUBSTRING(Card, 5,1) AS INT)*2 > 9 THEN CAST(SUBSTRING(Card, 5,1) AS INT)*2-9 ELSE CAST(SUBSTRING(Card, 5,1) AS INT)*2 END +
            CASE WHEN CAST(SUBSTRING(Card, 3,1) AS INT)*2 > 9 THEN CAST(SUBSTRING(Card, 3,1) AS INT)*2-9 ELSE CAST(SUBSTRING(Card, 3,1) AS INT)*2 END +
            CASE WHEN CAST(SUBSTRING(Card, 1,1) AS INT)*2 > 9 THEN CAST(SUBSTRING(Card, 1,1) AS INT)*2-9 ELSE CAST(SUBSTRING(Card, 1,1) AS INT)*2 END
        ) AS LuhnSum
    FROM CardDigits
    WHERE LEN(Card) = 16  -- Luhn for 16-digit cards
)
SELECT
    OrderID,
    Card,
    LuhnSum,
    LuhnSum % 10 AS LuhnMod10,
    CASE
        WHEN LuhnSum % 10 = 0 THEN 'Luhn check PASSED'
        ELSE 'Luhn check FAILED — invalid card number'
    END AS LuhnResult
FROM LuhnCalc;

-- Step 3: Detect unmasked card numbers (PCI-DSS violation)
SELECT
    OrderID,
    CardNumber,
    'WARNING: Appears to be an unmasked card number — PCI-DSS violation' AS SecurityAlert
FROM Orders
WHERE CardNumber IS NOT NULL
  AND REPLACE(REPLACE(CardNumber,' ',''),'-','') NOT LIKE '%[^0-9]%'
  AND LEN(REPLACE(REPLACE(CardNumber,' ',''),'-','')) BETWEEN 13 AND 19;
```

## Expected Output

**Step 1 — Format check:**
| OrderID | CardNumber | DigitCount | CardFormatCheck |
|---|---|---|---|
| 1001 | 4111111111111111 | 16 | Visa format |
| 1003 | 4111-1111-1111-1111 | 16 | Visa format |
| 1007 | 41111111111111 | 14 | Invalid length: 14 digits |

**Step 2 — Luhn check:**
| OrderID | Card | LuhnSum | LuhnMod10 | LuhnResult |
|---|---|---|---|---|
| 1001 | 4111111111111111 | 20 | 0 | Luhn check PASSED |
| 1005 | 4111111111111112 | 21 | 1 | Luhn check FAILED |

## Explanation

**The Luhn algorithm**
Start from the rightmost digit (check digit), moving left: every second digit is doubled; if the doubled value > 9, subtract 9. Sum all digits. A valid card number produces a sum divisible by 10 (mod 10 = 0). The 16-digit implementation in Step 2 is hard-coded to 16 positions for clarity.

**IIN (Issuer Identification Number) prefixes**
The first 6 digits of a card number identify the card scheme and issuer. Common ranges: Visa starts with 4; Mastercard starts with 51–55 (or newer 2221–2720 range); Amex starts with 34 or 37; Discover starts with 6011, 622, 64, 65. Length varies by scheme: Visa 13 or 16, Mastercard 16, Amex 15.

**PCI-DSS and card data**
The PCI Data Security Standard prohibits storing full card numbers in plaintext. Step 3 flags any value that looks like an unmasked 13–19 digit number as a PCI-DSS compliance alert. The query itself is educational — in a real PCI environment, access to this column should be restricted and audited.

**Test card numbers**
`4111111111111111` is a widely used Visa test number (Luhn-valid). `4111111111111112` fails the Luhn check. These are safe to use in non-production testing because no real account is associated with them.

## Severity
**Critical** — Credit card format errors cause payment processing failures. Unmasked card numbers in a database are a PCI-DSS violation that triggers mandatory breach reporting, fines, and potential loss of card processing capability.
