# G04-T12 — Format/Pattern | Case Convention Violation

## ID
G04-T12

## Group
4 — Format/Pattern

## Type
Case Convention Violation — Mixed Case, Wrong Case, or Inconsistent Capitalisation

## Live Scenario
A CRM exports customer records to a downstream marketing platform. The platform uses case-sensitive string matching to deduplicate contacts and merge campaign responses. The CRM has accumulated `"JOHN SMITH"`, `"John Smith"`, `"john smith"`, `"JOHN smith"`, and `"John  SMITH"` for the same person. The deduplication logic treats each variant as a different person. The customer receives 5 versions of the same promotional email. An unsubscribe from `"JOHN SMITH"` doesn't suppress emails to `"john smith"`.

## The Question
> Case inconsistency causes false duplicates in case-sensitive systems and breaks string matching. A consistent convention — Title Case for names, UPPERCASE for codes, lowercase for emails — should be enforced across the column.
> **"Find all Customers where FirstName or LastName is entirely uppercase, entirely lowercase, or has inconsistent capitalisation (first letter lowercase when it should be uppercase)."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Detect case convention violations in name fields
SELECT
    CustomerID,
    FirstName,
    LastName,
    CASE
        WHEN FirstName IS NULL                          THEN 'FirstName: NULL'
        WHEN FirstName = UPPER(FirstName)              THEN 'FirstName: ALL CAPS'
        WHEN FirstName = LOWER(FirstName)              THEN 'FirstName: all lowercase'
        WHEN LEFT(FirstName, 1) = LOWER(LEFT(FirstName, 1))
                                                        THEN 'FirstName: starts with lowercase'
        ELSE 'FirstName: OK (appears Title Case)'
    END AS FirstNameCaseCheck,
    CASE
        WHEN LastName IS NULL                           THEN 'LastName: NULL'
        WHEN LastName = UPPER(LastName)                THEN 'LastName: ALL CAPS'
        WHEN LastName = LOWER(LastName)                THEN 'LastName: all lowercase'
        WHEN LEFT(LastName, 1) = LOWER(LEFT(LastName, 1))
                                                        THEN 'LastName: starts with lowercase'
        ELSE 'LastName: OK (appears Title Case)'
    END AS LastNameCaseCheck
FROM Customers
WHERE FirstName = UPPER(FirstName)
   OR FirstName = LOWER(FirstName)
   OR LastName  = UPPER(LastName)
   OR LastName  = LOWER(LastName)
   OR LEFT(FirstName, 1) = LOWER(LEFT(FirstName, 1))
   OR LEFT(LastName,  1) = LOWER(LEFT(LastName,  1));

-- Step 2: Detect ALL-CAPS product names (should be Title Case)
SELECT
    ProductID,
    ProductName,
    'ProductName is ALL CAPS' AS Issue
FROM Products
WHERE ProductName = UPPER(ProductName)
  AND ProductName NOT LIKE '%[^A-Z ]%';  -- ensure it's actual letters, not code

-- Step 3: Detect lowercase email addresses that have uppercase (emails should be lowercase)
SELECT
    CustomerID,
    Email,
    LOWER(Email) AS ExpectedEmail,
    'Email contains uppercase — should be all lowercase' AS Issue
FROM Customers
WHERE Email <> LOWER(Email)
  AND Email IS NOT NULL;

-- Step 4: Detect inconsistent country/status codes (should be UPPERCASE)
SELECT
    CustomerID,
    Country,
    Status,
    CASE
        WHEN Country <> UPPER(Country)  THEN 'Country code not uppercase'
        ELSE 'Country OK'
    END AS CountryCase,
    CASE
        WHEN Status <> UPPER(Status)    THEN 'Status not uppercase'
        ELSE 'Status OK'
    END AS StatusCase
FROM Customers
WHERE Country <> UPPER(Country)
   OR Status <> UPPER(Status);

-- Step 5: Show corrected values for bulk update
SELECT
    CustomerID,
    FirstName                                                AS CurrentFirstName,
    -- Title Case approximation: uppercase first letter, lowercase rest
    UPPER(LEFT(LTRIM(FirstName), 1)) + LOWER(SUBSTRING(LTRIM(FirstName), 2, LEN(FirstName)))
                                                             AS SuggestedFirstName,
    LastName                                                 AS CurrentLastName,
    UPPER(LEFT(LTRIM(LastName), 1)) + LOWER(SUBSTRING(LTRIM(LastName), 2, LEN(LastName)))
                                                             AS SuggestedLastName
FROM Customers
WHERE FirstName = UPPER(FirstName) OR FirstName = LOWER(FirstName)
   OR LastName  = UPPER(LastName)  OR LastName  = LOWER(LastName);
```

## Expected Output

**Step 1 — Case violations:**
| CustomerID | FirstName | LastName | FirstNameCaseCheck | LastNameCaseCheck |
|---|---|---|---|---|
| 3 | JOHN | SMITH | FirstName: ALL CAPS | LastName: ALL CAPS |
| 8 | jane | doe | FirstName: all lowercase | LastName: all lowercase |
| 14 | alice | JONES | FirstName: all lowercase | LastName: ALL CAPS |

**Step 5 — Suggested corrections:**
| CustomerID | CurrentFirstName | SuggestedFirstName | CurrentLastName | SuggestedLastName |
|---|---|---|---|---|
| 3 | JOHN | John | SMITH | Smith |
| 8 | jane | Jane | doe | Doe |

## Explanation

**`value = UPPER(value)` as an ALL-CAPS test**
Comparing a string to its own UPPER version is the simplest ALL-CAPS test. If they're equal, the string is already all uppercase. Similarly, `value = LOWER(value)` tests for all lowercase. These comparisons are case-sensitive when the column collation is case-sensitive (CS); on case-insensitive (CI) collations, use `CAST(value AS VARCHAR) COLLATE Latin1_General_CS_AS`.

**Title Case approximation for single-word values**
`UPPER(LEFT(value, 1)) + LOWER(SUBSTRING(value, 2, LEN(value)))` uppercases the first letter and lowercases the rest. This works for single-word names (`john` → `John`) but is insufficient for multi-word names with internal capitalisation (`MCDONALD` → `Mcdonald` instead of `McDonald`). More sophisticated Title Case requires a function or application-layer processing.

**Email addresses should always be lowercase**
Email local parts are technically case-sensitive per RFC 5321 but in practice all major email providers treat them as case-insensitive. Storing emails as lowercase prevents duplicate detection failures in case-sensitive joins and ensures consistent LIKE pattern matching.

**Codes vs names have opposite case conventions**
Country codes (`GB`, `US`) and status codes (`ACTIVE`, `PENDING`) are conventionally ALL CAPS. Personal names are conventionally Title Case. Product names are mixed — validate against the specific convention for each column type.

## Severity
**Medium** — Case inconsistency causes false duplicates in case-sensitive string matching, breaks sorting (uppercase letters sort before lowercase in most collations), and produces poor-quality data in customer-facing communications. In identity systems, case variants of the same name may bypass duplicate detection entirely.
