# G04-T02 — Format/Pattern | Phone Number Format

## ID
G04-T02

## Group
4 — Format/Pattern

## Type
Phone Number Format Validation

## Live Scenario
A contact centre stores customer phone numbers in a VARCHAR(50) column with no input mask. Over three years the column has accumulated: `"07911 123456"`, `"07911123456"`, `"+447911123456"`, `"(0044) 7911-123456"`, `"07911-123-456"`, `"call me on mobile"`, and `"N/A"`. An outbound dialler system requires numbers in E.164 format (`+447911123456`). The normalisation script fails on 40% of rows because the data is too inconsistent to parse reliably.

## The Question
> Phone number fields are among the most inconsistently formatted columns in any database. A single phone number can be expressed in dozens of valid-looking but incompatible formats.
> **"Find all customers where the Phone column does not contain a plausible phone number — specifically: flag values that contain non-numeric characters (other than +, -, space, and parentheses), are too short, are too long, or contain only letters/placeholders."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Flag structural phone number violations
SELECT
    CustomerID,
    FirstName,
    LastName,
    Phone,
    CASE
        WHEN Phone IS NULL                                          THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(Phone))) = 0                          THEN 'Empty'
        WHEN Phone LIKE '%[A-Za-z]%'                               THEN 'Contains letters'
        WHEN LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
                Phone, '+',''), '-',''), ' ',''), '(',''), ')',''))
             < 7                                                    THEN 'Too short (< 7 digits)'
        WHEN LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
                Phone, '+',''), '-',''), ' ',''), '(',''), ')',''))
             > 15                                                   THEN 'Too long (> 15 digits, E.164 max)'
        WHEN Phone LIKE '%[^0-9+() -]%'                           THEN 'Contains invalid characters'
        ELSE 'Format OK'
    END AS ValidationResult
FROM Customers
WHERE Phone IS NULL
   OR LEN(LTRIM(RTRIM(Phone))) = 0
   OR Phone LIKE '%[A-Za-z]%'
   OR Phone LIKE '%[^0-9+() -]%'
   OR LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
       Phone, '+',''), '-',''), ' ',''), '(',''), ')','')) < 7
   OR LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
       Phone, '+',''), '-',''), ' ',''), '(',''), ')','')) > 15;

-- Step 2: Extract digit-only count for length validation
SELECT
    CustomerID,
    Phone,
    LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
        Phone, '+',''), '-',''), ' ',''), '(',''), ')','')) AS DigitCount,
    CASE
        WHEN LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
             Phone, '+',''), '-',''), ' ',''), '(',''), ')','')) BETWEEN 7 AND 15
        THEN 'Plausible digit count'
        ELSE 'Invalid digit count'
    END AS LengthCheck
FROM Customers
WHERE Phone IS NOT NULL;

-- Step 3: Normalisation preview — what the phone would look like stripped to digits
SELECT
    CustomerID,
    Phone AS OriginalPhone,
    REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
        Phone, '+',''), '-',''), ' ',''), '(',''), ')','') AS DigitsOnly
FROM Customers
WHERE Phone IS NOT NULL
  AND Phone NOT LIKE '%[A-Za-z]%';

-- Step 4: Summary by format violation type
SELECT
    CASE
        WHEN Phone IS NULL              THEN 'NULL'
        WHEN Phone LIKE '%[A-Za-z]%'   THEN 'Contains letters'
        WHEN LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
             Phone,'+',''),'-',''),' ',''),'(',''),')','')) < 7  THEN 'Too short'
        WHEN LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
             Phone,'+',''),'-',''),' ',''),'(',''),')','')) > 15 THEN 'Too long'
        ELSE 'Plausible'
    END AS FormatCategory,
    COUNT(*) AS Count
FROM Customers
GROUP BY
    CASE
        WHEN Phone IS NULL              THEN 'NULL'
        WHEN Phone LIKE '%[A-Za-z]%'   THEN 'Contains letters'
        WHEN LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
             Phone,'+',''),'-',''),' ',''),'(',''),')','')) < 7  THEN 'Too short'
        WHEN LEN(REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
             Phone,'+',''),'-',''),' ',''),'(',''),')','')) > 15 THEN 'Too long'
        ELSE 'Plausible'
    END;
```

## Explanation

**Strip-then-count pattern**
Removing formatting characters (`+`, `-`, space, `(`, `)`) with nested REPLACE calls gives the raw digit count. This lets you validate length independently of whatever formatting convention the data entry used. The E.164 international standard allows 7–15 digits maximum.

**`LIKE '%[^0-9+() -]%'`** 
The `[^ ]` bracket expression inside LIKE matches any character NOT in the set. This catches characters that are never valid in a phone field: `@`, `#`, `*`, commas, letters, etc.

**Why this isn't a definitive validator**
A 10-digit US number and a 10-digit UK mobile share the same digit count but different structures. SQL can verify plausibility (right length, no letters) but not validity (is this a real number in the right country format). Country-specific format rules (US: `(NXX) NXX-XXXX`, UK: `07XXX XXXXXX`) require additional LIKE patterns per region.

**Normalisation as a follow-up step**
Step 3 shows what the phone looks like after stripping formatting. This output can feed an UPDATE statement that standardises all numbers to digits-only or E.164 format as a cleansing operation (see G19 Cleansing Operations).

## Severity
**Medium** — Invalid phone numbers cause outbound contact failures but rarely break downstream systems. Impact escalates to High in call centre, emergency services, and two-factor authentication contexts where reaching the customer is operationally critical.
