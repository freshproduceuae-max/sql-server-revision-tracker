# G04-T11 — Format/Pattern | Product Code / SKU Format

## ID
G04-T11

## Group
4 — Format/Pattern

## Type
Product Code / SKU Format Validation

## Live Scenario
A warehouse management system assigns SKUs to every product using the format `CAT-SUBCAT-NNNNNN` (category code, sub-category code, 6-digit sequence number, e.g., `ELC-MOB-000042`). A bulk product import from a supplier delivers 3,000 SKUs in their own format. The import team maps them manually. The results include: `"ELC-MOB-000042"` (correct), `"ELC-MOB-42"` (sequence not zero-padded), `"ELCMOB000042"` (hyphens missing), `"ELC-MOB-000042-B"` (extra suffix added), `"ELC--000042"` (empty sub-category), and free text like `"see supplier catalogue"`. The WMS cannot locate these items in the pick list.

## The Question
> Product codes and SKUs follow organisation-specific format rules: fixed-length segments, required separators, character class restrictions per segment, and optional check suffixes. LIKE pattern matching enforces these rules precisely.
> **"Find all Products where ProductCode does not match the required format: 3 uppercase letters, hyphen, 3 uppercase letters, hyphen, 6 digits (e.g., ELC-MOB-000042)."**

## Table Reference
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Validate ProductCode against required format CAT-SUB-NNNNNN
SELECT
    ProductID,
    ProductName,
    ProductCode,
    CASE
        WHEN ProductCode IS NULL
             THEN 'NULL — no product code'
        WHEN LEN(ProductCode) <> 14
             THEN 'Wrong length (expected 14: AAA-BBB-NNNNNN)'
        WHEN ProductCode NOT LIKE '[A-Z][A-Z][A-Z]-[A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]'
             THEN 'Pattern mismatch (expected 3 letters - 3 letters - 6 digits)'
        ELSE 'Valid'
    END AS CodeValidation
FROM Products;

-- Step 2: Decompose the code to validate each segment independently
SELECT
    ProductID,
    ProductCode,
    LEFT(ProductCode, 3)            AS CategoryCode,
    SUBSTRING(ProductCode, 5, 3)    AS SubCategoryCode,
    RIGHT(ProductCode, 6)           AS SequenceNumber,
    CASE
        WHEN LEFT(ProductCode, 3) NOT LIKE '[A-Z][A-Z][A-Z]'          THEN 'Category: must be 3 uppercase letters'
        WHEN SUBSTRING(ProductCode, 4, 1) <> '-'                       THEN 'First hyphen missing at position 4'
        WHEN SUBSTRING(ProductCode, 5, 3) NOT LIKE '[A-Z][A-Z][A-Z]'  THEN 'Sub-category: must be 3 uppercase letters'
        WHEN SUBSTRING(ProductCode, 8, 1) <> '-'                       THEN 'Second hyphen missing at position 8'
        WHEN RIGHT(ProductCode, 6) NOT LIKE '[0-9][0-9][0-9][0-9][0-9][0-9]'
                                                                        THEN 'Sequence: must be 6 digits'
        ELSE 'All segments valid'
    END AS SegmentValidation
FROM Products
WHERE ProductCode IS NOT NULL
  AND LEN(ProductCode) = 14;

-- Step 3: Check for valid category codes against known list
SELECT
    p.ProductID,
    p.ProductCode,
    LEFT(p.ProductCode, 3) AS CategoryCode,
    CASE
        WHEN LEFT(p.ProductCode, 3) NOT IN ('ELC','CLO','FUR','TOY','FDS','SPT')
             THEN 'Unknown category code — not in approved list'
        ELSE 'Valid category'
    END AS CategoryCheck
FROM Products p
WHERE p.ProductCode LIKE '[A-Z][A-Z][A-Z]-[A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]';

-- Step 4: Duplicate sequence number check within the same category
SELECT
    LEFT(ProductCode, 7) AS CategorySubcat,
    RIGHT(ProductCode, 6) AS Sequence,
    COUNT(*) AS ProductCount,
    STRING_AGG(ProductID, ', ') AS ProductIDs
FROM Products
WHERE ProductCode LIKE '[A-Z][A-Z][A-Z]-[A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]'
GROUP BY LEFT(ProductCode, 7), RIGHT(ProductCode, 6)
HAVING COUNT(*) > 1
ORDER BY ProductCount DESC;

-- Step 5: Summary counts
SELECT
    CASE
        WHEN ProductCode IS NULL                                                          THEN 'NULL'
        WHEN ProductCode LIKE '[A-Z][A-Z][A-Z]-[A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]'
                                                                                          THEN 'Valid'
        ELSE 'Invalid format'
    END AS CodeStatus,
    COUNT(*) AS ProductCount
FROM Products
GROUP BY
    CASE
        WHEN ProductCode IS NULL                                                          THEN 'NULL'
        WHEN ProductCode LIKE '[A-Z][A-Z][A-Z]-[A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]'
                                                                                          THEN 'Valid'
        ELSE 'Invalid format'
    END;
```

## Explanation

**Fixed-length LIKE pattern is the right tool for structured codes**
When a code has a fixed total length and fixed-length segments, `LIKE '[A-Z][A-Z][A-Z]-...'` is precise and readable. Each character position is explicitly validated. This is more reliable than a regex-equivalent because LIKE patterns make each position's rule visible.

**Segment decomposition for better error messages**
Step 2 decomposes the code into named segments using LEFT, SUBSTRING, and RIGHT. This produces a specific error message ("Sub-category: must be 3 uppercase letters") rather than just "pattern mismatch," which is essential when the import team needs to fix the data.

**Approved category code list**
A LIKE pattern validates structure but not semantics. `ZZZ-ZZZ-000001` passes the structural check but `ZZZ` may not be an approved category. Step 3 adds a business rule check: the category segment must be from a known list. Maintain this list in a reference table.

**Zero-padded sequence numbers**
`ELC-MOB-42` vs `ELC-MOB-000042` — the sequence number must be zero-padded to 6 digits. `RIGHT(ProductCode, 6) NOT LIKE '[0-9][0-9][0-9][0-9][0-9][0-9]'` catches both non-digits and sequences that are shorter than 6 characters.

## Severity
**High** — Invalid SKUs prevent warehouse management systems from locating items in pick lists, break barcode scanning, and cause inventory count discrepancies. In e-commerce, an invalid SKU means a product cannot be added to cart.
