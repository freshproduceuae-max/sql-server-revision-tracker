# G04-T05 — Format/Pattern | Numeric String Format

## ID
G04-T05

## Group
4 — Format/Pattern

## Type
Numeric String Format — Value Stored as Text Should Be a Number

## Live Scenario
A pricing system migrated from a legacy flat-file system stores all values in VARCHAR columns. The `UnitPrice` column contains: `"19.99"`, `"£19.99"`, `"19,99"` (European decimal comma), `"19.990"` (trailing zero in wrong position), `"FREE"`, `"TBC"`, and `"19.99 incl. VAT"`. When the accounting module tries to SUM the prices, it fails because the column is VARCHAR and the values are not uniformly numeric.

## The Question
> Numeric data stored as strings must be validated before aggregation or arithmetic. Values with currency symbols, thousand separators, text, or wrong decimal formats cannot be cast to DECIMAL without cleaning.
> **"Find all Products where the Price column (stored as VARCHAR) contains a value that cannot be safely converted to a DECIMAL number, or that contains non-numeric characters that would prevent arithmetic."**

## Table Reference
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Find values that cannot be cast to DECIMAL
SELECT
    ProductID,
    ProductName,
    Price,
    'Cannot convert to DECIMAL' AS Issue
FROM Products
WHERE TRY_CAST(Price AS DECIMAL(18,4)) IS NULL
  AND Price IS NOT NULL;

-- Step 2: Categorise non-numeric patterns
SELECT
    ProductID,
    ProductName,
    Price,
    CASE
        WHEN Price IS NULL                              THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(Price))) = 0              THEN 'Empty'
        WHEN Price LIKE '%[A-Za-z]%'                   THEN 'Contains letters'
        WHEN Price LIKE '%[£$€¥]%'                     THEN 'Contains currency symbol'
        WHEN Price LIKE '%,%'                           THEN 'Comma — decimal or thousands separator?'
        WHEN Price LIKE '% %'                          THEN 'Contains spaces'
        WHEN Price LIKE '%-%' AND Price NOT LIKE '-%'  THEN 'Embedded minus sign'
        WHEN TRY_CAST(Price AS DECIMAL(18,4)) IS NULL  THEN 'Other — unparseable'
        WHEN CAST(Price AS DECIMAL(18,4)) < 0          THEN 'Negative price'
        ELSE 'Valid numeric'
    END AS PriceIssue
FROM Products
WHERE Price IS NULL
   OR TRY_CAST(Price AS DECIMAL(18,4)) IS NULL
   OR (TRY_CAST(Price AS DECIMAL(18,4)) IS NOT NULL
       AND CAST(Price AS DECIMAL(18,4)) < 0);

-- Step 3: Attempt to clean common patterns and re-cast
SELECT
    ProductID,
    Price AS OriginalPrice,
    -- Remove currency symbols, spaces, commas (thousand separator)
    REPLACE(REPLACE(REPLACE(REPLACE(
        LTRIM(RTRIM(Price)),
        '£', ''), '$', ''), '€', ''), ',', '') AS CleanedString,
    TRY_CAST(
        REPLACE(REPLACE(REPLACE(REPLACE(
            LTRIM(RTRIM(Price)),
            '£', ''), '$', ''), '€', ''), ',', '')
    AS DECIMAL(18,4)) AS ParsedPrice
FROM Products
WHERE Price IS NOT NULL;

-- Step 4: Validate DECIMAL precision and scale
SELECT
    ProductID,
    Price,
    TRY_CAST(Price AS DECIMAL(18,4)) AS NumericValue,
    CASE
        WHEN CHARINDEX('.', Price) > 0
             AND LEN(Price) - CHARINDEX('.', Price) > 4 THEN 'Too many decimal places'
        WHEN TRY_CAST(Price AS DECIMAL(18,4)) > 999999  THEN 'Suspiciously large price'
        WHEN TRY_CAST(Price AS DECIMAL(18,4)) = 0       THEN 'Zero price — intentional?'
        ELSE 'OK'
    END AS PrecisionCheck
FROM Products
WHERE TRY_CAST(Price AS DECIMAL(18,4)) IS NOT NULL;
```

## Expected Output

**Step 1 — Non-convertible values:**
| ProductID | ProductName | Price | Issue |
|---|---|---|---|
| P003 | Widget A | £19.99 | Cannot convert to DECIMAL |
| P007 | Widget B | FREE | Cannot convert to DECIMAL |
| P011 | Widget C | 19,99 | Cannot convert to DECIMAL |

**Step 3 — After cleaning:**
| ProductID | OriginalPrice | CleanedString | ParsedPrice |
|---|---|---|---|
| P003 | £19.99 | 19.99 | 19.9900 |
| P007 | FREE | FREE | NULL |
| P011 | 19,99 | 1999 | 1999.0000 |

## Explanation

**TRY_CAST vs TRY_CONVERT for numerics**
Both work for simple numeric conversion. `TRY_CAST(val AS DECIMAL(18,4))` is sufficient for most cases. `TRY_CONVERT` accepts a style parameter but style codes for numeric types are limited — DECIMAL conversion doesn't support format codes the way DATE does.

**The comma ambiguity**
`19,99` could be `19.99` (European decimal comma) or `1999` (thousand separator in `1,999`). Blindly replacing commas with dots or removing them produces different results. This must be resolved by knowing the data's locale — not by guessing in SQL.

**Currency symbol removal order matters**
Removing `£` from `£19.99` leaves `19.99` which is castable. But if the string is `19.99 incl. VAT`, removing the currency symbol still leaves non-numeric text. Always validate after cleaning, not just before.

**Zero prices as a separate concern**
A price of `0` is a valid DECIMAL but may indicate a missing price rather than a free item. Flag it separately (Step 4) so business users can review intentional vs accidental zeros.

## Severity
**High** — Numeric strings that can't be cast to numbers cause aggregation queries to fail or silently exclude rows. In pricing, billing, and financial systems this produces incorrect totals that may not be noticed until reconciliation.
