# G04-T30 — Format/Pattern | Concatenated Name Format

## ID
G04-T30

## Group
4 — Format/Pattern

## Type
Concatenated Name Format — Full Name Split Inconsistency

## Live Scenario
A healthcare system stores patient names in three separate columns: `FirstName`, `MiddleName`, `LastName`. A third-party registration system sends names as a single `FullName` string. An import script splits on the first space to separate first and last name — `"John Michael Smith"` becomes `FirstName = "John"`, `LastName = "Michael Smith"` (middle name folded into last name). `"Mary-Jane Watson"` becomes `FirstName = "Mary-Jane"`, `LastName = "Watson"` (correct). `"Cher"` (mononym) becomes `FirstName = "Cher"`, `LastName = ""` (empty). The mis-splits cause prescription labels with wrong names and patient identity mismatches.

## The Question
> When a full name is split into parts, the split logic must handle: multiple spaces, hyphenated names, name prefixes (Dr., Mr.), name suffixes (Jr., III), mononyms (single-name people), and names with non-ASCII characters.
> **"Find all Customers where FirstName + LastName concatenation does not match a stored FullName field, or where LastName contains multiple words that suggest a mis-split (middle name absorbed into last name)."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Detect reconstructed name mismatch
-- Concatenate FirstName + ' ' + LastName and compare to FullName
SELECT
    CustomerID,
    FirstName,
    LastName,
    FullName,
    FirstName + ' ' + LastName AS ReconstructedName,
    CASE
        WHEN FullName IS NULL                               THEN 'FullName is NULL'
        WHEN LTRIM(RTRIM(FirstName + ' ' + LastName))
             = LTRIM(RTRIM(FullName))                      THEN 'Match'
        WHEN LTRIM(RTRIM(LOWER(FirstName + ' ' + LastName)))
             = LTRIM(RTRIM(LOWER(FullName)))               THEN 'Match (case-insensitive)'
        ELSE 'MISMATCH: parts do not reconstruct to FullName'
    END AS NameMatchCheck
FROM Customers
WHERE FullName IS NOT NULL
  AND LTRIM(RTRIM(LOWER(FirstName + ' ' + LastName))) <> LTRIM(RTRIM(LOWER(FullName)));

-- Step 2: Detect middle name potentially absorbed into LastName
-- Signal: LastName contains a space (suggests two words)
SELECT
    CustomerID,
    FirstName,
    LastName,
    CASE
        WHEN LastName LIKE '% %'                            THEN 'LastName contains space — possible mis-split (middle name absorbed)'
        WHEN FirstName LIKE '% %'                           THEN 'FirstName contains space — possible mis-split or compound name'
        ELSE 'Single-word names — split looks correct'
    END AS SplitCheck,
    CHARINDEX(' ', LastName) AS FirstSpaceInLastName
FROM Customers
WHERE LastName LIKE '% %' OR FirstName LIKE '% %';

-- Step 3: Detect empty LastName (mononym or failed split)
SELECT
    CustomerID,
    FirstName,
    LastName,
    FullName,
    CASE
        WHEN LastName IS NULL                               THEN 'LastName NULL — mononym or split failed'
        WHEN LEN(LTRIM(RTRIM(LastName))) = 0               THEN 'LastName empty — mononym or split failed'
        WHEN FirstName IS NULL OR LEN(LTRIM(RTRIM(FirstName))) = 0
                                                            THEN 'FirstName empty — only last name captured?'
        ELSE 'Both names present'
    END AS MononymCheck
FROM Customers
WHERE LastName IS NULL
   OR LEN(LTRIM(RTRIM(LastName))) = 0
   OR FirstName IS NULL
   OR LEN(LTRIM(RTRIM(FirstName))) = 0;

-- Step 4: Detect name prefixes/suffixes improperly absorbed into name fields
SELECT
    CustomerID,
    FirstName,
    LastName,
    CASE
        WHEN FirstName LIKE 'Dr.%' OR FirstName LIKE 'Mr.%' OR FirstName LIKE 'Mrs.%'
             OR FirstName LIKE 'Ms.%' OR FirstName LIKE 'Prof.%'
             THEN 'Prefix in FirstName: ' + LEFT(FirstName, CHARINDEX(' ', FirstName + ' ') - 1)
        ELSE 'No prefix'
    END AS PrefixCheck,
    CASE
        WHEN LastName LIKE '% Jr.' OR LastName LIKE '% Jr'
             OR LastName LIKE '% Sr.' OR LastName LIKE '% II'
             OR LastName LIKE '% III' OR LastName LIKE '% IV'
             THEN 'Suffix in LastName — should be in separate Suffix column'
        ELSE 'No suffix'
    END AS SuffixCheck
FROM Customers
WHERE FirstName LIKE 'Dr.%'   OR FirstName LIKE 'Mr.%'
   OR FirstName LIKE 'Mrs.%'  OR FirstName LIKE 'Prof.%'
   OR LastName LIKE '% Jr.'   OR LastName LIKE '% Jr'
   OR LastName LIKE '% III'   OR LastName LIKE '% II';

-- Step 5: Summary
SELECT
    SUM(CASE WHEN LastName LIKE '% %' THEN 1 ELSE 0 END) AS LastNameHasSpace,
    SUM(CASE WHEN FirstName LIKE '% %' THEN 1 ELSE 0 END) AS FirstNameHasSpace,
    SUM(CASE WHEN LEN(LTRIM(RTRIM(ISNULL(LastName,'')))) = 0 THEN 1 ELSE 0 END) AS EmptyLastName,
    COUNT(*) AS TotalCustomers
FROM Customers;
```

## Expected Output

**Step 2 — Split check:**
| CustomerID | FirstName | LastName | SplitCheck |
|---|---|---|---|
| 5 | John | Michael Smith | LastName contains space — possible mis-split |
| 9 | Mary-Jane | Watson | Single-word names — split looks correct |

**Step 3 — Mononym check:**
| CustomerID | FirstName | LastName | MononymCheck |
|---|---|---|---|
| 14 | Cher | (empty) | LastName empty — mononym or split failed |

## Explanation

**Split-on-first-space is the wrong algorithm for names**
Splitting on the first space fails for: `"Mary Jane"` (compound first name), `"John Michael Smith"` (middle name), `"Dr. Smith"` (prefix), `"Maria de la Cruz"` (multi-word surname). A robust name splitter must handle these cases explicitly.

**LastName containing a space as a mis-split signal**
In most Western naming conventions, a last name is a single word (with exceptions: `"de la Cruz"`, `"van der Berg"`). When LastName contains a space in a system that stores first+last separately, it's a reliable signal that a middle name or additional given name was absorbed.

**FullName as a ground truth comparison**
If both `FullName` and `FirstName/LastName` are stored, comparing the reconstructed name to the stored full name (Step 1) gives a definitive mismatch signal. This requires the FullName to be reliable — which must be verified separately.

**Mononyms are a real data quality challenge**
People with a single name (Cher, Adele, Prince) require special handling. Systems that require both first and last name will either: reject the record, leave one field blank, or repeat the single name in both fields (e.g., FirstName = `"Cher"`, LastName = `"Cher"`). All three patterns need to be detected.

## Severity
**Medium** — Name split errors cause patient misidentification (healthcare), incorrect legal documents, failed biometric matching, and customer communication errors. In healthcare, severity is Critical — a wrong patient name on a prescription is a patient safety issue.
