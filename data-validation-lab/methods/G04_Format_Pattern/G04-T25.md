# G04-T25 — Format/Pattern | Barcode / EAN Format

## ID
G04-T25

## Group
4 — Format/Pattern

## Type
Barcode / EAN / UPC Format Validation with Check Digit

## Live Scenario
A retail inventory system stores product barcodes in a `Barcode` column. Products use EAN-13 (13-digit European Article Number) and UPC-A (12-digit Universal Product Code). A supplier data feed delivers 4,000 new products. Spot checks find: valid EAN-13 (`5901234123457`), EAN-13 with wrong check digit (`5901234123456`), EAN-13 with 12 digits (missing check digit), UPC-A values treated as EAN-13, leading zeros stripped (`901234123457` instead of `0901234123457`), and placeholder codes (`999999999999`). The barcode scanner validates check digits at point of sale — 8% of scans fail.

## The Question
> EAN-13 barcodes use a modulo-10 check digit algorithm. The check digit is the last digit; the first 12 digits are weighted alternately by 1 and 3. Any structural error or check digit mismatch means the barcode is invalid.
> **"Find all Products where the Barcode is not a valid EAN-13 — wrong length, non-numeric characters, or a check digit that does not match the EAN-13 algorithm."**

## Table Reference
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Structural validation — must be 13 digits
SELECT
    ProductID,
    ProductName,
    Barcode,
    CASE
        WHEN Barcode IS NULL                                        THEN 'NULL'
        WHEN Barcode LIKE '%[^0-9]%'                               THEN 'Contains non-numeric characters'
        WHEN LEN(Barcode) <> 13                                    THEN 'Wrong length: ' + CAST(LEN(Barcode) AS VARCHAR) + ' digits (must be 13)'
        ELSE 'Structural check passed'
    END AS StructuralCheck
FROM Products
WHERE Barcode IS NULL
   OR Barcode LIKE '%[^0-9]%'
   OR LEN(Barcode) <> 13;

-- Step 2: EAN-13 check digit validation
-- Algorithm: weight each of first 12 digits alternately by 1 and 3
-- Sum = d1*1 + d2*3 + d3*1 + d4*3 + d5*1 + d6*3 + d7*1 + d8*3 + d9*1 + d10*3 + d11*1 + d12*3
-- Check digit = (10 - (Sum MOD 10)) MOD 10
SELECT
    ProductID,
    Barcode,
    -- Calculate weighted sum of first 12 digits
    (
        CAST(SUBSTRING(Barcode, 1,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 2,  1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 3,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 4,  1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 5,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 6,  1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 7,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 8,  1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 9,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 10, 1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 11, 1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 12, 1) AS INT) * 3
    ) % 10 AS WeightedSumMod10,
    (10 - (
        CAST(SUBSTRING(Barcode, 1,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 2,  1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 3,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 4,  1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 5,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 6,  1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 7,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 8,  1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 9,  1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 10, 1) AS INT) * 3 +
        CAST(SUBSTRING(Barcode, 11, 1) AS INT) * 1 +
        CAST(SUBSTRING(Barcode, 12, 1) AS INT) * 3
    ) % 10) % 10                                    AS ExpectedCheckDigit,
    CAST(SUBSTRING(Barcode, 13, 1) AS INT)          AS ActualCheckDigit,
    CASE
        WHEN CAST(SUBSTRING(Barcode,13,1) AS INT) =
             (10 - (
                CAST(SUBSTRING(Barcode,1,1)  AS INT)*1 +
                CAST(SUBSTRING(Barcode,2,1)  AS INT)*3 +
                CAST(SUBSTRING(Barcode,3,1)  AS INT)*1 +
                CAST(SUBSTRING(Barcode,4,1)  AS INT)*3 +
                CAST(SUBSTRING(Barcode,5,1)  AS INT)*1 +
                CAST(SUBSTRING(Barcode,6,1)  AS INT)*3 +
                CAST(SUBSTRING(Barcode,7,1)  AS INT)*1 +
                CAST(SUBSTRING(Barcode,8,1)  AS INT)*3 +
                CAST(SUBSTRING(Barcode,9,1)  AS INT)*1 +
                CAST(SUBSTRING(Barcode,10,1) AS INT)*3 +
                CAST(SUBSTRING(Barcode,11,1) AS INT)*1 +
                CAST(SUBSTRING(Barcode,12,1) AS INT)*3
             ) % 10) % 10
             THEN 'Check digit VALID'
        ELSE 'Check digit INVALID'
    END AS CheckDigitValidation
FROM Products
WHERE LEN(Barcode) = 13
  AND Barcode NOT LIKE '%[^0-9]%';

-- Step 3: Flag placeholder/test barcodes
SELECT
    ProductID,
    Barcode,
    CASE
        WHEN Barcode = REPLICATE(LEFT(Barcode,1), 13) THEN 'All same digit — placeholder'
        WHEN Barcode LIKE '999%'                       THEN 'Starts with 999 — often a test prefix'
        WHEN Barcode LIKE '000%'                       THEN 'Starts with 000 — likely leading-zero stripped'
        ELSE 'Not a placeholder'
    END AS PlaceholderCheck
FROM Products
WHERE LEN(Barcode) = 13;
```

## Explanation

**EAN-13 check digit algorithm**
The first 12 digits are weighted alternately 1 and 3 (positions 1,3,5,7,9,11 → weight 1; positions 2,4,6,8,10,12 → weight 3). Sum the weighted values. The check digit = `(10 - (sum mod 10)) mod 10`. The outer `mod 10` handles the case where the sum is divisible by 10 (making the inner expression 10, which should be 0).

**UPC-A is EAN-13 with a leading zero**
A 12-digit UPC-A becomes an EAN-13 by prepending `0`. `0901234123457` is the EAN-13 equivalent of UPC-A `901234123457`. If barcodes with 12 digits appear in a column expected to store EAN-13, check whether a leading zero was stripped by an import process.

**Why check digit validation matters**
A single transposition error in a 13-digit barcode (e.g., `...457` → `...475`) changes the check digit. The EAN-13 algorithm detects all single-digit errors and most transposition errors. This is the point of the check digit — it makes barcode transcription errors detectable.

**Placeholder detection (Step 3)**
`1111111111111`, `9999999999999`, and `0000000000000` are test barcodes that pass structural and check digit validation but are not real EAN-13 codes. Flag these separately for business review.

## Severity
**High** — Invalid barcodes cause scan failures at point of sale, warehouse pick failures, and inventory count errors. A check digit error on a barcode means the product cannot be scanned into or out of inventory, and must be manually keyed — increasing error rates and processing time.
