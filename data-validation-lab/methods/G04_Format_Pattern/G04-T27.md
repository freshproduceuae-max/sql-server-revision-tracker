# G04-T27 — Format/Pattern | Regex-Like Pattern Matching with PATINDEX

## ID
G04-T27

## Group
4 — Format/Pattern

## Type
Advanced Pattern Matching with PATINDEX — Validating Complex Custom Formats

## Live Scenario
A logistics company assigns shipment reference numbers in the format `LLNN-LLLL-NNNNNN` where `L` = uppercase letter and `N` = digit (e.g., `AB12-WXYZ-000042`). Standard LIKE works for simple patterns but becomes unwieldy for positions where the pattern rule is "one of several options." An operations team needs to validate 50,000 shipment references imported from partner systems, where some partners use the correct format, some use lowercase letters, some omit the hyphens, and some use their own internal reference format entirely.

## The Question
> `PATINDEX` returns the position of the first occurrence of a pattern, returning 0 if not found. Unlike LIKE (which returns true/false), PATINDEX can pinpoint WHERE in the string a violation occurs. It supports the same character class `[...]` syntax as LIKE.
> **"Use PATINDEX to validate Orders.OrderReference against the required format and, for invalid values, identify the exact character position where the format first violates the pattern."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Validate OrderReference format AA99-AAAA-999999 using LIKE
-- Then use PATINDEX to locate the first invalid character in failures
SELECT
    OrderID,
    OrderReference,
    -- LIKE validates the full pattern
    CASE
        WHEN OrderReference IS NULL                                     THEN 'NULL'
        WHEN OrderReference LIKE
             '[A-Z][A-Z][0-9][0-9]-[A-Z][A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]'
                                                                        THEN 'Valid'
        ELSE 'Invalid'
    END AS FormatCheck,
    -- PATINDEX finds the first non-uppercase-letter in the first segment
    PATINDEX('%[^A-Z]%', LEFT(OrderReference, 2))           AS FirstSegmentLetterError,
    -- PATINDEX finds first non-digit in the second part of first segment
    PATINDEX('%[^0-9]%', SUBSTRING(OrderReference, 3, 2))   AS FirstSegmentDigitError,
    -- Full invalid character check: find any char outside allowed set
    PATINDEX('%[^A-Z0-9-]%', ISNULL(OrderReference,''))     AS FirstInvalidCharPosition
FROM Orders
WHERE OrderReference IS NOT NULL
  AND OrderReference NOT LIKE
      '[A-Z][A-Z][0-9][0-9]-[A-Z][A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]';

-- Step 2: Segment-by-segment validation using PATINDEX
SELECT
    OrderID,
    OrderReference,
    -- Segment 1: first 2 chars must be uppercase letters
    CASE
        WHEN PATINDEX('%[^A-Z]%', LEFT(ISNULL(OrderReference,''), 2)) > 0
             THEN 'Segment 1 error at position ' + CAST(PATINDEX('%[^A-Z]%', LEFT(OrderReference,2)) AS VARCHAR)
        ELSE 'Segment 1 OK'
    END AS Segment1Check,
    -- Segment 2: chars 3-4 must be digits
    CASE
        WHEN PATINDEX('%[^0-9]%', SUBSTRING(ISNULL(OrderReference,''), 3, 2)) > 0
             THEN 'Segment 2 error (positions 3-4 must be digits)'
        ELSE 'Segment 2 OK'
    END AS Segment2Check,
    -- Position 5 must be hyphen
    CASE
        WHEN SUBSTRING(ISNULL(OrderReference,''), 5, 1) <> '-'
             THEN 'First hyphen missing at position 5'
        ELSE 'First hyphen OK'
    END AS Hyphen1Check,
    -- Segment 3: chars 6-9 must be uppercase letters
    CASE
        WHEN PATINDEX('%[^A-Z]%', SUBSTRING(ISNULL(OrderReference,''), 6, 4)) > 0
             THEN 'Segment 3 error at position ' + CAST(5 + PATINDEX('%[^A-Z]%', SUBSTRING(OrderReference,6,4)) AS VARCHAR)
        ELSE 'Segment 3 OK'
    END AS Segment3Check,
    -- Position 10 must be hyphen
    CASE
        WHEN SUBSTRING(ISNULL(OrderReference,''), 10, 1) <> '-'
             THEN 'Second hyphen missing at position 10'
        ELSE 'Second hyphen OK'
    END AS Hyphen2Check,
    -- Segment 4: chars 11-16 must be digits
    CASE
        WHEN PATINDEX('%[^0-9]%', SUBSTRING(ISNULL(OrderReference,''), 11, 6)) > 0
             THEN 'Segment 4 error at position ' + CAST(10 + PATINDEX('%[^0-9]%', SUBSTRING(OrderReference,11,6)) AS VARCHAR)
        ELSE 'Segment 4 OK'
    END AS Segment4Check
FROM Orders
WHERE OrderReference IS NOT NULL;

-- Step 3: Use PATINDEX to find all positions of a pattern in a string (simulate global search)
-- Find the position of every digit in the first 4 characters of OrderReference
SELECT
    OrderID,
    OrderReference,
    PATINDEX('%[0-9]%', LEFT(OrderReference, 2)) AS FirstDigitInLetterSegment,
    CASE
        WHEN PATINDEX('%[0-9]%', LEFT(OrderReference, 2)) > 0
             THEN 'Digit found in letter-only segment at position ' +
                  CAST(PATINDEX('%[0-9]%', LEFT(OrderReference, 2)) AS VARCHAR)
        ELSE 'No digit in letter segment'
    END AS LetterSegmentCheck
FROM Orders
WHERE OrderReference IS NOT NULL;

-- Step 4: PATINDEX vs LIKE performance note — summary with counts
SELECT
    CASE
        WHEN OrderReference IS NULL THEN 'NULL'
        WHEN OrderReference LIKE '[A-Z][A-Z][0-9][0-9]-[A-Z][A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]'
                            THEN 'Valid'
        ELSE 'Invalid'
    END AS Status,
    COUNT(*) AS OrderCount
FROM Orders
GROUP BY
    CASE
        WHEN OrderReference IS NULL THEN 'NULL'
        WHEN OrderReference LIKE '[A-Z][A-Z][0-9][0-9]-[A-Z][A-Z][A-Z][A-Z]-[0-9][0-9][0-9][0-9][0-9][0-9]'
                            THEN 'Valid'
        ELSE 'Invalid'
    END;
```

## Explanation

**PATINDEX vs LIKE: the key difference**
`LIKE` returns true/false (1/0). `PATINDEX` returns the position of the first match (or 0 if no match). For validation, LIKE is more readable; for diagnosis, PATINDEX tells you WHERE the problem is. Use LIKE to filter invalid rows; use PATINDEX to produce actionable error messages.

**Character class negation `[^...]`**
`PATINDEX('%[^A-Z]%', value)` returns the position of the first character that is NOT an uppercase letter. This is the primary tool for "find the first invalid character in this segment." The `^` inside `[]` negates the class, exactly as in LIKE patterns.

**Segment isolation with SUBSTRING before PATINDEX**
`PATINDEX('%[^A-Z]%', LEFT(OrderReference, 2))` searches only the first 2 characters, not the whole string. This gives position within the segment. To convert to absolute string position, add the segment's starting offset: `5 + PATINDEX(...)` for a segment starting at position 6.

**PATINDEX with LIKE for a two-step approach**
A common pattern: use LIKE for the initial filter (find all invalid rows efficiently), then use PATINDEX only on the failed rows to generate specific error messages. Running PATINDEX on every row is more expensive than LIKE filtering first.

## Severity
**Medium** — PATINDEX is primarily a diagnostic tool used in data quality investigations rather than ongoing validation. As a validation outcome, format violations have the severity of the specific format being validated (see G04-T01 through G04-T26 for domain-specific severities).
