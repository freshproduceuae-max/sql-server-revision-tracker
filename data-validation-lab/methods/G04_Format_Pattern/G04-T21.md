# G04-T21 — Format/Pattern | Delimiter Consistency in Delimited Fields

## ID
G04-T21

## Group
4 — Format/Pattern

## Type
Delimiter Consistency — Inconsistent Separators in a Multi-Value Field

## Live Scenario
A product catalogue allows up to five tags per product, stored in a single VARCHAR column as a comma-separated list (e.g., `"electronics,mobile,sale"`). Over time: some tags use semicolons (`"electronics;mobile;sale"`), some use pipe (`"electronics|mobile|sale"`), some mix delimiters (`"electronics,mobile;sale"`), some have spaces after delimiters (`"electronics, mobile, sale"`), some have leading/trailing delimiters (`",electronics,mobile,"`), and some use no delimiter at all with a single value (`"electronics"`). The tag-search feature splits on comma only and finds no tags for semicolon/pipe rows.

## The Question
> A delimited field must use a single, consistent delimiter throughout. Mixed delimiters prevent reliable splitting and cause search failures.
> **"Find all Products where the Tags column uses an inconsistent or non-standard delimiter — either mixing comma/semicolon/pipe within the same value, or using a non-comma delimiter when the standard is comma-separated."**

## Table Reference
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Detect delimiter type and inconsistency
SELECT
    ProductID,
    Tags,
    CASE
        WHEN Tags IS NULL                                               THEN 'NULL'
        WHEN LEN(Tags) = 0                                             THEN 'Empty'
        WHEN Tags LIKE '%,%' AND Tags LIKE '%;%'                       THEN 'Mixed: comma and semicolon'
        WHEN Tags LIKE '%,%' AND Tags LIKE '%|%'                       THEN 'Mixed: comma and pipe'
        WHEN Tags LIKE '%;%' AND Tags LIKE '%|%'                       THEN 'Mixed: semicolon and pipe'
        WHEN Tags LIKE '%,%' AND Tags NOT LIKE '%;%' AND Tags NOT LIKE '%|%' THEN 'Comma only (standard)'
        WHEN Tags LIKE '%;%' AND Tags NOT LIKE '%,%'                   THEN 'Semicolon only (non-standard)'
        WHEN Tags LIKE '%|%'  AND Tags NOT LIKE '%,%'                  THEN 'Pipe only (non-standard)'
        ELSE 'Single value or no delimiter'
    END AS DelimiterCheck
FROM Products;

-- Step 2: Detect leading/trailing delimiters
SELECT
    ProductID,
    Tags,
    CASE
        WHEN Tags LIKE ',%'     THEN 'Leading comma'
        WHEN Tags LIKE '%,'     THEN 'Trailing comma'
        WHEN Tags LIKE ';%'     THEN 'Leading semicolon'
        WHEN Tags LIKE '%;'     THEN 'Trailing semicolon'
        WHEN Tags LIKE '|%'     THEN 'Leading pipe'
        WHEN Tags LIKE '%|'     THEN 'Trailing pipe'
        ELSE 'No leading/trailing delimiter'
    END AS BoundaryCheck
FROM Products
WHERE Tags IS NOT NULL
  AND (Tags LIKE ',%' OR Tags LIKE '%,' OR Tags LIKE ';%' OR Tags LIKE '%;'
    OR Tags LIKE '|%' OR Tags LIKE '%|');

-- Step 3: Detect double delimiters (empty segment between delimiters)
SELECT
    ProductID,
    Tags,
    CASE
        WHEN Tags LIKE '%,,%'   THEN 'Double comma — empty tag segment'
        WHEN Tags LIKE '%;;%'   THEN 'Double semicolon — empty segment'
        WHEN Tags LIKE '%||%'   THEN 'Double pipe — empty segment'
        ELSE 'No double delimiters'
    END AS DoubleDelimiterCheck
FROM Products
WHERE Tags LIKE '%,,%' OR Tags LIKE '%;;%' OR Tags LIKE '%||%';

-- Step 4: Count segments using each delimiter to infer intended delimiter
SELECT
    ProductID,
    Tags,
    LEN(Tags) - LEN(REPLACE(Tags, ',', '')) AS CommaCount,
    LEN(Tags) - LEN(REPLACE(Tags, ';', '')) AS SemicolonCount,
    LEN(Tags) - LEN(REPLACE(Tags, '|', '')) AS PipeCount
FROM Products
WHERE Tags IS NOT NULL;

-- Step 5: Normalise — replace non-standard delimiters with comma
SELECT
    ProductID,
    Tags AS OriginalTags,
    -- Replace semicolons and pipes with commas, then clean up spaces
    REPLACE(REPLACE(
        LTRIM(RTRIM(
            REPLACE(REPLACE(Tags, ';', ','), '|', ',')
        )), ', ', ','), ' ,', ',')         AS NormalisedTags
FROM Products
WHERE Tags LIKE '%;%' OR Tags LIKE '%|%';
```

|---|---|---|

## Explanation

**Why delimited fields exist and why they cause problems**
First Normal Form (1NF) says each column should contain atomic values — not lists. Delimited fields violate 1NF and create exactly this problem: the application must choose and enforce a delimiter convention, and when it doesn't, the field becomes unreliable. The correct long-term fix is a separate Tags table with one row per tag.

**Counting delimiters with `LEN - LEN(REPLACE)`**
`LEN(Tags) - LEN(REPLACE(Tags, ',', ''))` counts the number of commas without splitting the string. This is the standard SQL Server pattern for counting occurrences of a character in a string.

**Leading/trailing delimiters produce empty segments when split**
Splitting `,electronics,mobile,` on comma produces `['', 'electronics', 'mobile', '']` — two empty segments. Step 2 flags these so they can be trimmed before or after the delimiter standardisation.

**Normalisation order matters**
Replace delimiters first, then clean up spaces. `REPLACE(REPLACE(Tags, ';', ','), '|', ',')` normalises delimiters. A subsequent REPLACE handles `', '` (comma-space) patterns introduced by some export tools.

## Severity
**Medium** — Inconsistent delimiters cause partial or total search failures for tag/category filtering. In e-commerce, a product that can't be found by its tags is effectively invisible to category browsing. The severity increases to High if the field is used for access control or routing decisions.
