# G04-T15 — Format/Pattern | Boolean / Flag Field Format

## ID
G04-T15

## Group
4 — Format/Pattern

## Type
Boolean / Flag Field Format — Inconsistent True/False Representations

## Live Scenario
A product catalogue has an `IsActive` column intended to store a boolean flag. Over four years of development, three different teams interpreted the field differently: Team A used `1`/`0`, Team B used `'Y'`/`'N'`, Team C used `'true'`/`'false'`. An automated feed from a third-party supplier uses `'yes'`/`'no'`. After three system integrations, the column contains all of the above. A WHERE clause `WHERE IsActive = 1` silently misses all Y/true/yes records. A product incorrectly appears as inactive and is hidden from the catalogue for six weeks.

## The Question
> Boolean/flag columns should contain a single consistent representation. Mixed representations mean some conditions silently exclude valid records.
> **"Find all Products where the IsActive column contains a value that is not in the approved set (`1`, `0`). Flag all non-standard true/false representations and quantify how many records use each variant."**

## Table Reference
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Find all non-standard values in a boolean column
SELECT
    ProductID,
    ProductName,
    IsActive,
    CASE
        WHEN IsActive IS NULL                               THEN 'NULL'
        WHEN IsActive IN ('1', '0')                        THEN 'Standard (1/0)'
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('Y', 'N')
                                                            THEN 'Non-standard (Y/N)'
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('YES', 'NO')
                                                            THEN 'Non-standard (Yes/No)'
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('TRUE', 'FALSE')
                                                            THEN 'Non-standard (True/False)'
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('ACTIVE', 'INACTIVE')
                                                            THEN 'Non-standard (Active/Inactive)'
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('ENABLED', 'DISABLED')
                                                            THEN 'Non-standard (Enabled/Disabled)'
        ELSE 'Unknown value — not a recognised boolean'
    END AS BooleanFormat
FROM Products;

-- Step 2: Count all distinct values in the flag column (profile the full set)
SELECT
    CAST(IsActive AS VARCHAR(20)) AS IsActiveValue,
    COUNT(*) AS RowCount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS PctOfTotal
FROM Products
GROUP BY CAST(IsActive AS VARCHAR(20))
ORDER BY RowCount DESC;

-- Step 3: Identify which variants map to TRUE vs FALSE for remediation
SELECT
    CAST(IsActive AS VARCHAR(20)) AS StoredValue,
    CASE
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('1','Y','YES','TRUE','ACTIVE','ENABLED','ON')
             THEN 'Maps to TRUE (1)'
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('0','N','NO','FALSE','INACTIVE','DISABLED','OFF')
             THEN 'Maps to FALSE (0)'
        WHEN IsActive IS NULL
             THEN 'NULL — unclear meaning'
        ELSE 'Unknown — cannot map'
    END AS MapsTo,
    COUNT(*) AS RecordCount
FROM Products
GROUP BY CAST(IsActive AS VARCHAR(20)),
    CASE
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('1','Y','YES','TRUE','ACTIVE','ENABLED','ON')
             THEN 'Maps to TRUE (1)'
        WHEN UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN ('0','N','NO','FALSE','INACTIVE','DISABLED','OFF')
             THEN 'Maps to FALSE (0)'
        WHEN IsActive IS NULL
             THEN 'NULL — unclear meaning'
        ELSE 'Unknown — cannot map'
    END;

-- Step 4: Generate UPDATE statements for normalisation preview
SELECT
    'UPDATE Products SET IsActive = 1 WHERE UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN (''Y'',''YES'',''TRUE'',''ACTIVE'',''ENABLED'');' AS NormalisationSQL
UNION ALL
SELECT
    'UPDATE Products SET IsActive = 0 WHERE UPPER(LTRIM(RTRIM(CAST(IsActive AS VARCHAR)))) IN (''N'',''NO'',''FALSE'',''INACTIVE'',''DISABLED'');';

-- Step 5: After normalisation — flag any remaining non-binary values
SELECT
    ProductID,
    IsActive,
    'Non-binary value remains after normalisation' AS Issue
FROM Products
WHERE IsActive IS NOT NULL
  AND IsActive NOT IN (0, 1);
```

## Explanation

**The silent exclusion problem**
`WHERE IsActive = 1` returns only rows where IsActive is literally the integer 1 (or `'1'` in implicit conversion). All `'Y'`, `'true'`, and `'yes'` records are silently excluded. This is one of the most dangerous classes of data quality error because the query runs without error, returns results that look plausible, but is missing a significant portion of the data.

**Profile before fixing**
Step 2 profiles all distinct values before any normalisation. This ensures no unexpected variant is missed. A direct UPDATE without profiling first risks overlooking an obscure variant like `'T'` or `'enabled'`.

**The correct fix: use BIT type and enforce it**
After normalisation, the column should be changed to SQL Server's BIT type (`ALTER TABLE Products ALTER COLUMN IsActive BIT NOT NULL`). The BIT type only accepts 0 and 1, preventing future format drift. This requires application code changes wherever the column is written.

**NULL in a boolean flag**
NULL in a boolean column is ambiguous — it could mean "we don't know," "not applicable," or "same as false." Establish and document the business meaning: should NULL be treated as active, inactive, or flagged for review?

## Severity
**High** — Boolean format inconsistency silently corrupts business logic. A product appearing as inactive when it is active causes missed sales, incorrect inventory reports, and customer-facing errors (item not orderable when it should be).
