# G04-T08 — Format/Pattern | URL / URI Format

## ID
G04-T08

## Group
4 — Format/Pattern

## Type
URL / URI Format Validation

## Live Scenario
A product catalogue stores a `ProductURL` column for each item's landing page. Content editors enter URLs manually. Over 18 months the column accumulates: valid URLs (`https://shop.example.com/products/widget-a`), URLs missing the scheme (`shop.example.com/products/widget-a`), malformed schemes (`htp://`, `htps://`), relative paths (`/products/widget-a`), placeholder text (`"to be added"`), bare domain names (`"example.com"`), and URLs with spaces (`"https://shop.example.com/my product"`). The sitemap generator crashes on relative paths, and the CDN rewrite rules fail on space-containing URLs.

## The Question
> A URL must have a valid scheme (http or https), a domain with at least one dot, and no unencoded spaces. SQL LIKE can validate the structural basics; CHARINDEX and PATINDEX catch embedded invalid characters.
> **"Find all Products where ProductURL is NULL, empty, missing a valid http/https scheme, contains spaces (which must be percent-encoded in a valid URL), or does not contain a domain with at least one dot after the scheme."**

## Table Reference
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Basic URL structure validation
SELECT
    ProductID,
    ProductName,
    ProductURL,
    CASE
        WHEN ProductURL IS NULL                                             THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(ProductURL))) = 0                             THEN 'Empty string'
        WHEN ProductURL LIKE '/ %' OR
             (ProductURL NOT LIKE 'http://%' AND
              ProductURL NOT LIKE 'https://%')                             THEN 'Missing http/https scheme'
        WHEN ProductURL LIKE 'http://' OR ProductURL LIKE 'https://'       THEN 'Scheme only — no domain'
        WHEN ProductURL LIKE '% %'                                         THEN 'Contains unencoded spaces'
        WHEN ProductURL NOT LIKE '%://_%._%'                               THEN 'Domain missing or has no dot'
        ELSE 'Format OK'
    END AS URLValidation
FROM Products
WHERE ProductURL IS NULL
   OR LEN(LTRIM(RTRIM(ProductURL))) = 0
   OR ProductURL LIKE '% %'
   OR (ProductURL NOT LIKE 'http://%' AND ProductURL NOT LIKE 'https://%')
   OR ProductURL NOT LIKE '%://_%._%';

-- Step 2: Detect specific scheme errors
SELECT
    ProductID,
    ProductURL,
    CASE
        WHEN ProductURL LIKE 'http//%'   THEN 'Malformed: http// instead of http://'
        WHEN ProductURL LIKE 'htp://%'   THEN 'Typo: htp instead of http'
        WHEN ProductURL LIKE 'htps://%'  THEN 'Typo: htps instead of https'
        WHEN ProductURL LIKE 'Http://%'
          OR ProductURL LIKE 'HTTP://%'  THEN 'Scheme uppercase — normalise to lowercase'
        WHEN ProductURL LIKE 'ftp://%'   THEN 'FTP scheme — expected http/https'
        WHEN ProductURL LIKE 'www.%'     THEN 'Missing scheme — starts with www'
        ELSE 'Scheme looks correct'
    END AS SchemeCheck
FROM Products
WHERE ProductURL IS NOT NULL;

-- Step 3: Check for invalid characters in the path
SELECT
    ProductID,
    ProductURL,
    CASE
        WHEN PATINDEX('%[ <>"\{\}|\\^`]%', ProductURL) > 0 THEN
            'Contains unencoded characters: space/<>/\{}|^`'
        WHEN ProductURL LIKE '%#%'
             AND ProductURL NOT LIKE '%#[^ ]%'              THEN 'Fragment identifier # with space after'
        ELSE 'Path characters OK'
    END AS PathCharCheck
FROM Products
WHERE ProductURL IS NOT NULL
  AND PATINDEX('%[ <>"\{\}|\\^`]%', ProductURL) > 0;

-- Step 4: URL length check (practical limits)
SELECT
    ProductID,
    ProductURL,
    LEN(ProductURL) AS URLLength,
    CASE
        WHEN LEN(ProductURL) > 2048     THEN 'Exceeds 2048 chars (browser/server limit)'
        WHEN LEN(ProductURL) > 255      THEN 'Exceeds 255 chars — may be truncated by some systems'
        ELSE 'Length OK'
    END AS LengthCheck
FROM Products
WHERE LEN(ProductURL) > 255;

-- Step 5: Consistency check — all products should have a URL
SELECT
    COUNT(*) AS TotalProducts,
    SUM(CASE WHEN ProductURL IS NULL OR LEN(LTRIM(RTRIM(ProductURL))) = 0 THEN 1 ELSE 0 END) AS MissingURL,
    SUM(CASE WHEN ProductURL LIKE 'https://%' THEN 1 ELSE 0 END) AS SecureHTTPS,
    SUM(CASE WHEN ProductURL LIKE 'http://%'
              AND ProductURL NOT LIKE 'https://%' THEN 1 ELSE 0 END) AS InsecureHTTP
FROM Products;
```

## Explanation

**Why SQL URL validation is structural only**
SQL can verify that a URL has the right shape (scheme + domain + path). It cannot verify that the URL resolves (returns a 200 status) — that requires an HTTP request. Format validation catches structural errors; link checking catches dead URLs. Both are needed but they use different tools.

**Unencoded spaces are the most common URL error**
A space in a URL must be percent-encoded as `%20`. A raw space in a URL string breaks HTTP routing because space is a delimiter in the HTTP request line. `LIKE '% %'` is the quickest way to catch this in SQL.

**HTTP vs HTTPS is a security concern, not just a format concern**
Step 5 separately counts HTTP and HTTPS URLs. All externally facing URLs should use HTTPS. An HTTP URL may work structurally but represents a security downgrade. Flag HTTP URLs for the security team in addition to format violations.

**The `%://_%._%` pattern explained**
- `%://` — matches any scheme ending in `://`
- `_` — at least one character (domain start)
- `%.` — must have a dot somewhere in the domain
- `_%` — at least one character after the dot (TLD)

## Severity
**Medium** — Invalid URLs cause broken links, failed integrations, and SEO penalties (404s hurt search ranking). In e-commerce, a broken product URL means lost sales from that page entry point.
