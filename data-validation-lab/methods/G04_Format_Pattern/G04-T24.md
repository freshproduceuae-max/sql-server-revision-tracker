# G04-T24 — Format/Pattern | Filename / File Path Format

## ID
G04-T24

## Group
4 — Format/Pattern

## Type
Filename / File Path Format Validation

## Live Scenario
A document management system stores file paths to uploaded contracts in a `FilePath` column. The system runs on Windows but paths are entered manually by users. The column contains: valid paths (`\\server\contracts\2024\C0042.pdf`), paths with forward slashes (`//server/contracts/2024/C0042.pdf`), paths with reserved Windows characters (`\\server\contracts\C0042?.pdf`), paths with trailing spaces (`\\server\contracts\C0042.pdf `), paths that don't end in the expected file extension (`.pdf`), and empty strings where the file was never uploaded. The document viewer fails silently when it tries to open any path with invalid characters.

## The Question
> File paths must not contain characters that are invalid in the target OS filesystem. Windows reserves `< > : " / \ | ? *` in filenames (except path separators). SQL can validate path structure and flag invalid characters before the application tries to use the path.
> **"Find all Orders where the AttachmentPath column contains characters invalid in Windows file paths (outside of the path separator backslash), does not end in an expected file extension, or has trailing/leading whitespace."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Flag invalid characters in file paths
-- Windows reserved characters in filenames: < > : " / | ? * and CHAR(0)-CHAR(31)
SELECT
    OrderID,
    AttachmentPath,
    CASE
        WHEN AttachmentPath IS NULL                                     THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(AttachmentPath))) = 0                     THEN 'Empty'
        WHEN AttachmentPath <> LTRIM(RTRIM(AttachmentPath))            THEN 'Leading/trailing whitespace'
        WHEN PATINDEX('%[<>:"|?*]%', AttachmentPath) > 0              THEN 'Contains reserved Windows character'
        WHEN PATINDEX('%' + CHAR(0) + '%', AttachmentPath) > 0        THEN 'Contains null byte'
        ELSE 'Characters OK'
    END AS CharacterCheck
FROM Orders
WHERE AttachmentPath IS NULL
   OR LEN(LTRIM(RTRIM(AttachmentPath))) = 0
   OR AttachmentPath <> LTRIM(RTRIM(AttachmentPath))
   OR PATINDEX('%[<>:"|?*]%', AttachmentPath) > 0;

-- Step 2: Validate file extension
SELECT
    OrderID,
    AttachmentPath,
    -- Extract extension: everything after the last dot
    CASE
        WHEN CHARINDEX('.', REVERSE(AttachmentPath)) = 0  THEN 'No file extension'
        ELSE LOWER(RIGHT(AttachmentPath, CHARINDEX('.', REVERSE(AttachmentPath))))
    END AS FileExtension,
    CASE
        WHEN AttachmentPath IS NULL                         THEN 'NULL'
        WHEN CHARINDEX('.', REVERSE(AttachmentPath)) = 0   THEN 'Missing file extension'
        WHEN LOWER(RIGHT(AttachmentPath, CHARINDEX('.', REVERSE(AttachmentPath))))
             NOT IN ('.pdf', '.docx', '.xlsx', '.png', '.jpg')
             THEN 'Unexpected extension: ' +
                  RIGHT(AttachmentPath, CHARINDEX('.', REVERSE(AttachmentPath)))
        ELSE 'Extension OK'
    END AS ExtensionCheck
FROM Orders
WHERE AttachmentPath IS NOT NULL;

-- Step 3: Validate UNC path structure (\\server\share\...)
SELECT
    OrderID,
    AttachmentPath,
    CASE
        WHEN AttachmentPath LIKE '\\%\%\%'               THEN 'UNC path — valid structure'
        WHEN AttachmentPath LIKE '[A-Z]:\\%'             THEN 'Local drive path (may not be accessible)'
        WHEN AttachmentPath LIKE '//%'                   THEN 'Forward-slash UNC — wrong separator'
        WHEN AttachmentPath LIKE 'http%'                 THEN 'URL, not a file path'
        ELSE 'Unrecognised path format'
    END AS PathStructure
FROM Orders
WHERE AttachmentPath IS NOT NULL;

-- Step 4: Check path length (Windows MAX_PATH = 260 chars)
SELECT
    OrderID,
    AttachmentPath,
    LEN(AttachmentPath) AS PathLength,
    CASE
        WHEN LEN(AttachmentPath) > 260  THEN 'Exceeds Windows MAX_PATH (260 chars)'
        WHEN LEN(AttachmentPath) > 200  THEN 'Approaching MAX_PATH limit'
        ELSE 'Length OK'
    END AS LengthCheck
FROM Orders
WHERE AttachmentPath IS NOT NULL
  AND LEN(AttachmentPath) > 200;

-- Step 5: Summary
SELECT
    CASE
        WHEN AttachmentPath IS NULL                                     THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(AttachmentPath))) = 0                     THEN 'Empty'
        WHEN PATINDEX('%[<>:"|?*]%', AttachmentPath) > 0              THEN 'Invalid chars'
        ELSE 'OK'
    END AS PathStatus,
    COUNT(*) AS Count
FROM Orders
GROUP BY
    CASE
        WHEN AttachmentPath IS NULL                                     THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(AttachmentPath))) = 0                     THEN 'Empty'
        WHEN PATINDEX('%[<>:"|?*]%', AttachmentPath) > 0              THEN 'Invalid chars'
        ELSE 'OK'
    END;
```

## Explanation

**Windows reserved characters**
Windows prohibits these characters in filenames: `< > : " / \ | ? *` (plus CHAR 0–31). The backslash `\` is the path separator and is valid in path strings (not individual filenames). `PATINDEX('%[<>:"|?*]%', path)` catches the invalid characters — forward slash is excluded from the bracket list here because it may appear in URL-style paths, but `?` and `*` (wildcard characters) are always invalid.

**Extracting file extension with CHARINDEX + REVERSE**
`CHARINDEX('.', REVERSE(path))` gives the position of the last dot (counted from the right). `RIGHT(path, CHARINDEX('.', REVERSE(path)))` extracts the extension including the dot. This approach handles paths with dots in directory names (`\\server\v2.0\file.pdf`) correctly.

**UNC path double-backslash in LIKE patterns**
T-SQL string literals have no backslash-escaping convention — unlike C, Python, or regex, a backslash inside a single-quoted T-SQL string is just a literal backslash character, with no special meaning and no need to double it. The LIKE pattern `'\\%\%\%'` contains exactly the literal backslashes it needs to match: two backslashes for the UNC prefix, then a wildcard, one backslash for the next separator, another wildcard, one more backslash, and a final wildcard. A UNC path starts with `\\` (two backslashes), so the pattern's leading `\\` matches that directly — no doubling required.

**MAX_PATH limit (260 characters)**
Windows historically limits file paths to 260 characters. Paths longer than this fail silently on some Windows API calls. Step 4 flags paths approaching this limit. Modern Windows with long-path registry setting enabled supports up to 32,767 characters, but most applications still use the old limit.

## Severity
**Medium** — Invalid file paths cause application errors when the system tries to open, move, or delete the file. In document management and contract systems, a broken attachment path means the document is effectively inaccessible.
