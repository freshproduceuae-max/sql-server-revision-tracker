# G19-T19 — Cleansing Operations | Cleansing Pipeline Orchestration and Audit Log

## ID
G19-T19

## Group
19 — Cleansing Operations

## Type
Cleansing Pipeline Orchestration and Audit Log — Executing All Cleansing Checks in a Single Orchestrated Pass and Recording the Results in an Audit Trail

## Live Scenario
A data engineering team runs 12 individual cleansing scripts manually before each monthly reporting cycle. The process takes 3 hours, requires a senior analyst, and has no audit trail — there is no way to prove to the external auditor that the cleansing was performed or what it found. After an audit finding, the team redesigns the process as an orchestrated cleansing pipeline: a single stored procedure runs all checks in sequence, writes results to a CleansedAuditLog table, and produces a sign-off report that the DBA signs off before the pipeline proceeds to the reporting load. The audit log becomes the evidence trail the auditor requires.

## The Question
> A cleansing pipeline orchestration executes multiple cleansing checks in a defined sequence, records each check's findings in a structured audit log, and produces a consolidated sign-off scorecard. SQL implements this as a multi-CTE query (or stored procedure) that runs each check in a single pass, accumulates results in a temp table or output, and produces a UNION-based summary scorecard. The audit log records: check name, run timestamp, records inspected, issues found, records auto-corrected, records requiring manual review, and the final pass/fail determination.
> **"Build an orchestrated cleansing pipeline for the Orders and Customers tables: run checks for NULL rates, whitespace, case conformance, value domain compliance, temporal sequence, and referential integrity in a single coordinated pass. Produce a consolidated audit log showing the result of each check, and a final sign-off scorecard with an overall pipeline pass/fail determination."**

## Solution Query

```sql
-- ============================================================
-- CLEANSING PIPELINE ORCHESTRATION — SINGLE PASS AUDIT
-- Run date: captured via GETDATE()
-- ============================================================

-- Step 1: Pipeline metadata
DECLARE @RunID        VARCHAR(30) = 'PIPELINE-' + FORMAT(GETDATE(), 'yyyyMMdd-HHmm');
DECLARE @RunTimestamp DATETIME    = GETDATE();
DECLARE @PassThreshold DECIMAL(5,2) = 95.0;  -- minimum conformance % to PASS

SELECT
    @RunID        AS PipelineRunID,
    @RunTimestamp AS RunTimestamp,
    @PassThreshold AS PassThresholdPct,
    SUSER_NAME()  AS ExecutedBy,
    @@SERVERNAME  AS ServerName,
    DB_NAME()     AS DatabaseName;

-- Step 2: Run all cleansing checks in a single coordinated pass
WITH
-- ---- CHECK 1: NULL rates for critical fields ----
NullChecks AS (
    SELECT
        'CHK-001' AS CheckID,
        'NULL_RATE' AS CheckType,
        'Orders.TotalAmount NULL rate' AS CheckName,
        COUNT(*) AS RowsInspected,
        SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END) AS IssuesFound,
        0 AS AutoCorrected,
        SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END) AS ManualReviewRequired,
        ROUND(100.0 * SUM(CASE WHEN TotalAmount IS NOT NULL THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1) AS ConformancePct,
        'HIGH' AS Severity
    FROM Orders
    UNION ALL
    SELECT 'CHK-002', 'NULL_RATE', 'Customers.Email NULL rate',
        COUNT(*),
        SUM(CASE WHEN Email IS NULL THEN 1 ELSE 0 END),
        0,
        SUM(CASE WHEN Email IS NULL THEN 1 ELSE 0 END),
        ROUND(100.0 * SUM(CASE WHEN Email IS NOT NULL THEN 1 ELSE 0 END) / NULLIF(COUNT(*), 0), 1),
        'HIGH'
    FROM Customers
    UNION ALL
    SELECT 'CHK-003', 'NULL_RATE', 'Orders.OrderDate NULL rate',
        COUNT(*),
        SUM(CASE WHEN OrderDate IS NULL THEN 1 ELSE 0 END),
        0,
        SUM(CASE WHEN OrderDate IS NULL THEN 1 ELSE 0 END),
        ROUND(100.0 * SUM(CASE WHEN OrderDate IS NOT NULL THEN 1 ELSE 0 END) / NULLIF(COUNT(*), 0), 1),
        'HIGH'
    FROM Orders
),

-- ---- CHECK 2: Whitespace conformance ----
WhitespaceChecks AS (
    SELECT
        'CHK-004' AS CheckID,
        'WHITESPACE' AS CheckType,
        'Customers.Email whitespace' AS CheckName,
        COUNT(*) AS RowsInspected,
        SUM(CASE WHEN Email <> LTRIM(RTRIM(ISNULL(Email,''))) THEN 1 ELSE 0 END) AS IssuesFound,
        SUM(CASE WHEN Email <> LTRIM(RTRIM(ISNULL(Email,''))) THEN 1 ELSE 0 END) AS AutoCorrected,
        0 AS ManualReviewRequired,
        ROUND(100.0 * SUM(CASE WHEN Email IS NULL
                                  OR Email = LTRIM(RTRIM(Email)) THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1) AS ConformancePct,
        'LOW' AS Severity
    FROM Customers
    UNION ALL
    SELECT 'CHK-005', 'WHITESPACE', 'Customers.FirstName whitespace',
        COUNT(*),
        SUM(CASE WHEN FirstName <> LTRIM(RTRIM(ISNULL(FirstName,''))) THEN 1 ELSE 0 END),
        SUM(CASE WHEN FirstName <> LTRIM(RTRIM(ISNULL(FirstName,''))) THEN 1 ELSE 0 END),
        0,
        ROUND(100.0 * SUM(CASE WHEN FirstName IS NULL
                                  OR FirstName = LTRIM(RTRIM(FirstName)) THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1),
        'LOW'
    FROM Customers
),

-- ---- CHECK 3: Case conformance ----
CaseChecks AS (
    SELECT
        'CHK-006' AS CheckID,
        'CASE_NORMALISATION' AS CheckType,
        'Customers.Email lowercase' AS CheckName,
        COUNT(*) AS RowsInspected,
        SUM(CASE WHEN Email IS NOT NULL AND Email <> LOWER(Email) THEN 1 ELSE 0 END) AS IssuesFound,
        SUM(CASE WHEN Email IS NOT NULL AND Email <> LOWER(Email) THEN 1 ELSE 0 END) AS AutoCorrected,
        0 AS ManualReviewRequired,
        ROUND(100.0 * SUM(CASE WHEN Email IS NULL
                                  OR Email = LOWER(Email) THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1) AS ConformancePct,
        'LOW' AS Severity
    FROM Customers
    UNION ALL
    SELECT 'CHK-007', 'CASE_NORMALISATION', 'Products.ProductCode uppercase',
        COUNT(*),
        SUM(CASE WHEN ProductCode IS NOT NULL AND ProductCode <> UPPER(ProductCode) THEN 1 ELSE 0 END),
        SUM(CASE WHEN ProductCode IS NOT NULL AND ProductCode <> UPPER(ProductCode) THEN 1 ELSE 0 END),
        0,
        ROUND(100.0 * SUM(CASE WHEN ProductCode IS NULL
                                  OR ProductCode = UPPER(ProductCode) THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1),
        'LOW'
    FROM Products
),

-- ---- CHECK 4: Value domain compliance ----
DomainChecks AS (
    SELECT
        'CHK-008' AS CheckID,
        'DOMAIN_COMPLIANCE' AS CheckType,
        'Orders.Status permitted values' AS CheckName,
        COUNT(*) AS RowsInspected,
        SUM(CASE WHEN Status NOT IN ('Pending','Processing','Delivered','Returned','Cancelled')
                     AND Status IS NOT NULL THEN 1 ELSE 0 END) AS IssuesFound,
        0 AS AutoCorrected,
        SUM(CASE WHEN Status NOT IN ('Pending','Processing','Delivered','Returned','Cancelled')
                     AND Status IS NOT NULL THEN 1 ELSE 0 END) AS ManualReviewRequired,
        ROUND(100.0 * SUM(CASE WHEN Status IN ('Pending','Processing','Delivered','Returned','Cancelled')
                               THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1) AS ConformancePct,
        'HIGH' AS Severity
    FROM Orders
    UNION ALL
    SELECT 'CHK-009', 'DOMAIN_COMPLIANCE', 'Customers.IsActive BIT values',
        COUNT(*),
        SUM(CASE WHEN IsActive NOT IN (0,1) AND IsActive IS NOT NULL THEN 1 ELSE 0 END),
        SUM(CASE WHEN IsActive NOT IN (0,1) AND IsActive IS NOT NULL THEN 1 ELSE 0 END),
        0,
        ROUND(100.0 * SUM(CASE WHEN IsActive IN (0,1) THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1),
        'HIGH'
    FROM Customers
),

-- ---- CHECK 5: Temporal sequence ----
TemporalChecks AS (
    SELECT
        'CHK-010' AS CheckID,
        'TEMPORAL_SEQUENCE' AS CheckType,
        'Orders: DeliveryDate > OrderDate' AS CheckName,
        COUNT(*) AS RowsInspected,
        SUM(CASE WHEN DeliveryDate IS NOT NULL
                 AND OrderDate IS NOT NULL
                 AND DeliveryDate < OrderDate THEN 1 ELSE 0 END) AS IssuesFound,
        0 AS AutoCorrected,
        SUM(CASE WHEN DeliveryDate IS NOT NULL
                 AND OrderDate IS NOT NULL
                 AND DeliveryDate < OrderDate THEN 1 ELSE 0 END) AS ManualReviewRequired,
        ROUND(100.0 * SUM(CASE WHEN DeliveryDate IS NULL
                               OR DeliveryDate >= OrderDate THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1) AS ConformancePct,
        'HIGH' AS Severity
    FROM Orders
),

-- ---- CHECK 6: Referential integrity ----
RIChecks AS (
    SELECT
        'CHK-011' AS CheckID,
        'REFERENTIAL_INTEGRITY' AS CheckType,
        'Orders.CustomerID → Customers' AS CheckName,
        COUNT(*) AS RowsInspected,
        SUM(CASE WHEN c.CustomerID IS NULL AND o.CustomerID IS NOT NULL THEN 1 ELSE 0 END) AS IssuesFound,
        0 AS AutoCorrected,
        SUM(CASE WHEN c.CustomerID IS NULL AND o.CustomerID IS NOT NULL THEN 1 ELSE 0 END) AS ManualReviewRequired,
        ROUND(100.0 * SUM(CASE WHEN c.CustomerID IS NOT NULL OR o.CustomerID IS NULL THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1) AS ConformancePct,
        'HIGH' AS Severity
    FROM Orders o LEFT JOIN Customers c ON o.CustomerID = c.CustomerID
    UNION ALL
    SELECT 'CHK-012', 'REFERENTIAL_INTEGRITY', 'Orders.ProductID → Products',
        COUNT(*),
        SUM(CASE WHEN p.ProductID IS NULL AND o.ProductID IS NOT NULL THEN 1 ELSE 0 END),
        0,
        SUM(CASE WHEN p.ProductID IS NULL AND o.ProductID IS NOT NULL THEN 1 ELSE 0 END),
        ROUND(100.0 * SUM(CASE WHEN p.ProductID IS NOT NULL OR o.ProductID IS NULL THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1),
        'HIGH'
    FROM Orders o LEFT JOIN Products p ON o.ProductID = p.ProductID
),

-- ---- COMBINE ALL CHECKS ----
AllChecks AS (
    SELECT * FROM NullChecks
    UNION ALL SELECT * FROM WhitespaceChecks
    UNION ALL SELECT * FROM CaseChecks
    UNION ALL SELECT * FROM DomainChecks
    UNION ALL SELECT * FROM TemporalChecks
    UNION ALL SELECT * FROM RIChecks
)

-- Step 3: Full audit log output
SELECT
    CheckID,
    CheckType,
    CheckName,
    RowsInspected,
    IssuesFound,
    AutoCorrected,
    ManualReviewRequired,
    ConformancePct,
    Severity,
    CASE
        WHEN ConformancePct >= 100.0 THEN 'PASS'
        WHEN ConformancePct >= 95.0  THEN 'PASS (minor issues)'
        WHEN ConformancePct >= 80.0  THEN 'WARN: Below 95% conformance'
        ELSE 'FAIL: Below 80% conformance — do not proceed to reporting load'
    END AS CheckResult
FROM AllChecks
ORDER BY CheckResult ASC, Severity DESC, CheckID;

-- Step 4: Pipeline sign-off scorecard
WITH AllChecks AS (
    SELECT 'CHK-001' AS CheckID, 'NULL_RATE' AS CheckType,
           COUNT(*) AS RowsInspected,
           SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END) AS Issues,
           ROUND(100.0 * SUM(CASE WHEN TotalAmount IS NOT NULL THEN 1 ELSE 0 END)/NULLIF(COUNT(*),0),1) AS ConformancePct,
           'HIGH' AS Severity FROM Orders
    UNION ALL
    SELECT 'CHK-006', 'CASE', COUNT(*),
           SUM(CASE WHEN Email IS NOT NULL AND Email <> LOWER(Email) THEN 1 ELSE 0 END),
           ROUND(100.0*SUM(CASE WHEN Email IS NULL OR Email=LOWER(Email) THEN 1 ELSE 0 END)/NULLIF(COUNT(*),0),1),
           'LOW' FROM Customers
    UNION ALL
    SELECT 'CHK-008', 'DOMAIN', COUNT(*),
           SUM(CASE WHEN Status NOT IN ('Pending','Processing','Delivered','Returned','Cancelled') AND Status IS NOT NULL THEN 1 ELSE 0 END),
           ROUND(100.0*SUM(CASE WHEN Status IN ('Pending','Processing','Delivered','Returned','Cancelled') THEN 1 ELSE 0 END)/NULLIF(COUNT(*),0),1),
           'HIGH' FROM Orders
    UNION ALL
    SELECT 'CHK-010', 'TEMPORAL', COUNT(*),
           SUM(CASE WHEN DeliveryDate IS NOT NULL AND DeliveryDate < OrderDate THEN 1 ELSE 0 END),
           ROUND(100.0*SUM(CASE WHEN DeliveryDate IS NULL OR DeliveryDate>=OrderDate THEN 1 ELSE 0 END)/NULLIF(COUNT(*),0),1),
           'HIGH' FROM Orders
)
SELECT
    'PIPELINE SIGN-OFF SUMMARY' AS ReportTitle,
    COUNT(*) AS TotalChecks,
    SUM(CASE WHEN ConformancePct >= 95.0 THEN 1 ELSE 0 END) AS PassedChecks,
    SUM(CASE WHEN ConformancePct < 95.0 THEN 1 ELSE 0 END) AS FailedChecks,
    SUM(Issues) AS TotalIssuesFound,
    ROUND(AVG(ConformancePct), 1) AS AvgConformancePct,
    ROUND(MIN(ConformancePct), 1) AS LowestConformancePct,
    CASE
        WHEN MIN(ConformancePct) >= 95.0
             THEN 'PIPELINE PASSED: All checks meet the 95% conformance threshold. '
                  + 'Data is approved for reporting load.'
        ELSE 'PIPELINE FAILED: One or more checks below 95% threshold. '
             + 'Resolve ' + CAST(SUM(CASE WHEN ConformancePct < 95.0 THEN 1 ELSE 0 END) AS VARCHAR)
             + ' failing check(s) before proceeding to reporting load.'
    END AS PipelineSignOff
FROM AllChecks;
```

## Explanation

**Pipeline as evidence for audit compliance**
A single orchestrated pipeline with a structured output provides auditable evidence that data quality checks were performed. An auditor can see: which checks ran, when they ran, who ran them, what they found, and what the overall sign-off determination was. Ad hoc scripts run in ad hoc order provide no such trail. Storing the pipeline output to a persistent CleansedAuditLog table (INSERT INTO CleansedAuditLog SELECT ... FROM AllChecks) creates a permanent record across multiple runs.

**Pass threshold as a policy decision**
The 95% conformance threshold (`@PassThreshold`) is a policy decision, not a technical one. Financial reporting pipelines may require 100% pass on all HIGH severity checks. Marketing campaign data may tolerate 90% for LOW severity checks. Embedding the threshold as a DECLARE variable makes it visible and auditable — the threshold used in any run is recorded in the log.

**Fail-fast vs run-all strategy**
This pipeline uses a "run all checks" strategy: all checks execute regardless of prior failures, producing a complete view of data quality in one pass. An alternative "fail-fast" strategy (RAISERROR if any check fails) stops at the first failure, preventing downstream checks from running. Run-all is generally preferable for data quality pipelines because understanding the full scope of failures helps triage and root-cause analysis.

**CTE composability as an architectural pattern**
Each check is implemented as an independent CTE that returns the same schema (CheckID, CheckType, CheckName, RowsInspected, IssuesFound, ConformancePct, Severity). The `AllChecks` CTE unions them all. This pattern is highly extensible: adding a new check requires writing one new CTE and adding it to the AllChecks UNION ALL. No other part of the query changes. This is the SQL equivalent of a plugin architecture.

**Automated vs manual remediation tracking**
The `AutoCorrected` and `ManualReviewRequired` columns in the audit log distinguish between issues that the pipeline can fix without human intervention (whitespace trimming, case normalisation) and issues that require a data steward's decision (orphan records, unmapped values). Tracking these separately allows the pipeline to report "100% of auto-correctable issues resolved; 12 records require manual review" — giving the sign-off reviewer exactly the information they need to make a go/no-go decision.

## Severity
**High** — Without an orchestrated cleansing pipeline with an audit log, data quality is a manual, undocumented, and unrepeatable process. Every reporting cycle is a potential data quality risk. The pipeline converts data quality from a manual artisan task to a governed, auditable, and repeatable engineering process. The audit log is the single most important output: it is the evidence that the data was validated before it entered the reporting layer.
