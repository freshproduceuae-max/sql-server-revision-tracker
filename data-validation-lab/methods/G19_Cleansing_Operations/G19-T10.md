# G19-T10 — Cleansing Operations | Special Character Removal and Sanitisation

## ID
G19-T10

## Group
19 — Cleansing Operations

## Type
Special Character Removal and Sanitisation — Removing or Escaping Characters That Cause Parsing, Display, or Security Problems

## Live Scenario
A retailer's product catalogue sync job exports product descriptions to an XML feed for a third-party marketplace. The sync fails for 47 products because their descriptions contain unescaped ampersands ("Batteries & Cables"), angle brackets ("Size <L>"), and double-quotes in embedded HTML attributes. The XML parser throws "entity reference not terminated" and "less-than sign in attribute value" errors, halting the entire feed. A pre-export sanitisation step that replaces `&` with `&amp;`, `<` with `&lt;`, and `>` with `&gt;` would have prevented the failures and allowed all 47 products to sync successfully.

## The Question
> Special character sanitisation removes or escapes characters that are valid in human-readable text but cause failures in structured formats (XML, JSON, CSV, HTML) or represent security risks (SQL injection patterns, shell metacharacters). SQL implements this with nested REPLACE() for known character replacements, PATINDEX() for character class detection, and CHAR() references for control characters. The sanitisation output shows the original value, the sanitised value, and a flag identifying which characters were removed or replaced.
> **"Sanitise special characters in the Orders and Products tables: detect and escape XML-unsafe characters in product descriptions, identify control characters and line breaks in order notes, flag CSV-unsafe characters (commas, quotes, newlines) in text fields, and produce a sanitisation report showing the proportion of records requiring cleansing."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: XML character sanitisation for product descriptions
SELECT
    ProductID,
    ProductName,
    Description,
    -- XML-safe version: escape the five reserved XML characters
    REPLACE(REPLACE(REPLACE(REPLACE(REPLACE(
        ISNULL(Description, ''),
        '&',  '&amp;'),   -- must be first to avoid double-escaping
        '<',  '&lt;'),
        '>',  '&gt;'),
        '"',  '&quot;'),
        '''', '&apos;')
    AS XmlSafeDescription,
    CASE
        WHEN Description IS NULL
             THEN 'NULL'
        WHEN CHARINDEX('&', Description) > 0
             THEN 'AMPERSAND: & at position ' + CAST(CHARINDEX('&', Description) AS VARCHAR)
                  + ' — must be escaped to &amp; in XML'
        WHEN CHARINDEX('<', Description) > 0
             THEN 'LESS-THAN: < at position ' + CAST(CHARINDEX('<', Description) AS VARCHAR)
                  + ' — must be escaped to &lt; in XML'
        WHEN CHARINDEX('>', Description) > 0
             THEN 'GREATER-THAN: > must be escaped to &gt; in XML'
        WHEN CHARINDEX('"', Description) > 0
             THEN 'DOUBLE QUOTE: " must be escaped to &quot; in XML attributes'
        ELSE 'XML SAFE: No reserved characters detected'
    END AS XmlSafetyFlag
FROM Products
WHERE Description IS NOT NULL;

-- Step 2: CSV-unsafe character detection in order notes and product fields
-- CSV unsafe: comma (,), double-quote ("), newline (CHAR(10)), carriage return (CHAR(13))
SELECT
    OrderID,
    Notes,
    -- CSV-safe version: wrap in quotes and escape internal quotes
    '"' + REPLACE(ISNULL(Notes,''), '"', '""') + '"' AS CsvSafeNotes,
    CASE
        WHEN Notes IS NULL
             THEN 'NULL'
        WHEN CHARINDEX(',',       ISNULL(Notes,'')) > 0
          OR CHARINDEX('"',       ISNULL(Notes,'')) > 0
          OR CHARINDEX(CHAR(10),  ISNULL(Notes,'')) > 0
          OR CHARINDEX(CHAR(13),  ISNULL(Notes,'')) > 0
             THEN 'CSV UNSAFE: Contains '
                  + CASE WHEN CHARINDEX(',', Notes) > 0 THEN 'comma ' ELSE '' END
                  + CASE WHEN CHARINDEX('"', Notes) > 0 THEN 'double-quote ' ELSE '' END
                  + CASE WHEN CHARINDEX(CHAR(10), Notes) > 0 THEN 'newline ' ELSE '' END
                  + CASE WHEN CHARINDEX(CHAR(13), Notes) > 0 THEN 'carriage-return ' ELSE '' END
                  + '— field must be quoted in CSV export'
        ELSE 'CSV SAFE'
    END AS CsvSafetyFlag
FROM Orders
WHERE Notes IS NOT NULL;

-- Step 3: JSON-unsafe character detection
-- JSON unsafe: backslash (\), double-quote ("), control characters (CHAR(0)-CHAR(31))
SELECT
    ProductID,
    ProductName,
    Tags,
    -- JSON-safe: escape backslash and double quotes
    REPLACE(REPLACE(
        ISNULL(Tags, ''),
        '\', '\\'),
        '"', '\"')
    AS JsonSafeTags,
    CASE
        WHEN Tags IS NULL
             THEN 'NULL'
        WHEN CHARINDEX('\', ISNULL(Tags,'')) > 0
             THEN 'BACKSLASH: \ must be escaped to \\ in JSON'
        WHEN CHARINDEX('"', ISNULL(Tags,'')) > 0
             THEN 'DOUBLE QUOTE: " must be escaped to \" in JSON'
        WHEN CHARINDEX(CHAR(9), ISNULL(Tags,'')) > 0
             THEN 'TAB: CHAR(9) must be escaped to \t in JSON'
        WHEN CHARINDEX(CHAR(10), ISNULL(Tags,'')) > 0
             THEN 'NEWLINE: CHAR(10) must be escaped to \n in JSON'
        WHEN CHARINDEX(CHAR(13), ISNULL(Tags,'')) > 0
             THEN 'CARRIAGE RETURN: CHAR(13) must be escaped to \r in JSON'
        ELSE 'JSON SAFE'
    END AS JsonSafetyFlag
FROM Products
WHERE Tags IS NOT NULL;

-- Step 4: Control character audit across all text fields
-- ASCII control characters: CHAR(0) to CHAR(31), CHAR(127) (DEL)
SELECT
    CustomerID,
    FirstName,
    Email,
    Notes = NULL,   -- Customers table has no Notes column; placeholder
    -- Detect any control character in FirstName
    CASE
        WHEN PATINDEX('%[' + CHAR(1) + '-' + CHAR(31) + ']%', ISNULL(FirstName,'')) > 0
             THEN 'CONTROL CHARACTER in FirstName at position '
                  + CAST(PATINDEX('%[' + CHAR(1) + '-' + CHAR(31) + ']%', FirstName) AS VARCHAR)
        ELSE 'Clean'
    END AS FirstNameControlFlag,
    CASE
        WHEN PATINDEX('%[' + CHAR(1) + '-' + CHAR(31) + ']%', ISNULL(Email,'')) > 0
             THEN 'CONTROL CHARACTER in Email'
        ELSE 'Clean'
    END AS EmailControlFlag
FROM Customers
WHERE PATINDEX('%[' + CHAR(1) + '-' + CHAR(31) + ']%', ISNULL(FirstName,'')) > 0
   OR PATINDEX('%[' + CHAR(1) + '-' + CHAR(31) + ']%', ISNULL(Email,'')) > 0;

-- Step 5: Sanitisation coverage scorecard
SELECT
    TableAndField,
    TotalRows,
    CleanRows,
    NeedsXmlEscape,
    NeedsCsvQuote,
    NullCount,
    ROUND(100.0 * CleanRows / NULLIF(TotalRows - NullCount, 0), 1) AS CleanPct
FROM (
    SELECT
        'Products.Description (XML)' AS TableAndField,
        COUNT(*) AS TotalRows,
        SUM(CASE WHEN Description IS NOT NULL
                 AND CHARINDEX('&', Description) = 0
                 AND CHARINDEX('<', Description) = 0
                 AND CHARINDEX('>', Description) = 0
                 THEN 1 ELSE 0 END) AS CleanRows,
        SUM(CASE WHEN Description IS NOT NULL
                 AND (CHARINDEX('&', Description) > 0
                   OR CHARINDEX('<', Description) > 0
                   OR CHARINDEX('>', Description) > 0)
                 THEN 1 ELSE 0 END) AS NeedsXmlEscape,
        0 AS NeedsCsvQuote,
        SUM(CASE WHEN Description IS NULL THEN 1 ELSE 0 END) AS NullCount
    FROM Products
    UNION ALL
    SELECT
        'Orders.Notes (CSV)',
        COUNT(*),
        SUM(CASE WHEN Notes IS NOT NULL
                 AND CHARINDEX(',', Notes) = 0
                 AND CHARINDEX('"', Notes) = 0
                 AND CHARINDEX(CHAR(10), Notes) = 0
                 THEN 1 ELSE 0 END),
        0,
        SUM(CASE WHEN Notes IS NOT NULL
                 AND (CHARINDEX(',', Notes) > 0
                   OR CHARINDEX('"', Notes) > 0
                   OR CHARINDEX(CHAR(10), Notes) > 0)
                 THEN 1 ELSE 0 END),
        SUM(CASE WHEN Notes IS NULL THEN 1 ELSE 0 END)
    FROM Orders
) Scorecard;
```

## Explanation

**Escape order for XML matters**
The ampersand (`&`) replacement must happen first. If `<` is replaced with `&lt;` before `&` is replaced with `&amp;`, the `&` in `&lt;` is then double-escaped to `&amp;lt;` — producing garbled output. Always replace `&` first when building XML escape logic with nested REPLACE().

**CSV quoting vs character removal**
For CSV export, the standard approach (RFC 4180) is to wrap any field containing commas, double quotes, or newlines in double quotes, and to escape any internal double quotes by doubling them (`"` → `""`). This preserves the original data intact. Removing commas or newlines (the simpler approach) alters the data and can change the meaning of product descriptions.

**PATINDEX with character class for control characters**
`PATINDEX('%[CHAR(1)-CHAR(31)]%', col)` uses a character class range to detect any control character in a single PATINDEX call, rather than checking CHAR(1) through CHAR(31) individually. This is efficient but relies on the collation treating the character range correctly — test on the specific SQL Server collation used in production.

**Sanitisation vs validation**
Sanitisation modifies the data to make it safe for a target format. Validation reports what needs changing without modifying data. In a cleansing pipeline, always validate first (understand the scope), then sanitise in a controlled UPDATE or transformation, then re-validate to confirm 100% coverage. Never run a sanitisation UPDATE without a prior row-count check to verify the WHERE clause captures exactly the expected set of rows.

## Severity
**Medium** — Special characters in structured format outputs (XML feeds, JSON APIs, CSV exports) cause parsing failures that silently drop or corrupt records. The impact is particularly severe for marketplace product feeds (lost sales, invisible products) and financial CSV exports (incorrect figures if commas in amount fields split columns). The fix is mechanical and low-risk but must be applied consistently across every export path.
