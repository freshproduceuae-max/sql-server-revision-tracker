# G19-T09 — Cleansing Operations | String Truncation and Length Enforcement

## ID
G19-T09

## Group
19 — Cleansing Operations

## Type
String Truncation and Length Enforcement — Detecting Values That Exceed Column Length Constraints or Are Suspiciously Short

## Live Scenario
A payment processor migrates customer data from a legacy system with 500-character address fields into a new system that enforces a 100-character limit. The migration script runs `INSERT INTO NewSystem SELECT Address FROM Legacy` and SQL Server silently truncates all addresses longer than 100 characters — no error, no warning. As a result, 3,400 customers have incomplete addresses that fail postcode extraction and cannot be used for fraud scoring. A length audit before the migration would have identified the 3,400 records, allowed the addresses to be manually reviewed, and prevented the silent truncation.

## The Question
> String length enforcement verifies that field values do not exceed the defined column length constraint and are not suspiciously short (which may indicate truncation already occurred). SQL implements this using LEN() to measure string length, comparing against the schema-defined maximum via INFORMATION_SCHEMA.COLUMNS, and flagging values close to the limit (within 5 characters) as potential truncation victims. Minimum length checks detect fields that are too short to be valid (a 2-character email, a 3-character phone number). The audit produces an actionable list of rows requiring manual review before any column length change or data migration.
> **"Audit string field lengths in the Customers and Products tables: identify fields where values are at or near the column length limit (potential silent truncation), detect values that are suspiciously short for the field's expected content, and produce a length distribution report showing the longest, average, and shortest values per field."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Retrieve column length metadata from schema
SELECT
    TABLE_NAME,
    COLUMN_NAME,
    DATA_TYPE,
    CHARACTER_MAXIMUM_LENGTH,
    IS_NULLABLE
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME IN ('Customers', 'Products')
  AND DATA_TYPE IN ('nvarchar', 'varchar', 'char', 'nchar')
ORDER BY TABLE_NAME, ORDINAL_POSITION;

-- Step 2: Detect values at or near the column length limit (potential truncation)
-- Check key Customers fields against their defined max lengths
SELECT
    'Customers' AS TableName,
    CustomerID,
    ColumnName,
    FieldValue,
    ActualLength,
    ColumnMaxLength,
    ColumnMaxLength - ActualLength AS CharactersRemaining,
    CASE
        WHEN ActualLength = ColumnMaxLength
             THEN 'AT LIMIT: Possible truncation — value fills entire column'
        WHEN ActualLength >= ColumnMaxLength - 5
             THEN 'NEAR LIMIT: Within 5 characters of column limit '
                  + CAST(ColumnMaxLength AS VARCHAR)
        ELSE 'LENGTH OK'
    END AS TruncationFlag
FROM (
    SELECT CustomerID, 'FirstName' AS ColumnName, FirstName AS FieldValue,
           LEN(ISNULL(FirstName,'')) AS ActualLength, 50 AS ColumnMaxLength
    FROM Customers WHERE FirstName IS NOT NULL
    UNION ALL
    SELECT CustomerID, 'LastName', LastName,
           LEN(ISNULL(LastName,'')), 50
    FROM Customers WHERE LastName IS NOT NULL
    UNION ALL
    SELECT CustomerID, 'Email', Email,
           LEN(ISNULL(Email,'')), 100
    FROM Customers WHERE Email IS NOT NULL
    UNION ALL
    SELECT CustomerID, 'Phone', Phone,
           LEN(ISNULL(Phone,'')), 20
    FROM Customers WHERE Phone IS NOT NULL
    UNION ALL
    SELECT CustomerID, 'PostalCode', PostalCode,
           LEN(ISNULL(PostalCode,'')), 10
    FROM Customers WHERE PostalCode IS NOT NULL
    UNION ALL
    SELECT CustomerID, 'Country', Country,
           LEN(ISNULL(Country,'')), 50
    FROM Customers WHERE Country IS NOT NULL
) FieldLengths
WHERE ActualLength >= ColumnMaxLength - 10
ORDER BY TruncationFlag, CharactersRemaining;

-- Step 3: Minimum length validation — detect suspiciously short values
SELECT
    CustomerID,
    FirstName,
    LastName,
    Email,
    Phone,
    PostalCode,
    -- Check for values too short to be valid
    CASE
        WHEN FirstName IS NOT NULL AND LEN(FirstName) < 2
             THEN 'FIRST NAME TOO SHORT: "' + FirstName + '" (min expected: 2 chars)'
        ELSE 'OK'
    END AS FirstNameLengthFlag,
    CASE
        WHEN Email IS NOT NULL AND LEN(Email) < 6
             THEN 'EMAIL TOO SHORT: "' + Email + '" (min valid email: a@b.cc = 6 chars)'
        WHEN Email IS NOT NULL AND CHARINDEX('@', Email) = 0
             THEN 'EMAIL NO AT-SIGN: "' + Email + '" missing @ character'
        ELSE 'OK'
    END AS EmailLengthFlag,
    CASE
        WHEN Phone IS NOT NULL AND LEN(REPLACE(Phone,' ','')) < 7
             THEN 'PHONE TOO SHORT: "' + Phone
                  + '" has fewer than 7 digits after stripping spaces'
        ELSE 'OK'
    END AS PhoneLengthFlag,
    CASE
        WHEN PostalCode IS NOT NULL AND LEN(REPLACE(PostalCode,' ','')) < 5
             THEN 'POSTCODE TOO SHORT: "' + PostalCode
                  + '" (UK postcodes are 5-7 chars)'
        ELSE 'OK'
    END AS PostalCodeLengthFlag
FROM Customers;

-- Step 4: Products description and name length audit
SELECT
    ProductID,
    ProductName,
    LEN(ISNULL(ProductName,''))        AS NameLength,
    LEN(ISNULL(Description,''))        AS DescLength,
    LEN(ISNULL(Tags,''))               AS TagsLength,
    CASE
        WHEN ProductName IS NULL
             THEN 'NULL NAME'
        WHEN LEN(ProductName) < 3
             THEN 'NAME TOO SHORT: "' + ProductName + '" — likely placeholder or error'
        WHEN LEN(ProductName) > 100
             THEN 'NAME VERY LONG: ' + CAST(LEN(ProductName) AS VARCHAR)
                  + ' chars — may truncate in UI displays'
        ELSE 'Name length OK'
    END AS NameLengthFlag,
    CASE
        WHEN Description IS NULL
             THEN 'NULL DESCRIPTION: Missing product description'
        WHEN LEN(Description) < 10
             THEN 'DESCRIPTION TOO SHORT: "' + Description + '" — insufficient for SEO'
        ELSE 'Description OK'
    END AS DescLengthFlag
FROM Products;

-- Step 5: Length distribution summary per field
SELECT
    FieldName,
    TotalRows,
    NullCount,
    MinLength,
    AvgLength,
    MaxLength,
    DefinedMaxLength,
    AtLimitCount,
    CASE
        WHEN AtLimitCount > 0
             THEN 'TRUNCATION RISK: ' + CAST(AtLimitCount AS VARCHAR)
                  + ' values fill the entire column'
        WHEN MaxLength >= DefinedMaxLength - 5
             THEN 'NEAR LIMIT: Largest value is within 5 chars of column maximum'
        ELSE 'No truncation risk detected'
    END AS TruncationRisk
FROM (
    SELECT 'Customers.FirstName' AS FieldName,
           COUNT(*) AS TotalRows,
           SUM(CASE WHEN FirstName IS NULL THEN 1 ELSE 0 END) AS NullCount,
           MIN(LEN(FirstName)) AS MinLength,
           ROUND(AVG(CAST(LEN(FirstName) AS FLOAT)), 1) AS AvgLength,
           MAX(LEN(FirstName)) AS MaxLength,
           50 AS DefinedMaxLength,
           SUM(CASE WHEN LEN(FirstName) = 50 THEN 1 ELSE 0 END) AS AtLimitCount
    FROM Customers
    UNION ALL
    SELECT 'Customers.Email',
           COUNT(*),
           SUM(CASE WHEN Email IS NULL THEN 1 ELSE 0 END),
           MIN(LEN(Email)),
           ROUND(AVG(CAST(LEN(Email) AS FLOAT)), 1),
           MAX(LEN(Email)),
           100,
           SUM(CASE WHEN LEN(Email) = 100 THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'Products.ProductName',
           COUNT(*),
           SUM(CASE WHEN ProductName IS NULL THEN 1 ELSE 0 END),
           MIN(LEN(ProductName)),
           ROUND(AVG(CAST(LEN(ProductName) AS FLOAT)), 1),
           MAX(LEN(ProductName)),
           100,
           SUM(CASE WHEN LEN(ProductName) = 100 THEN 1 ELSE 0 END)
    FROM Products
    UNION ALL
    SELECT 'Customers.PostalCode',
           COUNT(*),
           SUM(CASE WHEN PostalCode IS NULL THEN 1 ELSE 0 END),
           MIN(LEN(PostalCode)),
           ROUND(AVG(CAST(LEN(PostalCode) AS FLOAT)), 1),
           MAX(LEN(PostalCode)),
           10,
           SUM(CASE WHEN LEN(PostalCode) = 10 THEN 1 ELSE 0 END)
    FROM Customers
) LengthStats
ORDER BY AtLimitCount DESC, TruncationRisk;
```

## Explanation

**Silent truncation is the critical risk**
SQL Server, when inserting a string value longer than the column's `CHARACTER_MAXIMUM_LENGTH`, silently truncates the value in many contexts (SSIS data flows, bulk inserts with MAXERRORS > 0, some ETL tools). No error is raised, no warning appears in the output, and the truncated value looks like a valid shorter string. The only way to detect that truncation occurred is to compare the maximum value length in the source against the column length in the target before the migration.

**Values at the exact column limit are suspicious**
If a field has a 50-character maximum and 40 records have exactly 50 characters, those records did not all have exactly 50-character values — they were truncated to 50. The `AtLimitCount` metric in Step 5 directly surfaces this pattern. A non-zero count at the exact column limit is strong evidence of past truncation.

**LEN vs DATALENGTH for length measurement**
`LEN(col)` counts characters (number of code points), ignoring trailing spaces. `DATALENGTH(col)` counts bytes, including trailing spaces. For NVARCHAR columns, `DATALENGTH = 2 × LEN` for standard characters. Use `LEN()` for comparing against `CHARACTER_MAXIMUM_LENGTH` since the schema limit is in characters, not bytes.

**Minimum length as a proxy for truncation at the other end**
A PostalCode with 2 characters ("SW") or an Email with 3 characters ("a@b") is suspicious not because it exceeds the limit, but because it is too short to be real. This pattern appears when a field was truncated during a load that had the wrong column length — the source had "SW1A 2AA" but only the first two characters were captured.

## Severity
**High in migration contexts, Low in steady state** — During data migrations, silent truncation can corrupt thousands of records permanently (the original data is no longer available once the legacy system is decommissioned). In steady-state operations, the application typically enforces maximum field lengths before the data reaches the database, making schema-level truncation rare. The audit is most valuable as a pre-migration gate check.
