# G19-T05 — Cleansing Operations | Value Standardisation and Code Mapping

## ID
G19-T05

## Group
19 — Cleansing Operations

## Type
Value Standardisation and Code Mapping — Mapping Inconsistent Free-Text and Abbreviated Values to a Controlled Vocabulary

## Live Scenario
A retailer's order management system allows sales agents to manually enter the Status field. Over two years, agents have entered "delivered", "DELIVERED", "Del", "Dlvrd", "Complete", "Done", and "OK" — all meaning the same thing as the canonical value "Delivered". When the BI team builds a revenue report filtered to `WHERE Status = 'Delivered'`, it captures only 60% of actually-delivered orders because the remaining 40% use non-standard variants. A value standardisation mapping table translates all variants to the canonical vocabulary ('Pending', 'Processing', 'Delivered', 'Returned', 'Cancelled'), enabling the revenue report to capture 100% of delivered orders.

## The Question
> Value standardisation replaces inconsistent free-text entries, abbreviations, and synonyms with values from a controlled vocabulary. SQL implements this as a mapping CTE or VALUES table that pairs each raw variant with its canonical target, then a LEFT JOIN or CASE expression applies the mapping. A coverage check confirms that 100% of raw values have a mapping; unmapped values are flagged for manual review. The standardisation result includes both the original value and the mapped value so changes can be audited before being committed with an UPDATE.
> **"Standardise the Status field in the Orders table and the Country field in the Customers table: build a mapping from all observed raw values to a canonical controlled vocabulary, identify any unmapped values, apply the mapping to produce standardised output, and produce a standardisation coverage report."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Inventory all distinct raw Status values observed in Orders
SELECT
    Status AS RawValue,
    COUNT(*) AS RecordCount,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS PctOfTotal
FROM Orders
GROUP BY Status
ORDER BY RecordCount DESC;

-- Step 2: Build Status mapping CTE and apply to Orders
WITH StatusMapping AS (
    -- Canonical vocabulary: Pending, Processing, Delivered, Returned, Cancelled
    SELECT 'Pending'    AS RawStatus, 'Pending'    AS CanonicalStatus UNION ALL
    SELECT 'pending',                  'Pending'                       UNION ALL
    SELECT 'PENDING',                  'Pending'                       UNION ALL
    SELECT 'Pndg',                     'Pending'                       UNION ALL
    SELECT 'Processing', 'Processing'                                  UNION ALL
    SELECT 'processing', 'Processing'                                  UNION ALL
    SELECT 'PROCESSING', 'Processing'                                  UNION ALL
    SELECT 'In Progress','Processing'                                  UNION ALL
    SELECT 'InProgress', 'Processing'                                  UNION ALL
    SELECT 'Delivered',  'Delivered'                                   UNION ALL
    SELECT 'delivered',  'Delivered'                                   UNION ALL
    SELECT 'DELIVERED',  'Delivered'                                   UNION ALL
    SELECT 'Del',        'Delivered'                                   UNION ALL
    SELECT 'Dlvrd',      'Delivered'                                   UNION ALL
    SELECT 'Complete',   'Delivered'                                   UNION ALL
    SELECT 'Done',       'Delivered'                                   UNION ALL
    SELECT 'OK',         'Delivered'                                   UNION ALL
    SELECT 'Returned',   'Returned'                                    UNION ALL
    SELECT 'returned',   'Returned'                                    UNION ALL
    SELECT 'Return',     'Returned'                                    UNION ALL
    SELECT 'Refunded',   'Returned'                                    UNION ALL
    SELECT 'Cancelled',  'Cancelled'                                   UNION ALL
    SELECT 'cancelled',  'Cancelled'                                   UNION ALL
    SELECT 'CANCELLED',  'Cancelled'                                   UNION ALL
    SELECT 'Cancel',     'Cancelled'                                   UNION ALL
    SELECT 'Void',       'Cancelled'
)
SELECT
    o.OrderID,
    o.Status AS OriginalStatus,
    sm.CanonicalStatus AS StandardisedStatus,
    CASE
        WHEN o.Status IS NULL
             THEN 'NULL: Apply default mapping (Pending)'
        WHEN sm.CanonicalStatus IS NULL
             THEN 'UNMAPPED: "' + o.Status + '" has no mapping — manual review required'
        WHEN o.Status = sm.CanonicalStatus
             THEN 'ALREADY CANONICAL: No change required'
        ELSE 'MAPPED: "' + o.Status + '" → "' + sm.CanonicalStatus + '"'
    END AS MappingFlag
FROM Orders o
LEFT JOIN StatusMapping sm ON o.Status = sm.RawStatus
ORDER BY MappingFlag, o.OrderID;

-- Step 3: Country mapping — normalise country values to consistent standard
WITH CountryMapping AS (
    SELECT 'UK'          AS RawCountry, 'UK'          AS CanonicalCountry UNION ALL
    SELECT 'United Kingdom',             'UK'                              UNION ALL
    SELECT 'Britain',                    'UK'                              UNION ALL
    SELECT 'England',                    'UK'                              UNION ALL
    SELECT 'GB',                         'UK'                              UNION ALL
    SELECT 'U.K.',                       'UK'                              UNION ALL
    SELECT 'US'          , 'US'                                            UNION ALL
    SELECT 'United States',              'US'                              UNION ALL
    SELECT 'USA',                        'US'                              UNION ALL
    SELECT 'U.S.A.',                     'US'                              UNION ALL
    SELECT 'America',                    'US'                              UNION ALL
    SELECT 'Germany'    , 'Germany'                                        UNION ALL
    SELECT 'DE',                         'Germany'                         UNION ALL
    SELECT 'Deutschland',                'Germany'                         UNION ALL
    SELECT 'Internal'   , 'Internal'                                       UNION ALL
    SELECT 'INT',                        'Internal'                        UNION ALL
    SELECT 'HQ',                         'Internal'
)
SELECT
    c.CustomerID,
    c.Country AS OriginalCountry,
    cm.CanonicalCountry AS StandardisedCountry,
    CASE
        WHEN c.Country IS NULL
             THEN 'NULL: Country unknown'
        WHEN cm.CanonicalCountry IS NULL
             THEN 'UNMAPPED: "' + c.Country + '" — add to mapping table'
        WHEN c.Country = cm.CanonicalCountry
             THEN 'CANONICAL'
        ELSE 'MAPPED: "' + c.Country + '" → "' + cm.CanonicalCountry + '"'
    END AS CountryMappingFlag
FROM Customers c
LEFT JOIN CountryMapping cm ON c.Country = cm.RawCountry;

-- Step 4: Mapping coverage check — find any unmapped values
WITH StatusMapping AS (
    SELECT 'Pending' AS RawStatus, 'Pending' AS Canonical UNION ALL
    SELECT 'Processing', 'Processing' UNION ALL
    SELECT 'Delivered',  'Delivered'  UNION ALL
    SELECT 'Returned',   'Returned'   UNION ALL
    SELECT 'Cancelled',  'Cancelled'
    -- abbreviated mapping for coverage check
)
SELECT
    'Orders.Status' AS FieldName,
    o.Status AS RawValue,
    COUNT(*) AS Occurrences,
    CASE
        WHEN sm.Canonical IS NOT NULL THEN 'MAPPED'
        WHEN o.Status IS NULL THEN 'NULL'
        ELSE 'UNMAPPED — add to StatusMapping'
    END AS CoverageStatus
FROM Orders o
LEFT JOIN StatusMapping sm ON o.Status = sm.RawStatus
GROUP BY o.Status, sm.Canonical
ORDER BY CoverageStatus DESC, Occurrences DESC;

-- Step 5: Standardisation coverage scorecard
WITH StatusMapping AS (
    SELECT 'Pending' AS R, 'Pending' AS C UNION ALL
    SELECT 'Processing','Processing' UNION ALL
    SELECT 'Delivered', 'Delivered'  UNION ALL
    SELECT 'Returned',  'Returned'   UNION ALL
    SELECT 'Cancelled', 'Cancelled'
),
CountryMapping AS (
    SELECT 'UK' AS R, 'UK' AS C UNION ALL
    SELECT 'US','US' UNION ALL
    SELECT 'Germany','Germany' UNION ALL
    SELECT 'Internal','Internal'
)
SELECT
    FieldName,
    TotalRecords,
    AlreadyCanonical,
    WillBeMapped,
    Unmapped,
    NullCount,
    ROUND(100.0 * (AlreadyCanonical + WillBeMapped)
          / NULLIF(TotalRecords - NullCount, 0), 1) AS CoveragePct
FROM (
    SELECT
        'Orders.Status' AS FieldName,
        COUNT(*) AS TotalRecords,
        SUM(CASE WHEN o.Status = sm.C AND o.Status IS NOT NULL THEN 1 ELSE 0 END) AS AlreadyCanonical,
        SUM(CASE WHEN o.Status <> sm.C AND sm.C IS NOT NULL THEN 1 ELSE 0 END)    AS WillBeMapped,
        SUM(CASE WHEN sm.C IS NULL AND o.Status IS NOT NULL THEN 1 ELSE 0 END)    AS Unmapped,
        SUM(CASE WHEN o.Status IS NULL THEN 1 ELSE 0 END)                          AS NullCount
    FROM Orders o
    LEFT JOIN StatusMapping sm ON o.Status = sm.R
    UNION ALL
    SELECT
        'Customers.Country',
        COUNT(*),
        SUM(CASE WHEN c.Country = cm.C AND c.Country IS NOT NULL THEN 1 ELSE 0 END),
        SUM(CASE WHEN c.Country <> cm.C AND cm.C IS NOT NULL THEN 1 ELSE 0 END),
        SUM(CASE WHEN cm.C IS NULL AND c.Country IS NOT NULL THEN 1 ELSE 0 END),
        SUM(CASE WHEN c.Country IS NULL THEN 1 ELSE 0 END)
    FROM Customers c
    LEFT JOIN CountryMapping cm ON c.Country = cm.R
) Scorecard;
```

## Explanation

**Mapping table as the source of truth**
The VALUES-based mapping CTE separates the cleansing logic from the query logic. When a new variant appears ("Dispatched" starts appearing after a system change), it is added to the mapping CTE in one place and all queries using it automatically handle it. Embedding the mapping as a CASE expression scatters the logic across multiple places and is harder to maintain.

**Coverage check before applying the mapping**
Step 4 runs the mapping and counts unmapped values before any UPDATE runs. A 100% coverage check ensures that no raw value will be silently left unchanged or converted to NULL when the mapping is applied. Even one unmapped value represents orders that will remain in the wrong canonical state — find them before committing the transformation.

**Case-insensitive matching with LOWER()**
In production, the LEFT JOIN `ON o.Status = sm.RawStatus` is case-sensitive if the collation is CS (case-sensitive). To handle case-insensitive matching, the join condition becomes `ON LOWER(o.Status) = LOWER(sm.RawStatus)` and the mapping CTE only needs one entry per variant (no need for 'pending', 'PENDING', 'Pending' as separate rows). For CI collations (SQL Server default), the original approach works without LOWER().

**Preserving original values during standardisation**
The query produces both OriginalStatus and StandardisedStatus side-by-side so a human reviewer can verify the mapping is correct before the UPDATE runs. Never run a bulk UPDATE without a preview stage — mapping errors (e.g., "OK" mapped to "Cancelled" instead of "Delivered") would silently corrupt data for every affected row.

## Severity
**High** — Unmapped or inconsistently valued status codes produce incorrect operational metrics: unfulfilled order counts are understated (some "Done" orders are counted as active), revenue in reporting is understated (delivered orders not counted), and SLA compliance measurements are wrong. Standardisation is a prerequisite for any aggregation or reporting that groups by these fields.
