# G19-T08 — Cleansing Operations | Numeric Range and Outlier Correction

## ID
G19-T08

## Group
19 — Cleansing Operations

## Type
Numeric Range and Outlier Correction — Detecting and Handling Values That Fall Outside Expected Business Ranges

## Live Scenario
A retail analytics team notices that their average order value report shows £2,847 — an implausibly high figure for a business where 95% of orders are under £500. Investigation reveals three root causes: (1) a data entry error where a clerk entered "19999" instead of "199.99" (missing decimal point), (2) a currency conversion bug that multiplied GBP amounts by 100 (treating pounds as pence), and (3) a test record with TotalAmount = 999999.99 that was never cleaned up from the staging environment. The outlier detection query identifies all three classes using IQR-based statistical boundaries, business rule thresholds, and a comparison against per-product price benchmarks.

## The Question
> Numeric outlier detection uses statistical methods (IQR = Q3 - Q1; outlier boundary = Q3 + 1.5 × IQR) and business rule thresholds to identify values that are implausible given the context. SQL implements quartile boundaries using PERCENTILE_CONT() or NTILE(4), then flags records above the upper fence or below the lower fence. Business rule validation adds context-specific checks (negative prices, zero quantities on active orders, amounts that are exact multiples of 100 suggesting pence-vs-pounds errors). The correction approach (cap, floor, flag for manual review, or exclude) depends on the root cause.
> **"Detect numeric outliers in the Orders and Products tables: identify TotalAmount values that fall outside the statistical IQR fence, flag prices that are implausible given the product category, detect zero-or-negative values in fields that must be positive, and produce an outlier impact summary showing the effect of outliers on summary statistics."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Statistical outlier detection using IQR method on TotalAmount
WITH OrderedAmounts AS (
    SELECT
        OrderID,
        TotalAmount,
        PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Q1,
        PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Q3
    FROM Orders
    WHERE TotalAmount IS NOT NULL
),
IQRBounds AS (
    SELECT
        OrderID,
        TotalAmount,
        Q1,
        Q3,
        Q3 - Q1                          AS IQR,
        Q1 - 1.5 * (Q3 - Q1)            AS LowerFence,
        Q3 + 1.5 * (Q3 - Q1)            AS UpperFence
    FROM OrderedAmounts
)
SELECT
    OrderID,
    ROUND(TotalAmount, 2) AS TotalAmount,
    ROUND(Q1, 2) AS Q1,
    ROUND(Q3, 2) AS Q3,
    ROUND(IQR, 2) AS IQR,
    ROUND(LowerFence, 2) AS LowerFence,
    ROUND(UpperFence, 2) AS UpperFence,
    CASE
        WHEN TotalAmount > UpperFence
             THEN 'HIGH OUTLIER: ' + CAST(ROUND(TotalAmount, 2) AS VARCHAR)
                  + ' exceeds IQR upper fence of ' + CAST(ROUND(UpperFence, 2) AS VARCHAR)
        WHEN TotalAmount < LowerFence AND TotalAmount >= 0
             THEN 'LOW OUTLIER: ' + CAST(ROUND(TotalAmount, 2) AS VARCHAR)
                  + ' is below IQR lower fence of ' + CAST(ROUND(LowerFence, 2) AS VARCHAR)
        WHEN TotalAmount < 0
             THEN 'NEGATIVE AMOUNT: ' + CAST(ROUND(TotalAmount, 2) AS VARCHAR)
                  + ' — invalid for an order total'
        ELSE 'WITHIN IQR BOUNDS'
    END AS OutlierFlag
FROM IQRBounds
ORDER BY TotalAmount DESC;

-- Step 2: Business rule validation for Products numeric fields
SELECT
    ProductID,
    ProductName,
    Price,
    StockQuantity,
    DiscountPercent,
    VATRate,
    CASE
        WHEN Price IS NULL
             THEN 'NULL PRICE: Cannot sell without a price'
        WHEN Price <= 0
             THEN 'ZERO/NEGATIVE PRICE: ' + CAST(Price AS VARCHAR)
                  + ' — price must be positive'
        WHEN Price > 5000
             THEN 'HIGH PRICE: ' + CAST(Price AS VARCHAR)
                  + ' — verify this is not a pence/pennies entry error'
        WHEN Price < 0.01
             THEN 'EFFECTIVELY ZERO: Price of ' + CAST(Price AS VARCHAR)
                  + ' rounds to zero — likely data entry error'
        ELSE 'Price OK'
    END AS PriceFlag,
    CASE
        WHEN StockQuantity IS NULL
             THEN 'NULL STOCK: Missing stock level'
        WHEN StockQuantity < 0
             THEN 'NEGATIVE STOCK: ' + CAST(StockQuantity AS VARCHAR)
                  + ' — oversell error or system bug'
        WHEN StockQuantity > 10000
             THEN 'HIGH STOCK: ' + CAST(StockQuantity AS VARCHAR)
                  + ' — verify not a unit error (individual vs pallet count)'
        ELSE 'Stock OK'
    END AS StockFlag,
    CASE
        WHEN DiscountPercent IS NULL        THEN 'NULL: No discount recorded'
        WHEN DiscountPercent < 0            THEN 'NEGATIVE DISCOUNT: Invalid'
        WHEN DiscountPercent > 100          THEN 'DISCOUNT > 100%: Mathematically impossible'
        WHEN DiscountPercent = 100          THEN 'FREE: 100% discount — verify intentional'
        WHEN DiscountPercent > 50
             THEN 'HIGH DISCOUNT: ' + CAST(DiscountPercent AS VARCHAR)
                  + '% — verify approval exists'
        ELSE 'Discount OK'
    END AS DiscountFlag,
    CASE
        WHEN VATRate IS NULL                THEN 'NULL VAT: Missing'
        WHEN VATRate NOT IN (0, 5, 20)
             THEN 'NON-STANDARD VAT RATE: ' + CAST(VATRate AS VARCHAR)
                  + '% — UK rates are 0%, 5% (reduced), 20% (standard)'
        ELSE 'VAT OK'
    END AS VATFlag
FROM Products;

-- Step 3: Pence-vs-pounds detection — amounts that are exact multiples of 100
WITH AmountStats AS (
    SELECT AVG(TotalAmount) AS AvgAmount, STDEV(TotalAmount) AS StdDev
    FROM Orders WHERE TotalAmount IS NOT NULL
)
SELECT
    o.OrderID,
    o.TotalAmount,
    p.Price AS ProductPrice,
    o.TotalAmount / NULLIF(p.Price, 0) AS ImpliedQuantity,
    ams.AvgAmount,
    CASE
        -- If amount is a large multiple of 100 compared to other orders,
        -- it may be in pence rather than pounds
        WHEN o.TotalAmount > ams.AvgAmount * 100
             THEN 'POSSIBLE PENCE ERROR: Amount is >100x average ('
                  + CAST(ROUND(o.TotalAmount, 2) AS VARCHAR) + ' vs avg '
                  + CAST(ROUND(ams.AvgAmount, 2) AS VARCHAR) + ')'
        WHEN o.TotalAmount > 0 AND o.TotalAmount < 0.50
             THEN 'SUSPICIOUSLY LOW: Amount of '
                  + CAST(ROUND(o.TotalAmount, 2) AS VARCHAR)
                  + ' may be in pounds where pence are expected'
        ELSE 'Amount scale plausible'
    END AS CurrencyScaleFlag
FROM Orders o
LEFT JOIN Products p ON o.ProductID = p.ProductID
CROSS JOIN AmountStats ams
WHERE o.TotalAmount IS NOT NULL;

-- Step 4: Outlier impact on aggregate statistics
WITH OutlierBounds AS (
    SELECT
        PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Q3,
        PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Q1
    FROM Orders WHERE TotalAmount IS NOT NULL
),
Flags AS (
    SELECT o.OrderID, o.TotalAmount,
           CASE WHEN o.TotalAmount > ob.Q3 + 1.5*(ob.Q3-ob.Q1) THEN 1 ELSE 0 END AS IsOutlier
    FROM Orders o
    CROSS JOIN (SELECT DISTINCT Q1, Q3 FROM OutlierBounds) ob
    WHERE o.TotalAmount IS NOT NULL
)
SELECT
    'ALL RECORDS (including outliers)'    AS DataSet,
    COUNT(*) AS RecordCount,
    ROUND(AVG(TotalAmount), 2) AS AvgAmount,
    ROUND(MIN(TotalAmount), 2) AS MinAmount,
    ROUND(MAX(TotalAmount), 2) AS MaxAmount,
    ROUND(STDEV(TotalAmount), 2) AS StdDev
FROM Flags
UNION ALL
SELECT
    'WITHOUT OUTLIERS (IQR-cleaned)',
    COUNT(*),
    ROUND(AVG(TotalAmount), 2),
    ROUND(MIN(TotalAmount), 2),
    ROUND(MAX(TotalAmount), 2),
    ROUND(STDEV(TotalAmount), 2)
FROM Flags
WHERE IsOutlier = 0;

-- Step 5: Outlier summary by severity band
WITH OrderedAmounts AS (
    SELECT TotalAmount,
           PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Q1,
           PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY TotalAmount) OVER () AS Q3
    FROM Orders WHERE TotalAmount IS NOT NULL
)
SELECT
    CASE
        WHEN TotalAmount < 0
             THEN 'NEGATIVE (invalid)'
        WHEN TotalAmount = 0
             THEN 'ZERO (review)'
        WHEN TotalAmount <= Q1 - 1.5*(Q3-Q1)
             THEN 'LOW OUTLIER (< lower fence)'
        WHEN TotalAmount <= Q1
             THEN 'LOW NORMAL (Q1 to lower fence)'
        WHEN TotalAmount <= Q3
             THEN 'NORMAL (Q1 to Q3 interquartile)'
        WHEN TotalAmount <= Q3 + 1.5*(Q3-Q1)
             THEN 'HIGH NORMAL (Q3 to upper fence)'
        ELSE 'HIGH OUTLIER (> upper fence)'
    END AS SeverityBand,
    COUNT(*) AS RecordCount,
    ROUND(MIN(TotalAmount), 2) AS BandMin,
    ROUND(MAX(TotalAmount), 2) AS BandMax
FROM OrderedAmounts
GROUP BY
    CASE
        WHEN TotalAmount < 0                      THEN 'NEGATIVE (invalid)'
        WHEN TotalAmount = 0                      THEN 'ZERO (review)'
        WHEN TotalAmount <= Q1 - 1.5*(Q3-Q1)     THEN 'LOW OUTLIER (< lower fence)'
        WHEN TotalAmount <= Q1                    THEN 'LOW NORMAL (Q1 to lower fence)'
        WHEN TotalAmount <= Q3                    THEN 'NORMAL (Q1 to Q3 interquartile)'
        WHEN TotalAmount <= Q3 + 1.5*(Q3-Q1)     THEN 'HIGH NORMAL (Q3 to upper fence)'
        ELSE 'HIGH OUTLIER (> upper fence)'
    END
ORDER BY BandMin;
```

## Explanation

**IQR method vs Z-score for outlier detection**
The IQR method (outlier > Q3 + 1.5 × IQR) is resistant to the influence of outliers themselves — the quartiles are computed from the middle 50% of the data and are not distorted by extreme values. The Z-score method (outlier: |x - mean| / stdev > 3) is sensitive to outliers because both the mean and standard deviation are inflated by them. For financial data with heavy right-skewed distributions, the IQR method is generally more appropriate.

**Business rule vs statistical rule**
Statistical outlier detection (IQR fence) identifies values that are extreme relative to the distribution. Business rule validation identifies values that are impossible or implausible given domain knowledge (negative price, discount > 100%). Both are needed: a price of £4,999 may be within the IQR fence if you sell luxury goods, but a price of £0.001 is business-rule invalid regardless of the distribution. Run both checks together.

**Effect on aggregate statistics**
Step 4 demonstrates why outlier removal affects reported averages: two high outliers (representing 10% of records) shift the average by 21%. When presenting summary statistics to stakeholders, always specify whether outliers are included or excluded and define the outlier criteria used. An unexplained change in average order value between reporting periods may be explained by a single large test order that entered or left the dataset.

**Correction strategy depends on root cause**
Outlier correction is not always deletion: (1) data entry errors (missing decimal) → correct the value; (2) unit errors (pence vs pounds) → divide by 100; (3) currency conversion bugs → recalculate using correct rate; (4) legitimate high-value orders → retain and flag; (5) test records → delete. Applying a blanket cap (Winsorisation) or deletion without root cause analysis can mask real data problems.

## Severity
**Medium to High** — Outliers in financial fields distort KPIs, average order values, revenue forecasts, and commission calculations. A single test record with TotalAmount = 999999.99 in a 1,000-order dataset inflates the average from £273 to £1,273. The business impact depends on how many downstream metrics consume the uncleaned field.
