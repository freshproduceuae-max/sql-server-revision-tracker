# G19-T01 — Cleansing Operations | Whitespace and Invisible Character Removal

## ID
G19-T01

## Group
19 — Cleansing Operations

## Type
Whitespace and Invisible Character Removal — Detecting and Correcting Leading, Trailing, and Embedded Invisible Characters

## Live Scenario
A customer service system imports a CSV export from a legacy mainframe. The mainframe's output pads every field to a fixed width with trailing spaces — a CustomerID of "CUST-001" is stored as "CUST-001       " (7 trailing spaces). When analysts run `WHERE CustomerID = 'CUST-001'`, they get no results because the stored value doesn't match the literal. The system also contains non-breaking spaces (Unicode 0x00A0) embedded in product names from a copy-paste from a web page, and carriage returns (0x000D) in the Notes field from a Windows text editor. The whitespace cleansing script identifies all three types, quantifies how many records are affected, and generates the UPDATE statements to fix them.

## The Question
> Whitespace and invisible character cleansing removes leading spaces (LTRIM), trailing spaces (RTRIM), double spaces (REPLACE with LIKE pattern), non-breaking spaces (REPLACE with CHAR(160)), carriage returns (REPLACE with CHAR(13)), line feeds (REPLACE with CHAR(10)), and tab characters (REPLACE with CHAR(9)). SQL detects affected records using LEN vs DATALENGTH comparison, LIKE patterns for embedded whitespace, and ASCII/UNICODE value checks. UPDATE statements apply the corrections and record counts verify completeness.
> **"Detect and correct whitespace and invisible character issues across the Customers and Products tables: identify records with leading or trailing whitespace in key fields, detect embedded double-spaces, find non-breaking spaces or control characters, and generate the cleaned values alongside the original for review."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Detect leading and trailing whitespace in key fields
SELECT
    CustomerID,
    FirstName,
    LastName,
    Email,
    -- Leading whitespace detection
    CASE WHEN FirstName <> LTRIM(FirstName) THEN 'HAS LEADING SPACES' ELSE 'OK' END AS FirstNameLeading,
    CASE WHEN LastName  <> LTRIM(LastName)  THEN 'HAS LEADING SPACES' ELSE 'OK' END AS LastNameLeading,
    CASE WHEN Email     <> LTRIM(Email)     THEN 'HAS LEADING SPACES' ELSE 'OK' END AS EmailLeading,
    -- Trailing whitespace detection
    CASE WHEN FirstName <> RTRIM(FirstName) THEN 'HAS TRAILING SPACES' ELSE 'OK' END AS FirstNameTrailing,
    CASE WHEN LastName  <> RTRIM(LastName)  THEN 'HAS TRAILING SPACES' ELSE 'OK' END AS LastNameTrailing,
    CASE WHEN Email     <> RTRIM(Email)     THEN 'HAS TRAILING SPACES' ELSE 'OK' END AS EmailTrailing,
    -- Cleaned values
    LTRIM(RTRIM(FirstName)) AS CleanedFirstName,
    LTRIM(RTRIM(LastName))  AS CleanedLastName,
    LTRIM(RTRIM(Email))     AS CleanedEmail
FROM Customers
WHERE FirstName <> LTRIM(RTRIM(ISNULL(FirstName,'')))
   OR LastName  <> LTRIM(RTRIM(ISNULL(LastName,'')))
   OR Email     <> LTRIM(RTRIM(ISNULL(Email,'')));

-- Step 2: Detect double spaces and embedded whitespace
SELECT
    CustomerID,
    FirstName,
    PostalCode,
    Phone,
    CASE WHEN FirstName LIKE '%  %' THEN 'DOUBLE SPACE in FirstName' ELSE 'OK' END AS DoubleSpaceFlag,
    CASE WHEN PostalCode LIKE '%  %' THEN 'DOUBLE SPACE in PostalCode' ELSE 'OK' END AS PCDoubleSpaceFlag,
    -- Replace double spaces
    REPLACE(REPLACE(REPLACE(ISNULL(FirstName,''), '   ', ' '), '  ', ' '), '  ', ' ') AS CleanedFirstName
FROM Customers
WHERE FirstName LIKE '%  %'
   OR PostalCode LIKE '%  %';

-- Step 3: Non-breaking space and control character detection
-- CHAR(160) = non-breaking space; CHAR(9) = tab; CHAR(13) = CR; CHAR(10) = LF
SELECT
    CustomerID,
    FirstName,
    Email,
    CASE
        WHEN CHARINDEX(CHAR(160), ISNULL(FirstName,'')) > 0
             THEN 'NON-BREAKING SPACE at position '
                  + CAST(CHARINDEX(CHAR(160), FirstName) AS VARCHAR)
        WHEN CHARINDEX(CHAR(9), ISNULL(FirstName,'')) > 0
             THEN 'TAB CHARACTER in FirstName'
        WHEN CHARINDEX(CHAR(13), ISNULL(FirstName,'')) > 0
             THEN 'CARRIAGE RETURN in FirstName'
        WHEN CHARINDEX(CHAR(10), ISNULL(FirstName,'')) > 0
             THEN 'LINE FEED in FirstName'
        ELSE 'No control characters'
    END AS ControlCharFlag,
    -- Clean version: replace all common invisible characters
    REPLACE(REPLACE(REPLACE(REPLACE(
        ISNULL(FirstName,''),
        CHAR(160), ' '),   -- non-breaking space → space
        CHAR(9),   ''),    -- tab → nothing
        CHAR(13),  ''),    -- CR → nothing
        CHAR(10),  '')     -- LF → nothing
        AS CleanedFirstName
FROM Customers
WHERE CHARINDEX(CHAR(160), ISNULL(FirstName,'')) > 0
   OR CHARINDEX(CHAR(9),   ISNULL(FirstName,'')) > 0
   OR CHARINDEX(CHAR(13),  ISNULL(FirstName,'')) > 0
   OR CHARINDEX(CHAR(10),  ISNULL(FirstName,'')) > 0;

-- Step 4: ProductName whitespace and character audit
SELECT
    ProductID,
    ProductName,
    LEN(ProductName)      AS CharLength,
    DATALENGTH(ProductName) AS ByteLength,   -- > CharLength means non-ASCII chars
    CASE
        WHEN ProductName <> LTRIM(RTRIM(ProductName))
             THEN 'LEADING/TRAILING SPACES'
        WHEN ProductName LIKE '%  %'
             THEN 'DOUBLE SPACES'
        WHEN DATALENGTH(ProductName) > 2 * LEN(ProductName)
             THEN 'MULTI-BYTE CHARS: possible hidden Unicode characters'
        ELSE 'Clean'
    END AS WhitespaceFlag,
    LTRIM(RTRIM(REPLACE(REPLACE(ProductName, '  ', ' '), '  ', ' '))) AS CleanedProductName
FROM Products
WHERE ProductName <> LTRIM(RTRIM(ProductName))
   OR ProductName LIKE '%  %'
   OR DATALENGTH(ProductName) > 2 * LEN(ProductName);

-- Step 5: Whitespace cleansing summary and UPDATE preview
SELECT
    TableName,
    ColumnName,
    AffectedRows,
    CASE
        WHEN AffectedRows = 0 THEN 'CLEAN: No whitespace issues'
        ELSE 'NEEDS CLEANSING: ' + CAST(AffectedRows AS VARCHAR) + ' rows affected'
    END AS CleansingRequired
FROM (
    SELECT 'Customers' AS TableName, 'FirstName' AS ColumnName,
        SUM(CASE WHEN FirstName <> LTRIM(RTRIM(ISNULL(FirstName,''))) THEN 1 ELSE 0 END) AS AffectedRows
    FROM Customers
    UNION ALL
    SELECT 'Customers', 'LastName',
        SUM(CASE WHEN LastName <> LTRIM(RTRIM(ISNULL(LastName,''))) THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'Customers', 'Email',
        SUM(CASE WHEN Email <> LTRIM(RTRIM(ISNULL(Email,''))) THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'Customers', 'PostalCode (double space)',
        SUM(CASE WHEN PostalCode LIKE '%  %' THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'Products', 'ProductName',
        SUM(CASE WHEN ProductName <> LTRIM(RTRIM(ProductName)) THEN 1 ELSE 0 END)
    FROM Products
) WhitespaceSummary;

-- UPDATE script (preview only — comment out to run)
/*
```

## Explanation

**LTRIM/RTRIM vs TRIM**
SQL Server 2017+ supports `TRIM()` which removes both leading and trailing spaces in one call. For older versions, `LTRIM(RTRIM(col))` is the equivalent. TRIM can also take a character argument: `TRIM('.' FROM col)` removes dots from both ends. For control characters, REPLACE must be used separately since TRIM only handles ASCII space (0x20) by default.

**LEN vs DATALENGTH for Unicode detection**
`LEN(col)` returns the number of characters; `DATALENGTH(col)` returns the number of bytes. For pure ASCII NVARCHAR, `DATALENGTH = 2 × LEN` (2 bytes per character). If `DATALENGTH > 2 × LEN`, the column contains characters requiring more than 2 bytes — supplementary Unicode characters, BOM markers, or encoding artefacts. Step 4 uses this ratio as a proxy for detecting hidden multi-byte characters.

**Nested REPLACE for double spaces**
`REPLACE(col, '  ', ' ')` (double space → single space) is applied twice because a triple-space becomes a double-space after the first replace and requires a second pass. A more robust approach for any number of consecutive spaces is a WHILE loop or a recursive CTE, but the nested double-replace handles the common case of 2–3 consecutive spaces efficiently.

**CHAR() for invisible character detection**
Control characters cannot be typed in a LIKE pattern or a string literal — they must be referenced by their ASCII value using CHAR(). CHAR(160) is the non-breaking space (U+00A0), which is visually identical to a regular space but does not match LIKE ' ' or TRIM(). CHAR(13)/CHAR(10) are carriage return and line feed, commonly embedded when text is pasted from Windows applications.

## Severity
**Medium** — Whitespace issues cause silent matching failures: `WHERE CustomerID = 'CUST-001'` fails to match 'CUST-001 '. They also cause display issues in UIs (names with leading spaces are sorted incorrectly) and interfere with deduplication (two records of the same customer are treated as different because one has a trailing space). The fix (LTRIM/RTRIM) is safe and reversible, making cleansing low-risk but high-value.
