# G19-T03 — Cleansing Operations | Null Imputation and Default Value Assignment

## ID
G19-T03

## Group
19 — Cleansing Operations

## Type
Null Imputation and Default Value Assignment — Replacing Missing Values with Appropriate Defaults or Derived Estimates

## Live Scenario
A machine learning team builds a customer lifetime value model using the Orders dataset. The model fails to score 340 customers because their `TotalAmount` is NULL for some orders — the model requires a numeric value for every observation. The data engineer applies NULL imputation: for TotalAmount, the product-category average replaces individual NULLs (business context: the amount is missing because of a system error during payment capture, not because the order had no value). For DeliveryDate, NULL is imputed as OrderDate + the average lead time for that product category. The model now scores all customers, with imputed values flagged so downstream analysts can treat them with appropriate uncertainty.

## The Question
> NULL imputation replaces missing values with statistically or business-justified substitutes: mean/median imputation for continuous variables, mode imputation for categorical variables, derived imputation (using a formula applied to related non-NULL fields), and forward/backward fill (using the previous or next non-NULL value in a time series). SQL implements each strategy using ISNULL/COALESCE with subqueries or window functions, and always produces an imputation flag so imputed values can be excluded from validation checks.
> **"Apply NULL imputation strategies to the Orders dataset: replace NULL TotalAmount with the average TotalAmount for the same ProductID (product-mean imputation), replace NULL DeliveryDate with OrderDate plus the average lead time for completed orders, and replace NULL Status with 'Pending' (default value imputation). Flag all imputed values so they can be excluded from downstream analysis."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Products** — `schemas/03_Products.csv`

## Solution Query

```sql
-- Step 1: Quantify NULL rates before imputation
SELECT
    'TotalAmount'   AS Column_, COUNT(*) AS TotalRows,
    SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END) AS NullCount,
    ROUND(100.0 * SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END) / COUNT(*), 1) AS NullPct
FROM Orders
UNION ALL
SELECT 'DeliveryDate', COUNT(*),
    SUM(CASE WHEN DeliveryDate IS NULL THEN 1 ELSE 0 END),
    ROUND(100.0 * SUM(CASE WHEN DeliveryDate IS NULL THEN 1 ELSE 0 END) / COUNT(*), 1)
FROM Orders
UNION ALL
SELECT 'Status', COUNT(*),
    SUM(CASE WHEN Status IS NULL THEN 1 ELSE 0 END),
    ROUND(100.0 * SUM(CASE WHEN Status IS NULL THEN 1 ELSE 0 END) / COUNT(*), 1)
FROM Orders;

-- Step 2: Product-mean imputation for TotalAmount
WITH ProductAvgAmount AS (
    SELECT ProductID,
           ROUND(AVG(TotalAmount), 2) AS AvgAmount,
           COUNT(*) AS NonNullCount
    FROM Orders
    WHERE TotalAmount IS NOT NULL AND ProductID IS NOT NULL
    GROUP BY ProductID
),
GlobalAvg AS (
    SELECT ROUND(AVG(TotalAmount), 2) AS GlobalAvgAmount
    FROM Orders WHERE TotalAmount IS NOT NULL
)
SELECT
    o.OrderID,
    o.ProductID,
    o.TotalAmount AS OriginalAmount,
    -- Imputed value: product mean, or global mean if no product average available
    ROUND(COALESCE(
        o.TotalAmount,             -- use original if not NULL
        pa.AvgAmount,              -- else use product-specific average
        ga.GlobalAvgAmount         -- else use global average as last resort
    ), 2) AS ImputedAmount,
    CASE
        WHEN o.TotalAmount IS NOT NULL
             THEN 'ORIGINAL'
        WHEN pa.AvgAmount IS NOT NULL
             THEN 'IMPUTED_PRODUCT_MEAN: Used average of ' + CAST(pa.NonNullCount AS VARCHAR)
                  + ' orders for ' + o.ProductID
        ELSE 'IMPUTED_GLOBAL_MEAN: No product-specific average available'
    END AS ImputationFlag
FROM Orders o
LEFT JOIN ProductAvgAmount pa ON o.ProductID = pa.ProductID
CROSS JOIN GlobalAvg ga
ORDER BY ImputationFlag DESC, o.OrderID;

-- Step 3: Lead time imputation for DeliveryDate
WITH AvgLeadTime AS (
    SELECT
        ProductID,
        AVG(DATEDIFF(DAY, OrderDate, DeliveryDate)) AS AvgLeadDays,
        COUNT(*) AS CompletedOrders
    FROM Orders
    WHERE DeliveryDate IS NOT NULL
      AND OrderDate IS NOT NULL
      AND DeliveryDate > OrderDate
    GROUP BY ProductID
),
GlobalLeadTime AS (
    SELECT AVG(DATEDIFF(DAY, OrderDate, DeliveryDate)) AS GlobalAvgLeadDays
    FROM Orders
    WHERE DeliveryDate IS NOT NULL AND OrderDate IS NOT NULL AND DeliveryDate > OrderDate
)
SELECT
    o.OrderID,
    o.ProductID,
    CAST(o.OrderDate AS DATE) AS OrderDate,
    CAST(o.DeliveryDate AS DATE) AS OriginalDeliveryDate,
    CAST(DATEADD(DAY,
        COALESCE(alt.AvgLeadDays, glt.GlobalAvgLeadDays, 7),
        o.OrderDate
    ) AS DATE) AS ImputedDeliveryDate,
    CASE
        WHEN o.DeliveryDate IS NOT NULL
             THEN 'ORIGINAL'
        WHEN alt.AvgLeadDays IS NOT NULL
             THEN 'IMPUTED: OrderDate + ' + CAST(alt.AvgLeadDays AS VARCHAR)
                  + '-day avg lead time for ' + o.ProductID
        ELSE 'IMPUTED_GLOBAL: OrderDate + ' + CAST(ISNULL(glt.GlobalAvgLeadDays, 7) AS VARCHAR)
             + '-day global average'
    END AS ImputationFlag
FROM Orders o
LEFT JOIN AvgLeadTime alt ON o.ProductID = alt.ProductID
CROSS JOIN GlobalLeadTime glt
WHERE o.DeliveryDate IS NULL AND o.OrderDate IS NOT NULL;

-- Step 4: Default value imputation for Status
SELECT
    OrderID,
    Status AS OriginalStatus,
    ISNULL(Status, 'Pending') AS ImputedStatus,
    CASE
        WHEN Status IS NOT NULL THEN 'ORIGINAL'
        ELSE 'IMPUTED_DEFAULT: Status set to "Pending" (no Status in source data)'
    END AS ImputationFlag
FROM Orders
WHERE Status IS NULL;

-- Step 5: Imputation impact summary
WITH ImputedDataset AS (
    SELECT
        o.OrderID,
        -- Apply all three imputations
        COALESCE(o.TotalAmount, pa.AvgAmount, ga.GlobalAvgAmount) AS ImputedAmount,
        COALESCE(o.Status, 'Pending') AS ImputedStatus,
        COALESCE(o.DeliveryDate,
            DATEADD(DAY, ISNULL(alt.AvgLeadDays, 7), o.OrderDate)) AS ImputedDelivery,
        CASE WHEN o.TotalAmount IS NULL THEN 1 ELSE 0 END AS AmountImputed,
        CASE WHEN o.Status IS NULL THEN 1 ELSE 0 END AS StatusImputed,
        CASE WHEN o.DeliveryDate IS NULL THEN 1 ELSE 0 END AS DeliveryImputed
    FROM Orders o
    CROSS JOIN (SELECT ROUND(AVG(TotalAmount), 2) AS GlobalAvgAmount FROM Orders WHERE TotalAmount IS NOT NULL) ga
    LEFT JOIN (
        SELECT ProductID, ROUND(AVG(TotalAmount), 2) AS AvgAmount
        FROM Orders WHERE TotalAmount IS NOT NULL GROUP BY ProductID
    ) pa ON o.ProductID = pa.ProductID
    LEFT JOIN (
        SELECT ProductID, AVG(DATEDIFF(DAY, OrderDate, DeliveryDate)) AS AvgLeadDays
        FROM Orders WHERE DeliveryDate IS NOT NULL AND DeliveryDate > OrderDate GROUP BY ProductID
    ) alt ON o.ProductID = alt.ProductID
)
SELECT
    COUNT(*) AS TotalOrders,
    SUM(AmountImputed) AS AmountImputedCount,
    SUM(StatusImputed) AS StatusImputedCount,
    SUM(DeliveryImputed) AS DeliveryImputedCount,
    SUM(CASE WHEN AmountImputed + StatusImputed + DeliveryImputed = 0 THEN 1 ELSE 0 END) AS FullyOriginalCount,
    ROUND(AVG(ImputedAmount), 2) AS AvgImputedAmount
FROM ImputedDataset;
```

## Explanation

**Hierarchy of imputation strategies**
Step 2 applies imputation in a priority hierarchy using COALESCE: original value (if not NULL) → product-specific mean (from orders of the same product) → global mean (fallback if no product-specific average exists). This hierarchy respects the most informative context available: a product-specific average incorporates the price point of that particular product, which may differ substantially from the global average.

**Imputation flag as a first-class column**
Every imputed value must be accompanied by an imputation flag that identifies the value as imputed and the strategy used. This flag serves two purposes: (1) it allows downstream analysts to exclude imputed values from accuracy-sensitive calculations; (2) it provides an audit trail that the imputation was applied, enabling the original NULL to be recovered or the imputation to be corrected if the real value is later found. Without the flag, imputed values are indistinguishable from real values.

**Lead time as a derived imputation**
Step 3's delivery date imputation is a derived imputation: the missing value is estimated using a formula applied to related observed values (OrderDate + average lead time). This is more informative than a constant default (e.g., "add 7 days to every missing delivery date") because it adapts to the actual historical lead time for that product. The CROSS JOIN with GlobalLeadTime and LEFT JOIN with product-level AvgLeadTime implement the two-level hierarchy.

**When NOT to impute**
NULL imputation is appropriate when the NULL represents a value that should exist but is missing due to a data capture failure. It is not appropriate when NULL represents "not applicable" (an active customer with no ContractEnd date), "not yet known" (an order with no delivery date because it hasn't been delivered), or "intentionally absent" (a product with no discount because no discount applies). Imputing in these cases introduces false data.

## Severity
**Medium** — Inappropriate NULL imputation can introduce systematic bias into models and reports: mean imputation reduces the variance of a column (all NULLs become the mean, compressing the distribution); forward-fill introduces temporal autocorrelation; default value imputation (Status = 'Pending') may misclassify orders. Imputation should always be accompanied by sensitivity analysis to measure the impact on downstream outputs.
