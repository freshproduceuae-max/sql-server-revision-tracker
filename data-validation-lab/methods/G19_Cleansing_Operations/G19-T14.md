# G19-T14 — Cleansing Operations | Data Type Coercion and Casting Validation

## ID
G19-T14

## Group
19 — Cleansing Operations

## Type
Data Type Coercion and Casting Validation — Detecting Values Stored in the Wrong Data Type and Safely Converting Them

## Live Scenario
A data warehouse ingests a JSON-based ERP export where every field arrives as NVARCHAR. The fields include OrderID (should be INT), TotalAmount (should be DECIMAL(10,2)), OrderDate (should be DATE), and IsActive (should be BIT). The ETL job runs `INSERT INTO Orders SELECT CAST(OrderID AS INT), CAST(TotalAmount AS DECIMAL(10,2))...` and fails with "Error converting data type nvarchar to decimal" because three TotalAmount values contain "N/A", "TBC", and "1,299.50" (comma as thousands separator). The type coercion audit identifies every value that will fail the cast, produces the corrected values where possible, and counts the records that require manual intervention.

## The Question
> Data type coercion validation uses TRY_CAST() and TRY_CONVERT() to test whether NVARCHAR values can be safely converted to their target data type without generating an error. TRY_CAST returns NULL for values that cannot be converted, distinguishing them from genuine NULLs and values that convert successfully. Pre-conversion cleaning (removing commas from numeric strings, standardising boolean synonyms to 1/0) maximises the proportion of values that can be automatically coerced, leaving only genuinely malformed values for manual review.
> **"Validate data type coercions for a simulated staging import of the Orders dataset stored as NVARCHAR: test each key field for safe castability, identify which values fail the cast and why, apply pre-conversion cleaning where possible (removing thousands separators, standardising boolean strings), and produce a coercion readiness report showing the percentage of each field that is castable."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Simulate NVARCHAR staging data and test safe castability
-- Using CAST(col AS NVARCHAR) to simulate a string-typed staging scenario
WITH StagedOrders AS (
    SELECT
        CAST(OrderID AS NVARCHAR(20))      AS s_OrderID,
        CAST(CustomerID AS NVARCHAR(20))   AS s_CustomerID,
        CAST(ProductID AS NVARCHAR(20))    AS s_ProductID,
        CAST(TotalAmount AS NVARCHAR(30))  AS s_TotalAmount,
        CAST(OrderDate AS NVARCHAR(30))    AS s_OrderDate,
        CAST(Status AS NVARCHAR(30))       AS s_Status
    FROM Orders
    UNION ALL
    -- Inject problematic values to demonstrate coercion failures
    SELECT 'ORD-BAD', 'CUST-99', 'PROD-99', 'N/A',  '2024-01-15', 'Pending'     UNION ALL
    SELECT 'ORD-XXX', 'CUST-10', 'PROD-02', 'TBC',  '15/01/2024', 'Processing'  UNION ALL
    SELECT 'ORD-999', 'CUST-01', 'PROD-03', '1,299.50', '2024-03-10', 'Delivered'
)
SELECT
    s_OrderID,
    s_TotalAmount,
    s_OrderDate,
    -- Test direct cast
    TRY_CAST(s_TotalAmount AS DECIMAL(10,2)) AS DirectCastAmount,
    -- Pre-clean: remove commas then try cast
    TRY_CAST(REPLACE(s_TotalAmount, ',', '') AS DECIMAL(10,2)) AS CleanedCastAmount,
    -- Test date cast
    TRY_CONVERT(DATE, s_OrderDate, 23) AS DateCast_ISO,
    TRY_CONVERT(DATE, s_OrderDate, 103) AS DateCast_UK,
    CASE
        WHEN TRY_CAST(s_TotalAmount AS DECIMAL(10,2)) IS NOT NULL
             THEN 'DIRECT CAST OK'
        WHEN TRY_CAST(REPLACE(s_TotalAmount, ',', '') AS DECIMAL(10,2)) IS NOT NULL
             THEN 'CASTABLE AFTER COMMA REMOVAL: "' + s_TotalAmount + '" → '
                  + CAST(TRY_CAST(REPLACE(s_TotalAmount, ',', '') AS DECIMAL(10,2)) AS VARCHAR)
        WHEN s_TotalAmount IS NULL
             THEN 'NULL'
        ELSE 'CAST FAILURE: "' + s_TotalAmount + '" cannot be converted to DECIMAL'
    END AS AmountCastResult,
    CASE
        WHEN TRY_CONVERT(DATE, s_OrderDate, 23) IS NOT NULL
             THEN 'ISO DATE OK: ' + CAST(TRY_CONVERT(DATE, s_OrderDate, 23) AS VARCHAR)
        WHEN TRY_CONVERT(DATE, s_OrderDate, 103) IS NOT NULL
             THEN 'UK DATE PARSE: ' + CAST(TRY_CONVERT(DATE, s_OrderDate, 103) AS VARCHAR)
        ELSE 'DATE CAST FAILURE: "' + ISNULL(s_OrderDate,'NULL') + '" — unrecognised format'
    END AS DateCastResult
FROM StagedOrders;

-- Step 2: Boolean / BIT coercion validation
WITH BooleanVariants AS (
    -- Simulate boolean values as they commonly arrive in string fields
    SELECT 1 AS RowNum, '1' AS RawValue UNION ALL
    SELECT 2, '0'       UNION ALL
    SELECT 3, 'true'    UNION ALL
    SELECT 4, 'false'   UNION ALL
    SELECT 5, 'True'    UNION ALL
    SELECT 6, 'False'   UNION ALL
    SELECT 7, 'TRUE'    UNION ALL
    SELECT 8, 'FALSE'   UNION ALL
    SELECT 9, 'Y'       UNION ALL
    SELECT 10,'N'       UNION ALL
    SELECT 11,'yes'     UNION ALL
    SELECT 12,'no'      UNION ALL
    SELECT 13,'on'      UNION ALL
    SELECT 14,'off'     UNION ALL
    SELECT 15,'active'  UNION ALL
    SELECT 16,'inactive'UNION ALL
    SELECT 17,'2'       UNION ALL  -- invalid
    SELECT 18,NULL
)
SELECT
    RowNum,
    RawValue,
    -- Direct BIT cast: only '0', '1', 'true', 'false' are valid for TRY_CAST to BIT
    TRY_CAST(RawValue AS BIT) AS DirectBitCast,
    -- Normalised mapping to 1/0
    CASE
        WHEN LOWER(ISNULL(RawValue,'')) IN ('1','true','y','yes','on','active')  THEN 1
        WHEN LOWER(ISNULL(RawValue,'')) IN ('0','false','n','no','off','inactive') THEN 0
        WHEN RawValue IS NULL THEN NULL
        ELSE -1  -- sentinel for unmapped value
    END AS NormalisedBit,
    CASE
        WHEN TRY_CAST(RawValue AS BIT) IS NOT NULL THEN 'DIRECT CAST OK'
        WHEN LOWER(ISNULL(RawValue,'')) IN ('1','true','y','yes','on','active',
                                             '0','false','n','no','off','inactive')
             THEN 'MAPPABLE: "' + RawValue + '" → '
                  + CASE WHEN LOWER(RawValue) IN ('1','true','y','yes','on','active')
                         THEN '1 (TRUE)' ELSE '0 (FALSE)' END
        WHEN RawValue IS NULL THEN 'NULL'
        ELSE 'UNMAPPABLE: "' + RawValue + '" — no boolean equivalent'
    END AS BooleanCastResult
FROM BooleanVariants;

-- Step 3: Numeric string cleaning patterns
WITH NumericStrings AS (
    SELECT 1 AS RowNum, '1,299.50' AS RawNum UNION ALL
    SELECT 2,  '£299.99'                       UNION ALL
    SELECT 3,  '$1,000'                        UNION ALL
    SELECT 4,  '(150.00)'                      UNION ALL  -- accounting negative
    SELECT 5,  '1.299,50'                      UNION ALL  -- European decimal format
    SELECT 6,  '999'                           UNION ALL
    SELECT 7,  '  250.00  '                    UNION ALL  -- whitespace
    SELECT 8,  'N/A'                           UNION ALL
    SELECT 9,  ''                              UNION ALL
    SELECT 10, NULL
)
SELECT
    RowNum,
    RawNum,
    -- Apply cleaning pipeline
    TRY_CAST(
        REPLACE(                      -- remove commas (thousands separator)
        REPLACE(                      -- remove currency symbols
        REPLACE(                      -- remove £
        LTRIM(RTRIM(ISNULL(RawNum,''))),
        '£',''),
        '$',''),
        ',','')
    AS CleanedDecimal,
    CASE
        WHEN RawNum IS NULL OR RawNum = ''
             THEN 'NULL/EMPTY: Treat as NULL in target'
        WHEN TRY_CAST(RawNum AS DECIMAL(12,2)) IS NOT NULL
             THEN 'DIRECT CAST: ' + CAST(TRY_CAST(RawNum AS DECIMAL(12,2)) AS VARCHAR)
        WHEN TRY_CAST(REPLACE(REPLACE(REPLACE(LTRIM(RTRIM(RawNum)),'£',''),'$',''),',','')
             AS DECIMAL(12,2)) IS NOT NULL
             THEN 'CLEANED CAST: After removing separators/symbols → '
                  + CAST(TRY_CAST(REPLACE(REPLACE(REPLACE(LTRIM(RTRIM(RawNum)),'£',''),'$',''),',','')
                  AS DECIMAL(12,2)) AS VARCHAR)
        WHEN RawNum LIKE '(%)' AND TRY_CAST(REPLACE(REPLACE(RawNum,'(',''),')','') AS DECIMAL(12,2)) IS NOT NULL
             THEN 'ACCOUNTING NEGATIVE: "' + RawNum + '" → -'
                  + CAST(TRY_CAST(REPLACE(REPLACE(RawNum,'(',''),')','') AS DECIMAL(12,2)) AS VARCHAR)
        ELSE 'CAST FAILURE: "' + RawNum + '" — manual review required'
    END AS CastResult
FROM NumericStrings;

-- Step 4: Coercion readiness report for each Orders field
SELECT
    FieldName,
    TotalRows,
    NullCount,
    DirectCastOK,
    CastableAfterCleaning,
    CastFailures,
    ROUND(100.0 * (DirectCastOK + CastableAfterCleaning)
          / NULLIF(TotalRows - NullCount, 0), 1) AS CastableAfterCleaningPct
FROM (
    SELECT
        'Orders.TotalAmount → DECIMAL(10,2)' AS FieldName,
        COUNT(*) AS TotalRows,
        SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END) AS NullCount,
        SUM(CASE WHEN TRY_CAST(CAST(TotalAmount AS NVARCHAR) AS DECIMAL(10,2)) IS NOT NULL
                 THEN 1 ELSE 0 END) AS DirectCastOK,
        0 AS CastableAfterCleaning,
        0 AS CastFailures
    FROM Orders
    UNION ALL
    SELECT
        'Orders.OrderDate → DATE',
        COUNT(*),
        SUM(CASE WHEN OrderDate IS NULL THEN 1 ELSE 0 END),
        SUM(CASE WHEN TRY_CONVERT(DATE, CAST(OrderDate AS NVARCHAR), 23) IS NOT NULL
                 THEN 1 ELSE 0 END),
        0, 0
    FROM Orders
) Coercion;
```

## Explanation

**TRY_CAST vs CAST for validation**
`CAST(value AS DECIMAL)` raises an error and aborts the batch if any single value cannot be converted. `TRY_CAST(value AS DECIMAL)` returns NULL for unconvertible values and continues. In a validation context, always use TRY_CAST so that all failures are detected in a single scan rather than stopping at the first error. Use CAST only in post-validated data paths where all values are guaranteed convertible.

**Pre-cleaning before casting**
Many numeric string failures are caused by cosmetic characters: currency symbols (£, $), thousands separators (,), whitespace, and accounting brackets for negative numbers. Removing these first with REPLACE/LTRIM/RTRIM dramatically increases the castable proportion. The remaining cast failures represent genuinely malformed data (e.g., "N/A", "TBC") that require human review.

**Boolean string mapping**
SQL Server's TRY_CAST to BIT only recognises '0', '1', 'true', and 'false' as valid inputs. The strings 'Y', 'N', 'yes', 'no', 'on', 'off', 'active', 'inactive' — common in CSV exports from other systems — all return NULL from TRY_CAST. A pre-cast CASE expression maps these to '1' or '0' before the BIT conversion, maximising coverage.

**European decimal format (1.299,50)**
Some European systems use a comma as the decimal separator and a period as the thousands separator — the reverse of the UK/US convention. REPLACE(val, ',', '.') would incorrectly convert "1.299,50" to "1.299.50" (unparseable) instead of "1299.50". Detecting European format requires checking whether the comma appears after the period (thousands then decimal) or vice versa, then applying the appropriate transformation.

## Severity
**High in ETL contexts** — Type coercion failures during a data load cause the ETL job to fail entirely (with CAST) or silently insert NULLs (with TRY_CAST). Both outcomes are unacceptable: failed ETL leaves the target table empty; silent NULLs corrupt financial aggregates without any error signal. Pre-validating coercion success before the load is essential for production ETL reliability.
