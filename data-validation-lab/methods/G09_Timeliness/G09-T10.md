# G09-T10 — Timeliness | Retention Breach Detection

## ID
G09-T10

## Group
9 — Timeliness

## Type
Retention Breach Detection — Records Retained Beyond the Permitted Retention Period

## Live Scenario
Under GDPR Article 5(1)(e), personal data may not be kept for longer than necessary for the stated purpose. A UK e-commerce company's privacy notice states that customer accounts inactive for more than 3 years will be deleted. An automated deletion job runs monthly but has a bug: it deletes accounts inactive for > 3 years based on `LastLoginDate`, but 847 accounts have NULL `LastLoginDate` (customers who registered but never logged in) — these are excluded from the deletion logic and retained indefinitely. When a data subject access request reveals a 6-year-old account, the ICO investigation finds the systematic retention failure. The company receives a £280,000 fine and must conduct a full data audit within 90 days.

## The Question
> Data retention compliance requires deleting or anonymising records after the retention period expires. SQL identifies records that should have been deleted based on their age, activity date, or the elapsed time since a specific trigger event.
> **"Identify Customers whose last order was more than 3 years ago (or who have never ordered) and flag them as candidates for the data retention review, along with any transaction records older than the 7-year financial record retention requirement."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Orders** — `schemas/02_Orders.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Step 1: Customer retention review — last order older than 3 years or no orders
DECLARE @CustomerRetentionYears INT = 3;
DECLARE @FinancialRetentionYears INT = 7;

WITH CustomerLastOrder AS (
    SELECT
        CustomerID,
        MAX(OrderDate) AS LastOrderDate,
        COUNT(*)       AS TotalOrders
    FROM Orders
    WHERE Status NOT IN ('Cancelled')
    GROUP BY CustomerID
)
SELECT
    c.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    c.IsActive,
    clo.LastOrderDate,
    clo.TotalOrders,
    DATEDIFF(DAY, clo.LastOrderDate, GETDATE()) AS DaysSinceLastOrder,
    CASE
        WHEN clo.CustomerID IS NULL
             THEN 'NO ORDERS: Customer registered but never ordered — review retention'
        WHEN DATEDIFF(YEAR, clo.LastOrderDate, GETDATE()) >= @CustomerRetentionYears
             THEN 'RETENTION BREACH: Last order '
                  + CAST(DATEDIFF(YEAR, clo.LastOrderDate, GETDATE()) AS VARCHAR)
                  + ' years ago — beyond ' + CAST(@CustomerRetentionYears AS VARCHAR) + '-year retention period'
        WHEN DATEDIFF(YEAR, clo.LastOrderDate, GETDATE()) >= @CustomerRetentionYears - 1
             THEN 'APPROACHING LIMIT: Last order approaching '
                  + CAST(@CustomerRetentionYears AS VARCHAR) + '-year retention period'
        ELSE 'Within retention: last order '
             + CAST(DATEDIFF(YEAR, clo.LastOrderDate, GETDATE()) AS VARCHAR) + ' years ago'
    END AS RetentionStatus
FROM Customers c
LEFT JOIN CustomerLastOrder clo ON c.CustomerID = clo.CustomerID
ORDER BY DaysSinceLastOrder DESC;

-- Step 2: Financial record retention — transactions older than 7 years
SELECT
    t.TransactionID,
    t.OrderID,
    t.Amount,
    t.TransactionDate,
    DATEDIFF(YEAR, t.TransactionDate, GETDATE()) AS AgeYears,
    CASE
        WHEN DATEDIFF(YEAR, t.TransactionDate, GETDATE()) > @FinancialRetentionYears
             THEN 'OVER RETENTION: Transaction ' + CAST(DATEDIFF(YEAR, t.TransactionDate, GETDATE()) AS VARCHAR)
                  + ' years old — beyond ' + CAST(@FinancialRetentionYears AS VARCHAR)
                  + '-year financial retention requirement'
        ELSE 'Within financial retention period'
    END AS FinancialRetentionStatus
FROM Transactions t
WHERE DATEDIFF(YEAR, t.TransactionDate, GETDATE()) > @FinancialRetentionYears
ORDER BY t.TransactionDate;

-- Step 3: Retention summary — how much data is in each age band?
SELECT
    CASE
        WHEN DATEDIFF(YEAR, OrderDate, GETDATE()) = 0 THEN 'Less than 1 year'
        WHEN DATEDIFF(YEAR, OrderDate, GETDATE()) = 1 THEN '1-2 years'
        WHEN DATEDIFF(YEAR, OrderDate, GETDATE()) = 2 THEN '2-3 years'
        WHEN DATEDIFF(YEAR, OrderDate, GETDATE()) < @CustomerRetentionYears
             THEN CAST(DATEDIFF(YEAR, OrderDate, GETDATE()) AS VARCHAR) + ' years'
        ELSE CAST(@CustomerRetentionYears AS VARCHAR) + '+ years (retention review)'
    END AS AgeBand,
    COUNT(DISTINCT CustomerID) AS CustomerCount,
    COUNT(*) AS OrderCount,
    SUM(TotalAmount) AS TotalValue
FROM Orders
GROUP BY
    CASE
        WHEN DATEDIFF(YEAR, OrderDate, GETDATE()) = 0 THEN 'Less than 1 year'
        WHEN DATEDIFF(YEAR, OrderDate, GETDATE()) = 1 THEN '1-2 years'
        WHEN DATEDIFF(YEAR, OrderDate, GETDATE()) = 2 THEN '2-3 years'
        WHEN DATEDIFF(YEAR, OrderDate, GETDATE()) < @CustomerRetentionYears
             THEN CAST(DATEDIFF(YEAR, OrderDate, GETDATE()) AS VARCHAR) + ' years'
        ELSE CAST(@CustomerRetentionYears AS VARCHAR) + '+ years (retention review)'
    END
ORDER BY MIN(DATEDIFF(YEAR, OrderDate, GETDATE()));

-- Step 4: Customers with no orders at all — highest retention risk (no purpose demonstrated)
SELECT
    c.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    c.IsActive,
    DATEDIFF(YEAR, c.DateOfBirth, GETDATE()) AS AgeAtReview,
    'NEVER ORDERED: No legitimate basis for retention — immediate review required' AS RetentionRisk
FROM Customers c
WHERE NOT EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerID = c.CustomerID)
ORDER BY c.CustomerID;
```

## Explanation

**DATEDIFF(YEAR) for retention age**
`DATEDIFF(YEAR, LastOrderDate, GETDATE())` returns the number of full years elapsed. This is a conservative approximation — it returns 1 after 365 days, even if 11 months and 29 days have passed. For precise retention calculations, use `DATEDIFF(DAY) >= retention_years × 365` or compare to `DATEADD(YEAR, -retention_years, GETDATE())`.

**NULL dates as the hidden retention failure**
The scenario highlights NULL `LastOrderDate` as the most dangerous retention gap — a WHERE clause `LastOrderDate < cutoff_date` excludes NULLs, so NULL-dated records are never selected for deletion. Step 4 explicitly surfaces customers with NULL order history as the highest-risk group.

**Two retention periods: operational and financial**
GDPR personal data retention (3 years of inactivity) differs from financial record retention (7 years under UK Companies Act / HMRC requirements). The SQL uses two DECLARE variables to make both thresholds explicit. Financial records may need to be retained but anonymised — personal identifiers removed while keeping the transaction amounts.

**Retention as a data quality obligation**
Unlike other data quality checks that flag missing or incorrect data, retention monitoring flags data that should no longer exist. The remediation action (deletion or anonymisation) is a legal obligation, not an optional cleanup. SQL provides the identification; the deletion process requires separate governance approval.

## Severity
**High** — Retention breaches are regulatory violations under GDPR (Article 83: fines up to €20M or 4% of global turnover), UK GDPR, CCPA, and HIPAA. They also create security risk: old records are typically not covered by current security controls and may contain data about deceased individuals, minors who have since grown up, or former customers who have requested deletion.
