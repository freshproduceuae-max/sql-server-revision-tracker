# G09-T06 — Timeliness | Batch Job Completion Monitoring

## ID
G09-T06

## Group
9 — Timeliness

## Type
Batch Job Completion Monitoring — Expected Regular Data Load Has Not Arrived

## Live Scenario
A nightly ETL job loads the previous day's sales transactions into the data warehouse, completing by 02:00 each morning. The BI team's reports run at 06:00 and always show complete data. One night, the ETL job fails silently at 01:47 due to a disk space error. No alert fires because the monitoring agent checks exit code — the job was killed by the OS, which returns exit code 0 (normal termination on some OS configurations). The 06:00 reports run on data from the previous day. The sales director presents metrics to the board that are 24 hours stale. The error is noticed at 14:00 when a regional manager notices their morning orders don't appear in the dashboard.

## The Question
> Batch completion monitoring checks that data has arrived for each expected period. SQL detects a missing batch by checking whether data exists for the expected date range and comparing today's data volume to the historical average.
> **"Identify any date where the expected number of Transactions is significantly lower than the historical daily average, which would indicate a partial load or missing batch."**

## Table Reference
**Transactions** — `schemas/05_Transactions.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Daily transaction count and comparison to rolling average
WITH DailyTxCounts AS (
    SELECT
        CAST(TransactionDate AS DATE) AS TxDay,
        COUNT(*)     AS DailyCount,
        SUM(Amount)  AS DailyTotal
    FROM Transactions
    WHERE TransactionDate IS NOT NULL
    GROUP BY CAST(TransactionDate AS DATE)
),
WithRollingAvg AS (
    SELECT
        TxDay,
        DailyCount,
        DailyTotal,
        AVG(DailyCount) OVER (
            ORDER BY TxDay
            ROWS BETWEEN 6 PRECEDING AND 1 PRECEDING
        ) AS Avg7DayCount,
        AVG(DailyTotal) OVER (
            ORDER BY TxDay
            ROWS BETWEEN 6 PRECEDING AND 1 PRECEDING
        ) AS Avg7DayTotal
    FROM DailyTxCounts
)
SELECT
    TxDay,
    DailyCount,
    DailyTotal,
    ROUND(Avg7DayCount, 1) AS Avg7DayCount,
    ROUND(CAST(DailyCount AS FLOAT) / NULLIF(Avg7DayCount, 0) * 100, 1) AS PctOfAvg,
    CASE
        WHEN Avg7DayCount IS NULL
             THEN 'Insufficient history for comparison'
        WHEN DailyCount = 0
             THEN 'MISSING BATCH: Zero records for this date'
        WHEN CAST(DailyCount AS FLOAT) / NULLIF(Avg7DayCount, 0) < 0.5
             THEN 'PARTIAL LOAD: Less than 50% of expected volume ('
                  + CAST(DailyCount AS VARCHAR) + ' vs avg ' + CAST(ROUND(Avg7DayCount,0) AS VARCHAR) + ')'
        WHEN CAST(DailyCount AS FLOAT) / NULLIF(Avg7DayCount, 0) < 0.8
             THEN 'LOW VOLUME: Less than 80% of expected — investigate'
        ELSE 'Normal volume'
    END AS BatchStatus
FROM WithRollingAvg
ORDER BY TxDay DESC;

-- Step 2: Detect date gaps — missing days in the sequence entirely
WITH DateRange AS (
    SELECT
        MIN(CAST(TransactionDate AS DATE)) AS MinDate,
        MAX(CAST(TransactionDate AS DATE)) AS MaxDate
    FROM Transactions
),
Calendar AS (
    SELECT DATEADD(DAY, ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) - 1, MinDate) AS CalDate
    FROM DateRange
    CROSS JOIN Transactions  -- Generate enough rows
    WHERE ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) - 1
          <= DATEDIFF(DAY, MinDate, MaxDate)
),
-- Simpler approach: check for gaps using LAG
TxDates AS (
    SELECT DISTINCT CAST(TransactionDate AS DATE) AS TxDay
    FROM Transactions
)
SELECT
    TxDay,
    LAG(TxDay) OVER (ORDER BY TxDay) AS PrevDay,
    DATEDIFF(DAY, LAG(TxDay) OVER (ORDER BY TxDay), TxDay) AS GapDays,
    CASE
        WHEN DATEDIFF(DAY, LAG(TxDay) OVER (ORDER BY TxDay), TxDay) = 1
             THEN 'Consecutive — OK'
        WHEN DATEDIFF(DAY, LAG(TxDay) OVER (ORDER BY TxDay), TxDay) = 2
             THEN 'One day missing (weekend?)'
        WHEN DATEDIFF(DAY, LAG(TxDay) OVER (ORDER BY TxDay), TxDay) > 2
             THEN 'GAP: ' + CAST(DATEDIFF(DAY, LAG(TxDay) OVER (ORDER BY TxDay), TxDay) - 1 AS VARCHAR)
                  + ' missing day(s) between ' + CAST(LAG(TxDay) OVER (ORDER BY TxDay) AS VARCHAR)
                  + ' and ' + CAST(TxDay AS VARCHAR)
        ELSE 'First record'
    END AS GapFlag
FROM TxDates
ORDER BY TxDay;

-- Step 3: Today's load completeness — has today's batch arrived?
SELECT
    CAST(GETDATE() AS DATE) AS Today,
    COUNT(CASE WHEN CAST(TransactionDate AS DATE) = CAST(GETDATE() AS DATE) THEN 1 END)
        AS TodayRecords,
    COUNT(CASE WHEN CAST(TransactionDate AS DATE) = CAST(DATEADD(DAY, -1, GETDATE()) AS DATE) THEN 1 END)
        AS YesterdayRecords,
    CASE
        WHEN COUNT(CASE WHEN CAST(TransactionDate AS DATE) = CAST(GETDATE() AS DATE) THEN 1 END) = 0
             THEN 'NO DATA TODAY: Batch may not have run'
        WHEN COUNT(CASE WHEN CAST(TransactionDate AS DATE) = CAST(GETDATE() AS DATE) THEN 1 END)
             < COUNT(CASE WHEN CAST(TransactionDate AS DATE) = CAST(DATEADD(DAY,-1,GETDATE()) AS DATE) THEN 1 END) * 0.5
             THEN 'PARTIAL LOAD: Today is less than 50% of yesterday'
        ELSE 'Load appears complete'
    END AS LoadStatus
FROM Transactions;
```

## Expected Output

**Step 1 — Daily volume check:**
| TxDay | DailyCount | DailyTotal | Avg7DayCount | PctOfAvg | BatchStatus |
|---|---|---|---|---|---|
| 2024-02-01 | 0 | 0.00 | 4.2 | 0.0 | MISSING BATCH: Zero records for this date |
| 2024-01-31 | 2 | 1200.00 | 4.2 | 47.6 | PARTIAL LOAD: Less than 50% of expected volume |

**Step 2 — Date gaps:**
| TxDay | PrevDay | GapDays | GapFlag |
|---|---|---|---|
| 2024-02-05 | 2024-02-01 | 4 | GAP: 3 missing day(s) between 2024-02-01 and 2024-02-05 |

## Explanation

**Rolling 7-day average as the baseline**
`AVG(DailyCount) OVER (ROWS BETWEEN 6 PRECEDING AND 1 PRECEDING)` computes the average of the 7 days before each day (excluding the current day). This trailing average is the expected volume baseline. A day with < 50% of this average has likely suffered a partial load.

**LAG for gap detection**
`DATEDIFF(DAY, LAG(TxDay), TxDay)` measures the gap between consecutive days with data. A gap of 1 is normal (consecutive days). A gap of 2 might indicate a weekend with no transactions (legitimate) or a missed Saturday batch (error). A gap of 3+ days on a weekday sequence indicates multiple missed batches.

**Zero-records day as the strongest signal**
A day where `DailyCount = 0` means the batch did not run at all (or ran but produced no records). This is distinct from a low-volume day — a true missing batch cannot be explained by natural volume variation. `DailyCount = 0` warrants immediate investigation.

**GETDATE() for today's completeness**
Step 3 is a real-time check: has today's data arrived? In a monitoring context, this query runs at the expected completion time (e.g., 07:00) to verify the overnight batch has loaded. Zero today-records at 07:00 is the trigger for a production incident.

## Severity
**High** — Missing batch loads cause reporting systems to present stale data without warning. Unlike an outage (users see an error), a missing batch is invisible — reports run normally, numbers look plausible, and the error is discovered only when an outlier is noticed. Automated batch completion monitoring is a standard data engineering requirement.
