# G09-T08 — Timeliness | Contract/Licence Expiry

## ID
G09-T08

## Group
9 — Timeliness

## Type
Contract/Licence Expiry — Active Records Whose Validity Period Has Lapsed

## Live Scenario
A software vendor manages 2,400 customer licences. Each licence has a `ContractEnd` date. An automated renewal process is supposed to deactivate customers 30 days after expiry if no renewal is received. A deployment error disables the deactivation job for 3 months. When the job is reactivated, 147 customers have been using the software for up to 90 days past their contract expiry, with no invoicing. The revenue leakage is £83,000. The vendor's legal team also notes that allowing post-expiry usage creates a deemed-renewal argument — the customer may now claim the contract renewed by conduct, complicating debt recovery.

## The Question
> Contract and licence expiry monitoring identifies records where the validity end date has passed but the record remains active. SQL uses GETDATE() compared to a ContractEnd date to find expired-but-active records, and DATEADD to produce proactive expiry warnings.
> **"Identify Customers whose ContractEnd date has passed (expired licences), those expiring in the next 30/60/90 days (renewal pipeline), and any Orders placed by customers after their ContractEnd date."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Orders** — `schemas/02_Orders.csv`

## Solution Query

```sql
-- Step 1: Expired contracts — ContractEnd in the past but customer still active
SELECT
    c.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    c.Country,
    c.IsActive,
    c.ContractEnd,
    DATEDIFF(DAY, c.ContractEnd, GETDATE()) AS DaysExpired,
    CASE
        WHEN c.ContractEnd IS NULL
             THEN 'NO END DATE: Perpetual contract or missing data'
        WHEN c.ContractEnd < CAST(GETDATE() AS DATE) AND c.IsActive = 1
             THEN 'EXPIRED ACTIVE: Contract expired '
                  + CAST(DATEDIFF(DAY, c.ContractEnd, GETDATE()) AS VARCHAR)
                  + ' days ago — customer still active'
        WHEN c.ContractEnd < CAST(GETDATE() AS DATE) AND c.IsActive = 0
             THEN 'Correctly deactivated after expiry'
        ELSE 'Valid contract'
    END AS ExpiryStatus
FROM Customers c
WHERE c.ContractEnd IS NOT NULL
  AND c.ContractEnd < CAST(GETDATE() AS DATE)
  AND c.IsActive = 1
ORDER BY DaysExpired DESC;

-- Step 2: Expiry pipeline — contracts expiring soon
SELECT
    c.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    c.ContractEnd,
    DATEDIFF(DAY, GETDATE(), c.ContractEnd) AS DaysUntilExpiry,
    CASE
        WHEN DATEDIFF(DAY, GETDATE(), c.ContractEnd) <= 30
             THEN 'URGENT: Expires within 30 days — renewal action required'
        WHEN DATEDIFF(DAY, GETDATE(), c.ContractEnd) <= 60
             THEN 'ACTION: Expires within 60 days — initiate renewal'
        WHEN DATEDIFF(DAY, GETDATE(), c.ContractEnd) <= 90
             THEN 'PIPELINE: Expires within 90 days — schedule renewal discussion'
        ELSE 'Not expiring soon'
    END AS RenewalUrgency
FROM Customers c
WHERE c.ContractEnd IS NOT NULL
  AND c.ContractEnd >= CAST(GETDATE() AS DATE)
  AND c.ContractEnd <= DATEADD(DAY, 90, GETDATE())
  AND c.IsActive = 1
ORDER BY DaysUntilExpiry;

-- Step 3: Orders placed after ContractEnd (post-expiry usage)
SELECT
    o.OrderID,
    o.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    c.ContractEnd,
    o.OrderDate,
    o.TotalAmount,
    o.Status,
    DATEDIFF(DAY, c.ContractEnd, o.OrderDate) AS DaysAfterExpiry,
    'POST-EXPIRY ORDER: Order placed ' + CAST(DATEDIFF(DAY, c.ContractEnd, o.OrderDate) AS VARCHAR)
        + ' days after contract ended' AS ExpiryViolation
FROM Orders o
JOIN Customers c ON o.CustomerID = c.CustomerID
WHERE c.ContractEnd IS NOT NULL
  AND o.OrderDate > c.ContractEnd
  AND o.Status NOT IN ('Cancelled')
ORDER BY DaysAfterExpiry DESC;

-- Step 4: Revenue at risk — value of post-expiry orders
SELECT
    'Post-expiry orders placed' AS Category,
    COUNT(o.OrderID) AS OrderCount,
    SUM(o.TotalAmount) AS RevenueAtRisk,
    COUNT(DISTINCT o.CustomerID) AS AffectedCustomers,
    MIN(DATEDIFF(DAY, c.ContractEnd, o.OrderDate)) AS MinDaysPostExpiry,
    MAX(DATEDIFF(DAY, c.ContractEnd, o.OrderDate)) AS MaxDaysPostExpiry
FROM Orders o
JOIN Customers c ON o.CustomerID = c.CustomerID
WHERE c.ContractEnd IS NOT NULL
  AND o.OrderDate > c.ContractEnd
  AND o.Status NOT IN ('Cancelled');
```

| 4 | Carol Davis | 2024-01-31 | 181 | EXPIRED ACTIVE: Contract expired 181 days ago — customer still active |

**Step 2 — Renewal pipeline:**
| CustomerID | CustomerName | ContractEnd | DaysUntilExpiry | RenewalUrgency |

| 7 | Frank Miller | 2024-08-15 | 15 | URGENT: Expires within 30 days — renewal action required |

**Step 3 — Post-expiry orders:**
| OrderID | CustomerName | ContractEnd | OrderDate | DaysAfterExpiry | ExpiryViolation |
|---|---|---|---|---|---|
| 1019 | Carol Davis | 2024-01-31 | 2024-03-20 | 49 | POST-EXPIRY ORDER: Order placed 49 days after contract ended |

## Explanation

**ContractEnd comparison to GETDATE()**
`c.ContractEnd < CAST(GETDATE() AS DATE)` uses `CAST(GETDATE() AS DATE)` (today's date, time stripped) rather than `GETDATE()` (which includes the current time). Without the cast, a contract expiring today at midnight would appear expired before midnight on the same day.

**Three-tier renewal pipeline**
Step 2 uses 30/60/90-day windows to create a renewal action plan. The 30-day window is operational (sales must act now); 60 days is management (schedule renewal meeting); 90 days is strategic planning (forecast renewal revenue). The window boundaries are parameters that should be configurable per organisation.

**Post-expiry order detection**
Step 3 catches the revenue leakage scenario: orders from customers whose contract has already ended. `o.OrderDate > c.ContractEnd` is the condition. Combined with `Status NOT IN ('Cancelled')`, this identifies actual fulfilled post-expiry orders rather than cancelled attempts.

**DATEADD for forward-looking windows**
`c.ContractEnd <= DATEADD(DAY, 90, GETDATE())` selects contracts expiring within 90 days. `DATEADD(DAY, n, GETDATE())` adds n days to the current date, a standard pattern for sliding-window date filters.

## Severity
**High** — Expired-but-active records cause revenue leakage (services provided without billing), legal risk (deemed renewal by conduct), and security risk (expired users retain system access). In regulated sectors (financial services, healthcare), expired credentials or authorisations are a compliance failure requiring immediate remediation.
