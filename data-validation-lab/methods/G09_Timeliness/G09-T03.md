# G09-T03 — Timeliness | Processing Time SLA Breach

## ID
G09-T03

## Group
9 — Timeliness

## Type
Processing Time SLA Breach — Time Between Event and Processing Exceeds Contractual Limit

## Live Scenario
An e-commerce platform guarantees that orders will be "processed and dispatched within 2 business days." A spike in sales over the Black Friday weekend causes a backlog. Of 3,400 orders placed 28–29 November, 847 are still in "Processing" status on 2 December — 3 business days later. The SLA breach triggers automatic customer emails offering a 10% discount voucher (a pre-agreed remedy clause). The cost is £18,340 in discount vouchers. More critically, the SLA monitoring report sent to management only counts calendar days, not business days, so the breach rate appears to be 4% when the true business-day breach rate is 25%.

## The Question
> Processing time SLA measures how long a record spends in an intermediate state before reaching a terminal state. SQL computes elapsed time between status entry and resolution, and flags records where this exceeds the SLA.
> **"Identify Orders that have been in a non-terminal status for longer than the SLA (3 days between OrderDate and DeliveryDate for Delivered orders, and flag any still-open order older than 3 days)."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Delivered orders — measure actual processing time vs SLA
DECLARE @SLADays INT = 3;

SELECT
    o.OrderID,
    o.CustomerID,
    c.FirstName + ' ' + c.LastName AS CustomerName,
    o.OrderDate,
    o.DeliveryDate,
    o.Status,
    DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) AS ProcessingDays,
    CASE
        WHEN DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) <= @SLADays
             THEN 'WITHIN SLA: ' + CAST(DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) AS VARCHAR) + ' days'
        WHEN DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) <= @SLADays * 2
             THEN 'SLA BREACH: ' + CAST(DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) AS VARCHAR) + ' days (max ' + CAST(@SLADays AS VARCHAR) + ')'
        ELSE 'CRITICAL SLA BREACH: ' + CAST(DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) AS VARCHAR) + ' days — over 2× SLA'
    END AS SLAStatus
FROM Orders o
JOIN Customers c ON o.CustomerID = c.CustomerID
WHERE o.Status = 'Delivered'
  AND o.DeliveryDate IS NOT NULL
ORDER BY ProcessingDays DESC;

-- Step 2: In-progress orders — flag those already past SLA with no delivery
SELECT
    o.OrderID,
    o.CustomerID,
    o.OrderDate,
    o.Status,
    o.TotalAmount,
    DATEDIFF(DAY, o.OrderDate, GETDATE()) AS DaysOpen,
    DATEDIFF(DAY, o.OrderDate, GETDATE()) - @SLADays AS DaysOverSLA,
    CASE
        WHEN DATEDIFF(DAY, o.OrderDate, GETDATE()) > @SLADays * 3
             THEN 'CRITICAL: ' + CAST(DATEDIFF(DAY, o.OrderDate, GETDATE()) AS VARCHAR)
                  + ' days open — escalate immediately'
        WHEN DATEDIFF(DAY, o.OrderDate, GETDATE()) > @SLADays
             THEN 'SLA BREACH: '
                  + CAST(DATEDIFF(DAY, o.OrderDate, GETDATE()) - @SLADays AS VARCHAR)
                  + ' days over SLA'
        ELSE 'Open but within SLA (' + CAST(@SLADays - DATEDIFF(DAY, o.OrderDate, GETDATE()) AS VARCHAR) + ' days remaining)'
    END AS SLAAlert
FROM Orders o
WHERE o.Status NOT IN ('Delivered', 'Cancelled', 'Refunded')
ORDER BY DaysOpen DESC;

-- Step 3: SLA performance by month — what % are delivered on time?
SELECT
    YEAR(o.OrderDate)  AS OrderYear,
    MONTH(o.OrderDate) AS OrderMonth,
    COUNT(*) AS TotalDelivered,
    SUM(CASE WHEN DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) <= @SLADays THEN 1 ELSE 0 END) AS OnTime,
    SUM(CASE WHEN DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) > @SLADays  THEN 1 ELSE 0 END) AS Breached,
    ROUND(100.0 * SUM(CASE WHEN DATEDIFF(DAY, o.OrderDate, o.DeliveryDate) <= @SLADays THEN 1 ELSE 0 END)
          / NULLIF(COUNT(*), 0), 1) AS OnTimePct,
    AVG(DATEDIFF(DAY, o.OrderDate, o.DeliveryDate)) AS AvgProcessingDays,
    MAX(DATEDIFF(DAY, o.OrderDate, o.DeliveryDate)) AS MaxProcessingDays
FROM Orders o
WHERE o.Status = 'Delivered'
  AND o.DeliveryDate IS NOT NULL
GROUP BY YEAR(o.OrderDate), MONTH(o.OrderDate)
ORDER BY OrderYear, OrderMonth;

-- Step 4: Percentile processing time — understand the distribution
SELECT
    MIN(DATEDIFF(DAY, OrderDate, DeliveryDate)) AS MinDays,
    MAX(DATEDIFF(DAY, OrderDate, DeliveryDate)) AS MaxDays,
    AVG(DATEDIFF(DAY, OrderDate, DeliveryDate)) AS MeanDays,
    PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY DATEDIFF(DAY, OrderDate, DeliveryDate))
        OVER () AS MedianDays,
    PERCENTILE_CONT(0.90) WITHIN GROUP (ORDER BY DATEDIFF(DAY, OrderDate, DeliveryDate))
        OVER () AS P90Days,
    PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY DATEDIFF(DAY, OrderDate, DeliveryDate))
        OVER () AS P95Days
FROM Orders
WHERE Status = 'Delivered' AND DeliveryDate IS NOT NULL;
```

| 1009 | 2024-02-14 | 2024-03-08 | 23 | CRITICAL SLA BREACH: 23 days — over 2× SLA |

**Step 3 — Monthly SLA performance:**
| OrderYear | OrderMonth | TotalDelivered | OnTime | Breached | OnTimePct | AvgProcessingDays |
|---|---|---|---|---|---|---|
| 2024 | 1 | 4 | 4 | 0 | 100.0 | 2 |
| 2024 | 2 | 3 | 2 | 1 | 66.7 | 4 |

## Explanation

**Calendar days vs business days**
`DATEDIFF(DAY, OrderDate, DeliveryDate)` counts all calendar days including weekends. For business-day SLAs, a more complex calculation is needed: count only weekdays between the two dates. A common approach uses a calendar table (a pre-populated table of all dates with business day flags) joined to count working days between two dates.

**Parametrised SLA threshold**
`DECLARE @SLADays INT = 3` makes the threshold easy to update. When an SLA changes contractually, one line changes in the query rather than hunting through multiple WHERE clauses.

**On-time percentage as the KPI**
Step 3 produces the on-time delivery percentage — the standard SLA KPI. `100.0 × OnTime / TotalDelivered` is the "service level." A 95% SLA means the provider commits to on-time delivery for at least 95% of orders; anything below this triggers the remedial clause.

**Percentile-based SLA design**
Step 4 shows the distribution. If P90 is 3 days but P95 is 8 days, a 3-day SLA will be breached by roughly 10% of orders. SLA design should use historical percentiles to set achievable but challenging targets.

## Severity
**High** — SLA breaches have direct contractual and reputational consequences: penalty payments, customer compensation, and loss of repeat business. In regulated sectors (financial services, healthcare), processing time limits may be statutory, not just contractual, and breaches trigger regulatory reporting obligations.
