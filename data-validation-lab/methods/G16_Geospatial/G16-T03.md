# G16-T03 — Geospatial | Postcode and Address Format Validation

## ID
G16-T03

## Group
16 — Geospatial

## Type
Postcode and Address Format Validation — Verifying That Address Fields Conform to Expected Format Patterns

## Live Scenario
A direct mail company merges two customer databases: one from a recently acquired subsidiary that stores UK postcodes in a different format. The subsidiary's system uses an 8-character padded format with no space ("SW1A2AA"), while the main system uses the standard format with a space ("SW1A 2AA"). After the merge, 34,000 records have non-standard postcodes. The mailing house's address validation API rejects all 34,000 as invalid, costing the company £17,000 in failed letter deliveries. A postcode format validation check run at merge time would have identified all 34,000 deviations and applied the space-insertion correction before the data reached the mailing house.

## The Question
> Postcode and address format validation checks that postal codes, email addresses, and phone numbers conform to expected structural patterns using LIKE expressions, LEN checks, and PATINDEX tests. UK postcode validation specifically checks the area code prefix, numeric district, and sector/unit structure. SQL also identifies values that appear valid in format but contain known sentinel or test values.
> **"Validate the address fields in the Customers table: verify UK postcodes match the standard format with a space (e.g., SW1A 2AA), check that email addresses conform to a basic structural pattern, validate phone numbers are in the correct format, and identify any test or placeholder values in address fields."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: UK postcode format validation
-- Standard UK postcode: 1-2 letters + 1-2 digits + optional letter, space, digit + 2 letters
-- LIKE patterns cover the main UK postcode formats
SELECT
    CustomerID,
    PostalCode,
    LEN(PostalCode) AS CodeLength,
    CASE
        WHEN PostalCode IS NULL
             THEN 'NULL: Postcode missing'
        -- Standard formats with space
        WHEN PostalCode LIKE '[A-Z][0-9] [0-9][A-Z][A-Z]'          -- A1 1AA
          OR PostalCode LIKE '[A-Z][0-9][0-9] [0-9][A-Z][A-Z]'     -- A11 1AA
          OR PostalCode LIKE '[A-Z][A-Z][0-9] [0-9][A-Z][A-Z]'     -- AA1 1AA
          OR PostalCode LIKE '[A-Z][A-Z][0-9][0-9] [0-9][A-Z][A-Z]' -- AA11 1AA
          OR PostalCode LIKE '[A-Z][0-9][A-Z] [0-9][A-Z][A-Z]'     -- A1A 1AA
          OR PostalCode LIKE '[A-Z][A-Z][0-9][A-Z] [0-9][A-Z][A-Z]' -- AA1A 1AA
             THEN 'VALID: Standard UK postcode with space'
        -- Missing space
        WHEN PostalCode LIKE '[A-Z][0-9][0-9][A-Z][A-Z]'
          OR PostalCode LIKE '[A-Z][0-9][0-9][0-9][A-Z][A-Z]'
          OR PostalCode LIKE '[A-Z][A-Z][0-9][0-9][A-Z][A-Z]'
          OR PostalCode LIKE '[A-Z][A-Z][0-9][0-9][0-9][A-Z][A-Z]'
             THEN 'MISSING SPACE: Postcode format valid but space omitted — needs reformatting'
        -- Lowercase
        WHEN PostalCode <> UPPER(PostalCode)
             THEN 'LOWERCASE: UK postcodes should be uppercase'
        -- Too short or too long
        WHEN LEN(REPLACE(PostalCode, ' ', '')) < 5
             THEN 'TOO SHORT: Postcode has fewer than 5 characters (excluding space)'
        WHEN LEN(REPLACE(PostalCode, ' ', '')) > 7
             THEN 'TOO LONG: Postcode has more than 7 characters (excluding space)'
        ELSE 'NON-STANDARD: Does not match UK postcode pattern'
    END AS PostcodeFlag,
    -- Corrected value for missing-space cases
    CASE
        WHEN LEN(REPLACE(PostalCode, ' ', '')) = 5
             THEN LEFT(REPLACE(PostalCode, ' ', ''), 2) + ' ' + RIGHT(REPLACE(PostalCode, ' ', ''), 3)
        WHEN LEN(REPLACE(PostalCode, ' ', '')) = 6
             THEN LEFT(REPLACE(PostalCode, ' ', ''), 3) + ' ' + RIGHT(REPLACE(PostalCode, ' ', ''), 3)
        WHEN LEN(REPLACE(PostalCode, ' ', '')) = 7
             THEN LEFT(REPLACE(PostalCode, ' ', ''), 4) + ' ' + RIGHT(REPLACE(PostalCode, ' ', ''), 3)
        ELSE PostalCode
    END AS SuggestedCorrection
FROM Customers;

-- Step 2: Email format validation
SELECT
    CustomerID,
    Email,
    CASE
        WHEN Email IS NULL
             THEN 'NULL: Email missing'
        WHEN CHARINDEX('@', Email) = 0
             THEN 'MISSING @: Email has no @ symbol'
        WHEN CHARINDEX('.', Email, CHARINDEX('@', Email)) = 0
             THEN 'MISSING DOMAIN DOT: No dot after @ symbol'
        WHEN Email LIKE '%@%@%'
             THEN 'DOUBLE @: Email contains more than one @ symbol'
        WHEN CHARINDEX(' ', Email) > 0
             THEN 'WHITESPACE: Email contains spaces'
        WHEN Email NOT LIKE '%@%.%'
             THEN 'INVALID FORMAT: Does not match basic x@y.z pattern'
        WHEN Email LIKE '%@test.%' OR Email LIKE '%@example.%' OR Email LIKE '%@placeholder.%'
             THEN 'TEST DOMAIN: Email uses a test/placeholder domain'
        WHEN Email LIKE 'test@%' OR Email LIKE 'dummy@%' OR Email LIKE 'noreply@%'
             THEN 'TEST LOCAL: Email local part suggests test/placeholder'
        WHEN Email <> LOWER(Email)
             THEN 'NOT NORMALISED: Email contains uppercase characters'
        ELSE 'Valid'
    END AS EmailFlag
FROM Customers;

-- Step 3: Phone number format validation (UK focus)
SELECT
    CustomerID,
    Phone,
    LEN(Phone) AS PhoneLength,
    CASE
        WHEN Phone IS NULL
             THEN 'NULL: Phone missing'
        WHEN Phone LIKE '+44[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]'
             THEN 'VALID E.164: +44 format, 10 digits'
        WHEN Phone LIKE '07[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]'
             THEN 'UK LOCAL: 07xxx format — not normalised to E.164'
        WHEN Phone LIKE '0[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]'
             THEN 'UK LOCAL: 0xx format — not normalised to E.164'
        WHEN Phone LIKE '+1%'
             THEN 'US FORMAT: +1 country code — unexpected for UK customers'
        WHEN Phone LIKE '00%'
             THEN 'IDD FORMAT: 00 prefix instead of + — not normalised'
        WHEN TRY_CAST(Phone AS BIGINT) IS NOT NULL
             THEN 'NUMERIC ONLY: No formatting characters — possible leading zero lost'
        WHEN LEN(Phone) < 10
             THEN 'TOO SHORT: Phone number has fewer than 10 digits'
        ELSE 'NON-STANDARD: Unknown format'
    END AS PhoneFlag
FROM Customers;

-- Step 4: Sentinel and test value detection across address fields
SELECT
    CustomerID,
    PostalCode,
    Email,
    Phone,
    CASE
        WHEN PostalCode IN ('AA9 9AA', 'ZZ99 9ZZ', 'XX1 1XX', 'TEST', 'N/A', 'TBC')
             THEN 'TEST POSTCODE'
        WHEN Email IN ('test@test.com', 'admin@admin.com', 'noreply@noreply.com')
             THEN 'TEST EMAIL'
        WHEN Phone IN ('0000000000', '1111111111', '07700900000')
             THEN 'TEST PHONE (Ofcom reserved)'
        ELSE NULL
    END AS SentinelFlag
FROM Customers
WHERE PostalCode IN ('AA9 9AA', 'ZZ99 9ZZ', 'XX1 1XX', 'TEST', 'N/A', 'TBC')
   OR Email    IN ('test@test.com', 'admin@admin.com', 'noreply@noreply.com')
   OR Phone    IN ('0000000000', '1111111111', '07700900000');

-- Step 5: Address field quality summary
SELECT
    'PostalCode: valid format' AS Metric,
    SUM(CASE
        WHEN PostalCode LIKE '[A-Z][0-9] [0-9][A-Z][A-Z]'
          OR PostalCode LIKE '[A-Z][0-9][0-9] [0-9][A-Z][A-Z]'
          OR PostalCode LIKE '[A-Z][A-Z][0-9] [0-9][A-Z][A-Z]'
          OR PostalCode LIKE '[A-Z][A-Z][0-9][0-9] [0-9][A-Z][A-Z]'
          OR PostalCode LIKE '[A-Z][0-9][A-Z] [0-9][A-Z][A-Z]'
          OR PostalCode LIKE '[A-Z][A-Z][0-9][A-Z] [0-9][A-Z][A-Z]'
        THEN 1 ELSE 0 END) AS Count,
    COUNT(*) AS Total
FROM Customers
UNION ALL
SELECT
    'Email: valid format',
    SUM(CASE WHEN Email LIKE '%@%.%' AND CHARINDEX(' ', Email) = 0 THEN 1 ELSE 0 END),
    COUNT(*)
FROM Customers
UNION ALL
SELECT
    'Phone: NULL or missing',
    SUM(CASE WHEN Phone IS NULL THEN 1 ELSE 0 END),
    COUNT(*)
FROM Customers;
```

## Explanation

**LIKE pattern for UK postcodes**
UK postcodes have six valid formats (A9 9AA, A99 9AA, A9A 9AA, AA9 9AA, AA99 9AA, AA9A 9AA). Each requires a distinct LIKE pattern because SQL Server's LIKE syntax does not support quantifiers (`{1,2}`). The patterns use character class syntax (`[A-Z]`, `[0-9]`) which is supported in T-SQL. The missing-space detection separates records that have the correct structure but need reformatting from those that are fundamentally invalid.

**Space insertion as a correction script**
The `SuggestedCorrection` column in Step 1 computes the corrected postcode by inserting a space before the last three characters (the inward code). For a 5-character code: `XX` + space + `9AA`; for a 6-character code: `XXX` + space + `9AA`; for 7-character: `XXXX` + space + `9AA`. This is the standard UK postcode reformatting rule and produces an UPDATE-ready correction without manual intervention.

**Test domain detection**
Email addresses with test domains (example.com, test.com, placeholder.com) are technically valid in format but indicate test data loaded into a production table. IANA reserves example.com explicitly for documentation and testing — real customers will never have an @example.com email. Detecting these prevents marketing campaigns from sending to test addresses that bounce or generate spam complaints.

**Ofcom reserved numbers**
The UK's Ofcom reserves the 07700 900xxx number range for use in TV, film, and fiction — these numbers cannot be assigned to real subscribers. `07700900000` through `07700900999` are commonly used as placeholder phone numbers in test data. Any of these values appearing in a production customer database indicates a test record that was not cleaned up before go-live.

## Severity
**Medium** — Address format errors cause silent failures in downstream systems: postcodes without spaces fail address validation APIs; non-E.164 phones fail SMS gateway validation; emails with uppercase characters may fail case-sensitive matching. These failures often generate no error in the ETL — the record loads with its original (invalid) value — and only surface when the downstream system rejects the record during campaign or communication dispatch.
