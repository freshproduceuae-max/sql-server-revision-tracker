# G16-T01 — Geospatial | Coordinate Range and Validity Check

## ID
G16-T01

## Group
16 — Geospatial

## Type
Coordinate Range and Validity Check — Validating That Latitude and Longitude Values Fall Within Physically Possible Ranges

## Live Scenario
A UK retail chain's customer database stores delivery coordinates captured from an address lookup API. A misconfiguration in the API wrapper transposes the latitude and longitude fields for all addresses in Scotland: a customer in Edinburgh (latitude 55.95, longitude -3.19) is stored as latitude -3.19, longitude 55.95. The coordinate range check immediately flags all Scottish customers: their latitudes are below 50° (Scotland is between 54°–61°N) and their longitudes are above 10° (Scotland is between 6°W–2°E). The 2,300 affected customers' orders are routed to incorrect delivery depots for six weeks before the check is added to the nightly ETL validation.

## The Question
> Coordinate validity checks verify that latitude and longitude values are within physically possible ranges (latitude: -90 to +90, longitude: -180 to +180), within an expected geographic region (e.g., UK: latitude 49–61°N, longitude 8°W–2°E), and are not default or sentinel values (0,0 — the Gulf of Guinea; NULL; exact integer degree values indicating rounded/dummy coordinates). SQL validates these properties using range comparisons and detects transposed pairs using domain-specific boundary checks.
> **"Validate the geospatial coordinates in the Customers table: check all latitude and longitude values are within valid global ranges, verify they fall within the expected UK region, detect likely transposed coordinate pairs, and identify sentinel or placeholder coordinates that indicate a geocoding failure."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: Global range validity check
SELECT
    CustomerID,
    Latitude,
    Longitude,
    CASE
        WHEN Latitude IS NULL OR Longitude IS NULL
             THEN 'NULL: Coordinate not geocoded'
        WHEN Latitude < -90  OR Latitude > 90
             THEN 'INVALID LATITUDE: ' + CAST(Latitude AS VARCHAR) + ' outside -90 to +90 range'
        WHEN Longitude < -180 OR Longitude > 180
             THEN 'INVALID LONGITUDE: ' + CAST(Longitude AS VARCHAR) + ' outside -180 to +180 range'
        ELSE 'Valid range'
    END AS GlobalRangeFlag
FROM Customers;

-- Step 2: Regional validity — UK expected bounds
-- UK: latitude 49.8 to 60.9, longitude -8.2 to 1.8
SELECT
    CustomerID,
    Latitude,
    Longitude,
    Country,
    CASE
        WHEN Latitude IS NULL OR Longitude IS NULL
             THEN 'NULL: Cannot check region'
        WHEN Country IN ('UK') AND (Latitude < 49.8 OR Latitude > 60.9)
             THEN 'OUT OF REGION: UK customer latitude ' + CAST(Latitude AS VARCHAR)
                  + ' outside UK range 49.8–60.9°N'
        WHEN Country IN ('UK') AND (Longitude < -8.2 OR Longitude > 1.8)
             THEN 'OUT OF REGION: UK customer longitude ' + CAST(Longitude AS VARCHAR)
                  + ' outside UK range 8.2°W–1.8°E'
        WHEN Country IN ('US') AND (Latitude < 24.0 OR Latitude > 71.5)
             THEN 'OUT OF REGION: US customer latitude outside continental/Alaska range'
        ELSE 'Within expected region'
    END AS RegionFlag
FROM Customers
WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL;

-- Step 3: Transposed coordinate detection
-- A transposed UK coordinate has latitude in longitude range and vice versa
SELECT
    CustomerID,
    Latitude,
    Longitude,
    Country,
    CASE
        WHEN Country IN ('UK')
             AND Latitude BETWEEN -8.2 AND 1.8
             AND Longitude BETWEEN 49.8 AND 60.9
             THEN 'LIKELY TRANSPOSED: Lat/Lon appear swapped — '
                  + CAST(Latitude AS VARCHAR) + ', ' + CAST(Longitude AS VARCHAR)
                  + ' should probably be ' + CAST(Longitude AS VARCHAR)
                  + ', ' + CAST(Latitude AS VARCHAR)
        ELSE 'Not transposed'
    END AS TransposedFlag
FROM Customers
WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL;

-- Step 4: Sentinel and placeholder coordinate detection
SELECT
    CustomerID,
    Latitude,
    Longitude,
    CASE
        WHEN Latitude = 0 AND Longitude = 0
             THEN 'SENTINEL (0,0): Gulf of Guinea — geocoding failure default'
        WHEN Latitude = 51.5 AND Longitude = -0.1
             THEN 'SENTINEL (London centroid): Default geocoding fallback for UK addresses'
        WHEN Latitude = FLOOR(Latitude) AND Longitude = FLOOR(Longitude)
             THEN 'ROUNDED: Whole-number coordinates — likely a manual entry or rounded geocode'
        WHEN ABS(Latitude) < 0.001 OR ABS(Longitude) < 0.001
             THEN 'NEAR-ZERO: Coordinate is very close to zero — possible geocoding failure'
        ELSE 'No sentinel detected'
    END AS SentinelFlag
FROM Customers
WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL;

-- Step 5: Coordinate quality summary
SELECT
    'Total customers'                      AS Metric, COUNT(*) AS Value
FROM Customers
UNION ALL
SELECT 'With coordinates (both not NULL)', COUNT(*)
FROM Customers WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL
UNION ALL
SELECT 'Missing coordinates (either NULL)', COUNT(*)
FROM Customers WHERE Latitude IS NULL OR Longitude IS NULL
UNION ALL
SELECT 'Out of UK region', COUNT(*)
FROM Customers
WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL AND Country = 'UK'
  AND (Latitude < 49.8 OR Latitude > 60.9 OR Longitude < -8.2 OR Longitude > 1.8)
UNION ALL
SELECT 'Sentinel (0,0)', COUNT(*)
FROM Customers WHERE Latitude = 0 AND Longitude = 0;
```

## Explanation

**Layered coordinate validation**
Coordinate validation proceeds in layers: global range (physically impossible values) → regional bounds (plausible but wrong geography) → sentinel detection (valid coordinates that indicate a default rather than a real location) → transposition detection (swapped fields). Each layer catches a different failure mode; a coordinate that passes the global range check may still fail the regional bounds check.

**Transposition detection via domain knowledge**
Detecting transposed coordinates requires knowing the expected bounds for both fields in the specific region. For UK addresses, latitude is approximately 50–61 and longitude is approximately -8 to +2. A transposed UK coordinate has latitude in the range -8 to +2 and longitude in the range 50–61 — a very distinctive signature that can only be detected using regional knowledge, not global range checks alone.

**The (0,0) sentinel problem**
The coordinate (0°N, 0°E) — the intersection of the prime meridian and the equator in the Gulf of Guinea — is not a valid address for any customer of a UK or US business, yet it is one of the most common geocoding failure values because many systems default to (0,0) when geocoding fails. A (0,0) check is a mandatory component of any geocoding quality validation.

**Whole-number coordinate quality signal**
Real GPS coordinates have 4–6 decimal places of precision. A latitude of exactly 51° or a longitude of exactly -1° indicates manual entry or a coarse lookup — not a precise geocode. Step 4's `Latitude = FLOOR(Latitude)` check identifies these rounded values, which may be accurate to within 100km but useless for precise delivery routing.

## Severity
**Medium** — Invalid coordinates cause silent failures in geographic analysis: distance calculations, depot assignment, and heat-map visualisations silently use incorrect locations. The impact ranges from minor (slightly wrong delivery distance) to severe (orders routed to wrong depots, customers excluded from geographic campaigns because their coordinates place them in the wrong region).
