# G16-T04 — Geospatial | Geographic Clustering and Density Analysis

## ID
G16-T04

## Group
16 — Geospatial

## Type
Geographic Clustering and Density Analysis — Detecting Unusual Concentrations and Sparse Regions in Spatial Data

## Live Scenario
A utility company maps its customer base to plan infrastructure investment. A post-load analysis reveals that 4,200 of 180,000 customer coordinates (2.3%) share the exact same latitude/longitude to 4 decimal places — they all plot to the centre of a single postcode area rather than to individual premises. These are customers whose addresses were geocoded at postcode-area centroid level rather than premise level, because the geocoding API had no match for their specific address. At centroid resolution, these customers appear as a dense cluster in the city centre that is indistinguishable from genuine high-density areas, skewing the infrastructure demand model. The clustering analysis, computing the number of customers within 0.1km of each coordinate, flags this cluster as statistically anomalous (density 400× higher than the next densest location).

## The Question
> Geographic clustering analysis identifies grid cells or radius zones with unusually high or low customer density, which may indicate geocoding failures (centroid clustering), data loading errors (records duplicated with the same address), or genuine business concentration (urban vs rural density). SQL approximates spatial density using degree-based grid partitioning and radius-based counting without requiring a dedicated spatial index.
> **"Analyse geographic clustering in the Customers table: group customer coordinates into 1-degree latitude/longitude grid cells to identify concentration zones, detect coordinate pairs that appear at identical or near-identical locations (suggesting centroid geocoding rather than premise geocoding), and flag any grid cell with a suspiciously high proportion of total customers."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Step 1: 1-degree grid cell density analysis
-- Partition coordinates into 1°×1° cells and count customers per cell
WITH GridCells AS (
    SELECT
        CustomerID,
        Latitude,
        Longitude,
        FLOOR(Latitude)  AS LatCell,   -- e.g. 51.5 → cell 51
        FLOOR(Longitude) AS LonCell    -- e.g. -0.1 → cell -1 (truncates toward zero)
    FROM Customers
    WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL
),
CellCounts AS (
    SELECT
        LatCell,
        LonCell,
        COUNT(*)                  AS CustomersInCell,
        (SELECT COUNT(*) FROM Customers WHERE Latitude IS NOT NULL) AS TotalCustomers
    FROM GridCells
    GROUP BY LatCell, LonCell
)
SELECT
    LatCell,
    LonCell,
    CAST(LatCell AS VARCHAR) + '°–' + CAST(LatCell + 1 AS VARCHAR) + '°N, '
    + CAST(LonCell AS VARCHAR) + '°–' + CAST(LonCell + 1 AS VARCHAR) + '°E/W' AS CellLabel,
    CustomersInCell,
    TotalCustomers,
    ROUND(100.0 * CustomersInCell / NULLIF(TotalCustomers, 0), 1) AS PctOfTotal,
    CASE
        WHEN 100.0 * CustomersInCell / NULLIF(TotalCustomers, 0) > 50
             THEN 'EXTREME CONCENTRATION: >50% of customers in one 1-degree cell'
        WHEN 100.0 * CustomersInCell / NULLIF(TotalCustomers, 0) > 25
             THEN 'HIGH CONCENTRATION: >25% of customers in one cell — investigate'
        ELSE 'Normal distribution'
    END AS DensityFlag
FROM CellCounts
ORDER BY CustomersInCell DESC;

-- Step 2: Exact coordinate duplicate detection
-- Customers sharing coordinates to 4 decimal places (~11m precision)
WITH CoordGroups AS (
    SELECT
        ROUND(Latitude,  4) AS RoundedLat,
        ROUND(Longitude, 4) AS RoundedLon,
        COUNT(*) AS CustomerCount,
        STRING_AGG(CAST(CustomerID AS VARCHAR), ', ') AS CustomerIDs
    FROM Customers
    WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL
    GROUP BY ROUND(Latitude, 4), ROUND(Longitude, 4)
)
SELECT
    RoundedLat,
    RoundedLon,
    CustomerCount,
    CustomerIDs,
    CASE
        WHEN CustomerCount >= 5
             THEN 'CLUSTER: ' + CAST(CustomerCount AS VARCHAR)
                  + ' customers at identical coordinates — probable centroid geocoding'
        WHEN CustomerCount >= 2
             THEN 'DUPLICATE LOCATION: Multiple customers at same coordinates — verify'
        ELSE 'Unique location'
    END AS ClusterFlag
FROM CoordGroups
ORDER BY CustomerCount DESC;

-- Step 3: 0.5-degree resolution density heatmap (finer grain)
SELECT
    FLOOR(Latitude  / 0.5) * 0.5 AS LatBand,
    FLOOR(Longitude / 0.5) * 0.5 AS LonBand,
    COUNT(*) AS CustomerCount,
    REPLICATE('█', COUNT(*)) AS DensityBar   -- visual density indicator
FROM Customers
WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL
GROUP BY
    FLOOR(Latitude  / 0.5) * 0.5,
    FLOOR(Longitude / 0.5) * 0.5
ORDER BY CustomerCount DESC;

-- Step 4: North/South/East/West distribution
SELECT
    CASE
        WHEN Latitude  >= 53.0 THEN 'North (≥53°N)'
        WHEN Latitude  >= 51.5 THEN 'Midlands (51.5°–53°N)'
        ELSE 'South (<51.5°N)'
    END AS LatitudeBand,
    CASE
        WHEN Longitude < -2.0 THEN 'West (<2°W)'
        WHEN Longitude < 0.0  THEN 'Central (0°–2°W)'
        ELSE 'East (≥0°E)'
    END AS LongitudeBand,
    COUNT(*) AS CustomerCount,
    ROUND(100.0 * COUNT(*) / NULLIF((SELECT COUNT(*) FROM Customers WHERE Latitude IS NOT NULL), 0), 1)
        AS PctOfTotal
FROM Customers
WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL
GROUP BY
    CASE WHEN Latitude >= 53.0 THEN 'North (≥53°N)'
         WHEN Latitude >= 51.5 THEN 'Midlands (51.5°–53°N)'
         ELSE 'South (<51.5°N)' END,
    CASE WHEN Longitude < -2.0 THEN 'West (<2°W)'
         WHEN Longitude < 0.0  THEN 'Central (0°–2°W)'
         ELSE 'East (≥0°E)' END
ORDER BY CustomerCount DESC;

-- Step 5: Coordinate precision analysis — how many decimal places?
SELECT
    CustomerID,
    Latitude,
    Longitude,
    LEN(CAST(Latitude  AS VARCHAR)) - CHARINDEX('.', CAST(Latitude  AS VARCHAR)) AS LatDecimalPlaces,
    LEN(CAST(Longitude AS VARCHAR)) - CHARINDEX('.', CAST(Longitude AS VARCHAR)) AS LonDecimalPlaces,
    CASE
        WHEN LEN(CAST(Latitude AS VARCHAR)) - CHARINDEX('.', CAST(Latitude AS VARCHAR)) <= 2
             THEN 'LOW PRECISION: ≤2 decimal places (~1km accuracy) — centroid-level geocode'
        WHEN LEN(CAST(Latitude AS VARCHAR)) - CHARINDEX('.', CAST(Latitude AS VARCHAR)) >= 5
             THEN 'HIGH PRECISION: ≥5 decimal places (~1m accuracy) — premise-level geocode'
        ELSE 'MEDIUM PRECISION: 3-4 decimal places (~10-100m accuracy)'
    END AS PrecisionFlag
FROM Customers
WHERE Latitude IS NOT NULL;
```

## Explanation

**Degree-based grid partitioning**
`FLOOR(Latitude)` partitions the coordinate space into 1°×1° cells — at 51°N latitude, this is approximately 111km × 70km (111km N-S × 111×cos(51°) km E-W). Finer grids (0.5°, 0.1°) increase resolution at the cost of more cells. For a UK customer base, 0.5° cells (~55km × 35km) provide a useful intermediate scale that highlights regional concentrations without creating hundreds of empty cells.

**REPLICATE for ASCII density bars**
`REPLICATE('█', COUNT(*))` generates a visual density bar proportional to the customer count. This is a practical technique for displaying spatial distribution in a query result without a dedicated visualisation tool — the DBA can see the relative density at a glance from the SQL result grid. The bar should be capped (e.g., `REPLICATE('█', LEAST(COUNT(*), 50))`) to prevent very large bars.

**Geocoding precision as a quality signal**
Step 5's decimal place count is a proxy for geocoding quality: 2 decimal places (~1km) indicates postcode-level geocoding; 4 decimal places (~10m) indicates address-level; 6 decimal places (~0.1m) indicates GPS-level. A database that should have premise-level geocoding but shows many coordinates with only 2–3 decimal places has been geocoded at a lower precision than required, which will degrade any distance or proximity analysis.

**Concentration percentage as anomaly threshold**
In a nationally distributed customer base, no single 1-degree cell should contain more than ~10–15% of customers (unless the business is hyper-local). A cell with 50%+ concentration is almost always an indicator of a data quality problem — either centroid clustering (many customers geocoded to the same postcode centre) or a load error that duplicated records with the same address.

## Severity
**Low to Medium** — Geographic clustering errors degrade spatial analysis quality but rarely cause immediate business failures. The severity escalates when the clustering is severe enough to distort strategic decisions: a geocoding failure that places 5% of customers at a single postcode centroid will materially overstate density in that area and understate it in the customers' actual locations, potentially misdirecting infrastructure investment or sales territory assignment.
