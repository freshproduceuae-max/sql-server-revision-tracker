# G15-T10 — ETL/Load Process | Post-Load Reconciliation and Sign-Off

## ID
G15-T10

## Group
15 — ETL/Load Process

## Type
Post-Load Reconciliation and Sign-Off — Generating an End-to-End Validation Report Confirming the Load Is Complete and Correct

## Live Scenario
A financial services firm's daily ETL loads trade confirmations into a regulatory reporting database. Their SLA requires the database to be reconciled and signed off by 06:00 GMT before trading opens. Previously, sign-off was manual — a DBA ran four separate queries, compared the results against an email from the source system, and recorded the outcome in a shared spreadsheet. Four times in a year the sign-off check was skipped due to time pressure, and twice the skipped checks had concealed load errors that only surfaced hours later during trading. The post-load reconciliation query, generating a single pass/fail scorecard across all validation dimensions in under 3 seconds, replaced the manual process and enabled automated sign-off with an alert triggered only when any check fails.

## The Question
> Post-load reconciliation produces a consolidated sign-off report across all key validation dimensions: row count, financial totals, date range coverage, FK integrity, duplicate rates, and NULL rates. A single query generating a PASS/FAIL scorecard per check enables automated load certification — the ETL pipeline continues only if all checks pass. SQL implements this as a UNION of individual check results, each returning a check name, expected value, actual value, variance, and pass/fail status.
> **"Generate a post-load reconciliation report for the Orders and Transactions ETL: check row counts against expected minimums, verify financial totals are within expected ranges, confirm date coverage is complete, validate FK integrity is intact, confirm there are no duplicate keys, and produce a single PASS/FAIL scorecard that could gate automated sign-off."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`
**Customers** — `schemas/01_Customers.csv`
**Products** — `schemas/03_Products.csv`
**Transactions** — `schemas/05_Transactions.csv`

## Solution Query

```sql
-- Post-load reconciliation scorecard — single UNION producing one row per check
-- Result: CheckName | ExpectedValue | ActualValue | Variance | PassFail | Details

-- Define expected thresholds (in production these would come from a control table)
DECLARE @MinOrderCount       INT     = 1;
DECLARE @MinTransactionCount INT     = 1;
DECLARE @MaxNullRatePct      DECIMAL(5,2) = 10.0;   -- max acceptable NULL % for required fields
DECLARE @MaxDuplicateRatePct DECIMAL(5,2) = 0.5;    -- max acceptable duplicate % by business key
DECLARE @MaxOrphanRatePct    DECIMAL(5,2) = 0.0;    -- zero tolerance for FK violations

SELECT
    CheckName,
    CAST(ExpectedValue AS VARCHAR(50)) AS ExpectedValue,
    CAST(ActualValue   AS VARCHAR(50)) AS ActualValue,
    CAST(Variance      AS VARCHAR(50)) AS Variance,
    CASE
        WHEN PassFail = 1 THEN 'PASS'
        ELSE 'FAIL'
    END AS PassFail,
    Details
FROM (

    -- Check 1: Orders row count
    SELECT
        'Orders row count'              AS CheckName,
        @MinOrderCount                  AS ExpectedValue,
        COUNT(*)                        AS ActualValue,
        COUNT(*) - @MinOrderCount       AS Variance,
        CASE WHEN COUNT(*) >= @MinOrderCount THEN 1 ELSE 0 END AS PassFail,
        'Minimum ' + CAST(@MinOrderCount AS VARCHAR) + ' records required' AS Details
    FROM Orders

    UNION ALL

    -- Check 2: Transactions row count
    SELECT
        'Transactions row count',
        @MinTransactionCount,
        COUNT(*),
        COUNT(*) - @MinTransactionCount,
        CASE WHEN COUNT(*) >= @MinTransactionCount THEN 1 ELSE 0 END,
        'Minimum ' + CAST(@MinTransactionCount AS VARCHAR) + ' records required'
    FROM Transactions

    UNION ALL

    -- Check 3: Orders TotalAmount NULL rate
    SELECT
        'Orders: TotalAmount NULL rate %',
        0,
        ROUND(100.0 * SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 2),
        ROUND(100.0 * SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 2) - 0,
        CASE WHEN 100.0 * SUM(CASE WHEN TotalAmount IS NULL THEN 1 ELSE 0 END)
                  / NULLIF(COUNT(*), 0) <= @MaxNullRatePct THEN 1 ELSE 0 END,
        'Max acceptable NULL rate: ' + CAST(@MaxNullRatePct AS VARCHAR) + '%'
    FROM Orders

    UNION ALL

    -- Check 4: Orders CustomerID NULL rate
    SELECT
        'Orders: CustomerID NULL rate %',
        0,
        ROUND(100.0 * SUM(CASE WHEN CustomerID IS NULL THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 2),
        ROUND(100.0 * SUM(CASE WHEN CustomerID IS NULL THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 2),
        CASE WHEN SUM(CASE WHEN CustomerID IS NULL THEN 1 ELSE 0 END) = 0 THEN 1 ELSE 0 END,
        'Zero tolerance: CustomerID must be populated on all orders'
    FROM Orders

    UNION ALL

    -- Check 5: Date range completeness — both tables have records
    SELECT
        'Orders date range present',
        1,
        CASE WHEN COUNT(DISTINCT CAST(OrderDate AS DATE)) > 0 THEN 1 ELSE 0 END,
        CASE WHEN COUNT(DISTINCT CAST(OrderDate AS DATE)) > 0 THEN 0 ELSE -1 END,
        CASE WHEN COUNT(DISTINCT CAST(OrderDate AS DATE)) > 0 THEN 1 ELSE 0 END,
        CAST(COUNT(DISTINCT CAST(OrderDate AS DATE)) AS VARCHAR) + ' distinct dates found'
    FROM Orders WHERE OrderDate IS NOT NULL

    UNION ALL

    -- Check 6: FK integrity — Orders referencing valid Customers
    SELECT
        'Orders→Customers FK orphan rate %',
        0,
        ROUND(100.0 * SUM(CASE WHEN c.CustomerID IS NULL AND o.CustomerID IS NOT NULL
                               THEN 1 ELSE 0 END) / NULLIF(COUNT(*), 0), 2),
        ROUND(100.0 * SUM(CASE WHEN c.CustomerID IS NULL AND o.CustomerID IS NOT NULL
                               THEN 1 ELSE 0 END) / NULLIF(COUNT(*), 0), 2),
        CASE WHEN SUM(CASE WHEN c.CustomerID IS NULL AND o.CustomerID IS NOT NULL
                           THEN 1 ELSE 0 END) / NULLIF(COUNT(*), 1.0)
                  <= @MaxOrphanRatePct / 100.0 THEN 1 ELSE 0 END,
        'Zero tolerance for FK violations'
    FROM Orders o
    LEFT JOIN Customers c ON o.CustomerID = c.CustomerID

    UNION ALL

    -- Check 7: FK integrity — Transactions referencing valid Orders
    SELECT
        'Transactions→Orders FK orphan rate %',
        0,
        ROUND(100.0 * SUM(CASE WHEN o.OrderID IS NULL AND t.OrderID IS NOT NULL
                               THEN 1 ELSE 0 END) / NULLIF(COUNT(*), 0), 2),
        ROUND(100.0 * SUM(CASE WHEN o.OrderID IS NULL AND t.OrderID IS NOT NULL
                               THEN 1 ELSE 0 END) / NULLIF(COUNT(*), 0), 2),
        CASE WHEN SUM(CASE WHEN o.OrderID IS NULL AND t.OrderID IS NOT NULL
                           THEN 1 ELSE 0 END) = 0 THEN 1 ELSE 0 END,
        'Zero tolerance: all Transactions must reference a valid Order'
    FROM Transactions t
    LEFT JOIN Orders o ON t.OrderID = o.OrderID

    UNION ALL

    -- Check 8: Duplicate Orders by business key (CustomerID + ProductID + date)
    SELECT
        'Orders business-key duplicate rate %',
        0,
        ROUND(100.0 *
            (SELECT COUNT(*) FROM (
                SELECT CustomerID, ProductID, CAST(OrderDate AS DATE) AS D
                FROM Orders WHERE CustomerID IS NOT NULL AND ProductID IS NOT NULL AND OrderDate IS NOT NULL
                GROUP BY CustomerID, ProductID, CAST(OrderDate AS DATE)
                HAVING COUNT(*) > 1
            ) DupGroups) / NULLIF(COUNT(*), 0), 2),
        ROUND(100.0 *
            (SELECT COUNT(*) FROM (
                SELECT CustomerID, ProductID, CAST(OrderDate AS DATE) AS D
                FROM Orders WHERE CustomerID IS NOT NULL AND ProductID IS NOT NULL AND OrderDate IS NOT NULL
                GROUP BY CustomerID, ProductID, CAST(OrderDate AS DATE)
                HAVING COUNT(*) > 1
            ) DupGroups) / NULLIF(COUNT(*), 0), 2),
        CASE WHEN (SELECT COUNT(*) FROM (
                SELECT CustomerID, ProductID, CAST(OrderDate AS DATE) AS D
                FROM Orders WHERE CustomerID IS NOT NULL AND ProductID IS NOT NULL AND OrderDate IS NOT NULL
                GROUP BY CustomerID, ProductID, CAST(OrderDate AS DATE)
                HAVING COUNT(*) > 1
            ) DupGroups) / NULLIF(COUNT(*), 1.0) * 100 <= @MaxDuplicateRatePct THEN 1 ELSE 0 END,
        'Max ' + CAST(@MaxDuplicateRatePct AS VARCHAR) + '% duplicate business keys allowed'
    FROM Orders

    UNION ALL

    -- Check 9: Financial total sanity — TotalAmount > 0
    SELECT
        'Orders: sum TotalAmount > 0',
        1,
        CASE WHEN SUM(TotalAmount) > 0 THEN 1 ELSE 0 END,
        0,
        CASE WHEN SUM(TotalAmount) > 0 THEN 1 ELSE 0 END,
        'Total revenue: ' + CAST(ROUND(SUM(TotalAmount), 2) AS VARCHAR)
    FROM Orders

    UNION ALL

    -- Check 10: Cross-table financial alignment
    SELECT
        'Orders vs Transactions amount alignment',
        1,
        CASE
            WHEN ABS(
                (SELECT SUM(TotalAmount) FROM Orders WHERE TotalAmount IS NOT NULL) -
                (SELECT SUM(Amount) FROM Transactions WHERE Amount IS NOT NULL)
            ) / NULLIF((SELECT SUM(TotalAmount) FROM Orders WHERE TotalAmount IS NOT NULL), 0)
            <= 0.05 THEN 1 ELSE 0 END,
        ROUND(
            ABS(
                (SELECT SUM(TotalAmount) FROM Orders WHERE TotalAmount IS NOT NULL) -
                (SELECT SUM(Amount) FROM Transactions WHERE Amount IS NOT NULL)
            ), 2),
        CASE
            WHEN ABS(
                (SELECT SUM(TotalAmount) FROM Orders WHERE TotalAmount IS NOT NULL) -
                (SELECT SUM(Amount) FROM Transactions WHERE Amount IS NOT NULL)
            ) / NULLIF((SELECT SUM(TotalAmount) FROM Orders WHERE TotalAmount IS NOT NULL), 0)
            <= 0.05 THEN 1 ELSE 0 END,
        'Orders total: ' + CAST(ROUND((SELECT SUM(TotalAmount) FROM Orders), 2) AS VARCHAR)
        + ' | Transactions total: ' + CAST(ROUND((SELECT SUM(Amount) FROM Transactions), 2) AS VARCHAR)

) Checks
ORDER BY PassFail ASC, CheckName;  -- FAIL rows first for immediate visibility
```

## Explanation

**UNION-based scorecard pattern**
Each check is an independent SELECT returning a single row with a consistent column signature (CheckName, ExpectedValue, ActualValue, Variance, PassFail, Details). UNION ALL combines them into a single result set that an orchestration tool, monitoring dashboard, or stored procedure can evaluate with `WHERE PassFail = 'FAIL'`. This pattern scales to any number of checks without changing the consuming code.

**FAIL rows first**
`ORDER BY PassFail ASC` sorts 'FAIL' before 'PASS' (F < P in ASCII). This means the first rows returned are always the failures — in a monitoring dashboard that shows only the first N rows, failures are always visible without scrolling.

**DECLARE thresholds for easy tuning**
Placing all tolerance values in DECLARE statements at the top (rather than hardcoding them inside CASE expressions) allows the reconciliation query to be maintained as a stored procedure where thresholds are parameters. A daily ETL that tolerates 0.5% duplicates during bulk loads but requires 0% duplicates in overnight reconciliation can call the same procedure with different parameter values.

**Cross-table financial alignment (Check 10)**
Comparing the sum of Orders.TotalAmount to the sum of Transactions.Amount provides an end-to-end financial reconciliation: if every order generates exactly one transaction, the totals should match. A 5% tolerance accommodates legitimate discrepancies (partial payments, adjustments) while flagging material mismatches that indicate a load shortfall or double-counting.

**Automated sign-off integration**
The scorecard is designed for automated consumption: a SQL Agent job or SSIS package can `SELECT COUNT(*) ... WHERE PassFail = 'FAIL'` and use the result as a conditional branch — zero failures proceeds to the next ETL step; any failure routes to an alert and halts the pipeline. The Details column provides the failure message that would appear in the alert email, eliminating the need for a DBA to re-query to diagnose the issue.

## Severity
**High** — Post-load reconciliation is the final control that prevents corrupt data from entering production reporting. Every ETL defect that is not caught by individual step checks (staging count, transformation validation, FK audit) is caught here. Without this gate, data quality failures propagate silently into reports, dashboards, and downstream systems until a downstream consumer notices an inconsistency — often days later and after business decisions have been made on incorrect data.
