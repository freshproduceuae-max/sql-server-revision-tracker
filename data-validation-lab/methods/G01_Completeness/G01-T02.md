# G01-T02 — Completeness | Blank / Empty String

## ID
G01-T02

## Group
1 — Completeness

## Type
Blank / Empty String

## Live Scenario
A telecoms company passes NULL checks after a data migration, but campaign emails still fail to send. Investigation reveals that the source CRM wrote empty strings (`''`) for missing email addresses instead of NULLs. The receiving system's NULL check passed every row. The fix requires detecting both NULLs and empty strings as missing data.

## The Question
> Your NULL check from G01-T01 passed, but the marketing team still reports bounced emails.
> **"Some records have an email field that looks populated but is actually empty. Find all rows where Email or Phone is either NULL or a blank string, and flag which issue each row has."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Detect both NULL and blank strings
SELECT
    CustomerID,
    FirstName + ' ' + LastName AS CustomerName,
    Email,
    Phone,
    CASE
        WHEN Email IS NULL                   THEN 'Email: NULL'
        WHEN LTRIM(RTRIM(Email)) = ''        THEN 'Email: blank string'
        ELSE 'Email: OK'
    END AS Email_Issue,
    CASE
        WHEN Phone IS NULL                   THEN 'Phone: NULL'
        WHEN LTRIM(RTRIM(Phone)) = ''        THEN 'Phone: blank string'
        ELSE 'Phone: OK'
    END AS Phone_Issue
FROM Customers
WHERE Email  IS NULL OR LTRIM(RTRIM(ISNULL(Email, '')))  = ''
   OR Phone  IS NULL OR LTRIM(RTRIM(ISNULL(Phone, '')))  = '';

-- Summary: how many NULL vs blank per field
SELECT
    'Email' AS Field,
    SUM(CASE WHEN Email IS NULL                     THEN 1 ELSE 0 END) AS NullCount,
    SUM(CASE WHEN LTRIM(RTRIM(Email)) = ''          THEN 1 ELSE 0 END) AS BlankCount
FROM Customers
UNION ALL
SELECT
    'Phone',
    SUM(CASE WHEN Phone IS NULL                     THEN 1 ELSE 0 END),
    SUM(CASE WHEN LTRIM(RTRIM(Phone)) = ''          THEN 1 ELSE 0 END)
FROM Customers;
```

## Expected Output

| CustomerID | CustomerName | Email_Issue | Phone_Issue |
|---|---|---|---|
| 3 | Mohammed Al-Rashid | Email: NULL | Phone: OK |
| 8 | (blank email row) | Email: blank string | Phone: OK |

## Explanation

**NULL vs blank — two different problems, same outcome**
A NULL means the value was never provided. A blank string `''` means the field was populated with nothing — it exists as a value, just an empty one. `IS NULL` will not catch blank strings; `= ''` will not catch NULLs. You must check for both every time.

**LTRIM / RTRIM before the empty check**
A value stored as `'   '` (three spaces) is not empty — it has characters. LTRIM/RTRIM strips all leading and trailing whitespace before the comparison, so space-only strings are caught correctly. SQL Server 2017+ has TRIM() as a shorthand.

**ISNULL before LTRIM in the WHERE clause**
`LTRIM(RTRIM(ISNULL(Email, '')))` converts a NULL to an empty string first, then trims. Without ISNULL, calling LTRIM on a NULL returns NULL, and the `= ''` comparison evaluates to UNKNOWN, silently dropping the row.

## Severity
**High** — Blank strings pass NULL validation gates and silently corrupt all downstream processes that assume a non-NULL field contains usable data.
