# G01-T07 — Completeness | Optional Field Population Rate

## ID
G01-T07

## Group
1 — Completeness

## Type
Optional Field Population Rate / Density Check

## Live Scenario
A CRM team wants to run a personalisation campaign using customer job title and company name — both optional fields. Before investing in the campaign, the data manager asks: "What percentage of our customer base actually has these fields populated?" If it's below 60%, the campaign isn't viable. This is not a data error check — it's a data density audit to understand what's usable.

## The Question
> Not every field is mandatory, but low population rates on optional fields can still block business use cases.
> **"Produce a completeness profile for the entire Customers table — for every column, show what percentage of rows have a non-NULL, non-blank value. Sort by population rate ascending so the worst columns appear first."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Column-level population rate across the whole table
SELECT
    ColumnName,
    TotalRows,
    PopulatedCount,
    TotalRows - PopulatedCount          AS MissingCount,
    CAST(PopulatedCount * 100.0 / TotalRows AS DECIMAL(5,1)) AS PopulationPct,
    CASE
        WHEN PopulatedCount * 100.0 / TotalRows >= 95 THEN 'Excellent'
        WHEN PopulatedCount * 100.0 / TotalRows >= 80 THEN 'Good'
        WHEN PopulatedCount * 100.0 / TotalRows >= 60 THEN 'Acceptable'
        WHEN PopulatedCount * 100.0 / TotalRows >= 40 THEN 'Poor'
        ELSE                                               'Critical'
    END AS PopulationRating
FROM (
    SELECT 'CustomerID' AS ColumnName,
           COUNT(*)     AS TotalRows,
           COUNT(CustomerID) AS PopulatedCount
    FROM Customers
    UNION ALL
    SELECT 'FirstName', COUNT(*), SUM(CASE WHEN LEN(LTRIM(RTRIM(ISNULL(FirstName,'')))) > 0 THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'LastName', COUNT(*), SUM(CASE WHEN LEN(LTRIM(RTRIM(ISNULL(LastName,'')))) > 0 THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'Email', COUNT(*), SUM(CASE WHEN LEN(LTRIM(RTRIM(ISNULL(Email,'')))) > 0 THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'Phone', COUNT(*), SUM(CASE WHEN LEN(LTRIM(RTRIM(ISNULL(Phone,'')))) > 0 THEN 1 ELSE 0 END)
    FROM Customers
    UNION ALL
    SELECT 'DOB', COUNT(*), COUNT(DOB)
    FROM Customers
    UNION ALL
    SELECT 'Country', COUNT(*), SUM(CASE WHEN LEN(LTRIM(RTRIM(ISNULL(Country,'')))) > 0 THEN 1 ELSE 0 END)
    FROM Customers
) profile
ORDER BY PopulationPct ASC;
```

## Expected Output

| ColumnName | TotalRows | PopulatedCount | MissingCount | PopulationPct | PopulationRating |
|---|---|---|---|---|---|
| DOB | 20 | 18 | 2 | 90.0% | Good |
| Phone | 20 | 18 | 2 | 90.0% | Good |
| Email | 20 | 18 | 2 | 90.0% | Good |
| Country | 20 | 20 | 0 | 100.0% | Excellent |
| FirstName | 20 | 20 | 0 | 100.0% | Excellent |

## Explanation

**Population rate vs NULL rate**
NULL rate = how many rows are NULL. Population rate = how many rows have a real, non-blank value. Population rate is more useful because it combines NULL and blank-string checks into a single metric. A column with 10% NULLs and 5% blank strings has a population rate of 85%, not 90%.

**Using UNION ALL to build a column profile**
Because SQL cannot dynamically iterate over columns without dynamic SQL, this pattern uses one SELECT per column stacked with UNION ALL. It is verbose but transparent and easy to audit. For tables with many columns, a dynamic SQL version using INFORMATION_SCHEMA can generate this automatically.

**The rating thresholds are business decisions**
95%+ Excellent, 80%+ Good, 60%+ Acceptable are example thresholds — the actual thresholds depend on the business context. A 60% population rate on an optional field might be fine for a marketing segment but unacceptable for a regulatory report. Always agree thresholds with stakeholders before treating them as pass/fail gates.

## Severity
**Informational / Medium** — Low population rates on optional fields are not errors but they block use cases. This check feeds strategic decisions about data collection improvement and campaign viability.
