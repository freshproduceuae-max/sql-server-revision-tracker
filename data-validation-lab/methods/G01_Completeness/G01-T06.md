# G01-T06 — Completeness | Conditional Completeness

## ID
G01-T06

## Group
1 — Completeness

## Type
Conditional Completeness — If A is Filled, B Must Be Too

## Live Scenario
An e-commerce platform allows customers to pay by card or bank transfer. If payment method is 'Card', the CardLastFour and CardExpiry fields must be populated. If it is 'BankTransfer', the IBAN field must be populated. Neither field is universally mandatory — the rule is conditional. A batch of orders passed basic NULL checks because the fields were optional, but 12 orders have PaymentMethod = 'Card' with no CardLastFour, causing payment processing to fail.

## The Question
> Some fields are only mandatory when another field has a specific value.
> **"In the Orders table, if PaymentMethod is 'Card' then CardLastFour must be present. If Status is 'Delivered' then ShipDate must be present. Find all records that violate these conditional rules."**

## Table Reference
**Orders** — `schemas/02_Orders.csv`

| Condition | Required Field |
|---|---|
| PaymentMethod = 'Card' | CardLastFour must not be NULL |
| Status = 'Delivered' | ShipDate must not be NULL |
| Status = 'Shipped' | ShipDate must not be NULL |
| DiscountPct > 0 | ApprovedBy must not be NULL |

## Solution Query

```sql
-- Conditional completeness violations
SELECT
    OrderID,
    CustomerID,
    Status,
    ShipDate,
    DiscountPct,
    CASE
        WHEN Status IN ('Delivered', 'Shipped') AND ShipDate IS NULL
            THEN 'ShipDate required when Status = ' + Status
        WHEN DiscountPct > 0 AND ApprovedBy IS NULL
            THEN 'ApprovedBy required when discount applied'
        ELSE 'OK'
    END AS ConditionalViolation
FROM Orders
WHERE
    (Status IN ('Delivered', 'Shipped') AND ShipDate IS NULL)
 OR (DiscountPct > 0 AND ApprovedBy IS NULL);

-- Summary count by rule broken
SELECT
    'ShipDate missing on Delivered/Shipped' AS Rule,
    COUNT(*) AS ViolationCount
FROM Orders
WHERE Status IN ('Delivered', 'Shipped') AND ShipDate IS NULL
UNION ALL
SELECT
    'ApprovedBy missing on discounted order',
    COUNT(*)
FROM Orders
WHERE DiscountPct > 0 AND ApprovedBy IS NULL;
```

| 1018 | Shipped | NULL | 0 | ShipDate required when Status = Shipped |
| 1021 | Processing | NULL | 10.00 | ApprovedBy required when discount applied |

## Explanation

**Why conditional completeness differs from simple NULL checks**
A simple NULL check treats every field the same. Conditional completeness says "this field is only required in certain situations." The pattern is always: `WHEN [trigger condition] AND [dependent field] IS NULL`. Both parts must be in the WHERE clause so only genuinely broken records are returned.

**Real-world conditional rules are business logic, not schema logic**
Database schemas enforce unconditional NOT NULL constraints. Conditional rules like "if payment method is Card then CardLastFour is required" live in application logic or validation scripts — they are rarely enforced at the schema level. This makes them invisible to standard NULL checks and easy to miss.

**CASE WHEN for labelling, WHERE for filtering**
The CASE WHEN in SELECT labels which rule was broken. The WHERE clause filters to only the offending rows. Together they give both the detail and the reason — without the CASE label, you would know a row is wrong but not why.

## Severity
**Critical** — Conditional completeness violations are often the most damaging because they are invisible to basic checks. An order with Status='Delivered' and no ShipDate is an SLA measurement failure; a discount with no approver is a fraud risk.
