# G01-T12 — Completeness | Missing Child Records

## ID
G01-T12

## Group
1 — Completeness

## Type
Missing Child Records — Parent Exists, No Children

## Live Scenario
A subscription SaaS platform creates an Account record for every sign-up, then expects at least one Subscription record to be created within the same transaction. A bug in the sign-up flow causes 23 accounts to be created with no linked subscription — the account exists, the user can log in, but they have no active plan and will never be billed. These orphaned parents look complete row-by-row but are functionally broken.

## The Question
> A parent record existing without any child records is often a sign of a failed transaction, a load error, or a business rule violation.
> **"Find all Customers who have never placed an Order, all Orders with no line items, and all Employees with no department assignment. Return counts and the specific parent IDs."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`
**Orders** — `schemas/02_Orders.csv`
**Employees** — `schemas/04_Employees.csv`

## Solution Query

```sql
-- Customers with no orders (parent with no children)
SELECT
    c.CustomerID,
    c.FirstName + ' ' + c.LastName  AS CustomerName,
    c.CreatedDate,
    DATEDIFF(DAY, c.CreatedDate, GETDATE()) AS DaysSinceCreated,
    'No orders placed' AS Issue
FROM Customers c
WHERE NOT EXISTS (
    SELECT 1 FROM Orders o WHERE o.CustomerID = c.CustomerID
)
ORDER BY c.CreatedDate DESC;

-- Alternate syntax using LEFT JOIN anti-join
SELECT
    c.CustomerID,
    c.FirstName + ' ' + c.LastName  AS CustomerName,
    c.CreatedDate
FROM Customers c
LEFT JOIN Orders o ON c.CustomerID = o.CustomerID
WHERE o.OrderID IS NULL
ORDER BY c.CreatedDate DESC;

-- Summary: how many parents have zero children?
SELECT
    'Customers with no Orders'          AS Check,
    COUNT(*) AS ParentCount
FROM Customers c
WHERE NOT EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerID = c.CustomerID)
UNION ALL
SELECT
    'Employees with no Department',
    COUNT(*)
FROM Employees e
WHERE e.Department IS NULL OR LTRIM(RTRIM(e.Department)) = ''
UNION ALL
SELECT
    'Orders with zero TotalAmount',
    COUNT(*)
FROM Orders
WHERE TotalAmount = 0 OR TotalAmount IS NULL;

-- Customers grouped by order count (0, 1, 2–5, 6+)
SELECT
    CASE
        WHEN OrderCount = 0  THEN '0 orders'
        WHEN OrderCount = 1  THEN '1 order'
        WHEN OrderCount <= 5 THEN '2–5 orders'
        ELSE                      '6+ orders'
    END AS OrderBand,
    COUNT(*) AS CustomerCount
FROM (
    SELECT c.CustomerID, COUNT(o.OrderID) AS OrderCount
    FROM Customers c
    LEFT JOIN Orders o ON c.CustomerID = o.CustomerID
    GROUP BY c.CustomerID
) s
GROUP BY
    CASE
        WHEN OrderCount = 0  THEN '0 orders'
        WHEN OrderCount = 1  THEN '1 order'
        WHEN OrderCount <= 5 THEN '2–5 orders'
        ELSE                      '6+ orders'
    END
ORDER BY MIN(OrderCount);
```

## Expected Output

**Customers with no orders:**
| CustomerID | CustomerName | CreatedDate | DaysSinceCreated | Issue |
|---|---|---|---|---|
| 18 | Priya Nair | 2024-03-01 | 304 | No orders placed |
| 20 | Omar Farooq | 2024-01-15 | 349 | No orders placed |

**Summary:**
| Check | ParentCount |
|---|---|
| Customers with no Orders | 2 |
| Employees with no Department | 1 |

## Explanation

**NOT EXISTS vs LEFT JOIN IS NULL — choose one, know both**
Both find the same rows. `NOT EXISTS` is often faster when the child table is large and the FK column is indexed — it stops scanning as soon as it finds one match. `LEFT JOIN IS NULL` materialises the full join first. In practice the query optimiser often produces the same plan. NOT EXISTS reads more clearly as English: "give me customers where no order exists."

**This is a business completeness check, not a schema constraint**
A schema constraint would prevent a customer row from existing without an order. But business reality is more nuanced — new customers exist before they place an order. The validation question is: "how long has this customer existed without an order?" The `DaysSinceCreated` column supports a business rule like "flag any customer with no order after 30 days for a sales outreach."

**The order band distribution**
The final query groups customers by how many orders they have placed. The 0-order band is the missing-child group, but seeing it alongside 1-order and 2–5-order customers gives business context — what percentage of the base is inactive?

## Severity
**High** — Missing child records represent broken business processes: unfulfilled sign-ups, incomplete transactions, or failed ETL joins. In billing systems, a parent with no children means revenue is not being captured.
