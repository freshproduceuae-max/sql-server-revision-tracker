# G01-T01 — Completeness | NULL in Mandatory Field

## ID
G01-T01

## Group
1 — Completeness

## Type
NULL in Mandatory Field

## Live Scenario
A retail bank runs a nightly batch to send e-statements. The job crashes at 2 AM because 47 customer records have NULL in the Email column — a field the system treats as mandatory. The data team needs a query to catch these before the batch runs, flag which mandatory fields are affected, and produce a count by field so the fix is prioritised.

## The Question
> You have just loaded 500 new customer records. Before any downstream job runs, your manager asks:
> **"Which records are missing critical fields — Email, Phone, or Date of Birth — and how many are affected per field?"**
> Write a query that returns the problem rows and a field-level summary count.

## Table Reference
**Customers** — `schemas/01_Customers.csv`

| Column | Rule |
|---|---|
| Email | Mandatory |
| Phone | Mandatory |
| DOB | Mandatory |

## Solution Query

```sql
-- Part A: Row-level detail
SELECT
    CustomerID,
    FirstName + ' ' + LastName         AS CustomerName,
    CASE WHEN Email IS NULL THEN 'MISSING' ELSE 'OK' END AS Email_Status,
    CASE WHEN Phone IS NULL THEN 'MISSING' ELSE 'OK' END AS Phone_Status,
    CASE WHEN DOB   IS NULL THEN 'MISSING' ELSE 'OK' END AS DOB_Status
FROM Customers
WHERE Email IS NULL
   OR Phone IS NULL
   OR DOB   IS NULL
ORDER BY CustomerID;

-- Part B: Field-level summary
SELECT 'Email' AS FieldName,
       COUNT(*) AS NullCount,
       CAST(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM Customers) AS DECIMAL(5,2)) AS NullPct
FROM Customers WHERE Email IS NULL
UNION ALL
SELECT 'Phone', COUNT(*),
       CAST(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM Customers) AS DECIMAL(5,2))
FROM Customers WHERE Phone IS NULL
UNION ALL
SELECT 'DOB', COUNT(*),
       CAST(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM Customers) AS DECIMAL(5,2))
FROM Customers WHERE DOB IS NULL
ORDER BY NullCount DESC;
```

## Expected Output

**Part A:**
| CustomerID | CustomerName | Email_Status | Phone_Status | DOB_Status |
|---|---|---|---|---|
| 3 | Mohammed Al-Rashid | MISSING | OK | OK |
| 5 | Chen Wei | OK | OK | MISSING |

**Part B:**
| FieldName | NullCount | NullPct |
|---|---|---|
| Email | 2 | 10.00% |
| DOB | 2 | 10.00% |
| Phone | 1 | 5.00% |

## Explanation

**Why `IS NULL` and not `= NULL`**
NULL is not a value — it is the absence of one. Any comparison with `= NULL` evaluates to UNKNOWN, not TRUE, so `WHERE Email = NULL` returns zero rows. `IS NULL` is the only correct operator.

**UNION ALL for a field-level report**
Each SELECT counts NULLs for one column. UNION ALL stacks them into one result without deduplication overhead. Using UNION instead of UNION ALL would silently merge rows with identical counts.

**Integer division trap**
`COUNT(*) * 100.0` forces decimal arithmetic. Without `.0`, SQL Server performs integer division and truncates the percentage to 0%.

## Severity
**Critical** — NULL mandatory fields block downstream jobs, break joins, and prevent communications from being sent.
