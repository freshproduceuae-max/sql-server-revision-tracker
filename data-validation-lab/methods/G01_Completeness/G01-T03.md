# G01-T03 — Completeness | Placeholder Text (N/A, Unknown, TBD, 999)

## ID
G01-T03

## Group
1 — Completeness

## Type
Placeholder Text

## Live Scenario
A logistics company imports customer records from three legacy systems. All three pass NULL and blank-string checks. But when the sales team queries for UK customers, hundreds of records appear with Country = 'N/A', Phone = '0000000000', and DOB = '01/01/1900'. These are placeholder values written by the legacy systems when real data was unavailable. They pass every basic check but corrupt every report they touch.

## The Question
> After fixing NULLs and blank strings, your QA lead says:
> **"Some fields have values, but those values are meaningless — placeholders like 'N/A', 'Unknown', '0000000000', or '01/01/1900'. Write a query that detects and classifies these across the key columns."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Detect placeholder values across key columns
SELECT
    CustomerID,
    FirstName,
    LastName,
    Email,
    Phone,
    DOB,
    Country,
    CASE
        WHEN Email IS NULL                                          THEN 'NULL'
        WHEN LTRIM(RTRIM(Email)) = ''                              THEN 'Blank'
        WHEN UPPER(LTRIM(RTRIM(Email)))
             IN ('N/A','NA','NONE','UNKNOWN','NULL','TBC','TBD',
                 'NO EMAIL','NOEMAIL','TEST@TEST.COM','@')          THEN 'Placeholder'
        ELSE 'OK'
    END AS Email_Flag,
    CASE
        WHEN Phone IS NULL                                          THEN 'NULL'
        WHEN LTRIM(RTRIM(Phone)) = ''                              THEN 'Blank'
        WHEN UPPER(LTRIM(RTRIM(Phone)))
             IN ('N/A','NA','NONE','UNKNOWN','NULL','TBC','TBD')    THEN 'Placeholder text'
        WHEN Phone LIKE '000%'                                      THEN 'Zero-fill placeholder'
        WHEN Phone LIKE '999%'                                      THEN 'Nine-fill placeholder'
        WHEN Phone LIKE '111%'                                      THEN 'Repeated-digit placeholder'
        ELSE 'OK'
    END AS Phone_Flag,
    CASE
        WHEN DOB IS NULL                                            THEN 'NULL'
        WHEN DOB = '19000101'                                       THEN 'Sentinel date 01/01/1900'
        WHEN DOB = '19010101'                                       THEN 'Sentinel date 01/01/1901'
        WHEN DOB > GETDATE()                                        THEN 'Future date — impossible'
        ELSE 'OK'
    END AS DOB_Flag
FROM Customers
WHERE
    UPPER(LTRIM(RTRIM(ISNULL(Email,'')))) IN ('N/A','NA','NONE','UNKNOWN','NULL','TBC','TBD','NO EMAIL','@')
    OR Phone LIKE '000%' OR Phone LIKE '999%' OR Phone LIKE '111%'
    OR UPPER(LTRIM(RTRIM(ISNULL(Phone,'')))) IN ('N/A','NA','NONE','UNKNOWN','NULL')
    OR DOB IN ('19000101','19010101')
    OR DOB > GETDATE();

-- Summary: how widespread is the placeholder problem?
SELECT
    'Email' AS Field, COUNT(*) AS PlaceholderCount
FROM Customers
WHERE UPPER(LTRIM(RTRIM(ISNULL(Email,'')))) IN ('N/A','NA','NONE','UNKNOWN','NULL','TBC','TBD')
UNION ALL
SELECT 'Phone', COUNT(*)
FROM Customers
WHERE UPPER(LTRIM(RTRIM(ISNULL(Phone,'')))) IN ('N/A','NA','NONE','UNKNOWN','NULL')
   OR Phone LIKE '000%' OR Phone LIKE '999%'
UNION ALL
SELECT 'DOB', COUNT(*)
FROM Customers
WHERE DOB IN ('19000101','19010101');
```

## Expected Output

| CustomerID | FirstName | Email_Flag | Phone_Flag | DOB_Flag |
|---|---|---|---|---|
| 16 | N/A | Placeholder | Placeholder text | Sentinel date 01/01/1900 |
| 19 | Ahmed | OK | Nine-fill placeholder | OK |

## Explanation

**Why a shared blocklist matters**
Different source systems use different conventions for "I don't have this value." Building a single IN list of known placeholders (`N/A`, `NONE`, `TBC`, `TBD`, `NULL` as text) and maintaining it in one place means validation rules stay consistent across all tables.

**UPPER before the IN comparison**
`N/A` and `n/a` and `N/a` are the same placeholder. Converting to UPPER first means one blocklist covers all case variations without multiplying entries.

**Sentinel dates**
`01/01/1900` is the most common date placeholder in legacy SQL systems — it is the default minimum DATE value in many tools. A DOB of 1900 for a living customer is impossible and should be treated as missing.

**Repeated-digit phone numbers**
`0000000000`, `9999999999`, `1111111111` are common fake phone entries. The LIKE '000%' / '999%' / '111%' patterns catch them without listing every possible variant.

## Severity
**High** — Placeholder values pass NULL and blank checks, inflate completeness metrics, and corrupt analytics. A customer with Phone = '0000000000' cannot be reached; they appear complete but are not.
