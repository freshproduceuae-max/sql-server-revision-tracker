# G01-T04 — Completeness | Whitespace-Only Value

## ID
G01-T04

## Group
1 — Completeness

## Type
Whitespace-Only Value

## Live Scenario
An insurance company's online form accepts a customer's name by pressing the spacebar and submitting. The field is not blank — it contains characters — but those characters are spaces. The database stores `'   '` (three spaces). LEN('   ') returns 3. IS NULL returns false. The record looks complete in every standard check, but the customer's name is missing.

## The Question
> A data engineer tells you some name fields appear populated but render as nothing on screen.
> **"Find all records where FirstName, LastName, or Address fields contain only whitespace characters — spaces, tabs, or carriage returns — and look non-empty but carry no real data."**

## Table Reference
**Customers** — `schemas/01_Customers.csv`

## Solution Query

```sql
-- Detect whitespace-only values
SELECT
    CustomerID,
    FirstName,
    LastName,
    LEN(FirstName)              AS RawLength,
    LEN(LTRIM(RTRIM(FirstName))) AS TrimmedLength,
    CASE
        WHEN FirstName IS NULL                   THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(FirstName))) = 0    THEN 'Whitespace only'
        ELSE 'OK'
    END AS FirstName_Flag,
    CASE
        WHEN LastName IS NULL                    THEN 'NULL'
        WHEN LEN(LTRIM(RTRIM(LastName))) = 0     THEN 'Whitespace only'
        ELSE 'OK'
    END AS LastName_Flag
FROM Customers
WHERE LEN(LTRIM(RTRIM(ISNULL(FirstName, '')))) = 0
   OR LEN(LTRIM(RTRIM(ISNULL(LastName,  '')))) = 0;

-- Also catch tab and carriage return characters (not stripped by LTRIM/RTRIM in older SQL Server)
SELECT
    CustomerID,
    FirstName,
    CASE
        WHEN REPLACE(REPLACE(REPLACE(FirstName, ' ', ''), CHAR(9), ''), CHAR(13), '') = ''
        THEN 'Contains only spaces/tabs/CR'
        ELSE 'OK'
    END AS FirstName_DeepCheck
FROM Customers
WHERE FirstName IS NOT NULL
  AND LEN(FirstName) > 0
  AND REPLACE(REPLACE(REPLACE(FirstName, ' ', ''), CHAR(9), ''), CHAR(13), '') = '';
```

## Expected Output

| CustomerID | FirstName | RawLength | TrimmedLength | FirstName_Flag |
|---|---|---|---|---|
| 22 | (three spaces) | 3 | 0 | Whitespace only |
| 23 | (tab character) | 1 | 0 | Whitespace only |

## Explanation

**Why LEN fails to catch this**
`LEN('   ')` returns 3 — there are three characters. The field is not empty by length. Only after `LTRIM(RTRIM(...))` strips the spaces does the length drop to 0, revealing the value is meaningless.

**LTRIM/RTRIM only strips spaces**
`LTRIM` and `RTRIM` remove space characters (ASCII 32). They do NOT remove tab characters (CHAR(9)), carriage returns (CHAR(13)), or line feeds (CHAR(10)). The deep-check query uses REPLACE to strip all three before testing for empty — this is important for data imported from CSV files or copy-pasted from spreadsheets.

**ISNULL before the length check**
`LEN(LTRIM(RTRIM(ISNULL(FirstName, ''))))` — the ISNULL converts NULL to an empty string first. Without it, `LTRIM(NULL)` returns NULL and `LEN(NULL)` returns NULL, which is not equal to 0, so whitespace-only NULL-variant rows would be missed.

## Severity
**Medium** — Whitespace-only values pass all standard completeness checks and display as empty on screen, causing broken personalisation (e.g., "Dear ,") and failed address lookups.
