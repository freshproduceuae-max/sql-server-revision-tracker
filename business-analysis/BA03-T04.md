# BA03-T04 — Planning and Monitoring | Planning Business Analysis Information Management

## ID
BA03-T04

## Chapter
3 — Planning and Monitoring

## Live Scenario
A programme ends and the operations team inherits it. The requirements live across 200 emails, a shared drive, two Confluence spaces and one analyst's laptop. Within a month nobody can answer why a rule was built the way it was.

## The Question
> How do you plan information management so that analysis survives the people who produced it?

## Approach
1. Decide what must be retained long-term versus what is working material.
2. Choose one authoritative location per artefact type and make the others explicitly non-authoritative.
3. Define naming and versioning so a reader can tell current from superseded.
4. Set access and retention against the organisation's regulatory obligations.

## Deliverables
- An information management plan naming the authoritative source per artefact
- A retention and access rule set

## Tools
- Confluence or SharePoint as the system of record
- Jira for requirement state
- Excel for the traceability matrix

## Common Pitfall
Allowing two authoritative sources. The moment a requirement exists in both Jira and a Word document with no stated precedence, they diverge and both become untrustworthy.

## Interview Angle
This connects directly to data governance. If you have a data background, say so — the reasoning is identical to defining a golden source.
