# BA04-T04 — Elicitation and Collaboration | Communicating Business Analysis Information

## ID
BA04-T04

## Chapter
4 — Elicitation and Collaboration

## Live Scenario
The same requirement set goes to a steering committee, a development team and a compliance officer. All three receive the 80-page specification. The committee does not read it, the developers cannot find the acceptance criteria, and compliance misses the retention rule.

## The Question
> How do you communicate one set of information to three audiences without maintaining three versions of the truth?

## Approach
1. Keep one authoritative requirement set and derive audience views from it.
2. Match form to audience — summary and decisions for the committee, acceptance criteria for developers, rule extracts for compliance.
3. State clearly which view is authoritative so derived views are never edited in place.
4. Confirm the message landed rather than assuming distribution equals communication.

## Deliverables
- Audience-specific views derived from a single source
- A statement of which artefact is authoritative

## Tools
- Confluence for the source
- PowerPoint for the committee view
- Jira for developer-facing criteria

## Common Pitfall
Maintaining parallel documents per audience. They drift within weeks and you can no longer say which one the build followed.

## Interview Angle
Tailoring communication to audience is a standard competency question. Use a concrete three-audience example rather than generalities.
