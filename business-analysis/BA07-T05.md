# BA07-T05 — Requirements Analysis and Design Definition | Defining Solution Options

## ID
BA07-T05

## Chapter
7 — Requirements Analysis and Design Definition

## Live Scenario
The steering committee is presented with a single recommended solution and asks what else was considered. The answer is that alternatives were discussed informally but not assessed.

## The Question
> How do you define and assess genuine solution options rather than retrofitting justification onto a decision already made?

## Approach
1. Generate options that differ structurally — build, buy, configure, do nothing — not variants of one idea.
2. Include the do-nothing option honestly, since it is the baseline every other option must beat.
3. Assess each against the same criteria derived from the business need.
4. Be explicit about which requirements each option cannot satisfy.

## Deliverables
- A defined option set with assessment against common criteria
- Stated requirement gaps per option

## Tools
- Excel for weighted option scoring
- PowerPoint for the recommendation
- Confluence for the option analysis record

## Common Pitfall
Omitting do-nothing. It is often genuinely viable, and excluding it means the cost of change is never compared against the cost of the status quo.

## Interview Angle
Mentioning the do-nothing baseline unprompted marks you out. Most candidates never raise it.
