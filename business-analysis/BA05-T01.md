# BA05-T01 — Requirements Life Cycle Management | Tracing Requirements

## ID
BA05-T01

## Chapter
5 — Requirements Life Cycle Management

## Live Scenario
A regulator asks the bank to demonstrate that a specific lending control is implemented. The team can show the code and the test, but cannot show which regulatory obligation the control derives from, or that it covers the obligation fully.

## The Question
> What traceability would let the bank answer that question in an afternoon rather than a month?

## Approach
1. Trace upward from solution requirements to the business need and the obligation behind it.
2. Trace downward to design, build and test artefacts so coverage is demonstrable.
3. Keep traceability in the tool where requirements live, not in a separate spreadsheet that ages.
4. Use the trace to find both orphans and gaps — obligations with no requirement are the audit risk.

## Deliverables
- A requirements traceability matrix linking obligation to test
- A gap list of obligations with no covering requirement

## Tools
- Jira or Azure DevOps for linked issues
- IBM DOORS for large regulated sets
- Excel for a lightweight RTM

## Common Pitfall
A traceability matrix maintained by hand in a spreadsheet. It is accurate on the day it is written and misleading thereafter.

## Interview Angle
Traceability is a favourite in regulated-sector interviews. Be able to explain forward and backward tracing and what each one catches.
